## Learnings

- **Server components don't invoke their child components synchronously** — `<PostForm initialData={...} />` is `React.createElement(PostForm, props)`, which returns an element, not a render. Tests that expect a `vi.fn()` mock to have been called by mounting a server component silently never assert what they meant to. Assert on the returned element's `props` instead. [source](dev-journal/2026-05-07.md)
- **`vi.mock` factories hoist above top-level `const`** — referencing a `vi.fn()` declared at module scope inside a `vi.mock` factory fails with a hoisting error. Either inline in the factory or use `vi.hoisted`. [source](dev-journal/2026-05-07.md)
- **`AnimatePresence` `mode="wait"` stalls under happy-dom** — animation events don't fire, so the swap never completes. Use `findBy*` polling for any role that appears post-swap. Don't strictly assert `onClose` call counts: a follow-up mousedown during unmount can fire close handlers a second time. [source](dev-journal/2026-05-07.md)
- **`role="alert"` already implies live-region behaviour** — adding `aria-live="polite"` on top is contradictory (alert defaults to assertive); ATs handle the combination inconsistently. [source](dev-journal/2026-05-07.md)
- **Next.js `"use client"` files reject non-serializable function props at the diagnostic level** — even when both parent and child are client. Prefer implicit label/input nesting over `useId` + `htmlFor` in shared primitives. [source](dev-journal/2026-05-07.md)
- **Code-review findings can be wrong** — `Header.tsx` already had segment-boundary protection; `ProjectContent`'s `<style>` injection was intentionally global. Reading the surrounding context before fixing matters. [source](dev-journal/2026-05-07.md)
- **The `Bash` hook denies `grep`; subagent prompts emphasizing Bash get soft-rejected** — always use `rg`; subagent prompts that lead with `Read`/`LSP` over `Bash` land cleanly. [source](dev-journal/2026-05-07.md)
