## Tradeoffs

- **2026-05-07 — `AbortController` everywhere admin-mutates** — in-flight PUTs don't outlive unmount or rapid succession; aborts are silent. Cost: every admin component carries extra `useRef` + `useEffect` cleanup. Reversibility: easy. [source](dev-journal/2026-05-07.md)
- **2026-05-07 — Page tests use mock components for children** — tests are self-contained; visual regressions in real children (`PostForm`/`ProjectForm`) aren't surfaced by page tests. Integration coverage lives in form/component tests. [source](dev-journal/2026-05-07.md)
- **2026-05-07 — `AnimatePresence toHaveBeenCalled` not `toHaveBeenCalledOnce`** — tests pass deterministically; lose the assertion that close fires exactly once. `mode="wait"` stalls swaps under happy-dom (animation events don't fire); `findBy*` polling required. [source](dev-journal/2026-05-07.md)
- **2026-05-09 — Inlining shared strings vs `errorMessages.ts`** — one fewer file; trivial drift risk on 3 short stable words across two files. Reversibility: easy. [source](dev-journal/2026-05-09.md)
- **2026-05-09 — Removing `error.digest` UI** — cleaner default error surface; lost (theoretical) ability for a user to report a hash that maps to a server log. With ~1h log retention that ability was already largely theoretical. Re-add when external tracking is wired. [source](dev-journal/2026-05-09.md)

## Learnings

- **Server components don't invoke their child components synchronously** — `<PostForm initialData={...} />` is `React.createElement(PostForm, props)`, not a render. Tests expecting a `vi.fn()` mock to have been called will silently never assert what they meant to. Assert on the element's `props` instead, or mount with a test renderer. [source](dev-journal/2026-05-07.md)
- **`vi.mock` factories hoist above top-level `const`** — referencing a `vi.fn()` declared at module scope inside a `vi.mock` factory fails with a hoisting error. Either inline the mock implementation or use `vi.hoisted`. [source](dev-journal/2026-05-07.md)
- **`AnimatePresence mode="wait"` stalls under happy-dom** — animation events don't fire; use `findBy*` polling for post-swap state. Don't strictly assert `onClose` call counts. [source](dev-journal/2026-05-07.md)
- **`role="alert"` already implies assertive live-region** — adding `aria-live="polite"` is contradictory; ATs handle the combination inconsistently. [source](dev-journal/2026-05-07.md)
- **Code-review findings can be wrong** — two findings withdrew on closer reading: `Header.tsx` already had segment-boundary protection (`+ "/"`); `ProjectContent`'s `<style>` injection is intentionally global (consumer is an ancestor of `ProjectContent`, not a descendant). Read surrounding context before writing a fix. [source](dev-journal/2026-05-07.md)
- **Personal-site error boundaries don't need digest UI without log aggregation** — re-add the digest the same day external aggregation is wired, not before. [source](dev-journal/2026-05-09.md)
- **`next/link` for non-route hrefs is a small but real foot-gun** — `<Link>` for `mailto:`, external URLs, and static assets like `/resume.pdf` still pulls a client component into the tree and depends on Next's undocumented prefetch behaviour for non-route URLs. [source](dev-journal/2026-05-09.md)
- **Tests for thin convention files (`error.tsx` / `global-error.tsx`) are cheap insurance** — with the harness already in place, ~3 cases per file catch Next.js error-boundary contract drift (prop shape, reset wiring) on future upgrades. [source](dev-journal/2026-05-09.md)
