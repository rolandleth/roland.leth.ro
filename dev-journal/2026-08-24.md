## Watch-outs & Tech Debt

- **`format.ts` is imported by a client component** — `src/components/admin/PostForm.tsx` has `"use client"`. Anything added to `src/lib/utils/format.ts` ships to the browser, so a markdown-pipeline import there would drag `unified` and Shiki into the client bundle. Trigger: any time a formatter needs to become markdown-aware, put it in `src/lib/content/markdown.ts` instead.
- **`PostCard` parses each post body three times** — `truncateBody`, `extractDefinitions`, then the render. Build-time only (the list routes are static) and each parse is sub-millisecond on a ~10KB body, so it was not worth a combined `buildPostExcerpt`. Trigger: revisit if list routes ever go dynamic.

## Session 1

### Decisions

- **Slice definitions out of the source by node offset, not by rebuilding the line** — `extractDefinitions` returns `markdown.slice(node.position.start.offset, node.position.end.offset)`. Rebuilding from `label`/`url`/`title` was the first plan and would have needed two escaping conditionals (a `"` inside a single-quoted title, whitespace in a URL). Slicing removes the class instead of handling the instances.
- **Append every definition, not just the referenced ones** — a definition whose label is never referenced renders nothing, so filtering would cost a second walk over the excerpt for no visible difference.
- **Moved `truncateBody` from `src/lib/utils/format.ts` to `src/lib/content/markdown.ts`** — making the cut code-block-aware needs the parser, and `format.ts` reaches a client component (see Watch-outs). The alternative, exporting a small offset-lookup helper from `markdown.ts` into `format.ts`, would have inverted the dependency and pulled Shiki client-side.
- **Ask the parser whether an offset is inside a code block** — `enclosingCodeBlockStart` walks mdast `code` nodes rather than scanning for fence delimiters. Covers tilde fences, fences indented up to three spaces, info strings, indented four-space blocks, and fences nested in a list or blockquote; a regex would have needed a documented ceiling for each.
- **Pull back out of a straddling code block, don't extend forward** — extending past the closing fence could pull an arbitrarily long block into a preview. Pull-back is bounded and predictable.

### Tradeoffs

- **Code-block pull-back runs before the heading trim** — costs one extra `lastIndexOf` pass, buys the case where pulling out of a block strands the heading that introduced it. Reversibility: easy.
- **A code block starting at offset 0 keeps its partial slice** — nothing to pull back to, so the excerpt would be empty otherwise. An unclosed fence runs to end of input in CommonMark, so it still renders as code, just truncated. Mirrors the existing `lastHeadingBreak > 0` guard. Reversibility: easy.

### Incidents / Bugs

- **Reference-style links rendered as literal brackets in blog list excerpts** — `truncateBody` slices the raw body at ~700 chars, but link reference definitions (`[series]: /blog/tech/… "…"`) are authored at the bottom of a post. The excerpt lost them, so remark parsed `[the opener][series]` as a `linkReference` with no matching definition and fell back to the literal text. Inline code and fenced blocks were unaffected because they're self-contained. Affected 11 tech posts including the four most recent. Fix: `PostCard` appends `extractDefinitions(post.body)` to the preview when it truncated. Regression risk: low, one call site (`PostCard`, used by list and search).
- **Latent: the paragraph cut could land inside a fenced code block** — `lastIndexOf("\n\n")` finds the last blank line under 700 chars, which can be a blank line *inside* a fence whose closing delimiter falls past 700. No post currently triggers it. Fixed alongside, since the excerpt work was already open.

### What did I, Claude Code, or my agents learn from this

- **Explaining a workaround is a good moment to check whether it's needed.** The two escaping conditionals only existed because I'd decided to rebuild definition lines from parsed fields. Being asked to explain them surfaced that the parser already carries source offsets, which deleted both conditionals and the reasoning behind them.
- **A test can fail because the test is wrong, and it's worth checking that first.** Two failures this session were bad test premises, not bugs: `[a]: /url "He said "hi" once"` is not a valid CommonMark definition (an unescaped `"` closes the title), and my first fence fixtures put the closing delimiter *before* the 700-char mark, so the last blank line in range was the one after the fence rather than inside it. Both looked like code failures on first read.
- **Check the client/server boundary before deciding where a helper lives.** `format.ts` looks like a neutral util module; one of its ~40 importers is a `"use client"` component, which is what ruled out the smaller-diff option of importing the markdown pipeline into it.
