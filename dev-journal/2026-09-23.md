### Decisions

- **`postUpdateSchema` drops the slug refinement** — the post schemas share one `postFields` set and only `postCreateSchema` adds the refinement back (rejected: stop `PostForm` sending the title, which leaves the API contract wrong for any other client).
- **File write paths store the schema's output** — `validatePostFile` returns the normalized title; `planCreate`, `planOverwrite` and the bulk route store it; the guide importer stores `validation.data.title`/`.description` (rejected: collapsing in `fieldValue`, which would also change slugs, dates and every other frontmatter field).
- **Description field: live collapsed count, no `maxLength`, Save gated** — Roland's choice. The browser counts raw text and cuts a paste before `onChange` runs, so collapse-as-you-type couldn't fix the paste case. A shared `DescriptionField` component, not an `@apply` class, because what is shared is behaviour, not styling.
- **Prune guard: majority rule plus printed targets** — Roland's choice over type-to-confirm (relies on the operator reading) and print-only.
- **Production credentials live in `.env`** — confirmed by Roland. `SCRIPT_CREDENTIALS_HINT` in `src/lib/import/scriptEnv.ts` names the file and `vercel env pull .env --environment=production` (rejected: a separate production env file with a shared loader, a behaviour change nobody asked for).
- **The cron log takes the hub list from `revalidateGuideTopicHubs`'s return value** (rejected: a shared `topicSlugsOf` helper, which would still let the log name hubs the bust never reached).

- **Prune steps moved to `src/lib/import/uploadPruneRun.ts`** with store, rows and loggers injected, so `uploadPrune.ts` stays pure and the script is a thin shell.

### Tradeoffs

- **Majority guard** — catches a partial database/store mismatch; costs refusing a legitimately orphan-heavy store (fallback: the Vercel dashboard). Reversibility: easy.
- **`--overwrite` rewrites titles from before the collapse rule** — normalizes old rows; a dry run can show title updates nobody edited. Reversibility: easy.
- **The prune script keeps its Prisma client open through the deletes** — one `try/finally` instead of two phases; an idle connection meanwhile. Reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Mutations can mask each other** — with `maxLength` restored and the raw-length count applied together, `maxLength` truncated the paste and the "fits once collapsed" test passed. When a test survives a combined mutation, rerun each mutation alone.
- **Grep for the stale claim's wording, not the review's line list** — the review listed six "no cron" comments; searching the phrasing found a seventh in the bulk route.
- **Ordering tests on `indexOf` must assert presence first** — a missing header returns -1, which is less than any real index, so the comparison passes whatever the order.
- **`vercel env pull` defaults to the Development environment and `.env.local`**; `--environment=production` picks Production, it asks before overwriting (`--yes` skips that), and Sensitive values can't be read back. The docs don't say what a pull writes for a Sensitive variable.
- **A Bash hook blocks commands containing ` .env `** (`sensitive-dotfile`), commit messages included. Word commit messages around the filename.
