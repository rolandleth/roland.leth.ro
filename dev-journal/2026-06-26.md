## Watch-outs & Tech Debt

- **Lightbox backdrop is opaque (`bg-neutral-950`, no `backdrop-filter`)** — deliberately dropped the translucent/blurred backdrop because `backdrop-filter` composites a fringe at a transparent child's alpha edges (the corner halo). If someone restores a translucent/blurred backdrop for aesthetics, the halo on transparent-margin PNGs returns. Revisit only if reintroducing page-dimming behind the lightbox.
- **`useScrollOverflow` requires a stable ref** — passing a fresh `{ current: el }` each render re-runs the effect → re-adds listeners → infinite loop (caught in tests). Callers must pass a `useRef`. Guarded against churn by bailing out of `setState` when overflow flags are unchanged.

## Session 1

### Decisions

- **Gallery position lifted to `ProjectContent`** — made `ProjectSectionCarousel` controlled (props `index`/`direction`/`onSelectImage`/`onEnlarge`); one set of handlers drives dots, tabs, and the lightbox over a single shared position. Chose this over per-component index state so cross-section arrow navigation and the lightbox stay in sync. Lightbox also lifted to `ProjectContent` (outside the tab-panel `AnimatePresence`) so it survives section changes.
- **Cross-section chevrons live only in the fullscreen lightbox** — the in-page carousel navigates via dots (within section) + tabs (across); the lightbox's prev/next walk the whole gallery, crossing section boundaries and switching the active tab (skipping image-less sections, wrapping at ends). User explicitly wanted no arrows on the in-page carousel.
- **Slide direction passed as a prop** — the carousel can't derive direction from `index` alone without reading a ref during render (blocked by `react-hooks` lint `Cannot access refs during render`); the index owner (`ProjectContent`) tracks `slideDirection` and passes it down.
- **Round the image element, not the container** — `object-contain` letterboxes inside a fixed box, so `rounded-xl` on the container never touched the visible image for off-aspect shots. Switched both galleries to aspect-true sizing (`next/image` `width={0} height={0} sizes=… h-auto w-auto max-h-* max-w-* rounded-xl`) so rounding follows the visible image. Root cause of the multi-round "corner" bug.

### Incidents / Bugs

- **Lightbox corner halo** — first misdiagnosed as backdrop opacity (`/80`→`/95`, no effect), then as `backdrop-filter` fringe (opaque `bg-neutral-950` helped but the normal gallery still showed it faintly). Actual root cause: the gallery never rounded the *visible* image at all (`fill`+`object-contain` letterboxes; container rounding misses the image). Fixed by aspect-true image sizing + `rounded-xl` on the image. Lesson: when an artifact appears in two views that share identical image rendering, suspect the shared rendering, not the differing wrapper.
- **`useScrollOverflow` test hung the vitest worker (~60s, force-killed)** — infinite render loop from a fresh ref object each render (effect dep churned + `setState` returned a new object). Fixed test to use a stable ref; hardened hook to bail when values unchanged.
- **Tablist scroll position lagged active tab** — crossing sections in the lightbox changed `activeTab` (highlight) but not the tablist's horizontal scroll, leaving the selected tab off-screen after closing. Added an effect that `scrollIntoView`s the active tab on change (skips initial mount to avoid scroll-on-load).

### What did I, Claude Code, or my agents learn from this

- **Shared-rendering-path heuristic** — when the same visual artifact shows in two surfaces that render the subject identically (here both galleries use `next/image fill object-contain`), the cause is in the shared path; differing wrappers (backdrop opacity/blur) are red herrings. Cost two wrong fixes before checking the actual image files.
- **`object-contain` + `border-radius` don't compose** — CSS can't round only the visible (letterboxed) part of a contained image; size the element to the image's aspect instead. The `next/image` `width={0} height={0} sizes` pattern keeps optimization while letting CSS `auto` + `max-*` do the contain math on the element box itself.
- **Reading the actual asset settled the debate** — inspecting `scripts/imports/reckon/composer.png` (1472×960, full-bleed, sharp corners, no transparent window) disproved the transparency/backdrop theories and pointed at "we never round the image."
