## Session 1

### Decisions

- **Field name `cardImage`** — chose over the user's shorthand "thumb"/"og" and the earlier "thumbnail". The `app-copy-to-project` skill's generated manifest uses `cardImage`/`ogImage` as keys; a mismatch would make the import silently drop the field. "thumbnail" was renamed mid-session because the asset is a card image, not a thumbnail.
- **`heroImage` kept as final fallback in both chains** — card = `cardImage ?? ogImage ?? heroImage ?? firstImage`; OG = `ogImage ?? cardImage ?? heroImage ?? firstImage`. Alternative (drop `heroImage`, per an earlier chat instruction) was rejected after surfacing that it contradicted the skill's documented chains; user confirmed keep. `heroImage` otherwise remains the detail-page hero only.
- **Card and OG share one resolution concept via two helpers** — `resolveCardImage` / `resolveOgImage` in `src/lib/db/projects.ts`, both delegating to a shared `firstSectionImage`. Gallery card exposes the result as `ProjectGalleryItem.featuredImage`; the detail page's OG metadata calls `resolveOgImage`. Avoids duplicating the precedence rule across surfaces.

### Incidents / Bugs

- **Import script dropped the new image field** — `scripts/import-projects.ts` `writeProject` never wrote `thumbnail`/`cardImage` to the DB, and `referencedImageUrls` omitted it, so the uploaded blob would be deleted by the post-import orphan sweep. Root cause: the script keeps its own create/ref logic instead of using the lib. Fixed both spots (and again for `ogImage`); surfaced as a tech-debt watch-out above.

### Environment / Config Changes

- `prisma/schema.prisma`: added `Project.cardImage` and `Project.ogImage` (both `String?`). Prisma client regenerated; DB push still pending (see Open Threads).

### What did I, Claude Code, or my agents learn from this

- **The import path has two implementations** — `src/lib/import/projectImport.ts` (pure, tested core) and `scripts/import-projects.ts` (its own `writeProject` + `referencedImageUrls`). A schema field change must touch both; editing the lib alone passes tests but ships a broken import.
- **Match field names to the consuming skill, not the user's shorthand** — the manifest key the skill emits is the binding contract; a friendly-sounding rename that diverges from it breaks the import quietly.
