## Session 2

Built the full project FAQ feature, then the SEO/structured-data layer from `CONTINUUM-SEO-plan.md` (metaTitle, keywords, offers, applicationCategory, FAQPage + SoftwareApplication JSON-LD). Branch `feature/project-faq`.

### Decisions

- **FAQ render = always-in-DOM accordion, not `<details>` or conditional-mount** — kept the Framer Motion accordion the user picked, but the answer panel is always mounted and collapsed via height/opacity + `inert`/`aria-hidden`. Chose over `AnimatePresence` conditional-mount (which kept collapsed answers out of the SSR HTML, defeating the SEO/AI-citation goal) and over plain `<details>` (loses the motion). `inert` keeps collapsed panels out of tab order + a11y tree while the text stays crawlable.
- **`faqs` plural everywhere** — input/schema/manifest field is `faqs`, matching `sections`/`links`. Chose over the plan's `faq` (which kept DB plural but input singular); adapted the Continuum/Reckon manifests instead.
- **Flat `offers` price-points array** — builder emits a single `Offer` for one entry, `AggregateOffer` (low–high) for 2+; free = an explicit `"0"` entry; absent `offers` = price unknown. Chose over a structured base-price-vs-IAP model (JSON-LD only needs the range; `name`/`billingPeriod` already distinguish plans). Covers paid-upfront (Reckon), multi-IAP (Continuum), free, freemium.
- **`applicationCategory` manifest-driven, omitted when unset** — chose over the initial hardcoded `"BusinessApplication"` for every app bucket (which mislabeled Reckon) and over a default fallback.
- **JSON-LD emitted from server `page.tsx`, `url` from a hardcoded `SITE_ORIGIN` constant** — not the client `ProjectContent` (guarantees it's in SSR HTML) and not `siteBase()` (which calls `headers()` and would force the statically-generated project pages dynamic).
- **`price` validated as `^\d+(\.\d{1,2})?$`** — rejects `"Free"`/`"$4"` and keeps `Number(price)` sorting safe.

### Tradeoffs

- **Hardcoded `SITE_ORIGIN` in `projectJsonLd.ts`** — gained static generation of project pages; accepted that a domain change needs a code edit (vs. deriving from request). Reversibility: easy.

Fix: clear `.next` (user did) / redeploy. Regression risk: recurs on every import until a revalidation hook exists (logged as an open thread).
- **Continuum staged manifest accidentally replaced/lost** — recovered: the source was intact and the full manifest was in conversation context; rebuilt `scripts/imports/continuum/project.json`. No data lost.

### Environment / Config Changes

Needs `db:push` on each target DB. `offers` writes use `Prisma.DbNull` for the absent case (a bare `null` is reserved for JSON filters).

### What did I, Claude Code, or my agents learn from this

- **Direct-DB import scripts can't bust Next's cache** — `revalidateTag` is Next-runtime-only, so a `tsx` import process leaves `unstable_cache` (no TTL) serving stale data. Any out-of-band DB write needs an explicit revalidation step (endpoint ping, or a redeploy) baked into the workflow.
- **Always-mounted + `inert` is the crawlable-and-accessible accordion pattern** — "in the HTML source" (crawlers) and "in the a11y tree / tab order" (assistive tech) are independent axes; CSS/`inert` hide from the latter without removing from the former. `AnimatePresence` conditional-mount removes from both.
- **Concurrent sessions on shared files** — when the user runs two sessions, verify file state (and avoid committing another session's in-flight edits) before writing.
