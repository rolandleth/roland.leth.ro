## Watch-outs & Tech Debt

- **Cron is now a single point of failure for scheduled content** — dropping `revalidate = 3600` from the feed, archive, and sitemap means a silently dead cron strands every scheduled post indefinitely. The old backstop was self-healing. The `nothing due` heartbeat makes it *detectable* by log grep, but nothing alerts. Revisit if a scheduled post is ever reported missing, or add `revalidate = 86400` as cheap insurance (3 regenerations/day instead of 72).
- **`WINDOW_HOURS` is coupled to the cron schedule in `vercel.json`** — the lookback must stay wider than the interval. Overlap costs one redundant revalidation; a gap strands content silently. Commented at both ends. Trigger: any change to the cron schedule.
- **Vercel cron schedules are deploy-time constants** — they live in `vercel.json` and take no env interpolation, so tuning cadence to posting frequency means editing a line and redeploying, not flipping an env var. Worth confirming against current Vercel docs before relying on it.
- **`getPostsBySection` page boundaries depend on filtering in SQL** — future-dated posts sort to the head of a `datetime desc` list, so any read-time filter reintroduced after `skip` shifts every page boundary by the scheduled-post count, duplicating or dropping posts across pages. Pinned by tests; revisit if anyone reintroduces padding.
- **`postListItemSelect` carries the full `body`** — this is why the section list can't be cached as one whole-list entry (Next's data cache has a per-entry size limit). Constrains any future "cache everything and slice in memory" refactor. Existing comment in `posts.ts` already documents the column-level tradeoff.

## Session 1

### Decisions

- **Legacy redirects/rewrites moved from middleware to `next.config.ts`** — Vercel compiles them into its routing layer, so they resolve with no function invocation, and `redirects()` runs ahead of middleware entirely. Rules live in `src/lib/routing/legacyRoutes.ts` so they can import `SECTIONS` and be unit-tested. (Alternative rejected: tightening `config.matcher` with a `.*\..*` exclusion — it would break `/rss.xml`, `/feed.xml`, `/blog/:section/feed.xml`, the `.md` export, and dotted legacy slugs, and it's the same unanchored-extension shape as the 2026-07-26 matcher bypass.)
- **Middleware matcher narrowed to `/admin*` + `/api/admin*`** — no catch-all entry kept as a backstop, since a broad pattern is exactly what produced the 2026-07-26 bypass. An explicit namespace list has no equivalent failure mode. The admin auth gate stays as defense in depth alongside `requireAdmin`.
- **Root-level `/:slug` catch-all deleted outright** — it was pure legacy support and invoked a function on every unmatched path, including scanner probes. Confirmed zero traffic. Unmatched paths now resolve to the static 404. (Alternatives considered: freezing the slug list into `next.config` redirects, or `generateStaticParams` + `dynamicParams = false`; both rejected as unnecessary once traffic was confirmed absent.) `LEGACY_POST_SLUG_ALIASES` is unaffected — the blog route uses it independently for the old slugifier's dirty slugs.
- **Bot-probe filter deleted** — it existed to keep scanner traffic off the `/:slug` route. With that route gone and the matcher admin-only, a probe either misses the matcher entirely or lands in the admin namespace and gets the same treatment as any unauthenticated request.
- **`revalidate = 3600` replaced with a due-check cron** on the feed, archive, and sitemap. The old backstop regenerated all three hourly regardless of change; crawlers and feed readers guarantee traffic every hour, so "at most 24/day" was really "exactly 24/day" per route. The cron counts posts and guides that came due in a 2h window and busts only on a hit. (Alternatives rejected: unconditional hourly bust — 24 crons + 72 regenerations, worse than doing nothing; a real one-shot scheduler — needs QStash/Inngest/a due-table for a personal blog.)
- **Blog pagination moved from `?page=N` to `/blog/:section/p/:page`** — reading `searchParams` is what kept the list rendering per request despite its `generateStaticParams`. Page 1 now takes no params. Both routes prerender. `dynamicParams` left at default so a newly-created page 4 renders on demand rather than needing a redeploy.

### Tradeoffs

- **Legacy redirects now emit 308, not 301** — gained routing-layer resolution; accepted a status change that is functionally identical for these GET-only URLs (both permanent; 308 additionally preserves method). Reversibility: easy.
- **Scheduled posts surface on the blog list up to an hour late instead of instantly** — gained CDN delivery for the two highest-traffic pages plus the elimination of two uncached Postgres queries per view on pages 2+. Accepted that the list now matches the ≤1h everything else already had. Reversibility: moderate (would mean reverting the route split and the `getPostsBySection` rewrite).
- **`getPostsBySection` lost its padded-superset + read-time filter** — gained uniform, exact page boundaries and one cached fetcher per `(section, page)`; accepted dependence on the cron for scheduled-post surfacing. Reversibility: moderate.

### Incidents / Bugs

- **Nearly shipped a design that would blow the data-cache entry limit** — planned to cache each section's whole post list and slice in memory, mirroring `allPublishedPostSlugsCache`. Caught that `postListItemSelect` includes `body: true` (full markdown), so one entry would hold every post's body. Switched to per-page caching before writing it.
- **Nearly shipped an instant/lazy split across page boundaries** — an early plan added caching only for pages 2+ while leaving page 1's read-time filter intact. Page 1 would self-correct the moment a post came due while page 2 waited for the cron, so for up to an hour a post could vanish from page 1 without appearing on page 2. Resolved by making all pages uniform.
- **Wrote a bad test asserting `/admin/.env` 404s as a bot probe** — `BOT_PROBE_PATH_PREFIXES` is anchored at the path root and the extension check skips leading-dot segments, so it was never matched. Fixed the test, not the filter; the auth gate handles that path safely. (Moot after the filter was later deleted.)
- **Wrote a bad test asserting `/admin/../etc/passwd`** — the `URL` constructor normalizes `..` before the middleware sees it, so it asserted the URL parser rather than the gate. Removed.
- **Left the cron's no-op path unlogged, then reversed** — reasoned that an hourly no-op would bury real runs, which made "nothing due" indistinguishable from "cron stopped running". With the `revalidate` backstop gone that's the exact failure that strands scheduled posts. Added a heartbeat matching the ping route's existing convention, plus a test.

### What did I, Claude Code, or my agents learn from this

- **Check the traffic assumption before pricing a caching tradeoff.** I dismissed the `revalidate = 3600` cost as a rounding error because it "costs nothing in hours with no traffic." For a site with crawlers and feed readers, every hour has traffic — the discount was imaginary and the real number was ~72 guaranteed regenerations a day. The user caught it. Idle-hours caveats are worth nothing until you know whether the site is ever idle.
- **A static route cannot run a read-time filter.** This one fact explains the whole session's shape: why the feed/archive/sitemap needed `revalidate` while the blog list didn't, why prerendering the list forced the cron, and why the padded-superset trick had to go. Reason from "when does this code actually execute" before proposing a caching change.
- **Anchoring on preserving an existing mechanism can invent complexity that doesn't exist.** I warned the `getPostsBySection` rewrite was delicate because of `futureCount` offset arithmetic — arithmetic only needed if the read-time filter is preserved. Filtering in SQL made page boundaries exact multiples of `PAGE_SIZE` and the whole problem disappeared. Ask what the constraint is actually for before treating it as fixed.
- **Route segment config is compile-time.** `export const revalidate` is statically analyzed, so no runtime-computed revalidation window is expressible. Worth knowing before designing around one.
- **Worktrees in this project have no `node_modules`.** Entering one blocks `tsc`/`yarn test`; symlinking was denied. Use a plain branch in the main checkout unless deps are installed per worktree.
