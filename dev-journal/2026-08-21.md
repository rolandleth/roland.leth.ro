## Session 1

### Decisions

- **Admin pagination gets its own parser with no probe-cost ceiling** — chose a separate `parseAdminPageParam` (vs. reusing the public `parsePageParam`/`MAX_PAGE`) because the ceiling exists to bound a public crawler's probe surface, and admin is authenticated, single-user; that cost doesn't apply. Added `MAX_SAFE_ADMIN_PAGE` as a *different* bound afterward — not probe-cost, just keeping `skip` inside a 32-bit range Postgres/pg can bind.
- **`AdminPagination` centralizes the out-of-range redirect** (vs. duplicating a `page > totalPages` check in each of the three tabs) — one place, and it naturally fires before any HTML streams since Next builds the whole server tree before flushing.
- **Restored `BlogPostList`'s empty-page guard** after initially removing it (in a prior session) on the reasoning that the two blog caches "agree by construction." Re-derived the failure mode under scrutiny: `unstable_cache` serves stale values immediately after a bust and regenerates in the background, so an unpublish/delete between `isRealPage`'s read and this component's own read can genuinely diverge — not the case my monotonic-datetime argument ruled out, which only covered *new* posts becoming due, not unpublish/delete.
- **Split `adminTags.ts` out of `adminMetadata.ts`** to give `middlewareBypass.ts`'s `requireAdminPageSession` a closed `AdminPageTag` union without a circular import (`middlewareBypass.ts` ← `adminMetadata.ts` ← `middlewareBypass.ts` would have resulted from importing the tag type the other way).
- **`hasGenerateMetadataExport` rewritten to dynamically import + `typeof` check** instead of regex-matching source text (its second attempt in two sessions at fixing false negatives) — eliminates the whole class of "regex misses a syntactic form" bug rather than patching another case.
- **Lint gate**: fixed all 16 `sonarjs/parameterized-tests` errors rather than disabling the rule (user's explicit choice) — release branch's lint gate is green again.

### Tradeoffs

- **`errorDetails` now spreads every own-enumerable property of an Error**, not just `{message, stack}` — gained Prisma's `code`/`meta`/`clientVersion` surviving the log line (verified directly against Prisma's runtime source: `this.code=r,this.meta=n` are plain, enumerable assignments), accepted a wider/less precise return type (`Record<string, unknown>` intersection). Reversibility: easy, it's a pure function.
- **`resolvePage` wrapped in React's `cache()`** to dedupe the stale-ceiling warning across `generateMetadata` + page body — gained one log line per request instead of two, accepted that the actual dedup can't be verified in a unit test outside a real request scope (same limitation `bypassIdForRequest`'s own test already documents); covered with a structural test instead (source contains the `cache()` wrapper) plus a behavioral test proving both call sites still emit the warning independently.

### Incidents / Bugs

- **Second-layer admin defense gap, found by an external review mid-session**: `adminEditMetadata` (used by all four `[id]/edit` pages) only guards the `<title>` — it logs and falls back but does not stop the page body from rendering, since `generateMetadata` and the body are independent Next calls. A prior session's fix covered `guides/new`/`guide-topics/new` with a real `requireAdminPageSession` call but didn't notice the same gap existed on the four edit pages and the dashboard root (`/admin`, the page every other protected page's nav links back into — the *most* exposed page to the underlying client-nav bypass). Verified directly by reading `guides/[id]/edit/page.tsx`'s body (no session check at all) before fixing. Root cause: fixed the two pages the previous review named, missed that the same class extended further. Fix: extended `requireAdminPageSession` to all six data-reading pages, added a contract test tying every page's body-level data read to an actual call (not just prose), fixed the misleading docblock that had claimed `adminEditMetadata` "carries this same check."
- **Self-caught regex bug**: my own replacement for a vacuous `searchParams` assertion used `/interface Props \{[^}]*\}/`, which stops at the *first* `}` — the inner one closing `Promise<{ section: string }>` — so it never reached a `searchParams` field on a second line. Caught via a manual sanity check (temporarily adding `searchParams` to the real `Props` interface and confirming the test still passed when it shouldn't have). Fixed by stripping `//` comments and checking the whole remaining source instead of pattern-matching a brace-delimited region.
- **Vacuous test in my own dashboard test file**: `expect(PostsTab).not.toHaveBeenCalled()` for the unauthenticated case — discovered that creating `<PostsTab />` JSX never actually invokes the component; only real rendering does, which nothing in that test does. The assertion would pass whether the guard worked or was a complete no-op. Removed it (the sibling `rejects.toThrow` test already proves execution halts at the guard); rewrote the positive-path test to inspect the returned element tree's props directly instead of asserting a mock was called.

### What did I, Claude Code, or my agents learn from this

- **Verify an automated review's claims before relaying them, even the alarming ones** — the second review's top finding (edit pages unguarded) was confirmed by reading the actual page body before reporting it to the user as real; a lower-confidence finding elsewhere in the same review (the clock-split claim) needed a full re-derivation of the failure mode before I trusted it enough to act on it, and even then the review's own stated mechanism (post *becoming due*) turned out not to be the actual reachable path (unpublish/delete was).
- **A regex over source text is a standing liability, not a one-time bug** — `hasGenerateMetadataExport` was already a rewrite of a previous regex failure this session, and the *replacement* regex I wrote for `searchParams` failed the same way (nested braces) within the same session. The durable fix both times was leaving source-text matching entirely (dynamic import + `typeof`, or strip-comments-and-substring-match) rather than patching the pattern.
- **Sanity-check a new regression test by breaking the thing it's supposed to catch, every time** — did this for every new/restored test this session (archive `dynamicParams`, `searchParams` assertion, `legacyRoutes` section pinning, `makeArchiveCache` tag, the count-delegation test, the dashboard positive-path test) and it caught the vacuous-JSX-assertion bug and the nested-brace regex bug, both of which would otherwise have shipped as tests that provide false confidence.
