## Watch-outs & Tech Debt

- **Miss-stampede negative cache still deferred** — detail-page 404s are deliberately never cached (self-healing), so a slug-enumerating crawler hits Postgres per request. Revisit when prod DB metrics show probe traffic reaching the DB; add a short-TTL *negative* cache then, not durable miss caching. (Carries forward the 2026-07-17 watch-out.)
- **Admin body search is a seq scan** — `listGuidesForAdmin`/`listPostsForAdmin` use `contains` + `mode: insensitive` with no trigram/GIN index. Imperceptible at current volume; revisit at ~thousands of rows (needs a Prisma migration + `pg_trgm` extension).
- **Cross-table slug race is unenforced at the DB** — a guide and a topic can concurrently claim the same slug (app-checked via `findSlugOwner`; Postgres can't enforce cross-table uniqueness). Fine at single-user; revisit if write concurrency ever rises. Note: a P2002 on create is therefore always same-table.
- **`atomicWrite` is not power-loss durable** — no `fsync` by design; a torn write can't happen but a *lost* write can, and an idempotent re-run heals it. Don't add fsync without a concrete reason.

### Decisions

- **One phased commit per concern, committed as I went** — reviewability over a single mega-commit; suite kept green between phases.
- **Deferred 2 findings, measure-first** — miss-stampede negative cache (wait for prod DB metrics; see Watch-outs) and the admin-search GIN index (premature at dozens of rows).
- **Skipped 6 findings deliberately, with reasons** — (1) the "misleading P2002 race message" is a **false positive**: `Guide.slug`/`GuideTopic.slug` are separate per-table `@unique`s with no cross-table constraint, so a P2002 is always same-table and the message is accurate; (2) `describeGuideRefProblem` published-check would break the valid "publish guide before its topic" flow — addressed the *visibility* gap via a draft-topic picker flag instead; (3) `/api/admin/login` gate exemption is misleading (login lives at `/api/auth/login`) — added a steering comment; (4) app-level bot-404 logging is redundant with Vercel access logs and sits on the hottest path; (5) parallel guide file reads risk EMFILE unbounded and are premature for a handful of files; (6) `atomicWrite` fsync is unneeded for a self-healing dev-machine importer (narrowed the docstring instead).
- **`wrapNullableDetail` helper over per-module duplication** — collapsed the 4 detail-cache wrappers; each caller's fetch keeps its own transform, and read-time scheduling filters stay at the call site (never frozen into cache).
- **Guide cache tags namespaced `guide-detail-` / `guide-topic-`** — the old `guide-${slug}` made a guide slugged `topic-foo` collide with topic `foo`.
- **`@apply` for repeated button chains + a `useFormState` hook, not a full AdminForm shell** — followed the tailwind-reuse preference and DRY'd the identical state boilerplate, but the four forms' fields diverge too much to justify a shared shell (avoided premature abstraction).
- **Revalidate endpoint: per-resource isolation + 207** — a mid-batch failure now reports `errors` per resource and keeps the buckets that succeeded (a bare 500 sent the operator back to retry and double-bust); the guides branch now resolves + busts each pasted guide's parent topic hub via a bounded, admin-gated DB lookup.

### Tradeoffs

- **`atomicWrite` now stats + chmods to preserve the target's mode** — gained: the exported primitive won't silently reset a non-default file mode on overwrite; accepted: one extra `stat` syscall per write. Reversibility: easy.
- **Revalidate guides branch is no longer pure tag-busting** — gained: parent hubs refresh on the panel/script path; accepted: a DB round-trip in the endpoint. Justified because it's admin-gated with bounded input (unlike the public `[slug]` catch-all, which stays DB-free).

### Incidents / Bugs

- **Latent: a pure guide folder-move was silently dropped** — moving a guide file to a new topic folder with byte-identical content produced an empty diff → skipped as `UNCHANGED` → its `topicId` never re-resolved, so the move didn't take. Root cause: `planGuide` diffed content fields but not topic membership. Fixed by carrying the row's current `topicSlug` on `ExistingGuide` and comparing it to the file's folder-resolved target slug. Regression risk: low — test added, and an unchanged-folder re-run still skips.

### What did I, Claude Code, or my agents learn from this

- **A "needs a design decision" bug can collapse to a clean fix once an invariant is confirmed** — the folder-move fix looked architecturally hard (planner in folder-space, row in topicId-space) until I read the parser and found it already skips any guide whose folder lacks an `index.md`. That guarantee removed the unresolvable-folder edge and made a slug comparison sufficient. Read the constraints before declaring scope.
- **Not every review finding is a fix** — of 6 skips, 1 was a false positive, 2 were better solved differently than the finding proposed, and 3 were cost/benefit no-gos. Verifying the claim (e.g. reading the schema for the P2002 message) beats reflexively "fixing" it.
- **Binary checkboxes lose resolution nuance** — status here was fix / defer / skip / false-positive, not done/not-done; captured the detail in a "Resolution" section in the code-review file rather than flattening it to `[x]`.
