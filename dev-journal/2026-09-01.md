## Session 1

### Decisions

- **One resolver instead of two lookups** — `resolvePost` in `src/lib/db/posts.ts` returns a `PostResolution` union (`live` / `scheduled` / `missing`) from one row fetch and one `currentDatetimeString()`. Rejected: documenting the race and leaving it (the option Roland was offered and declined), and threading an optional `now` through both public signatures (pushes clock management to every call site).
- **`isFutureDatetime` carries the comparison** — the hand-rolled `<=` / `>` in `getPostBySlug` / `getScheduledPost` had been bypassing the existing helper, whose docblock already argued for a single captured `now`. Using it makes live and scheduled exact complements by construction.
- **Deleted `loadPost`, `getScheduledPost`, `loadScheduledPost`** — all three lost their last production caller once both detail routes read `loadPostResolution`. `getPostBySlug` stays as the narrow live-only accessor: `src/lib/db/detailCacheMiss.test.ts` exercises the cache layer through it.
- **Scheduled metadata routes through `buildPageMetadata`** — a hand-rolled `{ title, robots }` emits no `alternates`, so the page inherited the root layout's tech-feed default and contradicted the section feed the notice itself renders on `/blog/life/*`. Rejected: patching in a lone `alternates` block, which fixes the instance and leaves the divergence class.
- **`description` and `markdownPath` stay omitted on the scheduled branch** — the tease is title-only by design, and the `.md` twin is a stub rather than a markdown view of the page.
- **Scheduled `.md` stub gets real frontmatter** — `buildScheduledPostMarkdownFile` shares `postFrontmatterLines` with the live export and appends `scheduled: true`. `X-Robots-Tag` reaches search crawlers only; an agent fetching the URL sees the body alone, and a bare `# Title` reads as the post's content.

### Tradeoffs

- **Four fewer exports, more test churn** — deleting the three accessors meant retargeting tests written the day before at `loadPostResolution`. Gained one way to ask the question (a surviving `loadPost` would let a future caller reintroduce the split verdict); accepted a larger diff on new code. Reversibility: easy.
- **Scheduled pages now carry an OG card** — routing through `buildPageMetadata` means a shared scheduled link previews with the post's title instead of the site-generic card. Costs nothing, but it does widen what a pre-publish URL discloses to a link unfurler. Consistent with the title tease already accepted on 2026-08-31.

### Incidents / Bugs

- **`max-w-m` in `ScheduledPostNotice`** — commit `b6ca1da` (pure visual tuning) turned `max-w-md` into `max-w-m`; Tailwind v4 resolves `max-w-*` against the `--container-*` namespace and `globals.css` defines no `--container-m`, so the class emitted nothing and the body copy ran to the parent's `max-w-4xl`. Found by the daily review, fixed by hand to `max-w-lg`. No mechanical guard exists — see Watch-outs.
- **Two clock reads at the publish boundary** — `getPostBySlug` and `getScheduledPost` each called `currentDatetimeString()`, so a post crossing its `datetime` between the two answered no to both and fell through to `notFound()`, pinning a 404 at the moment it went live. Sub-millisecond window that must straddle the post's exact minute; the next cron run healed it, so the ceiling was the old behaviour on one post. Fixed by the single-read resolver; boundary tests pin `datetime === now` under fake timers.

### What did I, Claude Code, or my agents learn from this

- **A review finding can be already-mitigated one layer up.** The observability finding ("a stale notice serves 200 and looks like a normal pageview") was withdrawn after reading the cron: it already logs a heartbeat on its quiet path, with a comment stating that exact purpose. A pinned prerendered page executes no code and cannot report on itself, so the cron is the only layer where detection can live. Read the adjacent mechanism before writing up a gap.
- **Check the helpers before proposing a fix.** `isFutureDatetime` already existed with a docblock arguing for the single captured `now` the race fix needed. The fix landed as "use the existing helper" rather than "invent a pattern" only because the grep happened first.
- **"I don't really get it" means the explanation was wrong, not the reader.** The first pass at the race described it in terms of function signatures and clock reads. The one that landed was a timeline with a concrete post date and two comparisons written out. Lead with the failure, not the mechanism.
