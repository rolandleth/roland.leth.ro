## Watch-outs & Tech Debt

- **Feed `<id>` stability** — the feed-level `<id>` is pinned to `/api/feed/:section` and must never change; it's the identifier readers dedup subscriptions on. `rel="self"` (the pretty `/blog/:section/feed.xml`) is the mutable one. Revisit only if the section scheme changes.
- **`alternates` is replace-not-merge in Next** (verified in `node_modules/next/dist/lib/metadata/resolve-metadata.js`) — a page that sets `alternates` for `canonical`/`markdown` silently wipes an inherited feed-autodiscovery link. Trigger: any new page that both should carry the feed and sets its own alternates must re-declare `feed:` via `feedLinkForSection`.
- **Dev server can't run under the command sandbox** — `listen EPERM 0.0.0.0:3000`. Trigger: any task needing a live localhost server must go through the app's preview panel (reads `.claude/launch.json`), not Bash.
- **Read-time filters degrade to regen-time on prerendered surfaces** — any prerendered route whose data is filtered `datetime <= now` at read time (feed, archive, sitemap pattern) only re-filters on regeneration, and a scheduled post going live busts no tag. Trigger: adding a new prerendered surface that lists scheduled-capable content → it needs a `revalidate` backstop (segment config must be a literal; can't import a shared constant).
- **Local Postgres.app rejected `trust` auth during preview verification** — every DB-backed page 500s under the browser-pane dev server (pre-existing, not code). Trigger: next browser-pane verification of DB-backed pages — check Postgres.app is running/auth config first.
- **Sandboxed `yarn build` can't complete** — Turbopack's build workers can't fetch Google Fonts (and `.env` stat is EPERM; `.env.local` loads fine). Trigger: build-level verification (route-table output) must run outside the sandbox. Side effect: a build flips generated `next-env.d.ts` between `.next/dev/types` and `.next/types` — revert, don't commit the churn.

## Session 1

### Decisions

- **Feed `<id>` vs `rel="self"`** — kept `<id>` at `/api/feed/:section` (stable dedup key) while pointing `rel="self"` and all autodiscovery links at the canonical `/blog/:section/feed.xml`. Rejected repointing `<id>` to the pretty URL (would orphan existing subscriptions); readers migrate to the pretty URL via `rel="self"` over time.
- **Autodiscovery via metadata `alternates`, not JSX-hoisted `<link>`** — metadata replaces per segment, so per-section pages cleanly override the site default. Rejected a React-19-hoisted `<link>` in the root layout: it would render on every page and duplicate/conflict with per-section links on blog pages.
- **Titled links via the `{url,title}` descriptor form** — Next's string form of `alternates.types` emits `<link>` with no `title` attribute (verified in `resolve-basics.js`), so readers list the raw URL; the array-of-descriptor form emits the title. Centralized author/path/title in `src/lib/content/feed.ts` so the `<link title>` can't drift from the Atom `<title>`.
- **Guess-URL redirects target `/api/feed/tech`** — same target as the existing `/feed` redirect, for uniformity. Rejected repointing `/feed` itself to the pretty URL to avoid churning a long-lived 301.

### Tradeoffs

- **Phase 3 guess-URL redirects** (`/rss`, `/feed.xml`, `/atom.xml`, `/index.xml`) — gained: humans/tools guessing a conventional path reach the feed. Accepted: URL-probing discovery tools now find the feed via several aliases, showing cosmetic duplicates in those tools (real autodiscovery readers see one `<link>` per page). Reversibility: easy (single regex in `proxy.ts`).

### Incidents / Bugs

- **Feed not discoverable at all** — no `<link rel="alternate">` anywhere on the site. Root cause: the Express→Next migration dropped feed autodiscovery entirely. Fixed by advertising it site-wide (layout tech default) + per-section (blog pages).
- **Invalid Atom** — missing feed-level `<author>` (RFC 4287 §4.1.1), plus dropped `<subtitle>`/`<icon>`/`<rights>` the old Express feed had. Strict readers reject the document. Restored all.
- **Stale feed `<updated>`** — was keyed off DB `updatedAt` (authoring-edit time), so a scheduled post published days after its last edit never advanced the feed; readers polling conditionally on `<updated>` never saw new posts. Fixed: entry `<updated>` = `max(published, updatedAt)`, feed `<updated>` = max over entries.
- **Untitled autodiscovery links** — string-form `alternates.types` drops the `title` attribute; readers displayed the raw URL. Fixed with the descriptor form.

### Environment / Config Changes

- Added `.claude/launch.json` with `next-dev` and `next-start` configs for the app's integrated preview panel (the sandbox blocks launching a dev server from Bash).

### What did I, Claude Code, or my agents learn from this

- **Next metadata `alternates` is replace-not-merge per route segment** — a deeper segment that defines `alternates` wipes the parent's; omitting it inherits. Confirmed in Next's own merge loop. This is why per-section overrides work and why a site-wide default only reaches pages that set no alternates of their own.
- **`alternates.types` string form silently omits the `title` attribute** — only the `[{ url, title }]` descriptor emits it. Verified against `node_modules`, not assumed.
- **The command sandbox forbids binding a listening socket** (`listen EPERM`), so dev servers can't be started via Bash in this environment; the preview panel launches them out-of-sandbox from `launch.json`.

## Session 2

### Decisions

- **Feed route is now static** — `force-static` + `generateStaticParams` + `revalidate = 3600` on `src/app/api/feed/[section]/route.ts`, replacing the dynamic handler + hand-set `Cache-Control` (dropped). Chose ISR because a `revalidateTag("feed-…")` bust purges the route cache but could never purge the CDN edge copy the old header created — publishes could sit stale up to an hour; also matches the `llms.txt` `force-static` precedent. (Rejected: keeping dynamic + header, for exactly that purge gap.)
- **No feed/page render reuse** — pages render markdown via react-markdown + Shiki (React tree with token spans); the feed's `markdownToHtml` deliberately emits plain HTML because feed readers strip Shiki spans (`src/lib/content/markdown.ts` documents this). Outputs aren't interchangeable, and the only shared layer (DB rows) diverges in select shape (`summary`/`updatedAt`/20 rows vs `body`/`readingTime`/`PAGE_SIZE`). Rendering cost is already amortized: `htmlBody` lives inside the tag-busted cached payload, so markdown re-renders only on post mutations, not on hourly regens. (Rejected: merging the feed and blog-list caches — couples payload shapes and tag lifecycles to save two small queries per bust.)
- **Blog list page stays dynamic** — it awaits `searchParams` for `?page=`, so it can't prerender; going static means path-based pagination (`/blog/:section/page/N`) — a public-URL change not worth saving one `count` query per view at this traffic. Its data layer is already cached.

### Tradeoffs

- **Scheduled posts on the feed** — surface at the first regeneration after `datetime` passes (≤1h late) instead of the first request; matches the old CDN header's practical staleness envelope. Reversibility: easy (tune/remove `revalidate`).

### Incidents / Bugs

- **Scheduled-post gap on archive + sitemap** — both are prerendered and filter `datetime <= now` at read time, which for a prerendered route means regen time; a scheduled post crossing its `datetime` busts no tag, so it stayed out of the archive and sitemap until the next content edit or deploy. Fixed with `revalidate = 3600` backstops on both. Landing page checked — fetches no posts, not affected; blog detail pages self-heal via on-demand rendering.

### Environment / Config Changes

- `revalidate = 3600` added to `src/app/blog/[section]/archive/page.tsx` and `src/app/sitemap.ts`; config-contract tests added to the feed and sitemap suites so silent removal of `force-static`/`revalidate` fails a test.

### What did I, Claude Code, or my agents learn from this

- **Tag→route-cache propagation is free wiring** — a tag on `unstable_cache` inside a `force-static` route rides up onto the route-cache entry, so the existing `revalidatePostSection` bust regenerates the feed XML with zero new revalidation code.
- **"Auto-surfaces at read time" claims are rendering-mode-dependent** — the same filter is per-request on dynamic surfaces but regen-only on prerendered ones; when auditing scheduled-content freshness, check each consumer's rendering mode, not just the shared helper.
