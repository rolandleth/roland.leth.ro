## Watch-outs & Tech Debt

- **Admin pages have no `requireAdmin` equivalent** — `requireAdmin` covers `/api/admin/*` route handlers only. Page-namespace protection is the middleware matcher + layout + `adminEditMetadata`. Revisit when adding an admin page that reads data in `generateMetadata` or any other hook that runs before the layout.
- **`STORE_HOSTNAMES` is Apple-only** — a non-Apple storefront (Play, Setapp, direct download) silently renders as a plain link with no `Get on` prefix and no repeated CTA, with nothing surfaced to the author. Revisit when a project ships outside the App Store.
- **`isStoreUrl` vs `APP_BUCKETS`** — two independent notions of "this is a shipping app": the CTA keys off link hostname, the JSON-LD off `project.bucket`. Authored separately, so a project can emit `SoftwareApplication` markup with no CTA or vice versa. Revisit if a third consumer appears.
- **Links grid is `shrink-0` with `grid-flow-col grid-rows-2`** — five or more links produce three columns, which overflows even stacked at 375pt. No project comes close today. Revisit at 5+ links on one project.

## Session 1

### Decisions

- **Closed the admin metadata auth gap, not just the comment** — the code review flagged only the `src/proxy.ts` matcher comment as overstating the invariant; fixed the underlying gap instead, since the comment was inaccurate precisely because the gap existed. Added `verifySession()` ahead of the DB read in all four admin edit pages' `generateMetadata`.
- **Extracted `src/lib/auth/adminMetadata.ts`** — chose one shared `adminEditMetadata(id, fallback, loadName)` helper over four inline `verifySession()` checks, so the guard is structural and a fifth edit page can't ship without it (rejected: inline checks, which repeat a security-relevant shape four times and rely on memory).
- **Discontinued projects stop selling but stay reachable** — bare label on the hero storefront pill, no repeated CTA below the content. The alternative argued for was keeping `Get on` in the hero, since delisting and discontinuing aren't the same thing and an unmaintained app can still be installable; user chose the stricter reading — a Discontinued badge beside a "Get on" button is a mixed message regardless.
- **`STORE_HOSTNAMES` as a named set** — hoisted the hardcoded `apps.apple.com` comparison into a `ReadonlySet` to name the extension seam, without adding hosts the data doesn't have yet (YAGNI held).
- **Hero row stacks via an `sm:` breakpoint, not `flex-wrap`** — explicit and predictable; `flex-wrap` would have depended on min-content behaviour of a `min-w-0` column that's hard to reason about.

### Tradeoffs

- **`ctaLabel(storeLink, isDiscontinued)` at the repeated-CTA call site** — always receives `false`, because `storeLink` is `undefined` when the project is discontinued. Kept for symmetry with the hero call site; arguably noise. Reversibility: easy.
- **New indirection for four call sites** — `adminEditMetadata` adds a file and a callback-shaped signature to remove four copies of a four-line guard. Reversibility: easy.

### Incidents / Bugs

- **Unauthenticated DB read in admin edit `generateMetadata`** — root cause: nested `generateMetadata` runs independently of `admin/(protected)/layout.tsx`, and `requireAdmin` protects only the 13 `/api/admin/*` route modules, so an unauthenticated request reaching an edit page loaded the record and leaked its title. Fixed by the shared guard. Regression risk: low; pinned by a test asserting the loader never runs without a session.
- **Project hero row overflows a 375pt viewport** — measured on the live site: `documentElement.scrollWidth` 379 vs `clientWidth` 375, with a *single* link (the code review predicted this only at 3+ links). Cause: `justify-between` row with a `shrink-0` links grid and a ~148px `Get on App Store` pill. Affects 375pt-class devices (iPhone SE, 12/13 mini); current iPhones at 393pt+ have room. Fixed by stacking below `sm`.
- **Two admin page test files broke on the new session check** — `cookies` was called outside a request scope once `generateMetadata` started calling `verifySession()`. Fixed in the tests (mock `@/lib/auth/auth`), not the code: the session check is what the app needs, the request scope was incidental test setup.

### What did I, Claude Code, or my agents learn from this

- **`rg -r` is `--replace`, not "recursive"** — `rg -rn "requireAdmin"` and `rg -rln "..."` silently rewrote every match to `n`/`ln` in the output, which made a normal Zod schema look like it was assigned to a one-letter variable. I nearly reported that as a code-quality finding. Use plain `rg -n` or `rg -l`; when `rg` output contradicts the codebase's established conventions, suspect the command before the code.
- **Probe the live DOM to verify a layout claim when the local server can't run** — forcing candidate styles onto the real page, re-measuring `scrollWidth`, then reverting proved the fix against real content and real fonts, which no unit test can do. Cheap and decisive.
- **State the measurement conditions with the measurement** — reported the overflow as affecting "every project page," dropping the 375pt qualifier. On the user's own phone (393pt+) nothing was wrong, so the claim read as simply false. Both observations were correct; only my framing was.
