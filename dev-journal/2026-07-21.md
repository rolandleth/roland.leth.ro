### Decisions

- **Shared class, not an `<AdminOutcome>` wrapper component** — the review floated a component for the duplicated outcome region; used `adminOutcomeClass` in `controlStyles.ts` instead, matching the standing preference (and the `controlStyles` header's own rationale) for shared classes/hooks over wrapper components. (Rejected: the wrapper component.)
- **`reset` as a `run` parameter, not a `useAdminAction` option** — moving "new run clears prior outcome" into the hook via an options callback tripped Next's RSC-serialization heuristic, and the latest-ref workaround tripped `react-hooks/refs`. Passing `reset` as a third `run` param (like `perform`, which trips neither) sidesteps both and keeps `run` referentially stable. Each panel's request was extracted to a named `performRequest` const so the 3-arg `run(...)` call stays tidy and body indentation is preserved. (Rejected: options-callback + latest-ref.)
- **Trim `INDEXNOW_KEY` in `getIndexNowKey`** — a trailing-newline/padded key was served verbatim at `/indexnow-key.txt` (200) yet rejected as "malformed" at submit, an invisible mismatch. Trimming accepts the key that looks correct. (Rejected: only naming whitespace in the error message, which leaves the footgun in place.)
- **`aria-controls` names both output regions, with an always-mounted `empty:hidden` error wrapper** — the buttons claimed to control only the polite outcome region, but the failure headline routes to the assertive `role="alert"` region. Referenced both IDs and wrapped `ErrorMessage` in a permanently-mounted `#{panel}-error` div so the IDREF never dangles. (Rejected: dropping `aria-controls`, which would revert the 2026-07-20 a11y fix; and routing the error headline into the polite region, which loses assertiveness.)
- **Analyzed the review inline in main, not via analyzer subagents** — main held the gatherer evidence plus the `dev-journal/2026-07-20.md` watch-outs and `code-reviews/2026-07-20.md` resolution state, the context needed to avoid re-raising deliberately declined/deferred items (throttle, middleware gating, `describeKeyProblem` coupling).

### Tradeoffs

- **`logResult` now logs per-batch `errorName`/`message` on failure** — gained a diagnosable server log (a transport failure logged `statuses: [0]`, opaque, before); the payload is slightly larger on the error path only. Reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Callbacks belong in a client hook's parameters, not its options object.** A function member on a `"use client"` hook's options object trips Next's RSC-serialization check (71007, IDE-only — `tsc`/`lint` pass it), and the latest-ref pattern (`ref.current = x` during render) trips `react-hooks/refs` (a real lint error). Passing the callback as a function parameter, alongside an existing one, avoids both and keeps the memoized function stable.
- **`vi.spyOn(namespaceImport, "export")` intercepts a statically-imported named export in the module under test.** Used `import * as env` + `vi.spyOn(env, "getSiteUrl")` to reach the otherwise-untestable non-`EnvConfigError` rethrow branch in the route — the real function only throws `EnvConfigError`, so this was the only way in.
- **`aria-controls` pointing at a sometimes-unmounted region is a dangling IDREF** (an axe violation), even though the live region still announces. An always-mounted wrapper with `empty:hidden` keeps the reference valid while staying out of layout when empty.
