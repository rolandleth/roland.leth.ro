### What did I, Claude Code, or my agents learned from this

- **Discriminated unions fail silently when callers pass computed booleans.** If `canMoveUp: index > 0` becomes `boolean`, the discriminant is gone. For required-together props, simpler to just make them required and use a comment; reserve unions for literal-typed callers.
- **Prop-mirror state (`useState(propValue)`) is almost always a bug waiting to happen.** The mirror doesn't re-sync on prop change without a `useEffect`, and `useEffect` for sync is the React anti-pattern. Derive instead. `PresetOrFreeformInput` had both bugs (drift on prop change, conditional `Freeform…` toggle) masked by "it works for the first render".
- **When tightening a `string` to a union/enum, test fixtures are the long tail.** 20+ fixtures needed `as const` after the Prisma enum change. Next time, grep `section:` first, fix fixtures proactively, then tighten the type.
- **Loop-closing checklist: when a middleware rewrites an unknown path to an internal route, that internal route must terminate (respond), never redirect to another path that re-enters middleware.** `/404` in the miss branch was a self-rewrite loop. Rule: API legacy-redirect must respond with status, never issue a new path that goes through the matcher again.
- **`useDeferredValue` already debounces.** Don't stack a `setTimeout` on top — it just adds fixed latency without changing coalescing behavior. If you need more throttling, increase the deferral threshold in React devtools, not in userland.

### Decisions

- **`ProjectSortOrderInput` displays 1-indexed, translates at the boundary** — user picked option (B). The DB stays 0-indexed (`sortOrder 0` = top); the input renders `initialSortOrder + 1`, clamps to `[1, totalCount]`, and subtracts 1 before the PUT. Kills the silent-swap bug where the top project's "0" blur-coerced to 1 and swapped with its neighbour. Alternative rejected: shift the clamp to `[0, totalCount - 1]` — matches the DB but makes "0" a surprising top-of-list position to every admin who's ever numbered anything.
- **Single-writer invariant documented inline, not enforced in Postgres** — option (D) for now. Added a comment block above the `$transaction` in `src/app/api/admin/projects/[id]/route.ts` stating the READ COMMITTED + no-`@@unique` race window, the cost-of-catch (Prisma P2002 with `@@unique`, serialization error with `Prisma.TransactionIsolationLevel.Serializable`), and the escalation path. Alternative rejected: `@@unique([sortOrder])` — Prisma's DSL can't express `DEFERRABLE INITIALLY DEFERRED`, which is required because the shift-and-write sequence transiently produces duplicates within the transaction.
- **`defaultProto` drops the port heuristic entirely** — option (A). Now returns `"http"` only for hosts starting with `localhost` or `127.0.0.1`; every other host defaults to `"https"`. Non-Vercel deploys behind a reverse proxy on `example.com:8443` no longer get silently downgraded to http URLs in the feed and sitemap.
- **Feed `<updated>` uses `Math.max` of `post.updatedAt`, not `posts[0].updatedAt`** — stricter than the review's suggestion of `posts[0].updatedAt.toISOString()`. Rationale: edits to older posts still qualify as feed modifications per RFC 4287, but would not show in `posts[0]` (which is ordered by `datetime desc`, not `updatedAt desc`). `Math.max` across the 20-entry slice catches edits anywhere in the feed window.
- **`navLinks` hoisted to `src/lib/navigation.ts` with `as const`** — tuple literal, not mutable array; `href`/`label` narrow to literal types at callsites. Module docstring calls out the drift concern so the next contributor adding a section doesn't need to find both files.
- **Zod `.min(0)` added at all four project sortOrder levels** — project, section, section image, and link. Defence-in-depth with the `min={0}` UI input; the anticipatory test that asserted "accepts a negative sortOrder" (with a comment saying it would flip) got flipped to "rejects a negative sortOrder" + a new "accepts a zero sortOrder" boundary test.
- **`FadeIn`'s `as` widened to `keyof typeof motion`** — the original `"div" | "aside" | "section"` union forced every animated `<h1>` and `<section>` in `AboutContent` into a `motion.div` wrapper, adding three pointless DOM nodes per page render. Pulling the tag set straight from Framer Motion's typed surface lets callsites use `as="h1"` / `as="section"` directly so the wrapper *is* the animated element. Alternative rejected: hand-maintained `"div" | "aside" | "section" | "h1" | "h2"` union — same maintenance cost as the original bug, just one tag further out.

### Tradeoffs

- **Single-writer invariant stays a doc-comment, not a DB constraint** — gained: zero migration, no schema change. Accepted: second admin will silently race. Escalation path documented inline. Reversibility: easy — add `Prisma.TransactionIsolationLevel.Serializable` in one place.
- **`defaultProto` no longer supports explicit-port dev setups without `x-forwarded-proto`** — gained: correct protocol in production for non-Vercel hosts. Accepted: anyone running dev on `example.com:3000` without setting `x-forwarded-proto` will now get `https` URLs. Reversibility: easy; in practice local dev uses `localhost:3000` which is still covered.
- **Feed `<updated>` using `Math.max` iterates the full slice every request** — O(20) per request, negligible. Gained: edits to older posts correctly advance the feed timestamp. Alternative: order by `updatedAt desc` in the Prisma query and take `posts[0].updatedAt` — rejected because the feed is supposed to be ordered by publish time, not edit time.

### Incidents / Bugs

- **Anticipatory "accepts a negative sortOrder" test caught the schema tightening** — the test had an explicit comment saying it would flip if we ever required non-negative values. When I added `.min(0)` and ran the suite, the test failed exactly as designed. Flipped the assertion + added a zero-boundary test. Lesson (for the future, not a regression): tests that encode "this is the current behaviour, this is the intended future behaviour" pay off precisely at the moment the code catches up.
- **One unrelated diff surfaced mid-session** — `eslint.config.mjs` showed a path fix from `./generated/prisma/**` to `./src/generated/prisma/**`. Flagged to user, left uncommitted; not mine to decide.

### Environment / Config Changes

- `src/lib/navigation.ts` added (shared `navLinks`).
- No changes to `.env`, `package.json`, CI, or build config.

### What did I, Claude Code, or my agents learned from this

- **0-indexed DB + 1-indexed UI is the right default for ordinal inputs.** Users expect "1st, 2nd, 3rd" in a position field; the DB can stay 0-indexed for cleaner modular arithmetic (`count` as next position, `@default(0)` for first). Translate once at the component boundary; don't leak the DB convention into UX.
- **Anticipatory tests with "this will flip" comments are high-value waste-of-time prevention.** When the schema tightens, the flip is a one-line edit instead of a grep-hunt for every callsite that might assume the old behaviour. Cost of writing one: ~90 seconds.
- **Race-conditions on a single-writer admin are still worth documenting.** The invariant comment isn't defensive — it's so the next contributor adding a second admin account knows exactly which line to change (`isolationLevel: Prisma.TransactionIsolationLevel.Serializable`) and why.
- **Second review pass finds a completely different set of issues from the first.** Seven findings, zero overlap with review 1. The lesson isn't "always run two reviews" — it's that review coverage is shaped by whatever dimensions the reviewer is attuned to. The first pass was architecture-heavy (KNOWN_ROUTES, catch-all, PAGE_SIZE); the second pass was correctness-at-boundary (sortOrder indexing, race windows, feed semantics, URL protocol inference). Running both gets you both shapes of issue.
- **Feed `<updated>` semantics are easy to get subtly wrong.** `posts[0].updatedAt` (ordered by `datetime`) is better than `posts[0].datetime` but still misses edits to older posts. `Math.max(...updatedAt)` across the slice is the right shape for a cache-advertising timestamp that drives refetch decisions in feed readers.
