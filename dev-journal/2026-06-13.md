## Session 1

### Decisions

- **Blob orphan handling** — chose prune-after-import (sweep unreferenced keys under the project prefix after a successful DB write, gated by `--no-prune`) over document-only or do-nothing. Rationale: content-addressed keys made edits leave old keys forever; monotonic growth on the 1 GB free tier. Deletion only runs during an attended import, so nothing happens unattended.
- **Content-hash width** — widened the key hash 48-bit → 64-bit and added a byte-size assert on the reuse path. The dedupe contract is "same key ⇒ same bytes", so a collision would silently serve wrong content; chose width + size-backstop over a much wider key (longer URLs) or no guard.
- **Extract `src/lib/import/blobSync.ts`** — pulled the reuse/upload/prune logic out of the imperative script into a pure, dependency-injected module (`BlobStore` interface) so pagination, concurrency, partial-failure, and prune are unit-testable with in-memory fakes; chose this over testing the script directly (which mixes real SDK + fs I/O). Also extracted `contentHashFor` to `projectImport.ts` so "same bytes → same hash" has a test.
- **`allowOverwrite: true` kept, not tightened to `false`** — it's load-bearing for `--reupload` and the fail-open "treat nothing as existing" path after a transient `list` failure; collision risk is instead covered by the byte-size assert on reuse. The real-SDK knobs now live in a single `blobStore` adapter.
- **`listExistingBlobs` error handling** — distinguish credential/store misconfig (`BlobAccessError`/`BlobStoreNotFoundError`/`BlobStoreSuspendedError` → rethrow, fail loudly) from transient errors (warn + treat-as-empty). Prevents a misconfigured token from silently triggering a full prod re-upload.
- **Generalize `PrivacyPageLayout` → `LegalPageLayout`** — added a `documentKind: "privacy" | "terms"` switch driving the boilerplate wording, plus an optional `relatedLinks` "Related" section. Chose the `documentKind` lookup over passing full boilerplate strings per page (the singular/plural self-reference differs only by kind). Scoped to the review's explicit recommendation: kept the `components/privacy/` folder and the `PrivacySection` name rather than a larger reorg, to keep the diff reviewable.
- **Login log levels split** — routine 429 → `info`, fail-open (Redis unreachable) → `error`, instead of both at `warn`, so a dashboard can alert on the operator-actionable case by level alone. Invalid-credentials payload now always carries the resolved key (`"global"` when no secret) rather than an empty `{}`.
- **Keyspace partition** — client rate-limit keys now carry an `ip:` prefix so they're formally disjoint from the `"global"` fallback under the shared `rl:login` Redis prefix; hoisted `bucketKey` so the HMAC runs once per request and the limiter/invalid-credentials logs can't drift.
- **responsible-use list a11y** — `aria-hidden` on the decorative `01`–`06` markers + `role="list"` on the `<ol>`, chosen over a CSS-counter/native-marker rewrite. Preserves the exact monospace visual while fixing the "1, 01 Opinions…" double-read; `role="list"` restores the list semantics WebKit drops under `list-style: none`.
- **Legal-page dates** — each page keeps its true substantive-revision date (privacy May 30, DPIA June 8, terms June 9, responsible-use June 10), NOT a forced alignment. Post-dating unchanged legal text would imply changes that didn't happen. Net-zero on dates across the session; confirmed the four-date spread the review flagged is genuine, not a copy-paste artifact.

### Tradeoffs

- **Bounded-concurrent uploads (4)** — gained wall-clock on large galleries; correctness-safe because each `put` targets a distinct content-addressed key. Fail-fast: after a failure no new uploads start, in-flight ones settle, first error rethrows. Reversibility: easy.
- **Skipped `robots` metadata param** — deferred as premature abstraction (no page needs `noindex`; DPIA intentionally indexable). Reversibility: easy.
- **Skipped extracting rate-limit helpers** — the review's recommendation was conditional on shared use; helpers remain single-consumer. Reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Legal/policy `lastUpdated` reflects substantive-text changes only** — the user applies this rigorously: a presentation refactor (layout swap, list markup, cross-links) does NOT bump a legal document's revision date. Established across three corrections (privacy → DPIA → terms). When touching policy pages, separate text changes from presentation changes before deciding the date.
- **Scope a review-flagged refactor to the review's explicit recommendation** — generalizing the layout (rename + parameterize) was wanted; the maximal version (folder move + rename every sibling) was not, and would have bloated the diff. Do the bounded version unless asked for more.

## Session 2

### Decisions

- **Featured project cards — equal height via flexbox, not a fixed height** — `FeaturedProjectCard` wrapper got `flex h-full flex-col` and the inner `Link` got `flex-1`, so the card stretches to the tallest in the `sm:grid-cols-2` row. The grid's default `align-items: stretch` gives the `AnimatedCard` motion-div grid item a definite height; the new chain propagates that down to the card. User explicitly ruled out a hardcoded/min height, so this is pure stretch — no magic number.

### Tradeoffs

- **Shorter card now shows whitespace** — MyTherme's one-line summary leaves a gap above the bottom-pinned "View project →" (the card body already used `flex-1` + `mt-auto`). Accepted over vertically centering the text, which would break the top-aligned consistency with the taller card. Reversibility: easy.

### Environment / Config Changes

- Committed a pre-existing (authored outside this conversation) hook migration alongside the session work: `.claude/CLAUDE.md` now points at the shared `~/.claude/hooks/web-auto-allow.jq` (wires `slug=rlr`) and the per-repo `.claude/hooks/auto-allow.jq` is deleted. The documented grammar now also covers project-tree `rg` searches and a Monitor-only log-watch loop.

### What did I, Claude Code, or my agents learn from this

- **`FeaturedProjectCard` is shared** — used on `/projects` (wrapped in `AnimatedCard`) and in admin via `ProjectAdminGroup` (with a `children` controls row below the `Link`). The `flex flex-col` wrapper + `flex-1` Link also improves admin (card fills the space above its controls) and is a no-op outside a grid (`h-full` collapses to auto). Equal-height in a CSS grid needs the height chain threaded explicitly down through wrapper → card; the stretched grid item alone doesn't make content-height inner blocks fill.
