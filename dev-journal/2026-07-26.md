## Watch-outs & Tech Debt

- **Denylist-shaped matcher in `src/proxy.ts`** — the asset exclusion is only
  ever as correct as its extension list, so it stays a latent auth risk. The
  explicit `/admin` + `/api/admin/:path*` entries are what actually keep the
  gate running; revisit if anyone edits the exclusion pattern or adds a gated
  namespace outside those two prefixes.
- **Integer ids are load-bearing for auth, incidentally** — the matcher gap was
  unexploitable only because every admin `[id]` route parses its segment as a
  plain integer (`parseIdParam` → `n()`), so a dotted path 400s before any DB
  access. Revisit the moment an admin route is keyed on a slug or string id;
  that alone would have turned the gap into unauthenticated data access.

## Session 1

### Decisions

- **`SESSION_SECRET` length floor in the accessor, not the zod schema** — chose
  `getSessionSecret()` over `envSchema`, following `isValidIndexNowKey`'s
  precedent. `readEnv()` validates the whole schema and throws one aggregated
  error, and `getDatabaseUrl()` goes through it, so a schema-level rule with a
  short secret would take every database-backed page down over a session-only
  problem.
- **Matcher fixed twice over** — anchored the extension group with `$` *and*
  added `/admin`, `/admin/:path*`, `/api/admin`, `/api/admin/:path*` as explicit
  entries. Anchoring alone still leaves a denylist that can only be as complete
  as its extension list; the explicit entries mean no future edit to the pattern
  can silently drop the gated namespaces.
- **`requireAdmin()` returns `NextResponse | null`** — matches the existing
  `parseIdParam` / `parseJsonBody` idiom so every handler keeps one early-return
  shape (rejected: throwing a custom error and catching centrally, which would
  have needed a wrapper around 21 handlers).
- **It logs at error level** — in normal operation the middleware answers
  unauthenticated requests, so this guard is unreachable. A line there means a
  request got past the matcher, which is a security event rather than a routine
  401 (which never reaches this code).

### Tradeoffs

- **Guard on all 21 handlers vs. middleware alone** — gained a second lock so no
  single matcher mistake is a complete auth bypass; accepted four extra lines in
  every handler and a mocked guard in 13 route test files. Reversibility: easy.
- **Mocking the guard in route tests** — those files now test handler behaviour,
  not authorization, which is why the guard has its own unit test and the
  contract test deliberately does not mock it. Reversibility: easy.
- **`resolveBaseUrl()` extraction in the indexnow route** — the added guard
  pushed `POST` over the cognitive-complexity ceiling; extracting site-URL
  resolution to a `string | NextResponse` helper flattened the handler into a
  sequence of guards. Unexpected failures still escape after logging, since a
  non-config error there is a bug, not a misconfiguration.

### Incidents / Bugs

- **Admin auth gate skippable via a dotted path** — `config.matcher`'s
  `.*\.(?:svg|png|…|css|js)` alternative was unanchored at both ends, so any
  path merely *containing* one of those substrings bypassed the middleware
  entirely; `.json` matches because it contains `.js`. Combined with no admin
  API handler re-checking the session, that was the whole authorization story
  for `/api/admin/*`. Not exploitable as it stood (integer-only ids reject a
  dotted segment before any DB access), and admin *pages* had a second check in
  `src/app/admin/(protected)/layout.tsx`. Regression risk now covered from both
  sides: matcher-level tests plus the handler contract test.
- **`SESSION_SECRET` accepted any non-empty string** — `z.string().optional()`
  plus a non-empty check, encoded straight into the HS256 key, so a short secret
  is brute-forceable offline and a forged `{ admin: true }` token is full admin
  access. The project's own `.claude/CLAUDE.md` documented it as "any string",
  which invited exactly that; both the code and the doc line were corrected.

### Environment / Config Changes

- `.claude/CLAUDE.md` — the `SESSION_SECRET` line now states the 32-character
  minimum and gives `openssl rand -hex 32`, matching how `INDEXNOW_KEY` is
  already documented.

### What did I, Claude Code, or my agents learn from this

- **A contract test can be structurally blind and still look thorough.** The
  pre-existing `proxy.test.ts` test asserts every admin path is gated, and its
  comment even notes the handlers don't re-check sessions — but it calls
  `proxy()` directly, so it presumes the request reached the middleware, which
  is precisely what the matcher decides. It passed happily while the real
  request walked past. Test the layer that makes the decision, not the layer
  downstream of it.
- **Verify that a new safety net actually catches something.** The admin
  contract test was checked by deliberately removing the guard from the
  keepalive handler and confirming the failure (`POST answered 503 without a
  session`) before restoring it. Worth the two minutes on anything claiming to
  be a backstop.
- **Read the codebase before picking where validation lives.** The instinct was
  to put the secret-length rule in the zod schema; `isValidIndexNowKey`'s
  comment already explained why value-shape checks belong in the accessor —
  blast radius. The convention was documented in the file the whole time.

### Notes

- Guard coverage is 21 handlers across 13 route modules. The contract test
  enumerates the modules explicitly rather than globbing (a glob that silently
  matched nothing would be a test that always passes) and separately walks the
  directory to fail if that list drifts from the tree.
- Full suite green afterwards: 2060 tests across 132 files, `tsc --noEmit` and
  `yarn lint` clean.
