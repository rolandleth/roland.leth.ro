## Session 1

### Decisions

- **Continuous cross-section gallery** — flattened every section's images into one ordered strip (`flattenSections` in `src/lib/client/gallery.ts`); the parent owns a single flat index and the active tab follows the landed slide. Chose "fully continuous everywhere" over within-section sliding (user pick); the fixed-height stage is the direct consequence.
- **Hand-rolled pointer-event zoom** for the lightbox over a library (rejected `@use-gesture/react` and `yet-another-react-lightbox`/PhotoSwipe). Pure geometry (focal-anchored zoom, pan clamp, double-tap toggle) lives in `src/lib/client/zoom.ts` and is unit-tested; the hook (`useLightboxGestures.ts`) is a thin event-wiring layer driving framer `MotionValue`s so drags never re-render React.
- **Split gesture engines** — carousel swipe uses framer-motion `drag`; the lightbox hand-rolls pointer events because pinch/pan/swipe must arbitrate on one surface. Both render a shared presentational `GalleryTrack`.

### Tradeoffs

- **Fixed-height stage vs. rounded corners** — a continuous strip needs a stable height, which letterboxes off-ratio images (`object-contain`). That removed the old aspect-ratio-hugging stage, and with it the CSS rounding that used to sit on the image. In-app per-slide rounding (measure ratio → `containedSize` → rounded frame) was built and then reverted; user will bake rounded corners into the source PNGs instead. Reversibility: moderate (the `containedSize` approach is documented in this session's history if revisited).
- **Trackpad zoom split** — gained correct pinch behaviour by branching on `event.ctrlKey` (pinch = ctrl+wheel, small deltas, own sensitivity + per-event cap; plain two-finger scroll pans when zoomed instead of zooming). Accepted that a plain mouse wheel no longer zooms (double-click / ctrl+wheel do). Reversibility: easy.

### Incidents / Bugs

- **Swipe opened the lightbox** — the carousel's enlarge `<button>` sits inside the framer drag layer, and framer's click-suppression is unreliable across the re-render a swipe triggers (the slide under the cursor changes mid-gesture). Fix: a moved drag (>8px offset) sets `suppressEnlargeRef`, reset via `onPointerDownCapture` on the stage; `handleEnlarge` guards the click. Deterministic, doesn't depend on framer.
- **Trackpad: scroll zoomed too fast, pinch zoomed too little** — root cause was treating all `wheel` events as zoom with one sensitivity; a trackpad delivers pinch as ctrl+wheel (tiny deltas) and two-finger scroll as plain wheel (large deltas). Fixed by the ctrlKey split, `deltaMode` normalization to pixels, and a per-event zoom cap. Now `preventDefault`s all wheel to stop a horizontal two-finger swipe from navigating back/forward out of the lightbox.
- **Lightbox track width stuck at 0** — `useElementSize` on the conditionally-rendered stage never re-measured because the hook stays mounted while the lightbox is closed (its mount effect ran with a null node). Fixed by owning the stage through a callback ref (`setStage`) that measures, observes resize, and binds the non-passive wheel listener each time the stage mounts.

### What did I, Claude Code, or my agents learn from this

- **eslint caching masks failures** — `yarn lint` (script is bare `eslint`) reported clean early in the session, then surfaced 20 pre-existing `sonarjs`/`prettier` errors in committed files once the cache invalidated. `yarn lint` fails repo-wide independent of any given change; scope lint conclusions to the files you touched (grep the log for your paths) before claiming clean.
- **Sanctioned Bash grammar is strict** — appending `; echo "exit=$?"` to an `rg`/`test` command, or using `rg` long flags (`--files`, `--glob`), breaks the `web-auto-allow` grammar. Use bare short-flag `rg`, and don't tail arbitrary commands with `echo`.

## Session 2

### Decisions

- **Cut Vercel CPU by making content pages static** — `unstable_cache` (Data Cache) spared the DB but not per-request compute; the Full Route Cache (static/ISR) does. Everything was `ƒ` because `cookies()` (theme) in the root layout + `headers()` (via `siteBase`) forced dynamic rendering. Fixed in two steps.
- **Resolve origin from env, not headers** — replaced `siteBase()`/`src/lib/api/request.ts` with `getSiteUrl()` in `src/lib/auth/env.ts` (chain: `NEXT_PUBLIC_SITE_URL` → `VERCEL_PROJECT_PRODUCTION_URL` → throw). Dropped `headers()` from every render/metadata/sitemap/robots/feed/llms/md path. Flipped `robots`/`sitemap` to `○`. (Env over headers: canonical URLs want build-time stability.)
- **Theme client-side (localStorage + pre-paint script)** — removed `cookies()` from the root layout. `ThemeScript` (raw inline `<script>`) sets the class before first paint; `ThemeProvider` reads/writes localStorage; `ThemeToggle` guards its active state with `useSyncExternalStore` (avoids a hydration mismatch and the `set-state-in-effect` lint). Flipped all marketing/blog/project/legal/tools pages to `○`/`●`.
- **Raw inline script over `next/script`** — `next/script` `beforeInteractive` ran a frame late → confirmed white flash. Raw inline `ThemeScript.tsx` (added to the eslint `no-restricted-syntax` allowlist beside `JsonLdScript`) runs synchronously before paint, no flash.
- **`force-static` on `/llms.txt`** — Route Handlers are dynamic by default; opted in (no dynamic dep; revalidated via the `projects` tag).
- **Left `/blog/[section]` list dynamic** — static would need a `/page/[n]` route restructure + SEO redirects for a low-traffic, lightweight list render. Not worth it.

### Tradeoffs

- **Cookie → localStorage theme** — gained static pages (no `cookies()`); accepted a one-time reset of existing visitors to "system" and a `<noscript>` unhide for no-JS visitors (else `visibility:hidden` blanks them). Reversibility: moderate.
- **Env-based canonical origin** — canonical/OG URLs are always the production domain, even on preview deploys (usually desired). Reversibility: easy.

### Incidents / Bugs

- **Local `yarn build` prerender crash, `reading 'length' of undefined`** — not a code bug. A non-standard local `NODE_ENV` made `next build` prerender with dev-mode React (tell: dev-only `<meta>`/`<head>` key warnings during build); dev React's prerender path crashed, and `--debug-prerender` masked it. Fix: clear the stray `NODE_ENV`. Distinct from the 2026-05-20 Turbopack chunking-leak incident (loud compile error there; clean compile here). See Watch-outs.
- **Invalid `route.ts` export** — `src/app/api/admin/upload/route.ts` exported test-only helpers (`sanitizeFilename`/`sanitizeLogString`/`detectImageMime`); Next forbids non-handler exports from a route file. Moved them to `uploadHelpers.ts`. Only a real build catches it — `tsc`/`vitest`/`eslint` pass.

### Environment / Config Changes

- New env var `NEXT_PUBLIC_SITE_URL` (full origin incl. scheme); `VERCEL_PROJECT_PRODUCTION_URL` is the Vercel-provided fallback. Added to `.env.test` for tests.

### What did I, Claude Code, or my agents learn from this

- **`revalidateTag` busts the Full Route Cache, not just the Data Cache** — why making pages static needed no edit-flow changes: it invalidates both the tagged data and every prerendered page whose render read that tag, so the existing tag wiring propagates edits to static pages via on-demand ISR.
- **`○` (Static) vs `●` (SSG) is cosmetic** — both prerender to CDN-served HTML; `●` just means a `[param]` route enumerated by `generateStaticParams`. Same zero-CPU benefit.
- **Special files vs Route Handlers** — `robots.ts`/`sitemap.ts` prerender by default; arbitrary `route.ts` handlers are dynamic by default (need `force-static`). Explains why `robots`/`sitemap` flipped but `llms.txt` had to opt in.
- **`--debug-prerender`** de-minifies the `ignore-listed frames` prerender stack — first reach for framework-framed build crashes.
