# Rolling History — last 90 days (through 2026-11-09)

## Themes

- **Scheduled-content correctness: a soft-404 bug found, fixed, then generalized into a public-facing feature.** The quarter's longest-running thread. 2026-08-15 moved legacy redirects/rewrites from middleware into `next.config.ts` (Vercel compiles these with no function invocation, resolving ahead of middleware) and replaced an hourly `revalidate = 3600` backstop on the feed/archive/sitemap with a due-check cron, discovering mid-change that the "costs nothing in idle hours" framing was wrong for a site crawlers and feed readers hit continuously (~72 guaranteed regenerations/day, not zero). 2026-08-17 found the real defect this unlocked: a `loading.tsx` creates a Suspense boundary over its entire nested segment, which lets React commit a 200 and start streaming before `notFound()` can ever reach the status-code assignment — three routes (`/blog/:section/:slug`, `/blog/:section/p/:page`, `/projects/:slug`) had been serving soft 404s in production, advertising every guessed slug and any not-yet-due scheduled post as a real page. Fixed by scoping the two list-view boundaries into route groups (keeping their skeletons) and deleting the two detail-view ones (unrecoverable — a route cannot be shielded from its own boundary); the cron was changed to return identities so each due item's own cache tag gets busted individually rather than a blanket bust regenerating everything. 2026-09-01 closed a microseconds-wide clock-split race in the detail-page miss path, and 2026-09-03 added a public, ungated `override-preview` route for previewing a scheduled post by URL (the URL itself is the secret). 2026-09-15 found guide topic hubs never received the due-guide cache bust the cron had promised — a "KNOWN GAP, latent" code comment that was, in production, not latent. The arc resolved 2026-08-31 into a product decision: scheduled posts now serve a real 200 "come back on {date}" notice (reusing the deleted 404's visual design, `robots: index:false`) instead of a pinned 404, sharing the exact same cached row and cron-driven bust as the fix above, so no new invalidation machinery was needed. [dev-journal/2026-08-15.md](dev-journal/2026-08-15.md), [dev-journal/2026-08-17.md](dev-journal/2026-08-17.md), [dev-journal/2026-08-31.md](dev-journal/2026-08-31.md), [dev-journal/2026-09.md](dev-journal/2026-09.md)
- **Admin auth defense-in-depth, built in layers, each layer missing one more path.** 2026-08-12 found and fixed an unauthenticated DB read in admin edit pages' `generateMetadata` (title only leaked), extracting a shared `adminEditMetadata` guard. 2026-08-13 added logging to the page-namespace bypass paths so a matcher miss becomes detectable rather than silent. 2026-08-21's external review found the second-layer gap this created: `adminEditMetadata` only guards the `<title>`, not the page body, since `generateMetadata` and the body render independently — a prior fix had covered two pages but missed that the same gap extended to all four `[id]/edit` pages and the `/admin` dashboard root itself, the most exposed page of all since every other protected page's nav links back into it. Fixed by extending `requireAdminPageSession` to all six data-reading pages, with a contract test tying every page's body-level data read to an actual guard call. The same session caught two of its own tests that could never fail (a vacuous `toHaveBeenCalled()` on unmounted JSX, a regex stopping at the first `}` instead of the real end of an interface) — from which "mutation-test every new guard by breaking the thing it protects" became standing practice for the rest of the quarter. September's admin-hardening sweep (09-26 to 09-29) added a CSRF `Origin` check across all 21 write handlers, an unsaved-changes guard, sniffed-byte content-type checks on uploads — and 09-28's review found the one miss: `/api/auth/login` ran neither check, so a cross-site page could exhaust the admin's own rate-limit bucket and lock them out. Fixed same day. [dev-journal/2026-08-12.md](dev-journal/2026-08-12.md), [dev-journal/2026-08-21.md](dev-journal/2026-08-21.md), [dev-journal/2026-09.md](dev-journal/2026-09.md)
- **`Post.description`: a six-day chain of fix-reveals-fix.** `Post.summary` was renamed to `Post.description` on 2026-09-14 with a derivation rule (frontmatter → admin form → body excerpt → title fallback). 09-15's review found five independent write paths disagreeing (the Published toggle silently wiped an authored description, a body edit re-derived over it, an image couldn't be cleared, a legacy 161-char value 400'd on every save, bulk upload stored uncapped values) — all fixed same-day behind one `postDescription.ts` resolver. The fix's own title fallback then shipped uncapped, reintroducing the exact 400 it had just removed, plus a newline-in-title bug; caught 09-16. 09-17's review found the cap/collapse rule held for the admin API only — import, bulk upload and the guide importer still stored raw values, and a stale slug refinement blocked saving a CJK-titled post. Both closed 09-23, when every file-write path was made to store the schema's own output rather than a hand-derived one. [dev-journal/2026-09.md](dev-journal/2026-09.md)
- **Project placement and product-page model, rebuilt from scratch and then kept additive.** 2026-10-02 shipped the own-apps product page (typed sections, steps as their own items). 10-03 replaced `isFeatured`×`isOwnApp` with independent `prominence`/`pageLayout`/`isDiscontinued`/`isOwnApp` fields, in a deliberate one-step release (push then deploy immediately, no temporary dual-schema window) alongside a full post/admin video-media pipeline (image-syntax `.mp4`/`.webm`, browser-to-Blob signed upload, 20MiB cap) that merged ahead of any real Blob verification. 10-11 added the `ProjectStatus` enum (comingSoon/live/discontinued), driven directly by a medical-claims review that also pivoted Digest's whole feature set away from guided tests toward per-symptom counts while `comingSoon` kept it unlisted. 10-17 through 10-20 generalized legal pages into a typed system (`LegalPagePath`, `yyyy-MM-dd` dates in one list, all pages in the sitemap) and folded four duplicated store-row implementations into one shared `StoreLinks` component. Every step kept the prior model's data additive — no destructive schema change landed without a hand-written SQL migration run ahead of the `db:push`. [dev-journal/2026-10.md](dev-journal/2026-10.md)
- **Social preview cards: a dynamic route replaced by a committed static asset, after Satori exposed its own rendering bugs.** 2026-08-13 found the `/og` route exported `size`/`contentType` (valid only for the file-convention form, invalid for a route handler — caught only by `next build`, not `tsc`) and that Satori silently mis-renders 8-digit hex colors as a near-solid fill rather than a fade, which first read as a layout bug. The route was replaced outright with a committed PNG plus a dev-only `yarn og:card` generator script, reasoned as strictly better: no render cost, no Google Fonts CDN dependency, immune to a future Satori upgrade changing output shape. 2026-08-15/17 extended the same card to every imageless page's JSON-LD and OG tags (a projectless guide had been telling Google it had no image while showing one to share debuggers), restricted width/height/alt metadata to the default card only, since a page-supplied image is an arbitrary upload of unknown size. [dev-journal/2026-08-13.md](dev-journal/2026-08-13.md)
- **Review-and-fix discipline became self-aware: back-to-back passes kept finding gaps in each other's remediation.** First named 2026-08-21 ("a review-then-fix pass can itself introduce new gaps large enough to need a second pass") after two independent reviews ran back-to-back on the same work. 2026-08-22 is explicitly logged as the third instance of the same pattern: a fix for one hole (widening `errorDetails` to preserve Prisma's error fields) silently reopened the function's JSON-safety guarantee, and a new contract test shipped with a blind spot (it matched on the guarded call's *text* appearing anywhere, so an unawaited call satisfied it) — both caught only by reviewing the remediation commits themselves, not the original code. The standing countermeasure, repeated through the quarter: mutation-test every new guard by deliberately breaking the thing it protects and confirming the test goes red; a test that cannot fail is treated as actively worse than no test, because it reads as coverage. [dev-journal/2026-08-21.md](dev-journal/2026-08-21.md), [dev-journal/2026-08-22.md](dev-journal/2026-08-22.md)
- **Sandbox constraints, learned once per month, each time newly.** This sandbox cannot start a dev server, run `next build`, reach the Neon/Postgres database, run `tsx` (its CLI needs a unix socket the sandbox refuses to bind), `git push` (SSH is proxy-refused), or `git -C` outside a worktree; worktrees in this repo carry no `node_modules`. Every layout/CSS claim and every script-level change (`og:card`, `db:import-*`) therefore needs Roland's own verification, and several sessions independently rediscovered the same constraints before they were consolidated into memory and `.claude/CLAUDE.md`.
