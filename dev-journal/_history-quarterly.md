- **`unstable_cache` discipline (2026-04-20)** — production 500 on `/api/feed/:section` (`Cannot read properties of undefined (reading 'getTime')`) surfaced the core bug: `unstable_cache` JSON-serializes `DateTime` → string on cache hits, so `post.updatedAt.getTime()` explodes only after the first revalidation. Classic "works locally, 500s in prod after first revalidation" trap. Fix: normalize to ISO inside the cached function so handler contract becomes "strings in, strings out". Same investigation found three call sites rebuilding the wrapper per call (Next.js logs each as "new cache registered" with the function body as the identifier). Resolutions differ per site: `lookupLegacySlug` lifted to module scope (dropped dead `legacy-redirect-${slug}` tag after grep-confirming no `revalidateTag` call sites existed); `getPostBySlug` / `getProjectBySlug` use `Map<slug, wrapper>` memoization because the per-slug tags in `projects.ts` **are** revalidated by admin routes on edit/delete. [source](dev-journal/2026-04.md)

- **Atom feed content quality (2026-04-20 → 2026-04-21)** — `excerptFromBody` emitted raw markdown in `<summary>`. Chose AST walk (`unified` + `remark-parse` + `remark-gfm`, all already in the dep graph) over regex (fragile for nested markdown) or `strip-markdown` package (new dependency). Block nodes (`paragraph`, `heading`, `blockquote`, `listItem`) get trailing `\n` so siblings don't run together; fenced code blocks skipped entirely; inline code kept. 04-21 follow-up extracted image/imageReference alt text via `Nodes` typed import (replaced local `MdastNode` shim + double-cast); added `escapeCdata` for `]]>` terminator collision. Key insight: `unified().parse()` is synchronous, so `stripMarkdown` doesn't need to be async. [source](dev-journal/2026-04.md)
