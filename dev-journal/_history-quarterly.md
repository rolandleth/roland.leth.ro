- **`unstable_cache` wrapper-per-call anti-pattern (2026-04-20 Session 1)** — production 500 on `/api/feed/:section` (`Cannot read properties of undefined (reading 'getTime')`) surfaced the core bug: `unstable_cache` JSON-serializes `DateTime` → string on cache hits, so `post.updatedAt.getTime()` explodes only after the first revalidation. Classic "works locally, 500s in prod after first revalidation" trap. Fix: normalize to ISO inside the cached function so handler contract becomes "strings in, strings out". Same investigation found three call sites rebuilding the wrapper per call (Next.js logs each as "new cache registered" with the function body as the identifier — Roland had flagged "that doesn't look right"). Resolutions differ per site: `lookupLegacySlug` lifted to module scope (dropped dead `legacy-redirect-${slug}` tag after grep-confirming no `revalidateTag` call sites existed); `getPostBySlug` / `getProjectBySlug` use `Map<slug, wrapper>` memoization because the per-slug tags in `projects.ts` **are** revalidated by admin routes on edit/delete. Same Map shape applied to `getPostBySlug` for consistency even though its per-slug tag is currently unused (section-level tags handle invalidation today). [source](dev-journal/2026-04-20.md)
- **Atom feed content quality (2026-04-20 Session 2)** — `excerptFromBody` emitted raw markdown in `<summary>`. Chose AST walk (`unified` + `remark-parse` + `remark-gfm`, all already in the dep graph) over regex (fragile for nested markdown) or `strip-markdown` package (new dependency). `textOnlyProcessor` as module-level constant matches existing `markdownProcessor` pattern. Block nodes (`paragraph`, `heading`, `blockquote`, `listItem`) get trailing `\n` so siblings don't run together after join; fenced code blocks skipped entirely (noisy in excerpts); inline code kept (often meaningful). Final `replace(/\s+/g, " ").trim()` collapses whitespace. Key insight: `unified().parse()` is synchronous (only `.run()` is async), so `stripMarkdown` can be sync despite living next to `markdownToReact`. [source](dev-journal/2026-04-20.md)
