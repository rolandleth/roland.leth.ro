## Watch-outs & Tech Debt

- **`description:` in a post file overrides an admin-authored description on `--overwrite`** — by design (the content repo is the source of truth), but an admin edit is silently lost the next time the file imports. Revisit if descriptions ever get edited primarily in the admin.
- **`getRecentPosts` freezes at generation like every prerendered surface** — the `datetime <= now` filter runs when the llms.txt route generates; the daily cron's `blog-tech` bust is what moves a scheduled post into it.
- **`/guides/:slug.md` serves guides only** — a topic hub slug 404s there, and hubs advertise no `markdownPath`. Fine today; revisit if hubs become reference pages in their own right.
- **`.link, .prose a` is unlayered in `globals.css`** — it has to be, to beat typography's utilities-layer link rule, so a colour utility on a `.link` element can't override it. Revisit when a text link needs a different colour: give it its own class instead of `.link` + utility.
- **An own app with several storefront links never gets the badge** — `linkCtasFor` shows "Download on" pills, because the bucket names one store and the URL can't tell listings apart. Upgrade path: a per-link storefront column, when a project should show two badges.
- **Project manifests must set `isFeatured`, `isDiscontinued` and `isOwnApp`** — `assertRequiredFlags` fails the import (dry run included) otherwise. Any older manifest without all three needs them added before re-import.
- **Hovered text links in light mode are ~3.7:1** (`#0d8fb5` on white) — acceptable because the underline stays visible at rest and on hover. Revisit if the accent colour changes or links lose the underline.

## Session 1

### Decisions

- **Renamed `Post.summary` to `Post.description`** — the field is the meta description, OG description, feed `<summary>` source and JSON-LD description, and nothing on-site renders it as an excerpt (`PostCard` previews the body). Chose a full rename (schema, importer, admin API and form, feed select, JSON-LD, seeds, tests) over mapping a `description:` key onto a `summary` column, so the frontmatter key, the API field and the column agree. `Project.summary` and the Atom `<summary>` element are untouched.
- **Post frontmatter gains an optional `description:`** — `parseFrontmatter` reads it (absent or blank → null → derive from the body); `parsePostFiles` carries it; `planCreate` uses it over `deriveDescription`; `schemaIssuesFor` validates it against `postCreateSchema`, so a line over 160 chars is a skip with a reason, not a truncated snippet. The bulk endpoint honours it too.
- **Overwrite rule for descriptions** — `resolveOverwriteDescription` sits outside the body-change guard: a file description that differs is written whether or not the body changed; equal → untouched; absent → the old rule (re-derive only when the stored value was itself derived and the body changed).
- **The post `.md` export emits `description:`** — live exports only; the scheduled stub keeps its tease title-only. Round-trip stays exact because a re-import sees an equal description and plans no write.
- **Canonical on posts** — `canonicalPath` on the live branch only; the scheduled notice is noindex and gets none.
- **`/blog/tech` description** — a per-section `SECTION_DESCRIPTIONS` map replaces the `Thoughts on ${section}.` placeholder for tech; life keeps its placeholder.
- **llms.txt `## Posts`** — the 10 newest tech posts with descriptions, from a new `getRecentPosts` cache (`blog-recent-{section}` key, `blog-{section}` tag) rather than widening `postListItemSelect`, which carries `body` for the card and deliberately not `description`. Slotted between Guides and Site; omitted when empty.
- **Guide markdown twin** — `buildGuideMarkdownFile` (title, slug, description, topic, project, updated, canonical), `src/app/api/guides/[slug]/md/route.ts` (force-static, `loadGuide`, 404 for hubs), a `beforeFiles` rewrite, and `markdownPath` on guide metadata only.
- **`BreadcrumbList` on guides** — Guides → topic (when live) → guide, emitted as a second JSON-LD block after the Article. `FAQPage` deliberately not added.
- **`Person.sameAs`** — GitHub, X and Bluesky, the three profiles the About page and posts already link; `PERSON_SAME_AS` exported for tests.

### Tradeoffs

- **Repo wins over admin for descriptions** — one source of truth versus lost admin edits on the next import; reversibility: easy (drop the `file.description != null` branch).
- **Prisma client regenerated and committed** — kept the repo consistent with the schema at the cost of a large generated diff; reversibility: mechanical.

The intended look the dead rule described (accent, hover-only underline) was rejected: without an underline, link-vs-text contrast is 2.75:1 light and 1.87:1 dark, under WCAG 1.4.1's 3:1.

### Tradeoffs

- **Eager badge loading** — no blank badge on load or theme toggle; accepted the other variant's SVG (~10 KB) once per first visit. Reversibility: easy.
- **Unlayered link rule** — reliably beats typography; accepted that utilities on `.link` elements can't override it. Reversibility: easy.
- **Required manifest flags** — no silent reset of admin-set flags; accepted three explicit booleans in every manifest. Reversibility: easy.

### Incidents / Bugs

- **`.link, .prose a` never applied inside prose** — it sat in `@layer components`, while typography's `.prose :where(a)` compiles into `@layer utilities`, and a later layer wins regardless of specificity. Links in markdown showed typography's dark, underlined look. Found from byte offsets in the compiled CSS, confirmed on the live site; replaced by the unlayered rule above.
- **`@source not inline("prose")` broke the build** — added to stop a duplicate `.prose` block (~16 KB) that scanning generated from the word "prose" in comments and test names; Tailwind refuses to `@apply` an explicitly disabled class. Claimed without verifying that `@apply` doesn't depend on scanning; reverted and replaced by the `.prose img` rule.
- **Badge SVGs committed as `100755`** — Apple's marketing-kit archive stores them as 0700, macOS unzip restores that, and git records the executable bit at `git add`. Roland ran `chmod 644`; mode-only commit.

### What did I, Claude Code, or my agents learn from this

- **Tailwind v4 generates CSS for any class-shaped word in scanned files** — comments, test names and journal Markdown included. `@apply`-ing a plugin class into a custom utility duplicates it while the bare word still appears anywhere, and `@source not inline()` blocks `@apply` as well.
- **Cascade layers beat specificity** — an override in `@layer components` can't beat typography's utilities; `.prose` overrides in `globals.css` stay unlayered. `rg -b -o` over `.next/static/chunks/*.css` shows which layer a rule landed in.
- **The Bash sandbox can't run `next build`** — Turbopack's PostCSS worker needs to bind a port — and this session type can't start the dev server. CSS changes need Roland's build or dev server to verify.
- **Worktrees here have no `node_modules`** — Roland chose a branch in the main checkout, which he was also working in; staging by explicit path kept the two sets of changes apart.
- **Every new test was seen to fail** — each step broke the code it guards (multi-store count, theme classes, flag type check, the four flag paths) before committing.
