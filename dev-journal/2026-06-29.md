## Watch-outs & Tech Debt

Fine within a section (screenshots share a device class); revisit if a section mixes portrait + landscape and the jump looks bad.
- **`transparent` keyword in gradients** — never fade to CSS `transparent` (it's transparent *black*, `rgba(0,0,0,0)`), which smears grey/black on light backgrounds under iOS Safari. Fade to a same-colour zero-alpha value (`--color-background-transparent`) instead. Trigger: any new edge-fade / mask gradient.

## Session 1

### Decisions

- **Gradient fade target** — added `--color-background-transparent` (same bg colour at zero alpha) in `globals.css` and pointed both tablist edge-fades at it, replacing `via-…/80 to-transparent`. Chose a CSS var over an inline `rgba` so light/dark resolve automatically and it's reusable (alternative: per-element inline gradient — rejected as non-DRY and theme-blind).
- **Carousel sizes from measured ratio** — `ProjectSectionCarousel` reads `naturalWidth/naturalHeight` in the image's `onLoad` and drives the stage's `aspect-ratio`, capped `max-h-[70vh] sm:max-h-120`, falling back to fixed `h-120` until measured. Chose measure-on-load over storing dimensions (not yet persisted) and over a per-section fixed ratio (would reintroduce letterboxing for off-ratio images).
- **Swipe via Framer drag** — horizontal `drag` layer over the slides (carousel) and on the stage `motion.div` (lightbox), gated on `canNavigate`, routed through the parent's existing `navigateImage` so swipes cross section boundaries like the arrows. Extracted `resolveSwipe(info)` + thresholds into `src/lib/client/swipe.ts` so both surfaces share one implementation.

### Tradeoffs

- **Stage hugs the image** — gained tight, letterbox-free sizing; accepted a one-time height snap when the first image loads and per-image snaps across differing ratios. Reversibility: easy (revert to fixed `h-120`).
- **Swipe untested in jsdom** — shipped without a unit test rather than writing brittle pointer-event theater that Framer's gesture layer ignores. Reversibility: easy; covered manually instead.

### Incidents / Bugs

- **Black gradient only on real iOS Safari** — root cause: `to-transparent` interpolates toward transparent black; desktop responsive mode/simulator premultiply alpha differently and hid it. Fixed by fading to `--color-background-transparent`. Low regression risk.

### What did I, Claude Code, or my agents learn from this

- **`transparent` is transparent black** — fading any opaque colour to the `transparent` keyword produces a grey/black midpoint that Safari renders most visibly. Always fade to the same colour at zero alpha.
- **Framer drag + AnimatePresence** — keep the `drag` element separate from the keyed, x-animating slide (use a stable drag layer wrapping the `AnimatePresence`) so the gesture state and the enter/exit animation don't fight. `draggable={false}` + `pointer-events-none`/`select-none` on the image stops native image-drag from stealing the gesture; a sub-threshold tap still reaches the enlarge button.
