## Session 1

### Decisions

- **Placement as four independent fields** — `prominence` (`high` | `medium` | `low`: tile, card, icon under More projects), `pageLayout` (`product` | `portfolio`), `isDiscontinued` (always under More projects, faded), and `isOwnApp`, which now only words the store buttons. Any combination is valid, so no rule has to forbid one (rejected: keeping `isFeatured` × `isOwnApp`, which tied the page and the placement to ownership; one placement enum mixing level and layout).
- **Semantic level names** — `high`/`medium`/`low` say how prominent, not how it looks, so a redesign changes the renderer, not the data. A new level (an `xHigh`, an `unlisted`) is a new enum value plus a case in `sectionForProminence`, which the type-check enforces; an unknown value from the database logs and lists the project under More projects.
- **Discontinued keeps the old rule** — under More projects, faded, grouped by platform (Roland: "As now").
- **"More projects"** replaces "Earlier projects"; `WorkCard` became `ProjectCard`.
- **Admin hint when Discontinued overrides the level** — added after Capsule, set to High, stayed in the icons and looked like a bug. Shown in the form and beside the list picker, only for a discontinued project at High or Medium.
- **The admin list groups by the stored level**, not by where the gallery shows the project: it's where the level is edited.
- **The import refuses a manifest that still sets `isFeatured`** and names the replacement, rather than ignoring it.
- **Data carried by one-off SQL** — adds the enum columns and fills them from `isFeatured`/`isOwnApp` before the push drops `isFeatured`. Not kept in the repo (Roland).
- **One-step release** — push, then deploy straight away (rejected: a two-phase push that keeps `isFeatured` one deploy longer).

### Tradeoffs

- **One-step release** — gained one push and no temporary schema; lost a gap-free cut-over: between the push and the deploy, the live code can't read projects. Static pages keep serving from cache. Reversibility: n/a.
- **Tiles and cards without an image take the full width** — no empty column, at the cost of uneven heights beside a tile that has one. Reversibility: easy.

- **Half tile without an image had no bottom padding** — its image used to close the tile; the padding now applies when there's none.

### What did I, Claude Code, or my agents learn from this

- **Target a database by env, not by file** — `prisma.config.ts` loads `.env` through `dotenv/config`, which doesn't override a variable already set, so `env DATABASE_URL=… yarn prisma db execute --file …` and `env DATABASE_URL=… yarn db:push` hit dev without touching `.env`.
- **Staging around another session's uncommitted work** — where hunks separate, a filtered patch with `git apply --cached`; where they don't, build HEAD plus only these changes in the scratchpad and put it in the index with `git hash-object -w` and `git update-index --cacheinfo`. The working tree stays untouched.

## Session 2

### Decisions

- **Video syntax** — image syntax with an `.mp4` or `.webm` URL, rewritten to `<video controls preload="metadata" playsinline>` by `rehypeVideo.ts` in both processors (a raw `<video>` tag would need `allowDangerousHtml` and reverse the 2026-04-21 choice; a directive needs a new dependency).
- **Storage** — Vercel Blob, capped at 20 MiB per video (`MAX_VIDEO_UPLOAD_MIB`); Roland chose it after checking that an app preview clip is 3–5 MB (`public/` rejected: videos in git; R2 rejected for now: a second vendor).
- **Admin upload goes from the browser to Blob** — `/api/admin/upload/video` only signs: it authors the key with `adminUploadKey` and issues a client token for that key, type and size (the SDK's `handleUpload` pair rejected: the client would author the key; the image route's path is impossible past 4.5 MB).
- **Video sniff in the browser** — `detectVideoMime`: MP4 by an `ftyp` major-brand allowlist, WebM by the EBML magic plus the `webm` doctype; `.mov` refused everywhere (a deny list rejected: an unknown brand would be stored and never play).
- **Editor insert never replaces or splits text** — `insertMarkdownBlock` inserts before a line when the cursor is at its start, otherwise after the cursor's line (raw-cursor insert rejected: it split sentences, deleted a selection, and put a second upload inside the first one's `![…]`).
- **Importer media** — a relative image-syntax path (no scheme, no leading `/`, no `..`) is a local file, uploaded under `posts/<section>/<slug>/` with a content-addressed key; the stored body gets the Blob URL, the file keeps its path (a `--media` flag rejected: breaks editor previews).
- **Two plans per import** — `planPostImportWithMedia` plans on preview bodies to decide which posts are written, uploads only for those, then plans again on the stored bodies (upload-then-plan rejected: skipped and invalid posts would upload).
- **A failed listing stops the post import** — the project importer falls open to "nothing exists"; for posts the listing also decides which posts are unchanged, so falling open would misreport every media post.
- **Sweeps left separate** — `pruneOrphans` and `prunePostMedia` share `listBlobs` and `deleteBlobs` already; one function for both needs six parameters and saves about three lines. Merged instead: `readFileInFolder`, `placeholderBlobUrl`, `storedBlobsByKey`, the `blobStore` adapter and the tests' `makeStore`.
- **Delete-time cleanup** — `mediaCleanup.ts`: a post delete removes its prefix, plus body-named blobs under the same slug in the other section; a project delete reuses `pruneOrphans` with no references; awaited before the 204 and never throws (per-prefix delete for both sections rejected: the other section's prefix can be another post).
- **Worktree, at Roland's request** — against the earlier plain-branch habit for this repo; `PostForm.test.tsx` went in as the committed file plus the video tests, without the uncommitted refactor it was mixed with.

### Tradeoffs

- **Image syntax for video** — no raw HTML and no dependency; other markdown renderers show the `.md` export's video as a broken image; reversibility: moderate, it is an authoring contract.
- **Browser-only type check** — uploads past 4.5 MB; no server-side sniff for video; reversibility: easy.
- **Cleanup inside the delete request** — it is sure to run; a post delete waits for two Blob list calls; reversibility: easy.
- **Images by extension in the importer** — matches the project importer's trusted-files stance; a mislabelled image uploads as it is; reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Limits come from the docs, not from memory** — I named the 4.5 MB body cap from memory and only checked it later, and I raised Blob's storage cap without its 10 GB transfer cap until Roland asked. Both shaped the storage choice.
- **A script can't be run from a session here** — it reads `.env`. The import flow first lived in `scripts/import-posts.ts`, untestable; it moved into `postMediaRun.ts` with injected reader and store.
- **A worktree inside the main checkout can borrow its tools** — calling `node_modules/.bin` by absolute path runs tsc, ESLint and Vitest on the worktree's files; only env-dependent suites fail.
- **Writing the tests found the insert bug** — the raw-cursor rule looked fine until a test stacked two inserts; the rule changed before anyone used it.
- **A "can you reuse" question deserved an audit first** — most of the project importer was already reused, but I had copied the folder read, the placeholder host and a listing map without noticing.
