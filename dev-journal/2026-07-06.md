- **`content → import` layer dependency** — `lib/content/postMarkdown.ts` imports `escapeYamlDoubleQuoted` from `lib/import/frontmatter.ts` to keep the `.md` writer's quoting in lockstep with the importer's `unquote` reader. Fine while `frontmatter.ts` stays pure; revisit if the import layer ever grows `next/*`/IO deps that shouldn't flow into content rendering.
- **`.md` export round-trip is partial** — `buildPostMarkdownFile` emits `title`/`section`/`date`/`canonical`, but `parseFrontmatter` only reads `title` and the importer derives the stored `datetime` from the *filename*, not the `date:` key. Title + body round-trip byte-for-byte; a full export→reimport restore would also need a correctly-named file. Revisit only if a real backup/restore workflow is wanted.

## Session 1

### Decisions

- **`.md` blog posts via middleware rewrite → route handler** — `NextResponse.rewrite` maps `/blog/:section/:slug.md` to a `route.ts` at `/api/blog/:section/:slug/md` that returns `text/markdown`. Forced because a `route.ts` can't coexist with the post `page.tsx` at one path, and a page can't set `Content-Type`. Rejected: `[slug].md` as a dynamic segment (Next requires brackets to own the whole segment — extension-in-segment unsupported); `/blog/.../md` subpath (user wanted the real `.md` URL); `next.config` `rewrites()` (repo centralizes all URL mapping in `proxy.ts`).
- **Frontmatter + verbatim body** over raw-body-only — YAML block (title/section/date/canonical) then the unchanged body, so LLMs get the title (the body has no H1) and the file self-describes. Reused the importer's `--- title ---` format so the export parses back cleanly.
- **Discovery via `<link rel="alternate" type="text/markdown">` only** — added optional `markdownPath` to `buildPageMetadata`. An initially-added visible "View as Markdown" header link was removed: not standard for a blog, and the audience (LLMs/crawlers) uses the alternate, not on-page chrome.
- **No legacy-alias handling in the `.md` route** — a miss returns a plain 404 (feed-route shape), not a 308. The `.md` URL shape is brand new, so no stale `.md` links to the handful of renamed old slugs can exist; aliases stay an HTML-only concern.

### Tradeoffs

- **Extracted `matchLegacyRedirect` from `proxy`** — the new rewrite branch pushed `proxy`'s cognitive complexity to 16 (sonarjs cap 15); pulled the six-way legacy-redirect chain into a helper returning `path | null`. Gained: back under budget, more cohesive. Behaviour-preserving (all 62 proxy tests green). Reversibility: easy.
- **Shared `escapeYamlDoubleQuoted` vs inline** — extracted the YAML double-quote escape so `buildPostFile` and `buildPostMarkdownFile` can't drift, at the cost of the `content → import` dependency above. Considered inlining (leaner, no cross-dep) but the shared helper is what makes the round-trip guarantee hold. Reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Next.js dynamic segments can't carry a file extension.** `[slug].md` is not a valid dynamic segment — brackets must wrap the entire folder name. Static-extension route folders (`rss.xml`, `llms.txt` — the repo already uses the latter) work only because the whole segment is literal. A *dynamic* slug + extension therefore always needs a rewrite; there's no folder-naming trick. Confirmed against official docs (Dynamic Route Segments + route.js, v16.2).
- **`page.tsx` and `route.ts` cannot share a route-segment path** (build-time conflict). The `text/markdown` content-type requirement is what forces the handler onto a separate path.
- **`postDatetimeToISO` normalizes to UTC**, so a test that hardcodes a wall-clock ISO string fails on a non-UTC machine (saw `09:30` expected vs `07:30Z` at +02:00). Derive the expectation from the formatter instead of hardcoding.
