### Decisions

- **Revert `<Link>` → `<a>` for non-route hrefs in `AboutContent.tsx`** — applied to all 9 bio links and the 3 `contactLinks` (`mailto:`, external, `/resume.pdf` with `download`). `next/link` adds nothing for these and the static-asset case is the worst (Next's prefetch logic isn't documented to skip non-route URLs). Alternative: keep `<Link>` and add a custom `<ExternalLink>` wrapper — rejected as over-engineering for a single page.
- **Drop `error.digest` rendering from `error.tsx` and `global-error.tsx`** — without external error aggregation, the digest is opaque to users and uncorrelatable for the developer (Vercel Hobby retains runtime logs ~1h; by the time a user reports a hash, the matching log is gone). Alternatives: keep it for "just in case" — rejected as YAGNI; wire Sentry now — rejected as a separate, larger decision out of scope for this cleanup pass.
- **Delete `src/app/errorMessages.ts`, inline strings** — once the digest was dropped, the only shared content was 2 stable strings ("Something went wrong", "Try again"). Extracting them into a module to dedupe was over-extracted. Alternative: move the file to `src/lib/` — rejected for the same reason.
- **Move `ClientAnalytics.{tsx,test.tsx}` to `src/components/`** — it's not a Next.js convention file, only imported from `layout.tsx`, and contributed to clutter in `src/app/` root. Alternative: leave it; rejected because the App Router root should hold convention files (`page.tsx`, `layout.tsx`, `error.tsx`, `global-error.tsx`, `not-found.tsx`, `sitemap.ts`, `globals.css`) plus route segments only.
- **Merge two `.prose a` rules in `globals.css` into one combined selector** — `.link, .prose a { @apply ...; font-weight: inherit }`. Applying `font-weight: inherit` to `.link` is a no-op in body context. Alternative: keep them separate to scope `font-weight: inherit` strictly to `.prose a` — rejected because there's no scenario where `.link` would want a non-inherited weight.
- **Refactor `ErrorMessage.tsx` className concat** — extract `extraClass` const so the template literal is no longer nested. Removes the `sonarjs/no-nested-template-literals` eslint-disable. Alternative: keep the disable comment — rejected because the fix is one line and addresses the actual lint complaint.
- **RTL tests for both error boundaries** — render, reset wiring, console.error logging. Initial proposal was 5 cases each (including digest visible / digest absent); after dropping the digest the suites collapsed to 3 cases each. Skipped a digest-related test for `global-error.tsx` because the Next.js convention there renders a full `<html><body>` shell — happy-dom permits it but adds no testable value beyond what the body assertions already cover.

### Tradeoffs

- **Inlining shared strings vs `errorMessages.ts`** — gained one fewer file in `src/app/`; accepted trivial drift risk on 3 short stable words across two files. Reversibility: easy.
- **Removing the `error.digest` UI** — gained a cleaner default error surface; lost the (currently theoretical) ability for a user to report an error hash that maps to a server log. With Vercel Hobby's ~1h runtime-log retention, that ability was already largely theoretical. Reversibility: easy — re-add the conditional `<p>` if external error tracking is wired up.
- **`<a>` instead of `<Link>` for `/resume.pdf`** — gained explicit "not a Next route" semantics and avoided depending on Next's undocumented prefetch behaviour for non-route URLs; accepted that internal navigation no longer benefits from soft-routing for this single href (irrelevant — it's a download). Reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Personal-site error boundaries don't need digest UI without log aggregation** — surfacing the Next.js error digest in user-facing UI only pays off when paired with extended-retention logs or external error tracking (Sentry / Logflare / Axiom / Vercel Pro+). On Hobby tier, ~1h runtime log retention makes user-reported hashes near-useless because the matching server log is gone before the user emails. Re-add the digest the same day external aggregation is wired up, not before.
- **`next/link` for non-route hrefs is a small but real foot-gun** — `<Link>` for `mailto:`, external URLs, and static assets like `/resume.pdf` falls through to `<a>` but still pulls a client component into the tree and depends on Next's undocumented prefetch behaviour for non-route URLs. The "consistency" of using `<Link>` everywhere is illusory; `<a>` is the correct primitive for anything that isn't a Next.js route.
- **Tests for thin convention files (`error.tsx` / `global-error.tsx`) are still cheap insurance** — initial instinct ("these are personal-site error surfaces, skip the tests") was wrong: the harness was already in place (happy-dom + RTL across 30+ component tests), so adding ~3 cases per file took minutes and now catches Next.js error-boundary contract drift (prop shape, reset wiring) on future upgrades.
