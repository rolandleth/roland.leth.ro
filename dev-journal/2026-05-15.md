## Watch-outs & Tech Debt

- **Bulk import body-size budget** — schema caps each file at 100KB and the batch at 50, so worst-case payload is ~5MB. Vercel App Router's default JSON body limit hasn't been exercised that hard from this app yet; revisit if a real bulk run hits 413 or a runtime hard-stop.

Acceptable today (your titles don't look like that); revisit if a parsed datetime ever doesn't match the user's intent.

## Session 1

### Decisions

- **Future-post marker rendered inline (no pill/badge)** — chose a `text-accent` `· Scheduled` suffix on the existing meta line over a separate badge component. Matches the existing `· Draft` shape; one render-time comparison, zero DB or API change. (Alternative: colored pill — rejected as overkill for a single-state indicator on an admin-only surface.)
- **Inline publish toggle reuses existing PUT, no bulk endpoint** — chose a per-row `PostPublishedToggle` mirroring `IsFeaturedToggle` (`useOptimisticMutation` → `PUT /api/admin/posts/[id]` with `{ published }`). The schema and audit log already cover this field. (Alternatives: dedicated `/publish` action endpoint — rejected, no extra invariants to enforce; bulk-publish multi-select — out of scope for this session.)
- **Bulk import: section picked once per batch, `published` derived per-file from the datetime** — section selector lives on the bulk page; future-dated posts auto-publish (so the existing scheduled-surface logic in `getPostsBySection` picks them up at their `datetime`), past-dated posts saved as drafts so the admin reviews each. (Alternatives considered for section: filename suffix or per-file picker — rejected as more UI for no current need. Alternative for `published`: blanket draft — rejected because the auto rule is what the user actually asked for.)
- **Bulk import: pre-query slug collisions, then `createManyAndReturn` with `skipDuplicates`** — one round-trip to detect existing slugs in the same `(section, slug)` unique scope, single `createManyAndReturn` insert, single `revalidatePostSection`, one audit line per created row under a new `[api:admin:posts:BULK]` tag. (Alternative: per-row `create` in a loop — rejected; N round-trips and N revalidates for what is structurally one batch operation. Alternative: skip the pre-query and let unique-constraint surface — rejected; without `skipDuplicates` it aborts the batch, and even with it the user loses per-file "skipped because" reporting.)
- **Bulk parser is a separate `src/lib/bulkImportParser.ts`** — single source of truth for the regex + validation, consumed by both the API route and the client preview. Returns a discriminated `{ ok: true, ... } | { ok: false, reason }` so the UI can surface the same reason string the server would.

### Tradeoffs

- **Bulk endpoint returns 200 even on partial success** — gained a single response shape (`{ created, skipped[] }`) the UI can render uniformly; accepted that "some failed" doesn't surface as a non-2xx. Reversibility: easy.
- **Within-batch slug dedupe runs client-blind on the server** — gained a clear "Duplicate slug within this batch" reason; accepted that the server still trusts the client to send distinct filenames most of the time. Reversibility: easy.

### Environment / Config Changes

- New audit tag `[api:admin:posts:BULK]` added to `ADMIN_AUDIT_TAGS` — bulk imports now greppable in Vercel logs distinct from one-off `POST`s.

### What did I, Claude Code, or my agents learn from this

- **`vi.resetAllMocks()` clears factory-set return values** — the bulk route test's `currentDatetimeString` mock was set in the `vi.mock` factory via `vi.fn().mockReturnValue(...)`, and the per-test `resetAllMocks()` wiped that implementation, so subsequent calls returned `undefined` and the `result.datetime > now` comparison degenerated. Fix: re-set the return value inside `beforeEach`. Mirror this whenever a module mock needs a stable default across tests that also call `resetAllMocks()`.

### Decisions

- **`writeKeepalive(redis): KeepaliveResult`** — discriminated `{ ok: true; value } | { ok: false; error }`. Each caller owns its own log tag, status code, and response shape (cron 200 on no-Redis, admin 503 — those policies aren't shared, the WRITE is). Returns the original `error` (not stringified) so callers can hand it to `console.error` and get a usable stack. Alternative considered: a single `keepalive(redis, opts)` taking log-tag + status-code maps — rejected as premature configuration; today there are exactly 2 callers and their differences are real, not accidental.
