## Session 1

### Decisions

- **Missing `IP_HASH_SECRET` → global-bucket fallback, not fail-open** — `src/app/api/auth/login/route.ts` now builds the `Ratelimit` whenever Redis (`getRedisConfig()`) is present, regardless of the HMAC secret. The secret controls only granularity via the new `bucketKey()` helper: HMAC'd-IP key when set, constant `globalBucketKey` (`"global"`) when not. Chose global bucket over the two alternatives — fail-open (prior behavior: no limiter at all) and plain-IP keys (GDPR regression, IPv4 keyspace is brute-forceable). Some rate limiting beats none; the global key carries no IP, so no GDPR concern.

### Tradeoffs

- **Re-accepted the admin-lockout DoS** — per-IP keying had deliberately replaced a global bucket precisely to avoid a botnet locking the admin out; the fallback reintroduces that for the no-secret case only. User explicitly accepted: a 15min lockout is tolerable and "screams something is wrong" (i.e. surfaces a missed `IP_HASH_SECRET` on deploy). Reversibility: easy — gated on one config var; correct deploys that set the secret keep per-IP isolation and are unaffected.

### Environment / Config Changes

- No new env vars. Behavioral change: the login limiter is now active whenever both `KV_REST_API_TOKEN` and `KV_REST_API_URL` are set, even if `IP_HASH_SECRET` is absent. The module-load warning text changed from "rate limiting disabled" to "...falls back to a global bucket". `getIpHashSecret` doc in `src/lib/auth/env.ts` updated to match (null degrades granularity, never disables the limiter).

### What did I, Claude Code, or my agents learn from this

- **Testing the route's Redis-present path needs module-load env control** — the route constructs `Ratelimit` at module load from env read at that moment, so `route.test.ts` (which loads under `.env.test` with no KV vars) can only reach the `ratelimit === null` branch. The Redis paths require a separate file that does `vi.resetModules()` → `vi.stubEnv(...)` → dynamic `import("./route")` per test. Mocks for `@upstash/redis`/`@upstash/ratelimit` must be **classes** (constructed with `new`); arrow-function `vi.fn(() => ({}))` throws "is not a constructor". An empty mock class trips eslint `no-extraneous-class` — give it a throwaway instance field. Static `Ratelimit.slidingWindow` is attached via `Object.assign(class {...}, { slidingWindow })`.

### Notes

- Left the invalid-credentials warn log untouched (it omits the bucket key when no secret is set). In global mode the key is the constant `"global"`, so logging it adds no correlation value over the rate-limit-exceeded warn that already logs it. User confirmed fine.
