# Dev Journal – 2026-04-16

## Session – 14:15

### Decisions

- **`projectInclude` extraction** — moved shared Prisma include clause from both the API route and edit page into `src/lib/projects.ts`; single source of truth (alternative: leave inline, accepted duplication risk).
- **`capitalizeSection` helper** — extracted repeated `section.charAt(0).toUpperCase() + section.slice(1)` (5 sites across 4 files) into `src/lib/sections.ts`; consumed in blog pages, archive, search, and feed route.
- **`AnimatedCard` shared component** — unified `AnimatedPostCard` and `AnimatedProjectCard` (identical except delay multiplier) into `src/components/AnimatedCard.tsx` with a `delayMultiplier` prop; both card components now delegate to it.
- **`searchPosts` — push filter to Prisma** — replaced JS in-memory filter (load all published posts, filter with `.filter()`) with Prisma `OR: [{ title: contains }, { body: contains }]` + `mode: "insensitive"`; avoids full table scan. Used explicit `AND: [publishedWhere, { OR: [...] }]` form for unambiguous intent.
- **`MarkdownEditor` deduplicate pipeline** — replaced a local `renderMarkdown` function (duplicated `unified` pipeline without `rehype-pretty-code`) with `import { markdownToReact }` from `src/lib/markdown.ts`.
- **`SectionManager` stable keys** — replaced index-based React `key` on section rows with `_key: crypto.randomUUID()` (same pattern already used by `LinkItem`); prevents `isOpen` state corruption on reorder/delete.
- **`IsFeaturedToggle` / `ProjectSortOrderInput` error surfacing** — added local `error` state rendered as a small red paragraph on failure; previously errors were silently swallowed.
- **`ProjectForm` deletion UX** — added `isDeleting` state; delete button shows "Deleting…" and becomes disabled during the request.
- **`LoanCalculatorClient` number parsing** — replaced bare `Number(e.target.value)` with a `parseNum(raw, fallback)` helper (`parseFloat` + `isNaN` guard) applied to all 8 input handlers including extra-payment sub-fields.
- **`ProjectContent.tsx` — keep raw `platform`** — intentional: detail page shows full keyword string (e.g. "iOS, React"); `formatPlatformDisplay` is only for list/gallery views. Comment added.
- **`Footer.tsx` — keep `year` inside function** — reverted module-level `CURRENT_YEAR` constant; in a `"use client"` component it would freeze at module load time across year boundaries post-hydration.
- **`auth.ts` `getSecret` stays a function** — not promoted to a module-level constant so `process.env.SESSION_SECRET` can be stubbed in tests. Comment added explaining why.

### Tradeoffs

- **Prisma OR filter vs JS filter** — gained: no full table scan; accepted: mock must simulate query behaviour in tests; reversibility: easy.
- **`AnimatedCard` abstraction** — gained: DRY; accepted: one more indirection layer; reversibility: easy (inline the two props).
- **Explicit `AND: [publishedWhere, { OR }]` form** — gained: unambiguous AND+OR intent; same SQL as spread form; reversibility: trivial.

### Incidents / Bugs

- **`route.test.ts` missing `unstable_cache` mock** — importing `projects.ts` (which calls `unstable_cache` at module level) into the route test caused vitest to error on the unmocked export; fixed by adding `unstable_cache: (fn) => fn` to the `next/cache` mock.
- **`searchPosts` test mock too structure-coupled** — initial mock fix checked `args.where.OR` directly; broke when query was restructured to explicit `AND` form. Replaced with a recursive `findContainsTerm` helper that extracts the `contains` value from anywhere in the where tree, making tests robust to restructuring.
- **`markdown.test.ts` — `rehype-pretty-code` tokenizes code** — asserting `toContain("const x = 1")` failed because the highlighter wraps each token in a `<span>`; fixed by asserting on `data-language="ts"` and `data-rehype-pretty-code-figure` attributes instead.
- **`ProjectForm.tsx` TS error on `_key`** — after making `_key` required in `SectionItem`, `InitialData.sections` (fed from DB data without `_key`) failed type-checking; fixed by using `Omit<SectionItem, "_key">` in `InitialData`, mirroring the existing pattern for links.

### Watch-outs & Tech Debt

- **`searchPosts` mock uses recursive term extraction** — `findContainsTerm` works for the current query shape but is a test-layer workaround; revisit if the query structure changes significantly or if integration tests against a real DB are added.
- **`revalidateTag(tag, "max")` two-param call** — initially flagged as incorrect by review agent; confirmed valid in Next.js 15 (`profile: string | CacheLifeConfig`). Worth re-checking if upgrading Next.js past 15.
