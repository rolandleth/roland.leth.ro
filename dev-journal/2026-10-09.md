## Session 1

### Decisions

- **More projects preview icons link to their project pages** — the same links as the open list (rejected: a tap opens the list). The preview is a real list now, no longer `aria-hidden`; visitors without JavaScript can reach those projects too.
- **Shared-element slide with two overlaid layers** — the preview row and the full list are both always rendered (every link stays in the server HTML) and share the box's origin; the out-of-flow layer is `absolute inset-x-0 top-0`. On toggle, `MoreProjectsDisclosure.measure()` reads each preview `li` against its twin in the list (paired by `data-project-id`) and both layer heights. One `progress` MotionValue drives the slides (`SlideFromPreview`), the fades (`FadeInWithList`) and the box height, so nothing drifts, and a tap mid-way reverses from where it is. Rejected: one list rearranged by Framer `layout` (needs `display: contents` to flatten the groups into one row, and on close the other icons would vanish instead of fade); Framer `layoutId` (needs one of each pair unmounted, but both must stay in the HTML).
- **Four phases** — `closed` / `opening` / `open` / `closing`. The list goes inert as soon as close starts; the preview takes over only when the icons land on it. The box has an explicit height only while moving, `auto` at rest, so a resize while open or closed needs no re-measure.
- **Preview pick** — no open source projects; of the rest, live first (`liveFirst`, a local stable sort that doesn't rely on the query's order), then grouped by platform, then the discontinued ones at the end of the row, also by platform. Up to 10. If every project is open source, no preview list renders (an empty one would still be announced). Rejected: the first 10 of the grouped list (the old rule; it filled the row with the first platform's discontinued projects ahead of other platforms' live ones), showing the pick in query order (icons cross on the way to their groups).
- **List copies of previewed projects load their icons eagerly** — a lazy one could be blank when it starts to slide; it's the same URL as the preview's icon, so no extra download.
- **0.3s easeOut** — longer than `CollapsiblePanel`'s 0.25s, since the icons travel further.

### Tradeoffs

- **Duplicate links** — gained a symmetric, interruptible animation with SSR intact; accepted 10 links twice in the HTML and about 120 more lines of client code (`MoreProjectsMotion.tsx` and the measuring in the disclosure); reversibility: moderate.
- **Discontinued at the end of the row** — their icons slide back up and across the row on open, where live ones move straight down; reversibility: easy.
- **Discontinued fill in section order** — with many discontinued iOS apps, discontinued Mac and Web projects never reach the preview; reversibility: easy.

### Incidents / Bugs

- **Preview favoured discontinued projects** — the preview took the first 10 after `groupByBucket`, which regroups by platform after the query's live-first sort, so discontinued iOS projects took slots ahead of live Web ones. It went unnoticed while the preview was decorative. Fixed by picking before grouping; covered by page tests.

### What did I, Claude Code, or my agents learn from this

- **Framer MotionValue semantics** — `animate(value, …)` stops the animation already on that value; a stopped animation calls `onStop`, never `onComplete`. `useTransform` over an array of MotionValues recomputes when any of them is `set`, so measured offsets kept as MotionValues move the slides without a re-render.
- **Check a fresh tab after multi-edit hot reloads** — the gallery threw `liveFirst is not defined` in a tab that reloaded between two edits; a fresh load was clean.
- **The browser pane's pending smooth scrolls finish when the page grows** — this looked like opening More projects scrolled the page; after a reload and a fresh scroll it didn't.
- **Slow the animation to inspect it** — a temporary 4s linear transition and a preview of 2 made the mid-flight frames visible in screenshots; both were reverted before committing.
