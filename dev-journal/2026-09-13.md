## Session 1

### Decisions

- **`isOwnApp` boolean on `Project`** — chose an explicit flag over deriving "creator" from `role` (free text despite the presets: "Head of Digital" exists, and copy must not decide behaviour) and over the hostname-only rule (DeinDeal and MyTherme were excluded only because they link to the legacy `itunes.apple.com` host — an accident, not intent).
- **Badge artwork chosen by `bucket`** — iOS and Mac listings share the `apps.apple.com/app/id…` URL shape with no `mt=12`, so the URL can't tell them apart, and the link label is copy. iOS → App Store badge, Mac → Mac App Store badge, Web/OpenSource keep the "Get on" pill.
- **Discontinued own apps keep the bare pill, no badge** — the badge says "Download", which asserts the app is on sale; same reasoning as dropping the "Get on" prefix on 2026-08-12.
- **Both theme variants rendered, switched by the `dark:` class** — a `<picture>` media query would ignore the manual toggle, and choosing `src` from theme state would flash the wrong badge at dark-mode visitors until hydration. Apple's SVGs are used unmodified at 40px, the guidelines' minimum.
- **`itunes.apple.com` added to storefront hosts** — Body Tracking is an own app linked to the legacy host and had no CTA at all. Safe now that the badge is gated on the flag rather than the host.
- **`ProjectLinkCta` extracted** — one component decides badge-or-pill for both the hero grid and the repeated CTA below the content, which also removed the duplicated pill markup.
- **Blog images centred with `prose-img:mx-auto` on the shared body wrapper** — preflight makes `<img>` block-level so they sat flush left. Applies to post pages, list excerpts and guides since they share `PostMarkdownContent`; the admin preview has its own wrapper and was left alone (not requested).

### Tradeoffs

- **Explicit flag vs zero-schema hostname rule** — gained intent that survives future client apps with a real `apps.apple.com` link; accepted touching ~10 files (schema, types, zod, routes, form, import script, skill docs, fixtures) and a `db:push`. Reversibility: easy, the column is independent.
- **Bucket-driven artwork** — gained no schema change on `ProjectLink`; accepted the wrong second badge if a project ever lists two Apple storefronts. Reversibility: easy.

### Environment / Config Changes

- `prisma/schema.prisma`: `isOwnApp Boolean @default(false)` on `Project`. Roland ran `yarn prisma generate` and `yarn db:push`; the regenerated client under `src/generated/prisma/` is committed with the schema.
- New static assets `public/images/app-store/{as,mas}-{black,white}.svg` — Apple's marketing-kit badges, unmodified.

### What did I, Claude Code, or my agents learn from this

- **Audit live content through the site when no DB command is sanctioned** — sweeping the 20 project pages in the browser (role, bucket, store link host) settled both open design questions in minutes and surfaced the `itunes.apple.com` quirk that no code read would have shown.
- **Apple listing URLs don't encode the platform** — per-store artwork needs a data field or a bucket mapping, never URL parsing.
- **Admin presets don't make a field an enum** — `PresetOrFreeformInput` stores whatever was typed, so any rule keyed on `role` would be keyed on copy.
