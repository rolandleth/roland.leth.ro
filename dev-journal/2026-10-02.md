## Watch-outs & Tech Debt

- **Cache keys for list queries** — `unstable_cache` keys on its callback's source plus the key parts, so a cached query that names its `select` instead of spelling it out keeps the same key when the select changes, and serves rows from older code to newer code. Detail lookups and the projects gallery now carry a shape part; the blog and guide list caches that use named selects (`postListItemSelect`, `postArchiveItemSelect`, `guideListItemSelect`, `guideTopicSummarySelect`) don't yet. Revisit before changing any of those selects.
- **Answers and the earlier projects list need JavaScript to open** — `CollapsiblePanel` animates by height with Framer; without JS they stay closed, and find-in-page can't open a closed answer. Revisit if no-JS reading matters.
- **Headline length on the product hero** — at 66px a 64–70 character headline takes two lines from a window of about 1,150px, three between 1,024 and 1,150px, and four on a phone.
- **Imports and the dev server read different databases** — the import scripts load `.env` (production); Next.js loads `.env.local` first. An import can land in production while the dev page still shows old data.
- **Shared heading structure** — the product hero's `h1` and the gallery tile's `TileTitle` repeat the name / eyebrow / headline structure and its hidden ": " and ". " joiners. Extract one component once the hero design settles.

## Session 1

### Decisions

- **Product page section structure** — required `kind` (`text` | `steps` | `pricing`), `text` with a required `layout` (`stacked` | `split`), steps as their own items with per-step galleries (rejected: markdown-parsed steps, one shared gallery).
- **Cache shape keys** — `wrapNullableDetail` takes a required `shape` that joins the key, so no detail lookup can omit it; the gallery cache gets `GALLERY_SHAPE` (rejected: per-call opt-in, which a new lookup could forget).
- **Best value** — optional `isBestValue` on a manifest offer, validated as at most one, paid, with another paid price in its plan; shown as an outlined tile with the badge on its edge and a computed "Save N%" (rejected: a plain pill, judged dull; typed savings copy that could drift from the prices).
- **FAQ motion** — one shared Framer panel (`CollapsiblePanel`) for both FAQs and the earlier projects list (rejected: CSS `::details-content` with `interpolate-size`, Chromium only; a second animation approach beside Framer).
- **Hero layout** — title row across the frame, then the summary on the left and the image on the right, tops aligned, 64px apart (rejected after a side-by-side try: the image on the left; everything stacked, which pushed the image below the fold on laptops).
- **"Back to top" only** — a rail link that scrolls up, drops the `#section` and focuses `<main>` (rejected for now: rail clicks that replace history; turning off scroll restoration, which would lose every reader's place on reload).
- **Gallery sections from existing flags** — My apps = featured own apps, Work = other featured, Earlier = the rest (rejected: a placement enum that could contradict `isOwnApp`). A wide app tile only for the first of an odd count, so no half tile sits alone.
- **Gallery tiles in the product palette per theme** (rejected: always the dark band, as the mock showed).
- **Continuum headline** — "Stop managing from memory and start from what changed, and when." picked by Roland from the copy agent's second round (rejected: "your notes", which undersells the app; "your read", which reads unnaturally).

### Tradeoffs

- **Framer panels over native `<details>`** — gained the same motion in every browser; lost opening without JavaScript and find-in-page; reversibility: easy.
- **No headings above the apps and the work cards** — gained a tighter page; the sections keep screen-reader names and the titles became `h2`; reversibility: easy.
- **Gallery query carries more fields (palette, links, hero copy)** — one query for every surface, at a slightly heavier admin list read; reversibility: easy.

### Incidents / Bugs

- **"Dead" FAQ button in the browser pane** — not a bug: the pane never advances smooth scrolling, so ref clicks landed off target; a temporary debug label proved the state toggled on coordinate clicks.
- **Broken "View project" underline** — the link was a flex box, so each word and the arrow were separate flex items with their own underline; fixed by putting the text in one span.
- **Missing best-value badge** — the dev server reads `.env.local`, so an import into `.env`'s database never reached it; no code fault.

### Environment / Config Changes

- New site colour `--color-surface` (white, or a 4% white lift in dark mode); the product page's `--product-surface` now reads it.
- `MAIN_CONTENT_ID` in `src/lib/client/navigation.ts` replaces three copies of the `main-content` literal.

### What did I, Claude Code, or my agents learn from this

- **Measure copy in a browser, not with character estimates** — the writer agent's line estimates for the headline options were off by a whole line at 1,040px; a test page in the real font settled it.
- **Lines from an app's `marketing/copy/` files are generated** — Continuum's old headline was listed as Roland's and wasn't; provenance notes now mark such lines as adopted.
- **The browser pane lies about motion and hit targets** — frozen transitions, smooth scroll that never moves, stale screenshots right after a click, and scaled emulation drawn into a corner.
