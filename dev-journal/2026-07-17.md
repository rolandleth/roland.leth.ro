## Watch-outs & Tech Debt

- **FKs to `Project` are a trap** — `import-projects.ts` replaces a project wholesale (`deleteMany` + `create` in a transaction), so any model referencing `Project` by FK either cascade-deletes on re-import or blocks the importer. Guides deliberately reference by `projectSlug` string. Revisit if the project importer ever moves to upsert-in-place.
- **Guide `publishedAt` has two write paths** — the importer reads it from the filename date and re-syncs on every `--overwrite`; the admin stamps it once on first publish and never rewrites (`resolvePublishedAt`). Trigger to revisit: if a guide's date ever looks wrong, check which path last wrote it. The importer wins on re-import, so a filename rename silently moves the date.
- **Guides don't infer `published` from date, and null `publishedAt` = live** — unlike posts (past→draft, future→published), an imported guide is always `published: true`; a future date only *schedules* it via the read-time `isScheduledGuide` filter. A null `publishedAt` is treated as live, never scheduled — deliberate, so a dateless admin row can't vanish. Watch when adding admin-created guides that skip the filename path.
- **`offers` is JSON-LD-only, not rendered** — a project's price appears in `SoftwareApplication` structured data and (for Reckon) a pricing FAQ, but nothing renders `offers` visually on the project page. Don't assume adding/editing `offers` changes the visible page.
- **Individual tag busts are unproven** — one prod observation of a correctly-formatted `revalidatePost` bust not clearing an entry that the `post-pages` bust then cleared; unreproduced, mechanism unknown (`_revalidate-fix-plan.md` Phase 0/1). Until proven, treat "All X" as the reliable panel path after script imports that *update* existing rows — stale detail entries have no TTL.
- **404 probes hit the DB on every request now** — detail-page misses are deliberately never cached (`CacheMissError` throw). Trigger to revisit: bot-probe traffic showing up in DB metrics → add a short-TTL miss cache; do not revert to durable miss caching.
- **`init-post-slugs` refuses re-dated files** — a title-only match at a datetime that differs from the filename is reported as "no unambiguous DB match", not auto-stamped (`slugInit.ts:matchRow` datetime-equality guard). Trigger to revisit: a re-dated post shows up as unmatched on the dry-run → fix the filename's datetime to match the DB row, or hand-add the `slug:` line. Deliberate — the tool can't tell a re-date from a title reuse, so it won't guess.

### Decisions

- **Topic membership by directory, not a `topic:` key** — a `guides/<topic>/index.md` declares the topic (its own `slug:` authoritative, directory name decorative); every other file in the folder is a guide in it, and guides carry no `topic:` key. Chose this over the plan's flat `topics/` + `topic:` frontmatter because directory names *are* valid topic slugs and it makes membership single-source. `index.md` (not `_topic.md`) since date-prefixed siblings sort it last anyway.
- **`publishedAt` from the filename date, like posts** — reversed the plan's "stamp at import time." Stamping used the wall clock, so a re-import into a fresh DB re-aged every guide. A date has none of the `:`/`/`/accent problems that keep titles in frontmatter, so the filename owns it (chose authored-date over import-time; the admin path still stamps-once since it has no file).
- **UTC date parse, separate from `postDatetimeToISO`** — new `datetimeToUtcDate`; the post helper builds a *local* Date, which is fine for a stored string formatted locally on both sides but wrong for a real `DateTime` column (a local `2026-07-13-0000` in UTC+2 persists as the 12th). Guide date pipeline is UTC end to end (`formatDateValue` also UTC-pinned).
- **Scheduling guard, read-time** — future `publishedAt` = scheduled; filtered on cached rows at read time (never in-query, never inside the cached fn) so a guide auto-surfaces the first request after its date, no cron. Null `publishedAt` is never scheduled (safe reading of a missing date is *live*).
- **Product link is authored prose, not a card** — deleted the `GuideProjectCta` component. A rendered "RELATED PROJECT" card never says *who made the thing*, so it can't be a disclosure; in-content prose is also the stronger internal link. Rejected a `disclosure` DB/frontmatter field too — the four disclosures are all different and contextual, so there's nothing to share. Link target is `/projects/<slug>` (indexable, passes equity), never the App Store.
- **Importer warns when a project is named but never linked** — recovers the "always present" guarantee the card gave, without a widget: `parseGuideFiles` warns (never skips) when a guide/hub declares `project:` but its body has no `/projects/<slug>` link.
- **No exact price in guide bodies** — dropped "$3.99" from all four + hub; kept "one-time, no subscription" (durable objection-remover), led disclosures with the *mechanism* (does the scoring so the habit sticks). Keeps four SEO pages evergreen; price lives in the project `offers` JSON-LD + a pricing FAQ.
- **Topic-hub disclosure below the guide list via a body split** — `splitTopicHubBody` splits the hub body on its *last* `---`: framing renders above the list, disclosure below. The `---` is both split point and visual separator; keeps the disclosure authored prose and out of the mid-page "in your face" slot.

## Session 3

Debugged a prod stale-404 (published post on the list, detail page 404) down to a durably cached `null`, then shipped the hardening: misses are never cached again, the revalidate endpoint reports what it actually did, and detail tags are single-sourced. Commits 07502c9, 2ab29a3, 33ceb4d.

### Decisions

- **Throw-on-miss (`CacheMissError`) over short-TTL miss caching** — `unstable_cache` stores only fulfilled results, so throwing keeps a miss out of the durable cache entirely and a stale 404 heals on the next request (rejected: short-TTL wrapper — still a window; leaving as-is — the incident). Applied to all four detail lookups: posts, projects, guides, guide topics.
- **Revalidate endpoint returns `{ ok, applied, skipped }`** with the panel warning on skipped entries (rejected: 400-reject the whole batch — partial application is right for a batch tool; the sin was silence, not partiality). Skipped keys appear only when non-empty.
- **Post entries must be exactly two segments** — `tech/a/b` previously split to `["tech","a","b"]` and silently busted the *wrong* tag (`post-tech-a`); now skipped and reported.
- **Detail tags single-sourced per module** (`postTag`/`projectTag`/`guideTag`/`guideTopicTag` + `*_PAGES_TAG` consts) so wrapper and buster can't drift. Scoped to the parametrized two-site tags; single-word aggregate literals (`posts`, `guides`) left inline.
- **Kept the other session's guides-bust design** (bust both `guide-` and `guide-topic-` tags per pasted slug, no DB lookup) — added the route tests it shipped without.

### Tradeoffs

- **Misses cost a DB hit per request** — gained incident-class immunity, accepted uncached 404-probe traffic (bounded wrapper map unchanged). Reversibility: easy (short-TTL miss cache if probes ever matter).

### Incidents / Bugs

- **Prod stale-404** — post published 4 days, clean ASCII slug, on the list, detail 404. Root cause: detail wrapper had durably cached `null` from a request predating the row; import scripts write via Prisma and can't bust tags. Diagnosis dead-ends worth recalling: list and detail share the *identical* read-time datetime gate (so list presence proves it), and `length` vs `octet_length` settles slug-byte questions in one query.
- **Unresolved asymmetry** — a log-verified, correctly-formatted individual bust didn't clear the entry; `posts: "all"` (`post-pages`) did, though both tags sit on the same cache entry. Tag format stable since Apr (a9dd2e2); companion tag changed Jul 7 (7c5d19a). Hypotheses + decisive experiment in `_revalidate-fix-plan.md`; also plausibly propagation timing, i.e. no bug at all.

### What did I, Claude Code, or my agents learn from this

- **`unstable_cache` stores `null` like any value, forever, tags fixed at write time** — never return a "not found" from inside a cached callback unless a pinned miss is acceptable; throw and translate at the boundary.
- **List-works/detail-404s is a precise diagnostic** — the slug is the only term that round-trips through a URL, so that split accuses the slug bytes or the detail cache, and acquits section/published/datetime.
- **A tool that drops input while reporting success poisons its own incident history** — the silent-skip endpoint made "bust failed" and "bust never ran" indistinguishable *retroactively*; the applied/skipped echo exists so the next incident carries evidence.
- **The tree can change mid-conversation** — the revalidate route gained guides handling between my first read and my edit (other session's merge landed). Re-read anything load-bearing before editing when a parallel session exists.

## Session 4

Handled the 2026-07-17 code review (`code-reviews/2026-07-17.md`) — the post-import slug tooling. Three commits (`0c4b98b`, `c79977a`, `44af722`), all findings addressed.

### Decisions

- **Slug drift heals via byte-canonical comparison** — chose comparing `setFrontmatterSlug(content, slug) === content` over the review's "trim-compare" suggestion, in both `postImport.ts:slugRewriteFor` and `slugInit.ts:planStamp`. Reusing the writer as the canonical-shape check catches quoted values, trailing whitespace, and missing lines in one comparison, and can't drift from the write path.
- **`matchRow` datetime-equality invariant** — chose *refuse the ambiguous case, no flag* over the review's "refuse + `--allow-mismatch`" (option 1) and its "bind but warn loudly" (option 2). A title-only fallback binds only a row at the file's own datetime (`slugInit.ts:matchRow`); a title match at a *different* datetime returns null → reported as a problem. Keeps the safe datetime-match-title-differs bind (admin edited the title); refuses only the genuinely ambiguous shape.
- **Slug-write ordering: keep + document** — chose documenting (in `import-posts.ts` header) that slug stamps land before the plan's validation skips, over deferring the writes. The slug is a property of the file, correct whether or not the body imports today; a body-skipped file's stamp is a no-op next run.

### Tradeoffs

- **`init-post-slugs` no longer auto-rescues a re-dated file** — gained: the corruption vector (a new file reusing an old title getting stamped with an unrelated slug, then clobbered by a later `--overwrite`) is closed with no flag. Cost: a genuine re-date now reports "no unambiguous DB match" and the operator disambiguates by hand. Reversibility: easy (a `--allow-mismatch` flag could restore auto-binding later).

### Incidents / Bugs

Latent bugs the review surfaced (no prod impact — the tools hadn't been re-run):
- **Slug drift never healed** — `slugRewriteFor` compared the *trimmed* parsed slug to the resolved one, so `slug: hello ` (trailing space) planned no rewrite and left the drift on disk. Fixed by the byte-canonical compare above.
- **Blank `slug:` was indistinguishable from a missing line** — both reported "Title produces an empty slug". `parseFrontmatter` now keeps a present-but-blank slug as `""` (was `null`), and the skip message branches three ways.
- **`matchRow` false-positive bind** + **no unknown-flag guard** + **non-atomic writes** — fixed as above, plus a `KNOWN_FLAGS` guard (a typo'd `--dry-run` no longer silently writes) and a shared `writeFileAtomic` (temp + rename). Per-file write failures are now reported and skipped rather than aborting the batch.

### What did I, Claude Code, or my agents learn from this

- **"Corruption case" was really the *ambiguous* case** — the user pushed back on my labeling a title-match-at-different-datetime as corrupting. It's identical data for a legitimate re-date and a title reuse; nothing distinguishes them. The right framing: when two intentions produce identical data, refuse-and-report beats guess. Precise labeling matters — I flattened "can corrupt" into "is corruption".
- **Reuse the writer as the canonical check** — comparing a function's own output to the input is a cheap, drift-proof "is this already canonical?" test, better than re-deriving the expected shape separately.

### Notes

- New lib split mirrors the existing `postImport.ts` ↔ `import-posts.ts` pattern: `slugInit.ts` (pure, 13 unit tests) + `atomicWrite.ts` + `applySlugRewrites.ts` (temp-dir tested). Full suite 1773 passing.

## Session 5

Diagnosed the Vercel Fluid CPU split (middleware 53.8% / function 46.2%) from an analytics screenshot, then added a middleware bot-probe short-circuit and fixed a latent admin-gate over-match. Advisory first, then `src/proxy.ts` + `src/proxy.test.ts`.

### Decisions

- **Feed/`.md` edge cache stays at `s-maxage=3600`** — rejected bumping to daily. A route handler's explicit `Cache-Control` header runs the Vercel edge cache on a pure timer; `revalidateTag` (in `revalidatePostSection`) busts only the `unstable_cache` data layer, not the cached edge response. So `s-maxage` *is* the worst-case feed-staleness-on-publish — daily would delay new posts reaching RSS readers up to 24h. 1h is the freshness ceiling, and the hourly regens are trivially cheap.
- **Catch-all `[slug]` stays in-memory — no DB fallback** — rejected letting it query Postgres to move work off the billed-CPU meter. Under Fluid, awaiting a DB round-trip isn't billed as active CPU, but that's the wrong axis: the in-memory index (`legacySlug.ts`, shared with the sitemap) saves only a microsecond array scan, while a DB fallback re-exposes Postgres to unbounded bot traffic (connection exhaustion / DoS amplification, metered DB compute). The `NO DB fallback` comment already documents this intent.
- **Bot short-circuit uses narrow patterns, not "any dot"** — chose an extension `Set` + segment-boundary-matched path-prefix list over a blanket dotfile/extension rule, which would eat legacy dotted slugs (`/v1.2.3`, `/node.js`) and `/.well-known/*`. Same trap the `/_next/` short-circuit already documents having hit once. `Set` (not one big alternation regex) also dodges `sonarjs/regex-complexity` and is log-extendable.
- **Admin-gate fix mirrors `isAdminApi`** — `isAdminPage` used bare `startsWith("/admin")`; changed to `(=== "/admin" || startsWith("/admin/"))`, matching the already-bounded sibling. User delegated the call "based on siblings".

### Tradeoffs

- **Short-circuit shifts the CPU ratio further toward middleware** — gained: zero function invocations on junk (bot probes get a bare 404 in middleware before the `[slug]` not-found render). Accepted: a hair more middleware CPU (already the larger bucket) and a bare 404 instead of styled chrome for junk paths. Reversibility: easy.

### Incidents / Bugs

- **Admin-gate over-match (latent)** — `isAdminPage`'s bare `startsWith("/admin")` treated `/administrator`, `/admin-notes`, `/administrative-*` as protected, redirecting them to `/admin/login` instead of resolving/404ing — a correctness bug plus a minor info-leak (confirms the admin area exists). Root cause: prefix check without a segment boundary, unlike sibling `isAdminApi`. Surfaced by a bot-filter test fixture (`/administrator-guide`); fixed + tested.

### What did I, Claude Code, or my agents learn from this

- **"I/O isn't billed" ≠ "move work to the DB"** — Fluid not charging for DB await time is real, but DB compute/connections are a separate, more fragile meter and an unbounded-bot exposure. Shifting CPU load onto Postgres trades a meter you're nowhere near for one with tighter limits and a DoS surface. The user raised this as a genuine optimization; the right answer was to reframe the axis, not agree.
- **Manual `s-maxage` is time-based, not tag-invalidated** — a route handler's explicit `Cache-Control` governs the edge cache purely by timer; `revalidateTag`/`revalidatePath` only bust the Next data cache. For such routes, treat `s-maxage` as the staleness ceiling on publish.
- **Middleware runs on 100% of matched requests** — including CDN-cached static hits. That's why middleware CPU dominates function CPU on a static-heavy site, and why killing junk *in middleware* (not in a route) removes the function invocation entirely rather than just shortening it.

### Notes

- The 2026-07-08 function-time step-down traced to 2026-07-07 commits, not a traffic change: `68c510b` (theme → client localStorage, which un-forced per-request dynamic rendering), `ed4be70` (canonical origin from env instead of request `headers()`), `b1e34dd` (force-static `llms.txt`). Removing those dynamic opt-outs let pages actually prerender and serve from cache.
- The short-circuit only *narrows* the Session-1 watch-out "404 probes hit the DB" (Watch-outs, `/blog/:section/:slug` `CacheMissError`): probes carrying a bad extension/path (`/blog/tech/wp-login.php`) now die in middleware first, but a generic nonexistent slug (`/blog/tech/no-such-post`) still reaches the detail page → DB miss. Not resolved.
