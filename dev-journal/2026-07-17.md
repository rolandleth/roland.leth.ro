## Session 1

### Decisions

- **Guides live at top-level `/guides/:slug`, not `/blog/guides/:slug`** — blog is a dated, subscribed, frozen-after-publish stream (sitemap marks posts `changeFrequency: "never"`); guides are maintained SEO pages iterated from Search Console data. Different lifecycle → different route; `SECTIONS` stays `["tech", "life"]`.
- **Section named "Guides"** (rejected: articles, notes, writing, misc, freeform, longform, learning-hub, library) — the path token is a one-word promise to search/social clickers; elasticity trades against promise. Only the token is permanent; display labels can be renamed anytime.
- **New `Guide` entity over `Post` reuse** — Post carries legacy guides shouldn't inherit (string `datetime`, section, feed/archive/search, frozen lifecycle); reuse would add a "not guides" filter to every post query.
- **`GuideTopic` grouping now, optional per guide** — hub-and-spoke SEO cluster; the hub carries the customizable copy shown on project pages. First topic: "Making better decisions" (*making*, not *taking* — matches search phrasing).
- **Project reference by slug, not FK; nullable** — see Watch-outs for the FK trap; nullable so future non-product pieces fit (no CTA, no project page, still indexed).
- **All-markdown authoring, no JSON manifest** — guides/topics are prose plus flat scalars (projects needed JSON for structured non-prose data). Importer mirrors the posts script (plan-based, idempotent, `--dry-run`/`--overwrite`), not the projects one.
- **Frontmatter: explicit `slug:` required, `published` DB-only, hand-rolled parser extended** (no YAML dependency) — slugs are SEO-load-bearing so chosen, not derived; `drafts/` folder is the draft mechanism; strict importer validation (unknown keys, duplicate keys, non-int `sortOrder`) closes the parser's silent failure modes. Filename date prefix kept for disk sorting only — importer ignores filenames.
- **Project-page guides block below content, above FAQ** (mirrors `ProjectFaq`), auto-associated — not in the hero `links` pill row (accent CTAs, `target="_blank"`; wrong register). Manifests stay marketing-copy-only.

### Incidents / Bugs

- **Cited Linear as filing essays under "guides" — wrong** — verification showed Linear uses "Method" for that content; Stripe's guides do hold essays/reports. Corrected in place; decision unaffected but the claim shrank from two examples to one.

### What did I, Claude Code, or my agents learn from this

- **Check importer write semantics before designing relations** — the delete-then-create in `import-projects.ts` would have silently nuked guides via a cascade FK; caught only by reading the script before finalizing the schema.
- **Project manifests support markdown paragraphs end-to-end** — the wall-of-text descriptions were an authoring artifact of `app-copy-to-project`, not a pipeline limit; `\n\n` in the JSON renders as real paragraphs.
- **The frontmatter parser's real restrictions** — single-line values, block anchored to byte zero, symmetric-quote stripping; the dangerous modes with many fields (typo'd optional keys, duplicate keys) are validation gaps to close in the importer, not parser bugs.
- **Verify examples before citing them** — the Linear claim was pattern-matched, not known; the user's "Really?" was the only thing that caught it.
