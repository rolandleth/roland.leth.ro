## Session 1

### Decisions

- **Vercel Schedules over Cron Jobs** — Cron Jobs on Hobby run at most once a day (±59 min), so scheduled posts waited up to ~25h; Schedules allow hourly and keep a run history (Hobby keeps function logs only 1h). Rejected every 15 minutes (~58% of the beta run cap, and sub-hour precision isn't needed) and private function targets (`schedule/v1beta` plus a new `@vercel/schedules` dependency).
- **Ping stays daily** — the Upstash keepalive needs one write a day.
- **`WINDOW_HOURS` 50 → 4** — same rule as before (2 × interval for one missed or late run, plus jitter, plus 1h for DST on a self-hosted deploy) with Schedules' 15-minute jitter: 3h15m, rounded up. It also equals the test's 4 × interval ceiling.
- **Cadence-free comments** — outside the route, `windowInvariant.test.ts` and `.claude/CLAUDE.md`, comments now say "scheduled-content run" instead of "daily cron", so the next cadence change can't make them wrong.

### Tradeoffs

- **Latency vs. re-busts** — scheduled posts surface within ~75 min instead of up to ~25h; each due post is now re-busted on ~4 hourly runs instead of ~2 daily ones, and the due-content queries run 24 times a day instead of once. Reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Path schedules default to POST** — Cron Jobs were GET-only. A schedule without `requestMethod: "GET"` gets a 405 from a GET-only route handler on every run.
- **The checked-in Prisma client embeds the schema text** — `src/generated/prisma/internal/class.ts` carries `schema.prisma` verbatim, comments included, and the build doesn't run `prisma generate`. A comment-only edit breaks nothing but drifts until the next regenerate.
- **Separate "breaks" from "drifts" before calling something required** — I overstated two things this session: the UTC offset as a new "wrong time" (it exists today, hidden by the daily delay) and "needs regenerating" for comment-only schema edits.

### Notes

- Schedules facts the design relies on, from Vercel's docs read through a subagent on 2026-11-10: no retry for path targets; a run still undelivered an interval past its jitter window is skipped; a run can be delivered twice; `CRON_SECRET` is sent as `Authorization: Bearer` and captured at deploy time; renaming a schedule deletes it and its history.
