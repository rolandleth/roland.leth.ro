### Decisions

- **`getPostBySlug` switch from `findUnique` to `findFirst`** — adding the `published: true` + `datetime <= now` filter requires non-unique-constraint query shape. Alternative: `findUnique` + JS-side filter — rejected as wasteful (loads the row to discard it) and confusing (caller sees a populated row, schema-level filter discards it). ### What did I, Claude Code, or my agents learn from this

- **Schema-level slug validation catches a class of failures the unique constraint can't articulate** — `min(1)` is necessary but not sufficient. The unique constraint blows up far from the form, with an opaque P2002 error. A `.refine(producesNonEmptySlug, …)` at the schema boundary surfaces a clean field-targeted 400. Generalizable: any derived-field-from-input pattern (slug from title, hash from body, normalized email from raw) should refine at the schema, not trust the derivation downstream.
- **`vi.resetAllMocks` clears `mockReturnValue` set in `vi.mock(...)` factories** — if a cached fetcher reads a mocked module-level fn inside a tag-cache wrapper, the value isn't injected at the factory level; it's set per-call. Rebind in `beforeEach` after `resetAllMocks`. Watch for this when adding `datetime`/`now`/`crypto.randomUUID()` style mocks to a fetcher that lives behind `unstable_cache`.
- **`findUnique` → `findFirst` migration cascades to every test mock** — Prisma's compound-unique constraint forces `findUnique` when you query by `(section, slug)` only. Adding filter clauses requires the switch. Every `vi.mocked(prisma.X.findUnique).mockResolvedValue(...)` becomes `findFirst`. There's no shortcut.
- **For unique-constraint filters in cached fetchers, capture `now` inside the cached fn** — same pattern as `getPostsBySection`'s page-1 cache. The cached entry then naturally becomes "valid for this `now`-snapshot, evicted on mutation bus or organic expire." Documented in inline comments since the trade (future-dated posts don't auto-surface at their time) is non-obvious.
- **`prisma.$transaction` in tests** — the cleanest mock shape is `vi.mocked(prisma.$transaction).mockImplementation((fn) => fn(makeTx()))` where `makeTx()` returns an object whose methods point at the same top-level mocked functions. This keeps existing per-mock `.mockResolvedValue(...)` calls working without rewrites.
- **Magic-byte sniff is cheap if formData has already buffered the body** — `file.slice(0, 12).arrayBuffer()` reads from the in-memory buffer, not the network. Don't preemptively reject magic-byte sniff as "too expensive"; the buffering already happened upstream.

### What did I, Claude Code, or my agents learn from this

- **`react-hooks/set-state-in-effect` is narrow** — fires on synchronous setState in the effect body, not event-handler setState. The simpler fix to a stale-after-resubscribe bug is often "keep the subscription attached unconditionally with `[]` deps" so setState only ever fires from the event handler. Don't pivot to `useSyncExternalStore` reflexively when the rule fires; check whether moving the assignment to the listener callback solves it more cheaply.
- **`disabled` while saving is the de-facto race guard for optimistic mutations** — extra `abortRef !== controller` guards on revert paths are dead code while the disable is in place. They're not wrong, they're just belt-and-suspenders. Mark them as such in comments so future readers don't waste time tracing an unreachable code path.
- **Layout-level dynamic APIs cascade** — once `await cookies()` lives in `src/app/layout.tsx`, every route below renders dynamically regardless of what individual pages do. Concerns about static-gen at the metadata layer (e.g. `await siteBase()` in `generateMetadata`) are downstream of the layout's dynamic-API use. Verify the layout's dynamics before optimizing per-route.
- **`await response.json()` returns `any` and silently widens contracts** — when `parseJsonBody` started returning `ZodIssue[]` for schema errors, every reader (e.g. `readErrorMessage`) needed updating, but tsc couldn't catch it. Worth considering a typed API-response shape (e.g. `type ApiError = { error: string | ZodIssue[] }`) so the contract narrows at the reader boundary.
- **For tests of races that production-code's `disabled` prop prevents** — don't bypass with `fireEvent`. The race is theoretical given the disable; the test would document a code path that can't actually happen. Better to write a code-level comment explaining the guard's defensive purpose than to force an artificial regression test.
- **Tablist APG keyboard nav is straightforward** — roving `tabIndex={i === active ? 0 : -1}` + `onKeyDown` for Arrow/Home/End on each tab button, with a ref array for focus management. ~30 LOC inline; extract to a hook only when a second tablist appears.
- **`useSyncExternalStore` is the canonical hook for `window.matchMedia` bindings** — React docs use it as the example. But for a single derived boolean from one media query, a plain `useState + useEffect` with `[]` deps is also fine and arguably simpler. Choose based on whether you want to eliminate local state or keep the snapshot reactive.

Alternative: `Number.isInteger(Number(value))` — rejected because `Number("")` is 0 (would PUT a phantom edit) and `Number("3.7")` is `3.7` (would surface a different "is integer" error vs reject upfront).
- **`LoginForm`/`AdminNav` through `readErrorMessage`** — closes the Phase 7 cross-cut Review 2 flagged. The login route still returns `{ error: string }` today, so the immediate effect is just `(HTTP NNN)` suffixing; the load-bearing benefit is uniform behaviour the moment login adds a `parseJsonBody`-style schema response. Alternative: leave LoginForm/AdminNav hand-rolled and document the divergence — rejected because the divergence was the regression class.
- **Skip abort-vs-controller guard tests in `IsFeaturedToggle`/`ProjectSortOrderInput`** — `disabled={isSaving}` blocks user-event from triggering the second interaction at the DOM layer, and `abortRef.current` isn't reachable from RTL. The guards stay belt-and-suspenders; the existing watch-out covers them.

### Tradeoffs

- **Optional `?` → required `T | null` audit payload** — gained tsc enforcement of the unified-shape promise; cost: every call site is more verbose (six lines per call vs. terse subset). Reversibility: easy.
- **`getAllProjectSlugs` new cache key** — gained sitemap completeness for project routes with `lastModified` honesty; cost: one more `unstable_cache` entry under the `projects` tag — every project mutation now busts gallery + slugs (already busting gallery, so the marginal cost is one extra map lookup). Reversibility: easy.
- **Skip-link wrapper around `{children}`** — gained one-touch a11y for every page; cost: a `<div>` wrapper introduces a layout-flow node every page must lay out around. The div has `flex flex-1 flex-col` so it matches the `<body>`'s flex column; no visible change. Reversibility: easy.
- **Carousel padded-button hit region** — gained click-route correctness and AAA hit-target conformance; cost: each dot's accessibility tree node is now a wrapper button + a child span (one extra DOM node per dot). Reversibility: easy.
- **`LoginForm` body suffix shape change** — error surface gained `(HTTP NNN)` for parity with the rest of the admin UI; existing test `Invalid credentials` text-match updated to `/Invalid credentials \(HTTP 401\)/`. Reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Required-vs-optional `T | null` is a cheap regression guard for "fixed shape" contracts** — the comment on `AdminAuditPayload` already said "every key is part of the shape regardless of handler"; optional `?` made that a promise of the runtime helper, not the call sites. Tightening to required `T | null` moved the enforcement to tsc so the next caller that drops a key (the way posts PUT dropped `previousSlug` and projects PUT dropped `sortOrder`) surfaces at compile time. Phase-sweep contracts that depend on every call site doing the right thing should default to required keys.
- **`<time dateTime>` is its own correctness surface, separate from metadata** — Reviews 1 and 2 inspected the metadata helpers, the OG card builders, and the post detail page extensively but never grepped for `dateTime=`. A correctness bug touching every blog post card and every post page header hid for two reviews. For the next sweep, add `<time dateTime>` to the explicit list of attribute-level audit targets.
- **`disabled` prop on a form control is a hard ceiling on user-event-driven race tests** — the Phase 5 abort-vs-controller guards are documented as un-writable through RTL precisely because the second interaction never reaches the handler. The guards still buy real value (they protect against a future refactor lifting the disable), but they belong in the "documented invariant" category, not "regression-test-locked behaviour." Same shape may apply to other belt-and-suspenders guards in the codebase.
- **Phase-sweep advertised scope ≠ actual scope** — Session 1's Phase 7 was described as "three pages routed through `buildPageMetadata`"; it was four, and `/about` was missed. Phase 6's label sweep covered `PostForm`/`ProjectForm` but missed `ImageUpload`/`SectionManager`/`LinkManager`. Phase 6's strict-parse on `ProjectForm.sortOrder` missed the peer `ProjectSortOrderInput.handleBlur`. Lesson: when a phase fixes a class of issue, the closing step should be a project-wide grep for the pattern, not "the files I had open." This session ran exactly that sweep.
