## Watch-outs & Tech Debt

- **Future-dated published post auto-surface** — `getPostBySlug` and `getAllPublishedPostSlugs` now filter `datetime <= now` inside their cached fns. A post scheduled for a future `datetime` and published won't auto-appear at its scheduled time; surfaces only when the cache organically expires or a mutation bus fires. Covers the manual publish flow; revisit if time-based scheduling becomes a feature.
- [x] **`DOMException` vs `Error` for `AbortError`** — `LoginForm` and `AdminNav` use `err instanceof DOMException && err.name === "AbortError"` to swallow aborts. `useAdminResource` and the other admin mutations use `err instanceof Error && err.name === "AbortError"`. Both work under happy-dom; revisit if the test environment changes or any caller starts wrapping errors. **Resolved Session 2**: extracted `src/lib/isAbortError.ts` checking both shapes; all 5 sites consume it now.
- **Schema → `createSlug` coupling** — `postCreateSchema`/`projectCreateSchema` now `.refine` on `createSlug(value) !== ""`. If `createSlug`'s output rules ever change (e.g. fall back to `"untitled"` instead of `""`), the refine becomes a no-op without surfacing. Revisit if `createSlug`'s empty-output contract shifts.
- **`auditLog` fixed shape** — every admin POST/PUT/DELETE now emits a normalized 6-key payload (`id, slug, section, sortOrder, previousSection, previousSlug`) via `src/lib/auditLog.ts`. Adding a new admin resource (e.g. comments, tags) means extending `AdminAuditPayload` or accepting that resource-specific fields don't surface. Revisit when adding the next admin write surface.
- **`useSyncExternalStore` snapshot called multiple times per render** — `getColorSchemeSnapshot` in `ThemeProvider` runs on every render plus during React's concurrent-mode tearing checks. `window.matchMedia(...).matches` is O(1) browser-cached, so the cost is microseconds, but worth knowing if a future ThemeProvider consumer becomes render-heavy. Revisit if profiling flags it.
- **`parseJsonBody` 400 response widens silently** — schema-validation 400s return `{ error: ZodIssue[] }` while every other handler returns `{ error: string }`. `readErrorMessage` now handles both shapes, but `await response.json()` is typed `any` so tsc won't catch new readers that miss the array case. Revisit when adding a third response-error shape or introducing a typed API client.
- **`response.ok && next handleChange` race is dead code today** — `IsFeaturedToggle` and `ProjectSortOrderInput` both wear belt-and-suspenders `abortRef.current !== controller` guards on their revert paths, but `disabled={isSaving}` blocks the second interaction at the DOM level. The guards protect against a future refactor lifting the disable. Revisit if the disabled-while-saving prop is removed.

## Session 1

Full-codebase review (`codebase-2026-05-11.md`) followed by 8-phase implementation of every high-priority finding. 8 commits, 903 tests passing, tsc + lint clean.

### Decisions

- **`getPostBySlug` switch from `findUnique` to `findFirst`** — adding the `published: true` + `datetime <= now` filter requires non-unique-constraint query shape. Alternative: `findUnique` + JS-side filter — rejected as wasteful (loads the row to discard it) and confusing (caller sees a populated row, schema-level filter discards it). Required updating every test mock from `findUnique` to `findFirst`.
- **Cron 401 instead of 500 on missing `CRON_SECRET`** — pre-auth callers must not learn the server is unconfigured. Alternative: keep 500 but strip the env-var name from the body — rejected because a 500 still signals "something different is happening here" to a probe. 401 is the right semantic (the caller cannot authenticate either way) and the server-side `console.error` log preserves operator visibility.
- **Magic-byte sniff for upload, accept-list `image/avif` brands** — `ftyp` at offset 4-7 plus any of `avif`/`avis`/`mif1` at 8-11. Alternative: pull in `file-type` package — rejected as overkill for 5 image formats; the inline detector is 60 lines and auditable.
- **Audit-log payload is structured, not a string** — `{ id, slug, section, previousSection }` rather than `"[api:admin:posts:PUT] success id=1 slug=foo section=tech previousSection=life"`. Alternative: human-readable string — rejected because future log aggregation (Logflare/Axiom) parses structured payloads natively.
- **Route `IsFeaturedToggle` + `ImageUpload` through existing `readErrorMessage` (in `useAdminResource.ts`) rather than extract a new module** — Alternative: move `readErrorMessage` to `lib/`. Rejected for now: it's already exported, the additional module would be one tiny file, and the import-from-hook is uncomfortable but not load-bearing. Flag if a fourth caller lands.
- **`parseJsonBody` logs schema-validation paths only, never values** — same shape as the login route. Locked with a test that pins "submitted value never appears in log calls" so a future "add more context to the log" PR can't accidentally leak credentials.
- **Phase 8 pairs `createSlug` dash-class expansion with schema `.refine`** — the test failures for U+2212 minus and soft hyphen forced the realization that the refine alone wasn't enough — `createSlug("−−−") === "−−−"` (non-empty) under the old regex. Paired both changes in one commit so they're atomic.
- **`refine` lives on the title/name field, not on the whole schema** — `z.string().refine(producesNonEmptySlug, …)` rather than `.refine` at the object level. Cleaner error path (Zod's `path: ["title"]` points the admin form at the right field).
- **Wrapped the posts PUT in `prisma.$transaction` without changing isolation level** — left at READ COMMITTED. Project PUT is Serializable because of the sortOrder shift; posts PUT has no shift, just a read+update. Same atomicity guarantee without the perf cost.

### Tradeoffs

- **Filtering future-dated posts everywhere broke "scheduled publish"** — gained: drafts and future-dated posts no longer leak via canonical URL / sitemap / generateStaticParams. Lost: a post scheduled for `2026-06-01T12:00` and marked published doesn't auto-surface at its scheduled time. Reversibility: easy (add `revalidate: 60` on the affected caches) — but deferred since time-based scheduling isn't a feature anyone uses.
- **Magic-byte sniff for upload** — gained: payloads mislabelled as `image/png` get rejected (covers the documented-but-understated XSS case). Cost: every upload reads an extra 12 bytes via `file.slice(0, 12).arrayBuffer()` (cheap, already buffered by formData). Reversibility: easy.
- **`LoginForm` + `AdminNav` AbortController + tagged catch** — gained: discipline matches the rest of the admin surface; flapping logins/logouts now show up in server logs. Cost: ~30 LOC and a slightly more complex flow. Reversibility: easy.
- **Schema refine couples `schemas.ts` to `createSlug`** — gained: empty-slug titles rejected at the form boundary with a clear message. Cost: `schemas.ts` now imports from `format.ts`. Reversibility: easy.
- **Audit logs without external aggregation** — gained: structured payloads greppable in Vercel's ~1h log window. Cost: no signal once logs roll over. Same tradeoff as the `error.digest` decision on 2026-05-09 — re-introduce paired with aggregation, not before.

### Incidents / Bugs

- **U+2212 minus and soft hyphen passed `createSlug` unchanged** — the existing regex `[\s.‐-―]+` covers U+2010-U+2015 but not U+2212 (math minus) or U+00AD (soft hyphen). My schema refine in Phase 8 didn't catch these because they produced non-empty slugs like `"−−−"`. Fix: extended the dash class to `[\s.‐-―−­]+` (+ U+2212 + U+00AD); paired schema refine now rejects them.
- **`vi.resetAllMocks()` cleared the `currentDatetimeString` mock in `sitemap.test.ts`** — after adding `datetime: { lte: now }` to `getAllPublishedPostSlugs`, the cached fn called `currentDatetimeString()` (mocked to return `"2025-06-01-1200"`) but `resetAllMocks` in `beforeEach` cleared the `mockReturnValue`, leaving `undefined`. ### What did I, Claude Code, or my agents learn from this

- **Schema-level slug validation catches a class of failures the unique constraint can't articulate** — `min(1)` is necessary but not sufficient. The unique constraint blows up far from the form, with an opaque P2002 error. A `.refine(producesNonEmptySlug, …)` at the schema boundary surfaces a clean field-targeted 400. Generalizable: any derived-field-from-input pattern (slug from title, hash from body, normalized email from raw) should refine at the schema, not trust the derivation downstream.
- **`vi.resetAllMocks` clears `mockReturnValue` set in `vi.mock(...)` factories** — if a cached fetcher reads a mocked module-level fn inside a tag-cache wrapper, the value isn't injected at the factory level; it's set per-call. Rebind in `beforeEach` after `resetAllMocks`. Watch for this when adding `datetime`/`now`/`crypto.randomUUID()` style mocks to a fetcher that lives behind `unstable_cache`.
- **`findUnique` → `findFirst` migration cascades to every test mock** — Prisma's compound-unique constraint forces `findUnique` when you query by `(section, slug)` only. Adding filter clauses requires the switch. Every `vi.mocked(prisma.X.findUnique).mockResolvedValue(...)` becomes `findFirst`. There's no shortcut.
- **For unique-constraint filters in cached fetchers, capture `now` inside the cached fn** — same pattern as `getPostsBySection`'s page-1 cache. The cached entry then naturally becomes "valid for this `now`-snapshot, evicted on mutation bus or organic expire." Documented in inline comments since the trade (future-dated posts don't auto-surface at their time) is non-obvious.
- **`prisma.$transaction` in tests** — the cleanest mock shape is `vi.mocked(prisma.$transaction).mockImplementation((fn) => fn(makeTx()))` where `makeTx()` returns an object whose methods point at the same top-level mocked functions. This keeps existing per-mock `.mockResolvedValue(...)` calls working without rewrites.
- **Magic-byte sniff is cheap if formData has already buffered the body** — `file.slice(0, 12).arrayBuffer()` reads from the in-memory buffer, not the network. Don't preemptively reject magic-byte sniff as "too expensive"; the buffering already happened upstream.

### Decisions

- **`readErrorMessage` formats `ZodIssue[]` as `path: message; path: message`** — alternative was showing only the first issue. Chose join because the admin form has no per-field error wiring yet, so all field-level mismatches need to be visible at once. Nested paths join with `.` (e.g. `sections.0.title: Required`). Falls back to plain message when path is empty.
- **`auditLog(tag, payload)` fixed 6-key shape (`id, slug, section, sortOrder, previousSection, previousSlug`) with explicit nulls** — alternative was per-handler payload shapes (status quo). Rejected because a log aggregator parser would need per-handler dispatch. Trade: every line carries 3 always-null keys (longer log lines) for one stable parser shape. Six route tests updated to match.
- **Posts DELETE selects `slug` in addition to `section`** — needed to populate the unified audit-log payload. Adds one column read per delete; negligible. The alternative (special-case posts DELETE to pass `slug: null`) would have undermined the "consistent shape" rationale of the helper.
- **`describeZodIssues` typed structurally, not via `z.ZodIssue`** — Zod v4 deprecated `ZodIssue`. Using a structural type (`ReadonlyArray<{ path: ReadonlyArray<PropertyKey>; code: string }>`) decouples the helper from Zod's internal type churn.
- **`isAbortError(err)` helper extracted** — alternative was keeping 5 inline checks with mixed `DOMException`/`Error` shapes. The watch-out from Session 1 made this a real maintenance hazard once a 5th call site appeared in Phase 5; the helper closes it.
- **Phase 5 race-guards kept as belt-and-suspenders, dead code today** — alternative was dropping them (they're dead because `disabled={isSaving}` blocks the second interaction). Kept because a future refactor lifting the disable would silently re-open the race. Tests for the abort-races-error path couldn't be written deterministically (see Incidents); comment in the source explains the rationale.
- **Phase 7 scope dropped `metadataBase`/`siteBase()`** — Review 2 flagged that `await siteBase()` in `generateMetadata` could force dynamic rendering. Investigated: the root layout already uses `await cookies()`, so the whole tree is dynamic regardless of `siteBase()`. The Review 2 concern was downstream of an existing dynamic API; not a regression.
- **`buildPageMetadata` not extended for landing-page `absolute` title** — alternative was adding an `absolute?: boolean` flag to the helper. Rejected: only one page needs it; YAGNI. Landing page sets `title: { absolute: "..." }` directly.
- **Phase 8 `ThemeProvider` switched to `useSyncExternalStore`** — chose over the simpler `[]`-deps `useEffect` patch (which would have worked too). React 18's canonical hook for binding to external mutable sources (e.g. `window.matchMedia`); removes local state and eliminates the stale-after-resubscribe class. Honest tradeoff acknowledged: the simpler patch was probably the right minimal call for a personal blog. Cost: a few microseconds per render reading `matchMedia(...).matches`, subscription always attached. Lint clean (no `set-state-in-effect`).
- **`useAdminResource` abort-on-unmount test now asserts on `signal.aborted`** — alternative kept the indirect `console.error` check (which React 18 doesn't emit, making the assertion always pass). Direct assertion on the captured `AbortSignal` matches `LoginForm.test.tsx:179` and pins the actual contract.
- **`CompactProjectCard` discontinued styling scoped to icon only** — alternative was reducing the whole-card opacity less aggressively (`opacity-75`). Rejected because the contrast issue is on `text-secondary` against the background, which is already low-contrast. Scoping `opacity-60 grayscale` to the icon container preserves the visual signal and keeps the project name legible.
- **Outer `<label>` headings in `PostForm`/`ProjectForm` converted to `<span>`** — these wrapped no form control and acted as section headings ("Published", "Body", "Sections", "Links"). Alternative was associating them with a control via `htmlFor`, but the targets are composite components (`MarkdownEditor`, `SectionManager`, `LinkManager`) with no single bindable input. Spans don't lie about role.
- **Carousel dot hit targets extended via `before:` pseudo (`-m-2.5` inset)** — alternative was enlarging the dot itself. Rejected because the visual indicator should stay subtle. `before:` extends the clickable region to ~24px (WCAG AAA) without inflating the rendered dot.
- **Carousel arrow visibility added `focus-visible:opacity-100`** — alternative was making them always visible. Rejected: hover-reveal is the design intent. `focus-visible` covers keyboard users specifically; mouse-hover still controls the visual reveal.
- **`ProjectContent` tablist roving tabIndex + arrow-key handler inlined** — alternative was extracting a reusable `useTablist` hook. Rejected: only one tablist in the codebase. Will re-evaluate if a second appears.
- **`SearchForm` imperative focus via `useEffect` instead of `autoFocus` prop** — matches `ExpandableSearch`'s pattern. The declarative `autoFocus` raced AnimatePresence's enter transition in some browsers. Layout-time effect runs after React mounts the element.

### What did I, Claude Code, or my agents learn from this

- **`react-hooks/set-state-in-effect` is narrow** — fires on synchronous setState in the effect body, not event-handler setState. The simpler fix to a stale-after-resubscribe bug is often "keep the subscription attached unconditionally with `[]` deps" so setState only ever fires from the event handler. Don't pivot to `useSyncExternalStore` reflexively when the rule fires; check whether moving the assignment to the listener callback solves it more cheaply.
- **`disabled` while saving is the de-facto race guard for optimistic mutations** — extra `abortRef !== controller` guards on revert paths are dead code while the disable is in place. They're not wrong, they're just belt-and-suspenders. Mark them as such in comments so future readers don't waste time tracing an unreachable code path.
- **Layout-level dynamic APIs cascade** — once `await cookies()` lives in `src/app/layout.tsx`, every route below renders dynamically regardless of what individual pages do. Concerns about static-gen at the metadata layer (e.g. `await siteBase()` in `generateMetadata`) are downstream of the layout's dynamic-API use. Verify the layout's dynamics before optimizing per-route.
- **`await response.json()` returns `any` and silently widens contracts** — when `parseJsonBody` started returning `ZodIssue[]` for schema errors, every reader (e.g. `readErrorMessage`) needed updating, but tsc couldn't catch it. Worth considering a typed API-response shape (e.g. `type ApiError = { error: string | ZodIssue[] }`) so the contract narrows at the reader boundary.
- **For tests of races that production-code's `disabled` prop prevents** — don't bypass with `fireEvent`. The race is theoretical given the disable; the test would document a code path that can't actually happen. Better to write a code-level comment explaining the guard's defensive purpose than to force an artificial regression test.
- **Tablist APG keyboard nav is straightforward** — roving `tabIndex={i === active ? 0 : -1}` + `onKeyDown` for Arrow/Home/End on each tab button, with a ref array for focus management. ~30 LOC inline; extract to a hook only when a second tablist appears.
- **`useSyncExternalStore` is the canonical hook for `window.matchMedia` bindings** — React docs use it as the example. But for a single derived boolean from one media query, a plain `useState + useEffect` with `[]` deps is also fine and arguably simpler. Choose based on whether you want to eliminate local state or keep the snapshot reactive.
