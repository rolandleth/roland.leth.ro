## Session 1

### Decisions

- **Scheduled posts serve a 200 notice instead of a pinned 404** — commit `8bc9132` on `scheduled-post-notice`. The notice reuses the 404's design (backdrop glyph = publish date via new `formatDayMonth`, title teased in body, feed link, "Back to the blog"); `robots: { index: false }` metadata so the placeholder is never indexed. Rejected: leaving 404s during a staggered series rollout (dead links from the series opener's index), manual link backfills.
- **Shared cached row, verdict at the callers** — `getPostBySlug`'s fetch split into private `fetchPostRow`; new `getScheduledPost`/`loadScheduledPost` read the same `wrapNullableDetail` entry and tags, so live and scheduled views can never disagree and no second cache entry exists. The notice pins exactly like the old 404 did and flips via the same `revalidate-scheduled` cron bust — zero new invalidation machinery.
- **`.md` twin mirrors the treatment** — 200 markdown stub (`# title` + "Scheduled: goes live on {date}") with `X-Robots-Tag: noindex`, since a markdown body can't carry robots meta. Alias redirect stays HTML-only, and the legacy catch-all keeps 404ing scheduled posts (no legacy links to unpublished content exist).
- **Alias check runs before the scheduled check** on the page's miss path, so an aliased scheduled slug 308s to canonical first and the notice only ever renders on the canonical URL (test pins this).
- **Day-granularity date in the copy** — the cron makes the surfacing minute approximate, so promising a time would be unearned precision.

### Tradeoffs

- **Backdrop glyph scale** — dates are ~2× wider than "404", so 5.5/7rem instead of the 404's fixed 9rem; gained mobile fit, accepted a slightly quieter glyph. Reversibility: easy (two classes).
- **Title teased pre-publish** — better UX than an anonymous notice; leaks nothing for this series (titles are public in the opener's index), but any future post whose title is itself a surprise would show early. Reversibility: easy.
