# Lookup Map — overview (through commit 3e0aa5b on 2026-07-21)

- `src/` — Next.js middleware (`proxy.ts`): a scanner/bot-probe short-circuit (`isBotProbe` from `@/lib/proxy/botProbes` — bare 404 before the auth gate so junk like `/wp-login.php` never reaches a function), a case-insensitive admin-API/page auth gate (lower-cases the pathname before matching so `/ADMIN/…` can't slip past), legacy URL redirects (section-blog, archive, search, feed, privacy-policy — all matched via the module-private `matchLegacyRedirect(pathname)` helper that returns a canonical path or null, kept out of `proxy` to stay under the sonarjs cognitive-complexity cap), and a `/blog/:section/:slug.md` → `/api/blog/:section/:slug/md` internal `rewrite` (via `BLOG_MD_REGEX`) exposing the raw-markdown post view at the pretty URL.
- `src/app/` — root layout, landing page, sitemap, `robots` (allow-all `MetadataRoute.Robots` welcoming AI-citation crawlers; `/api/` disallowed with `/api/feed/` re-allowed; `Sitemap:` pointer; env-derived host via `getSiteUrl()`), `not-found`, error boundaries (`error`, `global-error` — `global-error` uses inline styles since the root layout's CSS is unavailable when it fires), `ClientAnalytics` client island. Root layout installs `NavigationTypeTracker` once so back/forward renders can skip entrance animations. Root layout owns the single document `<main id="main-content" tabIndex={-1}>` wrapping `{children}` so the skip-link `<a href="#main-content">` lands on the real landmark — page-level files render plain `<div>`/`<section>` wrappers, NOT their own `<main>` (multiple `<main>` per document is invalid HTML5). Sitemap emits 4 extra static routes (`/projects`, `/tools/loan-calculator`, `/privacy`, `/privacy/body-tracking`) + `/guides` + dynamic project AND guide/topic routes; post + project listings filter `datetime <= now` via `getAllPublishedPostSlugs`/`getAllProjectSlugs`, and guides come from `getGuidesOverview()`/`allGuides` with real `lastModified` + `changeFrequency: monthly` (unlike posts' `"never"`) and scheduled ones held out at read time.
- `src/app/[slug]/` — root-level catch-all for legacy URLs; runs only when no static top-level route matches. `permanentRedirect`/`notFound` based on `lookupLegacySlug`.
- `src/app/about/` — about page server component + content.
- `src/app/admin/(protected)/` — protected admin shell; `layout.tsx` adds defense-in-depth `verifySession`. `page.tsx` is the tab-router (posts / projects / guides — the guides tab renders `GuidesTab`), and stacks the two operational panels above the tabs: `RevalidatePanel` then `IndexNowPanel`.
- `src/app/admin/(protected)/posts/[id]/edit/`, `…/posts/new/`, `…/projects/[id]/edit/`, `…/projects/new/` — admin CRUD pages. Edit pages share a single DB hit between `generateMetadata` and the body via React `cache()` inside `loadPostForAdmin`/`loadProjectForAdmin`.
- `src/app/admin/login/` — login page; redirects authenticated visitors to `/admin`.
- `src/app/api/admin/posts/`, `…/posts/[id]/`, `…/posts/bulk/`, `…/projects/`, `…/projects/[id]/` — admin write API. All goes through `parseJsonBody` for body parsing; PUT/POST/DELETE/BULK emit a structured `[api:admin:…] success` audit log via `auditLog(tag, AdminAuditPayload)` where `tag: AdminAuditTag` is closed (derived from `ADMIN_AUDIT_TAGS as const`); every payload key is required including `batchId: string | null` — `null` on single-row handlers, a per-request `randomUUID()` on bulk so a 50-file run is grep-collapsible in the ~1h Vercel log retention window. Call sites pass explicit `null` for inapplicable fields. `previousSlug` is unified across posts and projects PUT as a rename signal only ("the slug renamed, here's what it was", not "name was edited") — derived via a single `isRenamed` local in projects PUT to keep the revalidate gate and audit payload in lockstep. Both posts and projects PUT run under `Prisma.TransactionIsolationLevel.Serializable` and read the prior section/slug inside the same `$transaction` as the update so cross-section/rename moves bust both old and new cache tags atomically. `serialization_failure` surfaces as a generic 500 with NO auto-retry — Prisma doesn't retry serialization conflicts and the 500 is also not client-retriable (admin must re-issue manually); audit-tag is NOT emitted on failure. 409 unique-slug paths log at warn with the colliding slug. The bulk endpoint (`/api/admin/posts/bulk`) partitions the batch via `prepareBatch`, which now delegates to the shared `parsePostFiles` from `@/lib/import/postImport` (honors an explicit frontmatter `slug:` over the title, same resolution as the import script — so a retitled/legacy file matches its existing row instead of forking a duplicate; drops the returned `slugRewrite` since an upload can't be written back) then maps survivors to DB-shaped `InsertRow`s; pre-queries `(section, slug)` collisions, then `createManyAndReturn` with `skipDuplicates: true`; a post-insert slug-set diff pushes any silently-dropped rows into `skipped` with reason `"Skipped at insert (concurrent write)"` so the response never claims "created N" without naming the file that was eaten. Originating filename rides on a parallel `Map<slug, filename>` (kept off the DB-shaped `InsertRow` so a future non-DB field on the prepared-row type can't accidentally leak through Prisma). One `[api:admin:posts:BULK] inserting` breadcrumb logs prepared slugs before the DB call so a subsequent 500 still tells us which were in-flight; `emitSkipSummary` emits `reasonsByType` on any non-empty `skipped`.
- `src/app/api/admin/revalidate/` — session-gated `POST` taking `{ posts?; projects?; guides? }`, each `"all" | string[]`: `"all"` busts every detail page of that type (`revalidateAllPosts`/`revalidateAllProjects`/`revalidateAllGuides`), an array busts only the named ones — posts as `section/slug`, projects as slugs, guides as slugs (each guide slug busts both `revalidateGuide` and `revalidateGuideTopic` since a slug can name either, and a topic publish-state flip should use `"all"`). Post entries must be exactly two segments with a known section — anything else lands in the response's `skipped`, never silently dropped; responds `{ ok, applied, skipped }` (skipped keys only when non-empty) and logs the same, so a bust that did nothing is distinguishable from one that ran [2026-07-17, after the stale-404 incident]. Companion to the direct-Prisma import scripts (which can't bust `unstable_cache` tags themselves); driven by the dashboard `RevalidatePanel`, into which the admin pastes the slug lists the import scripts print.
- `src/app/api/admin/keepalive/` — session-gated manual trigger; resolves the Redis client via the lazy memoized `getKeepaliveRedis()` from `@/lib/keepalive` and performs the same Upstash write as the cron route via the shared `writeKeepalive(redis)` helper. Parallel to `/api/cron/ping`, not bearer-shared: each route owns its own auth concern + status codes + log tags; only the client construction + write are centralized. 503 when Redis isn't configured (button can show a real error instead of pretending it worked); 502 on `redis.set()` reject; success line `[api:admin:keepalive] success` distinguishes manual triggers from scheduled cron in Vercel logs.
- `src/app/api/admin/indexnow/` — session-gated `POST` announcing every sitemap URL to IndexNow. Derives everything server-side (no request body): `getSiteUrl()` for the origin, `getIndexNowKey()` for the key, `await sitemap()` as the single URL source, so new posts/projects/guides need no upkeep. `?dryRun` previews the partitioned URL list without egress — an explicit falsy value (`false`/`0`/`no`/`off`) disables it via `isDryRunRequest`, because presence-only parsing made `?dryRun=false` return a 200 that looked like a completed submission. `describeKeyProblem` is the single source for both the dry-run warning and the real path's 503, so the two can't drift; the key's format is checked here rather than in the env schema. Status codes follow `keepalive`'s precedent — 503 for deploy-config gaps (missing/malformed key, non-public origin), 422 when the sitemap yields nothing this host can claim, 502 when IndexNow rejects a batch. Off-host URLs are partitioned out via `findForeignHostUrls` and reported in `skipped` rather than dropped.
- `src/app/indexnow-key.txt/` — public `GET` serving `INDEXNOW_KEY` verbatim as `text/plain`; 404s when unset. The key is a public verification token by design, not a secret — serving it openly is how the protocol works. `export const dynamic = "force-dynamic"` (the only one in the codebase) so the env value isn't baked at build time, plus `Cache-Control: no-store` so rotating the key takes effect on the next crawl. Folder name is the literal URL segment and must stay in lockstep with the `keyLocation` template in the submit route — renaming one breaks verification with a 403.
- `src/app/api/admin/upload/` — Vercel Blob upload (moved from `/api/upload` so the route is auth-gated by the generic `startsWith("/api/admin/")` gate in `src/proxy.ts` — one namespace, one gate, no per-path exception). Gated on `ALLOW_UPLOADS=true` (lazy-read so `vi.stubEnv` works); Content-Length precheck before `formData()` parse, then magic-byte sniff via `detectImageMime` (PNG/JPEG/GIF/WebP/AVIF) rejects payloads mislabelled as allowed image MIMEs. 413/415 paths log at warn. The malformed-multipart 400 routes the parser's `error.message` through `sanitizeLogString` (strips CR/LF/TAB/NUL, clamps to 200 chars) before logging — closes a log-injection vector where attacker-controlled boundary bytes in `error.message` could forge fake log lines beneath the real one. Log tag is `[api:admin:upload:POST]` to match the path-shape convention used elsewhere. The `detectImageMime`/`sanitizeLogString`/`sanitizeFilename` helpers live in a sibling `uploadHelpers.ts` — a `route.ts` may only export HTTP handlers + route-segment config, so test-imported helpers can't sit in the route file.
- `src/app/api/auth/login/`, `…/auth/logout/` — public auth entry. Login uses Upstash rate-limit, per-IP when `IP_HASH_SECRET` is set: `bucketKey(request)` (resolved once per request, shared by the limiter and the invalid-credentials log so the HMAC runs once and the two can't drift) returns `clientBucketKey(request, secret)` (HMAC-SHA256s the leftmost `x-forwarded-for` IP, truncates to 22 base64url chars, prefixes `ip:` so the per-client keyspace is formally disjoint from the `"global"` fallback under the shared `rl:login` Redis prefix) when the secret is present, else the constant `"global"` bucket. The limiter is built whenever `getRedisConfig()` is non-null; `getIpHashSecret()` controls only granularity, NOT whether the limiter runs — a missing secret while Redis is set logs a module-load warn and degrades to the shared global bucket (re-accepting a botnet admin-lockout DoS as the lesser evil over no limiter; never regresses to plain-IP keys). Plain SHA-256 was rejected because the ~4B IPv4 keyspace is brute-forceable; HMAC with a server-held secret blocks rainbow-table reversal. Leftmost-XFF trust is Vercel-specific (documented in-code; attacker-controlled behind an untrusted proxy). Log levels split by severity: 429 rate-limit-exceeded at `info` (routine hostile traffic), fail-open on an Upstash error at `error` (Redis down is operator-actionable), invalid-credentials at `warn` always carrying the resolved bucket key (`"global"` when no secret — never a raw IP) for correlation, success at `info`. Try/catch fail-open on Upstash errors so a Redis blip doesn't lock the admin out.
- `src/app/api/cron/ping/` — Vercel cron keepalive (daily at 00:00 UTC per `vercel.json`); constant-time Bearer check; resolves the Redis client via the lazy memoized `getKeepaliveRedis()` from `@/lib/keepalive` and performs the Upstash write via the shared `writeKeepalive(redis)` helper. `SET` not `PING`: Upstash excludes `PING` from idle detection, and the timestamp value doubles as an observable "last successful run" marker in the data browser. Emits `[api:cron:ping] success` info line on every successful write so "no cron success in N hours" alerting can be a log grep instead of an Upstash scrape (mirrors the admin route — together they answer "who wrote this timestamp"). Missing `CRON_SECRET` returns 401 (not 500 naming the env var) while the server-side `console.error` preserves operator visibility; unauthorized hits log at warn.
