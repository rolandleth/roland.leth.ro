[source](dev-journal/2026-07-17.md) [source](dev-journal/2026-07-24.md)

- **Post-import slug tooling hardening** — 2026-07-16 made `slug:` frontmatter the explicit source of truth (`createSlug` idempotency doubles as the canonical-shape check: unchanged means valid, changed means rewrite), fixed the admin bulk-import route's silent regression to title-derived slugs by sharing `parsePostFiles` with the script, and kept `init-post-slugs.ts` as a resync tool rather than a one-shot throwaway. 2026-07-17 session 4 acted on that day's code review: byte-canonical slug-drift healing (comparing `setFrontmatterSlug`'s own output to the file, not a trim-only string compare), `matchRow` now refuses an ambiguous title-match-at-a-different-datetime bind rather than guessing, plus a `KNOWN_FLAGS` guard and atomic file writes (`writeFileAtomic`). [source](dev-journal/2026-07-16.md) [source](dev-journal/2026-07-17.md)

- **Guides section: build, review, fix-the-fixes** — 2026-07-17 sessions 1-2 built the entire guides feature in one day: a new `Guide`/`GuideTopic` entity (not `Post` reuse, which would inherit a dated/frozen lifecycle guides don't have), top-level `/guides/:slug` routes, project referenced by slug rather than FK (dodging the project importer's delete-then-create cascade trap), topic membership by directory rather than a `topic:` key, and product links as authored prose rather than a `GuideProjectCta` card (a rendered card can't disclose *who made the thing*; an importer warning recovers the "always present" guarantee instead). The same day, a prod stale-404 incident was debugged and fixed (see Cache theme). 2026-07-18 resolved that day's ~39-finding code review in 8 phased commits, deliberately deferring 2 findings (a miss-stampede negative cache, an admin-search GIN index — both premature at current scale) and skipping 6 with recorded reasons, including a false positive on cross-table `Guide`/`GuideTopic` slug uniqueness. [source](dev-journal/2026-07-17.md) [source](dev-journal/2026-07-18.md)

- **IndexNow submission feature** — 2026-07-19 built admin-triggered IndexNow submission: a session-gated dashboard button, not a local script, so `getSiteUrl()` resolves the real prod origin with zero risk of announcing localhost; the verification key is served from `INDEXNOW_KEY` at a fixed `/indexnow-key.txt` path so the served body and the submitted key read the same accessor and can't drift. 2026-07-20's scheduled code review found the lib reported `submitted: N` even when every batch 403'd — split into `attempted`/`accepted` — and fixed `isSubmittableOrigin` to actually reject IP literals as its comment already claimed. 2026-07-21 fixed a double-body-read bug (`response.json()` consumed the `Response` before the error-message fallback re-read it) that had been swallowing real error messages behind a generic "Request failed", and extracted a shared `useAdminAction` hook (not a wrapper component) after ~25 lines of fetch/abort/supersede scaffolding had been copied verbatim into a second admin panel. [source](dev-journal/2026-07-19.md) [source](dev-journal/2026-07-20.md) [source](dev-journal/2026-07-21.md)

- **Admin auth: single gate to defense in depth** — 2026-07-17 session 5 fixed a latent `isAdminPage` over-match (`/administrator`, `/admin-notes` wrongly treated as protected via a bare `startsWith`) while building bot-probe-filter test fixtures. 2026-07-20 flagged, and deliberately deferred, that `src/proxy.ts` middleware is the sole authorization boundary for all 12 admin routes — correct on Next 16.2.10 but against Vercel's own guidance, with the `x-middleware-subrequest` CVE (2025-29927) as precedent. 2026-07-26 turned that watch-out into a real incident: `config.matcher`'s extension-exclusion group was unanchored, so any path merely *containing* an excluded extension's substring (a `.json` path contains `.js`) bypassed the middleware entirely, with no handler re-checking the session as a backstop — unexploitable in practice only because every admin `[id]` route parses its segment as a plain integer, rejecting a dotted path before any DB access. Fixed from both sides: an anchored, explicit-namespace matcher plus a new `requireAdmin()` guard added to all 21 handlers across 13 route modules, alongside a `SESSION_SECRET` 32-character floor in `getSessionSecret()`. 2026-08-12 narrowed the remaining half: `requireAdmin` was confirmed to cover `/api/admin/*` route handlers **only**, so admin *pages* had no equivalent — and all four `[id]/edit` pages read the DB in `generateMetadata`, which runs independently of `admin/(protected)/layout.tsx`. A shared `adminEditMetadata` guard in `src/lib/auth/adminMetadata.ts` now runs `verifySession()` before the loader, and the `src/proxy.ts` matcher comment was rewritten to state the invariant per namespace instead of claiming one that held only for the API side. 2026-08-13 closed the observability half: both `adminEditMetadata` and `admin/(protected)/layout.tsx` were failing *silently* when the session check failed, while `requireAdmin` logged the identical "the matcher missed this path" condition at error level and called it a security event. All three now log with a per-page tag (`adminEditMetadata` takes it as an explicit first argument, so editing a browser title can't rename a log line). The thread stays open — this makes a matcher hole detectable, not structurally impossible. [source](dev-journal/2026-07-26.md) [source](dev-journal/2026-08-12.md) [source](dev-journal/2026-08-13.md)

- **Social card metadata: fields, then images, then a lock** — 2026-08-12 found that every content page had been silently dropping `siteName`, `locale`, `card`, and `creator`, because Next resolves `openGraph`/`twitter` one top-level key at a time and assigns a page's object *over* the layout's rather than merging (`other` is the lone deep-merged key). Fixed by hoisting `siteOpenGraph`/`siteTwitter` in `src/lib/content/metadata.ts` and spreading them from both `buildPageMetadata` and the root layout. 2026-08-13 found the other half still open: `card: "summary_large_image"` was reaching every page while `images` stayed empty on the landing page, `not-found`, and every surface without an asset — a promise of a large image with nothing in it. `defaultOgImage` now points at a committed `public/images/og-card.png`, generated by a dev-only `src/app/og` route that 404s in production so the committed file stays the single source. The bug class itself is locked down by a `no-restricted-syntax` rule banning `openGraph`/`twitter` properties in `src/app/**/page.tsx`, which forces every page through `buildPageMetadata`. [source](dev-journal/2026-08-12.md) [source](dev-journal/2026-08-13.md)

- **2026-08-12** — Tooling gotcha worth not repeating: `rg -r` is `--replace`, not "recursive". `rg -rn "requireAdmin"` silently rewrote every match in the output to `n`, making a normal Zod schema look like it was bound to a one-letter variable and nearly producing a bogus code-quality finding. Use plain `rg -n` / `rg -l`. [source](dev-journal/2026-08-12.md)
- **2026-08-13** — `SoftwareApplication` JSON-LD was still emitting `offers` with a live price for discontinued projects, one day after the UI stopped showing their "Get on …" CTA for exactly that reason. Every offer shape (`Offer`, `AggregateOffer`, and the mixed-currency array) now carries `schema:Discontinued`; a live project asserts no `availability` at all, since `isDiscontinued === false` means "not marked discontinued", not "confirmed on sale". [source](dev-journal/2026-08-13.md)
- **2026-08-13** — Satori (behind `next/og`) does not parse 8-digit hex colours: `#12a8da33` rendered as a near-solid fill instead of a fade, so the OG card's gradient box showed a hard edge that read by eye as cropped artwork rather than a colour bug. Use `rgba()` in anything Satori renders. [source](dev-journal/2026-08-13.md)
- **2026-08-13** — A route handler that exported `size`/`contentType` (valid only for the `opengraph-image` file convention) would have failed `next build`, because Next generates its route-export validation types during the build — `tsc --noEmit` passes it clean. Caught by reading, not tooling. [source](dev-journal/2026-08-13.md)
- **2026-08-13** — A code-review finding was raised and then deliberately withdrawn rather than fixed: wrapping `verifySession` in React `cache()` to dedupe the two calls per admin page render. The gain is one avoided HMAC verify on a single-user admin; the cost is changed behaviour on the auth path via a memoization primitive whose route-handler scope was never established. Recorded as `**Withdrawn**` in the review file so it isn't re-raised. [source](dev-journal/2026-08-13.md)
