# Rolling History — last 30 days (through 2026-09-14)

## Themes

- **Scheduled-content lifecycle: pinned 404 → notice → single-clock-read resolver → preview route** — A soft-404 incident on 2026-08-17 (a `loading.tsx` Suspense boundary let three routes commit HTTP 200 while streaming the 404 page, since a status can't be revised after the first byte) was fixed with route groups (`(list)`/`(gallery)`) plus per-item cron tag-busts ([source](dev-journal/2026-08-17.md)). 2026-08-31 built on that lifecycle to replace scheduled posts' pinned 404 with a 200 `ScheduledPostNotice`, sharing `getPostBySlug`'s cached row via `wrapNullableDetail` so live and scheduled views can't disagree ([source](dev-journal/2026-08-31.md)). That surfaced a subtler race on 2026-09-01: `getPostBySlug` and `getScheduledPost` each called `currentDatetimeString()` independently, so a post crossing its `datetime` between the two calls could pin a fresh 404 at the exact publish minute — fixed by collapsing both into one `resolvePost` resolver (`PostResolution` union from one row fetch, one clock read), deleting `loadPost`/`getScheduledPost`/`loadScheduledPost` ([source](dev-journal/2026-09-01.md)). A same-day review (2026-09-02) confirmed every fix held, flagging only second-order consequences — an uncached `getPostBySlug` twin, orphaned docblocks ([source](dev-journal/2026-09-02.md)). 2026-09-03 extended the same resolver into a public `/override-preview` route (`resolvePostRow` + a narrowing wrapper) for previewing scheduled posts pre-publish, un-gated after a mid-session reversal, with a 307 redirect once the post goes live ([source](dev-journal/2026-09-03.md)).

- **Admin auth defense-in-depth and self-testing guards** — 2026-08-21 found `adminEditMetadata` guarded only the `<title>` on all four `[id]/edit` pages and the dashboard root, leaving the page body rendering unauthenticated data; fixed by extending `requireAdminPageSession` to all six data-reading admin pages, alongside restoring `BlogPostList`'s empty-page guard (re-derived as an unpublish/delete race, not the monotonic-datetime case it was first dismissed under) and a second rewrite of `hasGenerateMetadataExport` — source-text regex matching had failed twice in two sessions, replaced with dynamic-import + `typeof` ([source](dev-journal/2026-08-21.md)). 2026-08-22's review of that remediation found the admin contract test itself couldn't fail for the case it was written for — it matched `source.includes("requireAdminPageSession(")`, which an unawaited call also satisfies — and separately found 08-21's `errorDetails` widening (from `{message, stack}` to a full property spread, to preserve Prisma's `code`/`meta`) had silently voided its own JSON-safety guarantee ([source](dev-journal/2026-08-22.md)). Both days independently land the same lesson: a guard that has never been seen to fail is a guard nobody has tested — every new or restored test in both sessions was verified by deliberately breaking the thing it protects.
