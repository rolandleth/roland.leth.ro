# Rolling History — last 30 days (through 2026-08-21)

## Themes

- **Admin auth: from single gate to defense in depth** — 07-20's review flagged (and deliberately deferred) that `src/proxy.ts` middleware was the sole authorization boundary for all 12 admin routes. It became a real incident 07-26: the matcher's extension-exclusion regex was unanchored, so any path merely *containing* an excluded extension's substring (`.json` contains `.js`) bypassed the gate; fixed with `requireAdmin()` added to all 21 admin handlers plus a 32-char `SESSION_SECRET` floor (it had accepted any non-empty string, and the project's own docs said so). The gap resurfaced 08-12 in a different shape — admin edit pages' `generateMetadata` ran an unauthenticated DB read because `requireAdmin` covers only `/api/admin/*`, not the page namespace — closed with a shared `adminEditMetadata()` helper. 08-13 added `console.error` bypass logging with a shared `bypassId`. A 08-20 fix gave `guides/new`/`guide-topics/new` a real `requireAdminPageSession` body check for the same client-nav bypass class, but an independent 08-21 review found the fix incomplete in the worst way: `adminEditMetadata` only guards the `<title>` — it never stops a page body from rendering, since `generateMetadata` and the body are independent Next calls — so all four `[id]/edit` pages and the dashboard root (`/admin`, the page every protected page's nav links back into) still ran DB reads unauthenticated on the same bypass. Extended `requireAdminPageSession` to all six data-reading pages 08-21, added a real `adminPageContract.test.ts` assertion tying every page's body read to an actual guard call (not prose), and split tag constants into `adminTags.ts` to avoid a circular import while giving the guard a closed `AdminPageTag` union instead of a bare `string`. [dev-journal/2026-07-26.md](dev-journal/2026-07-26.md) [dev-journal/2026-08-12.md](dev-journal/2026-08-12.md) [dev-journal/2026-08-21.md](dev-journal/2026-08-21.md)

- **Static-rendering push and scheduled-content revalidation** — 08-15's `perf/routing-to-config` moved legacy redirects/rewrites from middleware into `next.config.ts` (resolves in Vercel's routing layer, zero function invocations), narrowed the admin matcher to an explicit namespace list, deleted the legacy `/:slug` catch-all after confirming zero traffic, and replaced the unconditional hourly `revalidate=3600` backstop on the feed/archive/sitemap with a due-check cron. That design had a gap: prerendered detail pages (`/blog/:section/:slug`, `/projects/:slug`) carry only per-post cache tags the cron never busted, so a post could stay pinned behind a stale 404 after going live — fixed 08-17 by having the cron bust each due item's own detail tag. The same 08-17 session found a separate, more severe bug: `loading.tsx` Suspense boundaries let React commit a 200 status before `notFound()` could run, so three routes served soft 404s (200 status, 404 content) in production; fixed by scoping list skeletons into `(list)`/`(gallery)` route groups and deleting the two detail-route boundaries entirely. [dev-journal/2026-08-15.md](dev-journal/2026-08-15.md) [dev-journal/2026-08-17.md](dev-journal/2026-08-17.md)

- **OG card generation: Satori route to committed static asset** — 08-13 built `/og` as a Satori-rendered route (a rendering seam was misdiagnosed as a layout bug before tracing it to Satori's inability to parse 8-digit hex colors), then 08-15's session 2 replaced it entirely with `scripts/generate-og-card.tsx` producing a byte-identical committed PNG — the route 404'd in production anyway while still bundling Satori+resvg WASM. The same session removed `projectJsonLd`'s unreachable non-numeric-price fallback (both write paths already enforce the price format via Zod) and extended the OG/site-card fallback to Article/BlogPosting/SoftwareApplication JSON-LD, so a projectless guide stops telling Google it has no image while telling share debuggers it does. Caught two of its own bugs via manual sanity checks before committing: a `[^}]*` regex that stopped at a nested brace, and a "not called" test assertion on a mocked child component that JSX construction never actually invokes.
