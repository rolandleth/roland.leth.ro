# Rolling History — last 30 days (through 2026-06-29)

Sources: [dev-journal/2026-06-08.md](dev-journal/2026-06-08.md), [dev-journal/2026-06-10.md](dev-journal/2026-06-10.md), [dev-journal/2026-06-13.md](dev-journal/2026-06-13.md).

Continuum DPIA + responsible-use pages added 06-10 via `PrivacyPageLayout`. `LegalPageLayout` generalized from `PrivacyPageLayout` 06-13 (`documentKind: "privacy" | "terms"` switch); `terms/continuum` reuses the shell; `continuumLegalLinks.ts` cross-links the four-page cluster via "Related" section. - **Auth rate-limit hardening** — `IP_HASH_SECRET` HMAC keying 06-10: `clientBucketKey` HMACs leftmost XFF IP (GDPR: plain SHA-256 is reversible at IPv4 scale ~4B addresses); global-bucket fallback when secret absent (some limiting beats none). Hardened 06-13: keyspace partitioned (`ip:<hash>` vs literal `"global"`, formally disjoint under `rl:login` prefix); bucket key hoisted to outer scope (HMAC runs once per request); log levels split (routine 429 → `info`, Redis-down fail-open → `error`); five new tests. Sources: [dev-journal/2026-06-10.md](dev-journal/2026-06-10.md), [dev-journal/2026-06-13.md](dev-journal/2026-06-13.md).

- **Project card & OG image fields + resolution** — `Project` gained `cardImage` and `ogImage` (06-28), renamed from an interim `thumbnail` because the asset is a card image and to match the `app-copy-to-project` manifest key (a divergent name would silently drop on import). Two resolvers in `src/lib/db/projects.ts` sharing `firstSectionImage`: `resolveCardImage` = `cardImage ?? ogImage ?? heroImage ?? first section image` (exposed as `ProjectGalleryItem.featuredImage`), `resolveOgImage` = `ogImage ?? cardImage ?? heroImage ?? first section image` (project page OG metadata). `heroImage` stays the detail-page hero and the final fallback in both chains (kept after surfacing it contradicted an earlier "drop it" instruction). Threaded through `gallerySelect`, `ProjectForm`, API routes, importer, tests, and the skill docs. Surfaced that `scripts/import-projects.ts` keeps its own `writeProject`/`referencedImageUrls` logic separate from the tested `projectImport.ts` core — both silently dropped the new field (and orphan-swept its blob) until fixed. Source: [dev-journal/2026-06-28.md](dev-journal/2026-06-28.md).

- **Project-detail gallery (lightbox + cross-section nav)** — built on the 06-08 `overflow-x-auto` scrollable tablist. 06-26 overhaul: click-to-enlarge fullscreen `ProjectImageLightbox` (portal to `document.body`, focus-trap, body-scroll-lock, opaque `bg-neutral-950` backdrop); new `useScrollOverflow` hook driving edge-fade affordances on the tablist; `ProjectSectionCarousel` made controlled with the gallery position lifted to `ProjectContent` so dots/tabs/lightbox share one index; lightbox chevrons walk the whole gallery (cross section boundaries, skip image-less sections, switch active tab + `scrollIntoView`). Multi-round "corner halo" bug root-caused not to the backdrop but to never rounding the *visible* image — `object-contain` letterboxes and container `rounded-xl` misses the image; fixed by aspect-true `next/image` sizing (`width={0} height={0}` + `h-auto w-auto max-h-* max-w-* rounded-xl`). 06-29 polish: tablist edge-fades were faded to the CSS `transparent` keyword (transparent *black*), smearing grey/black on light bg under iOS Safari only — fixed via new `--color-background-transparent` (same colour, zero alpha) in `globals.css`. Carousel stage switched from fixed `h-120` to measuring each image's `naturalWidth/Height` in `onLoad` and driving `aspect-ratio` (capped `max-h-[70vh] sm:max-h-120`, `h-120` fallback until measured) so landscape shots stop letterboxing. Touch swipe added to both carousel and lightbox via Framer `drag="x"` routed through the parent's `navigateImage`; shared `resolveSwipe(info)` + thresholds extracted to `src/lib/client/swipe.ts`. Sources: [dev-journal/2026-06-26.md](dev-journal/2026-06-26.md), [dev-journal/2026-06-29.md](dev-journal/2026-06-29.md).
