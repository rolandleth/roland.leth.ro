## Themes

- **Cache/revalidation granularity** — 2026-07-07 split the coarse `blog-{section}`/`projects` tags (caught via an ISR-dashboard tell — 8 blind writes on an unedited page) into per-slug detail tags plus dedicated `*-pages` aggregate tags, and added a session-gated admin `RevalidatePanel` since import scripts write via Prisma and can't call `revalidateTag`. 2026-07-17 session 3 debugged a prod stale-404 (a durably cached `null` in `unstable_cache`, predating the row) into a `CacheMissError` throw-on-miss pattern applied to all four detail lookups (posts, projects, guides, guide topics). 2026-07-18's guides review caught a `guide-` vs `guide-topic-` tag-namespace collision, fixed by prefixing to `guide-detail-`/`guide-topic-`. 2026-07-24 made the Atom feed route `force-static` with `revalidate=3600` (replacing a hand-set `Cache-Control` header `revalidateTag` could never purge from the CDN). 2026-08-15 reversed that last part: the hourly window regenerated all three routes every hour whether or not anything had changed, and crawlers plus feed readers guarantee traffic in every hour. `/api/cron/revalidate-scheduled` now counts content that came due inside a lookback window and busts tags only on a hit — the window is deliberately wider than the interval, since overlap costs one redundant revalidation while a gap strands content silently. The governing rule found that day: a static route has no read-time code, so its `datetime <= now` filter freezes at generation. 2026-08-17 applied the feed's own lesson to the post `.md` export (`force-static` + `generateStaticParams` shared with the post page, hand-set `Cache-Control` dropped) and then found the granularity split had left a hole: detail entries carry only `post-{section}-{slug}`/`post-pages` (guides: `guide-detail-{slug}`/`guide-pages`), which `revalidatePostSection`/`revalidateGuides` never bust, so a request landing while content was still future-dated pinned a 404 that survived until the next manual save. The cron now returns identities rather than counts (`findPostsBecameLive`/`findGuidesBecameLive`) and busts each due item's own detail tag. - **Static rendering swallows the 404 status** — 2026-08-17 found `/blog/:section/:slug`, `/blog/:section/p/:page`, and `/projects/:slug` serving the 404 page under a **200** in production, advertising every guessed slug to crawlers as a real page. Root cause: a `loading.tsx` creates a Suspense boundary over its segment *and every route nested below it*; the boundary lets React commit a 200 and stream the shell before the page resolves, and a status can't be revised after the first byte, so `notFound()` only swapped the boundary's content and never reached the `catch` in Next's `app-render.js` that assigns `metadata.statusCode`. `/guides/:slug` was the lone detail route returning a real 404 — the only one with no `loading.tsx` above it, and the clue that cracked it. Fixed by scoping the two list skeletons into `(list)`/`(gallery)` route groups (a group adds no URL segment, so the boundary covers one page instead of a subtree) and deleting the two detail skeletons; a route cannot be shielded from its own boundary, so detail-route skeletons are unrecoverable while those routes must 404. `/blog/:section` and `/blog/:section/archive` took `dynamicParams = false` instead, viable only because their params come from the `SECTIONS` constant. Rejected en route: `await connection()` before `notFound()` (throws `DYNAMIC_SERVER_USAGE`, 500s), `notFound()` from `generateMetadata` (does not escape the boundary either), and a `robots: noindex` mitigation (papers over a wrong status rather than fixing it). `src/app/blog/loadingBoundaries.test.ts` guards the arrangement — nothing else would catch a re-added `loading.tsx`. [source](dev-journal/2026-08-17.md)

- **Admin auth: single gate to defense in depth** — 2026-07-20 flagged, and deliberately deferred, that `src/proxy.ts` middleware is the sole authorization boundary for all 12 admin routes — correct on Next 16.2.10 but against Vercel's own guidance, with the `x-middleware-subrequest` CVE (2025-29927) as precedent. 2026-07-26 turned that watch-out into a real incident: `config.matcher`'s extension-exclusion group was unanchored, so any path merely *containing* an excluded extension's substring (a `.json` path contains `.js`) bypassed the middleware entirely, with no handler re-checking the session as a backstop — unexploitable in practice only because every admin `[id]` route parses its segment as a plain integer, rejecting a dotted path before any DB access. Fixed from both sides: an anchored, explicit-namespace matcher plus a new `requireAdmin()` guard added to all 21 handlers across 13 route modules, alongside a `SESSION_SECRET` 32-character floor in `getSessionSecret()`. 2026-08-12 narrowed the remaining half: `requireAdmin` covered `/api/admin/*` route handlers **only**, so admin *pages* had no equivalent — and all four `[id]/edit` pages read the DB in `generateMetadata`, which runs independently of `admin/(protected)/layout.tsx`. A shared `adminEditMetadata` guard in `src/lib/auth/adminMetadata.ts` now runs `verifySession()` before the loader. 2026-08-13 closed the observability half: `adminEditMetadata` and the protected layout were failing *silently*, while `requireAdmin` logged the identical condition as a security event; all three now log with a per-page tag. 2026-08-15 narrowed `config.matcher` to exactly `/admin`, `/admin/:path*`, `/api/admin`, `/api/admin/:path*` and deliberately kept **no** catch-all backstop: a broad negative-lookahead pattern is what produced the 2026-07-26 bypass. - **Vercel compute reduction: routing off the function path** — 2026-08-15 acted on the 2026-07-17 CPU split. Legacy redirects and the `:slug.md` / `feed.xml` rewrites moved from `src/proxy.ts` into `next.config.ts` via `src/lib/routing/legacyRoutes.ts`, where Vercel compiles them into its routing layer and resolves them with no function invocation — and `redirects()` runs ahead of middleware entirely, so a legacy hit never reaches one. The root-level `/:slug` catch-all was deleted outright (pure legacy support, confirmed zero traffic, invoking a function on every unmatched path including scanner probes); unmatched paths now resolve to the static 404. That in turn made the bot-probe filter dead, so `src/lib/proxy/botProbes.ts` went too, leaving `src/proxy.ts` as nothing but the auth gate. `Post`'s `@@index([slug])` served only the deleted `lookupLegacySlug` and was removed from the schema. Blog pagination then moved from `?page=N` to `/blog/:section/p/:page`: reading `searchParams` was what kept the list rendering per request despite its `generateStaticParams`. 2026-08-17 continued the same push by prerendering the `.md` export, taking its rewrite off the function path too. Rejected along the way: tightening the matcher with a `.*\..*` exclusion, which would break `/rss.xml`, `/feed.xml`, `/blog/:section/feed.xml`, the `.md` export, and dotted legacy slugs — the same unanchored-extension shape as the 2026-07-26 bypass.
