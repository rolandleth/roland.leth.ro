# Rolling History — last 30 days (through 2026-09-16)

## Themes

- **Scheduled-content lifecycle: pinned 404 → notice → single-clock-read resolver → preview route** — A soft-404 incident on 2026-08-17 (a `loading.tsx` Suspense boundary let three routes commit HTTP 200 while streaming the 404 page, since a status can't be revised after the first byte) was fixed with route groups (`(list)`/`(gallery)`) plus per-item cron tag-busts ([source](dev-journal/2026-08-17.md)). 2026-08-31 built on that lifecycle to replace scheduled posts' pinned 404 with a 200 `ScheduledPostNotice`, sharing `getPostBySlug`'s cached row via `wrapNullableDetail` so live and scheduled views can't disagree ([source](dev-journal/2026-08-31.md)). That surfaced a subtler race on 2026-09-01: `getPostBySlug` and `getScheduledPost` each called `currentDatetimeString()` independently, so a post crossing its `datetime` between the two calls could pin a fresh 404 at the exact publish minute — fixed by collapsing both into one `resolvePost` resolver (`PostResolution` union from one row fetch, one clock read), deleting `loadPost`/`getScheduledPost`/`loadScheduledPost` ([source](dev-journal/2026-09-01.md)). A same-day review (2026-09-02) confirmed every fix held, flagging only second-order consequences — an uncached `getPostBySlug` twin, orphaned docblocks ([source](dev-journal/2026-09-02.md)). 2026-09-03 extended the same resolver into a public `/override-preview` route (`resolvePostRow` + a narrowing wrapper) for previewing scheduled posts pre-publish, un-gated after a mid-session reversal, with a 307 redirect once the post goes live ([source](dev-journal/2026-09-03.md)). On 2026-09-15 the guide side closed its own gap: the "KNOWN GAP, latent" comment in `getGuideTopicBySlug` claimed no hub route existed, but hubs render at `/guides/[slug]` via `loadGuideTopic`, so a due guide never reached its hub; `findGuidesBecameLive` now returns `GuideRef` (`slug` + `topicSlug`) and the cron calls `revalidateGuideTopicHubs` ([source](dev-journal/2026-09-15.md)). The 2026-09-16 review tidied the edges: `revalidateGuideDetails` takes `GuideRef[]` like `revalidatePostDetails`, `findGuidesBecameLive` reports no topic for an unpublished one (its hub 404s), the cron's success log carries `dueGuideTopicSlugs`, the new `liveGuides` in `guideMappers.ts` replaces hand-written visibility filters, and the feed's scheduled-post padding is capped at `FEED_FUTURE_PADDING_CAP = 200` because each padded row is a markdown render per regeneration ([source](dev-journal/2026-09-16.md)).

- **Admin auth defense-in-depth and self-testing guards** — 2026-08-21 found `adminEditMetadata` guarded only the `<title>` on all four `[id]/edit` pages and the dashboard root, leaving the page body rendering unauthenticated data; fixed by extending `requireAdminPageSession` to all six data-reading admin pages, alongside restoring `BlogPostList`'s empty-page guard (re-derived as an unpublish/delete race, not the monotonic-datetime case it was first dismissed under) and a second rewrite of `hasGenerateMetadataExport` — source-text regex matching had failed twice in two sessions, replaced with dynamic-import + `typeof` ([source](dev-journal/2026-08-21.md)). 2026-08-22's review of that remediation found the admin contract test itself couldn't fail for the case it was written for — it matched `source.includes("requireAdminPageSession(")`, which an unawaited call also satisfies — and separately found 08-21's `errorDetails` widening (from `{message, stack}` to a full property spread, to preserve Prisma's `code`/`meta`) had silently voided its own JSON-safety guarantee ([source](dev-journal/2026-08-22.md)). Both days independently land the same lesson: a guard that has never been seen to fail is a guard nobody has tested — every new or restored test in both sessions was verified by deliberately breaking the thing it protects.

- **Post description: renamed column → one write rule for every path** — 2026-09-14 renamed `Post.summary` to `Post.description` (meta, OG, feed `<summary>`, JSON-LD), added an optional `description:` frontmatter line read by the import and the bulk upload, let a differing file line win on `--overwrite` (`resolveOverwriteDescription`), and emitted `description:` in the post `.md` export ([source](dev-journal/2026-09-14.md)). The 2026-09-15 review found the write paths disagreed: the Published toggle's `{ published }` PUT and any body edit replaced authored descriptions, bulk skipped the 160 cap, `deriveDescription`'s hard slice produced 161 chars, and spaces-only or multi-line values were stored. All paths now go through `src/lib/content/postDescription.ts` (`descriptionForCreate` / `descriptionForUpdate`: a value equal to the stored one counts as not sent, a derived description follows body and title edits, a body with no prose derives the title), with `PostForm` sending `""` to clear, `collapsedWhitespace` in `schemas.ts`, `validatePostFile` in bulk, `fieldValue` trimming inside frontmatter quotes, and `DESCRIPTION_MAX_CHARS` in dependency-free `descriptionLength.ts` because `schemas.ts` reaches the client bundle ([source](dev-journal/2026-09-15.md)). The 2026-09-16 review found the title fallback itself broke the cap: `derivedDescription` returned `post.title` uncapped (titles allow 200) and uncollapsed. `descriptionLength.ts` became `descriptionRules.ts` with `collapseWhitespace` and a surrogate-safe `capDescription` that both branches use; titles now collapse at input in `postCreateSchema` and `guideFields`, `quotedFrontmatterLine` collapses too for older rows, and the import and bulk paths validate through `postFileSchema`, which drops the title's slug refinement since `resolveSlug` decides there. Authorship stays inferred by `wasDerived` — a `descriptionIsAuthored` column was deferred ([source](dev-journal/2026-09-16.md)).

- **SEO and agent-facing surfaces** — 2026-09-14 added the guide `.md` twin (`src/app/api/guides/[slug]/md/route.ts`, force-static through `loadGuide`, 404 for hubs), a guide `BreadcrumbList`, `Person.sameAs`, an llms.txt `## Posts` block from a new `getRecentPosts` cache, a canonical on live posts and a real `/blog/tech` description ([source](dev-journal/2026-09-14.md)). 2026-09-15 hardened them: llms.txt dropped its hand-set `s-maxage` (a tag bust couldn't clear the CDN copy — the same defect the feed and post `.md` routes had shed), `SECTION_DESCRIPTIONS` moved to `src/lib/db/sections.ts` for both list routes and llms.txt, the Guides intro mentions `.md`, and `plainTextNotFound`, `frontmatterFile` + `quotedFrontmatterLine` and one llms.txt `linkLine` replaced three-way copies ([source](dev-journal/2026-09-15.md)). On 2026-09-16 `## Projects` moved into `projectsSection`, which omits the header when every project is discontinued like its guides and posts siblings, and paginated list pages append `Page N` to the section description, reversing `5521775`'s byte-identical assertion ([source](dev-journal/2026-09-16.md)).

- **App Store CTAs and required import flags** — 2026-09-13 added `isOwnApp`, driving App Store / Mac App Store badge artwork keyed on `bucket` (the `apps.apple.com` URL doesn't disclose platform), and counted `itunes.apple.com` as a storefront ([source](dev-journal/2026-09-13.md)). 2026-09-14 moved every link rule into the pure `linkCtasFor` (`badge` / `storePill` / `plainPill`), gave an own app with several storefront links "Download on" pills instead of a badge that would name the wrong store, and made `assertRequiredFlags` fail an import that omits `isFeatured`, `isDiscontinued` or `isOwnApp`, since the replace-the-row import would reset admin-set flags ([source](dev-journal/2026-09-14.md)). 2026-09-15 made the check unskippable — manifests are read only through `parseManifest`, which returns the flags typed as booleans, so `writeProject` lost its `?? false` — and documented the rules in the `app-copy-to-project` skill's `field-mapping.md` ([source](dev-journal/2026-09-15.md)).

- **Text-link styling and cascade layers** — On 2026-09-14 the `.link, .prose a` rule turned out never to apply inside prose: it sat in `@layer components` while typography compiles into `@layer utilities`, and a later layer wins regardless of specificity. It moved unlayered (dark, weight 500, underlined, accent on hover), `.prose img` centring became one unlayered rule, and a `@source not inline("prose")` attempt broke the build because Tailwind won't `@apply` a disabled class ([source](dev-journal/2026-09-14.md)). On 2026-09-15, legal pages' bare anchors (plain text under preflight's `color: inherit`) got the same style via a `legal-content` class on `PrivacySection` added to the rule, and the global link colour fade dropped from 0.4s to 0.3s ([source](dev-journal/2026-09-15.md)). On 2026-09-16 `LegalPageLayout.test.tsx` gained a test that the `.legal-content a` rule sits outside any at-rule block, since a layered rule still matches the selector test while losing the cascade ([source](dev-journal/2026-09-16.md)).

- **Orphaned admin uploads** — `POST /api/admin/upload` writes every admin image (post image, project icon/card/OG/hero, section images) to the blob root as `<uuid>-<name>`, and nothing deleted a replaced or removed one; the 2026-09-16 review first scoped it to posts. Roland chose a sweep over a delete on each write (one upload is often referenced twice, and project deletes cascade section images with no hook) and a dry-run-by-default script over an admin button or cron: `yarn blob:prune-uploads [--apply]` in `scripts/prune-uploads.ts`, rules in `src/lib/import/uploadPrune.ts`. It matches uploads by UUID found anywhere in any row rather than parsing URLs, exempts uploads under 24h old, reads every model through `ROW_READERS: Record<Prisma.ModelName, …>` so a new model fails `tsc`, and refuses `--apply` when the database references none of the store's uploads. `adminUploadKey` in `uploadHelpers.ts` now builds the key so the sweep's pattern is tested against it, and `blobSync.ts` gained shared `listBlobs` and `deleteBlobs`. The first production dry run found nothing to prune ([source](dev-journal/2026-09-16.md)).
