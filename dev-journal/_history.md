- **Admin auth boundary — the sole-middleware gate closed** — 07-20 established that middleware was the only auth boundary for all admin routes and deferred a shared `requireAdminSession()` refactor, noting vendor guidance against a sole middleware boundary and the CVE-2025-29927 bypass precedent. 07-26 found the concrete hole that deferral was exposed to: `config.matcher`'s asset exclusion (`.*\.(?:svg|png|…|css|js)`) was unanchored at both ends, so any path merely *containing* one of those substrings skipped the middleware entirely — `.json` matches because it contains `.js` — while no `/api/admin` handler re-checked the session. It was unexploitable only by accident: every admin `[id]` route parses its segment as a plain integer (`parseIdParam` → `n()` in `src/lib/utils/format.ts`), so a dotted path 400s before any DB access, and admin *pages* carry a second check in `src/app/admin/(protected)/layout.tsx`. Fixed on both axes — the extension group anchored with `$` plus explicit `/admin` and `/api/admin/:path*` matcher entries, and a new `src/lib/api/requireAdmin.ts` guarding all 21 handlers across the 13 admin route modules, logging at error level because in normal operation it is unreachable. The pre-existing gate contract test in `src/proxy.test.ts` could not have caught this: it calls `proxy()` directly, which presumes the request reached the middleware, and the matcher is exactly what decides that — so new tests exercise `config.matcher` itself, with `src/app/api/admin/adminAuthContract.test.ts` covering the handler side.
