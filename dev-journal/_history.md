# Rolling History — last 30 days (through 2026-09-03)

## Themes

- **Admin auth: defense in depth, found one layer at a time** — The month's dominant thread. 2026-08-12 extracted `adminEditMetadata` to close an unauthenticated DB read in the four edit pages' `generateMetadata`. 2026-08-13 added `console.error` bypass logging so a middleware-matcher miss becomes detectable instead of silent. 2026-08-21 found — via an external review run mid-session — that `adminEditMetadata` only guarded the page `<title>`, not the body: `generateMetadata` and the page body are independent Next calls, so the dashboard root and four edit pages could still render admin data to an unauthenticated request. Fixed by extending `requireAdminPageSession` to all six data-reading pages plus a contract test. 2026-08-22 then found the new contract test itself couldn't fail for the case it was written for — it matched `requireAdminPageSession(` as a string, which an unawaited (floating-promise) call also satisfies. Each fix narrowed the gap; each review found the fix's own blind spot. [source](dev-journal/2026-08-12.md) [source](dev-journal/2026-08-21.md) [source](dev-journal/2026-08-22.md)
- **Static rendering push and the soft-404 incident** — 2026-08-15 moved legacy redirects/rewrites into `next.config.ts`'s routing layer (resolved with zero function invocations, ahead of middleware), narrowed the middleware matcher to `/admin*` + `/api/admin*` only, deleted the legacy `/:slug` catch-all, switched blog pagination to path-based `/blog/:section/p/:page`, and replaced hourly `revalidate=3600` busts with a due-check cron. 2026-08-17 surfaced the cost: a `loading.tsx` Suspense boundary lets React commit a 200 status and stream the shell before `notFound()` can run, so three routes (`/blog/:section/:slug`, `/blog/:section/p/:page`, `/projects/:slug`) were silently serving soft 404s in production. Fixed by scoping list-page skeletons into route groups, deleting the detail-page ones, and having the cron bust each due item's own detail tag instead of only list tags. [source](dev-journal/2026-08-15.md) [source](dev-journal/2026-08-17.md)
- **OG/social-card pipeline rebuilt** — 2026-08-13 chased two Satori rendering bugs (8-digit hex colors rendering near-solid; an invalid route-export shape that only failed at `next build`) before replacing the dynamic `/og` route entirely with a committed PNG regenerated on demand by `scripts/generate-og-card.tsx`, deliberately dropping the font-CDN dependency at request time. 2026-08-15 extended the change so a projectless guide's structured data carries the same site card instead of a mismatched imageless summary card. [source](dev-journal/2026-08-13.md) [source](dev-journal/2026-08-15.md)
- **Scheduled posts: a notice instead of a pinned 404, then hardened** — 2026-08-31 replaced the 404 a future-dated post's URL used to serve with a 200 `ScheduledPostNotice` (404's design, publish date as the backdrop glyph via a new `formatDayMonth`, `robots: { index: false }`), plus a matching `.md` stub. The mechanism reused the existing pin-and-bust lifecycle exactly: `getPostBySlug`'s fetch split into a private `fetchPostRow` so live and scheduled views read one cached row and one tag set, and the same `revalidate-scheduled` cron bust that healed the 404 now flips the notice into the live page. 2026-09-01's daily review found six issues in the day-old code and fixed five: a `max-w-md` → `max-w-m` typo that Tailwind v4 silently dropped, `formatDayMonth` duplicating `formatDate` verbatim, a frontmatter-less `.md` stub, scheduled metadata bypassing `buildPageMetadata` (so a life post advertised the tech feed), and two independent clock reads that could pin a 404 at a post's exact publish minute. That last one collapsed four accessors into one `resolvePost` returning a `live`/`scheduled`/`missing` union from a single clock read. 2026-09-02's review verified all five resolutions hold and found only second-order consequences of them, not regressions: `getPostBySlug` survived as an exported but *uncached* twin of the production path (it calls `resolvePost` directly, reopening the split-verdict door that deleting `loadPost` was meant to close), two `posts.ts` docblocks were orphaned by the export deletions — including `revalidateAllPosts`'s, which still tells the reader `post-pages` "rides only on `loadPost`" when it now rides on `fetchPostRow` backing two entry points — and the scheduled metadata branch's test coverage did not follow its change in shape. 2026-09-03 added the escape hatch the notice implies: `/blog/:section/:slug/override-preview`, a `force-dynamic` route that renders a scheduled post's real body. It is deliberately public — the URL is the override, so a preview link works for someone with no account — and it stays the only surface that overrides the schedule, with list, archive, search, feed, `llms.txt`, sitemap and the `.md` twin all still filtering the post out. `resolvePost` split into `resolvePostRow` (verdict + full row) and a wrapper narrowing the scheduled branch to its title/date teaser, so the narrowing that protects the prerendered page is a visible step rather than an implicit one. Once `datetime` passes, the preview URL 307s to the canonical post. [source](dev-journal/2026-08-31.md) [source](dev-journal/2026-09-01.md) [source](dev-journal/2026-09-02.md) [source](dev-journal/2026-09-03.md)
- **Recurring learning: an untested guard is an unverified guard** — The month's strongest cross-session pattern. Vacuous tests kept passing for the wrong reason — JSX construction without rendering, presence-only source-text checks, a contract test blind to a missing `await` — and the fix was always the same: break the thing the test claims to guard and confirm it goes red. Named explicitly as a generalizing pattern (not a one-off) in both 2026-08-21 and 2026-08-22. 2026-09-02 caught the inverse failure of the same pattern: not a test that cannot fail, but one that describes behaviour the code no longer has — `page.test.tsx`'s "returns noindex, title-only metadata for a scheduled post" kept its name after the branch started emitting a full OG card, and the `expect(result.openGraph).toBeUndefined()` that pinned the old shape was deleted with nothing replacing it. A gap gets found; a name that falsely claims coverage gets trusted. 2026-09-03 applied the pattern preventively rather than forensically: both load-bearing tests on the new override-preview route were run against a deliberately broken implementation and confirmed red before the code was called done.
