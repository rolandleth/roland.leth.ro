## Watch-outs & Tech Debt

- **Direct-Prisma import skips cache revalidation** — `import-projects.ts` writes via Prisma directly, so it can't call `revalidateProject` (no Next request context). New/updated projects won't surface on the gallery/detail until a redeploy or revalidation. Revisit if imports need to go live without a deploy.
- **bucket↔tag coherence vs universal apps** — `refineBucketTagCoherence` (`src/lib/api/schemas.ts`) scopes `platformTags` to the bucket's natural set, so a universal iOS+iPad+Mac app (Reckon) can't carry `macOS` as a tag under the `iOS` bucket. Revisit if the portfolio needs full per-project platform spread.
- **Single `accentColor` across themes** — a custom project accent is one value applied to both light and dark; only the global default (`--color-accent-value`) is theme-split. No single mid-tone hits AA 4.5:1 on both `#f9fafb` and `#030712`. Revisit if accent contrast becomes an issue.

## Session 1

### Decisions

- **Manifest-driven importer** — built a project-agnostic tool (`scripts/import-projects.ts` + per-project `project.json` + the `app-copy-to-project` skill) over (B) parsing raw marketing markdown (no stable schema → fragile) and (C) driving the admin HTTP API (needs a running server, admin auth, `ALLOW_UPLOADS`, gives random blob keys + auto-slug/sortOrder-shift — wrong for a controlled import).
- **Direct Prisma + direct Blob** — same shape as `seed-projects.ts`: own `PrismaClient` (PrismaPg adapter), `put()` to Blob, transactional delete-by-slug + create. Not the admin API.
- **Idempotent uploads** — deterministic blob keys `projects/<slug>/<sanitized-path>` with `addRandomSuffix:false, allowOverwrite:true`, so re-runs overwrite instead of leaking duplicates on the 1 GB free tier.
- **Images on Vercel Blob, manifest as `project.json`** — chosen over committing to `public/images` and over a TS manifest module (data over code; validated at runtime by the reused `projectCreateSchema`).
- **Skill is project-level** — `.claude/skills/app-copy-to-project/`, co-located with the schema + script it targets (reads the live contract instead of hardcoding it), rather than joining the global `app-copy-*` group.
- **Dropped the importer's image security checks** — reverted the `uploadValidation` extraction and the upload-route change. The MIME-sniff/size-cap exist for the route's *untrusted network uploads*; the importer handles trusted first-party files (own app icon + own screenshots), so they were ceremony. Kept `projectCreateSchema` validation as data-integrity (powers `--dry-run`), not security.
- **Kept `projectMappers` + `projectImport`, inlined nothing else** — mappers are shared by the admin POST/PUT routes *and* tested, so inlining them would duplicate shared logic and drop coverage; `projectImport` holds the genuinely-new tested logic (slug, deterministic keys, ref resolution). Relocated the mapper tests to `projectMappers.test.ts`.
- **Reckon platform** — `bucket: iOS`, tags `[iOS, iPad]`; `macOS` can't be tagged under the iOS bucket (coherence rule), so the Mac build lives in the copy.
- **Reckon accent** — terracotta `#B5673F` (from the icon) over the app's `AccentColor` slate-blue `#4C5D8F`; terracotta is the better-balanced dual-theme accent (~4.1:1 on light, ~4.8:1 on dark vs slate-blue's 6.1/3.2).

### Tradeoffs

- **Inlined `sanitizePathSegment` in `projectImport`** — small dup of the route's `sanitizeFilename`, accepted so the importer stays free of any Next-route dependency after `uploadValidation` was deleted; reversibility: easy.
- **Cache staleness after import** — see Watch-outs; accepted because imports are paired with a deploy anyway. Reversibility: easy.

### What did I, Claude Code, or my agents learn from this

- **Xcode asset discovery for the skill** — an app's icon lives at `Assets.xcassets/AppIcon.appiconset/icon_1024.png` and its accent at `AccentColor.colorset/Contents.json` (sRGB components × 255 → hex). ## Session 3

### Decisions

- **Blob-reuse fail-safe on import** — `resolveImageUrls` now `list`s `projects/<slug>/` and reuses an existing blob when its key (slug + per-image path) AND byte size match the staged file, instead of always re-uploading. Match unit is the per-image key + size, not the slug alone; a size mismatch re-uploads, `--reupload` forces. Motivated by the local-DB-test-then-prod flow: Blob is a single store, so a prod run reuses what a local run already pushed. Reuses log `↺` (not silent, per no-silent-suppression); a failed `list` warns and uploads all (safe via `allowOverwrite`). New tested `blobPrefixFor(slug)` in `projectImport.ts`.
- **Hero default at import** — `writeProject` defaults `heroImage` to the first section's first image when the manifest has none, so a hero-less project gets a banner instead of an empty card. Chose import-side data default over (a) a card-side gallery-query fallback (would need `gallerySelect` / `ProjectGalleryItem` / cache surgery) and (b) rendering the icon in the hero (tried, looked weird — duplicate of the body icon — reverted). Escape hatch: set `heroImage` explicitly in the manifest.
- **Section titles → 2–3 words + scrollable tabs** — the detail-page tablist wrapped long titles to 3 lines; shortened all 10 (both manifests), with the substance moved into the descriptions. Tablist also made horizontally scrollable (`overflow-x-auto` + `whitespace-nowrap`/`shrink-0`) so titles stay one line and scroll when crowded.
- **Cache invalidation left manual** — weighed a Vercel deploy hook (no app code, only a hook URL; worst case redeploy-spam), a secret-gated `/api/revalidate` endpoint (instant tag-bust but a new internet-facing surface + secret), and a `revalidate` TTL on the projects caches (zero surface, self-healing, not instant). User opted to keep it manual via the admin panel — no trigger added.

### What did I, Claude Code, or my agents learn from this

- **The marketing "screenshots" are landscape showcase graphics, not portrait screenshots** — Reckon's `decision.png` is 1472×960, Continuum's `entry.png` 2560×1920 (framed phones on a tinted background). They fit a 16:9 hero with `object-cover`; my earlier portrait-crop objection was wrong. Check the actual asset's dimensions before assuming aspect.
- **Blob is one store across DB targets** — local and prod runs both write to the same Blob (one `BLOB_READ_WRITE_TOKEN`); only `DATABASE_URL` differs. Hence reuse-by-key+size avoids redundant uploads when testing local then running prod. Also: `dotenv/config` reads only `.env` (not `.env.local`), so prod creds are best inlined for the run.
