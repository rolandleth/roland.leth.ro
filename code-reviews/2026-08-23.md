## Issues and Observations

- **[src/test/sourceText.ts — `stripComments`]** — the docblock's safety claim is wrong for two of its three callers. It states both failure modes are "false-POSITIVE risks (a match disappears, the test fails loudly)"; that holds only for *presence* assertions. Verified by executing the regex against constructed sources:
  - `blog/[section]/(list)/page.test.tsx` asserts `not.toContain("searchParams")`. A stray `/*` in prose makes the non-greedy block regex swallow forward to the next `*/`; when every real use falls inside that range, the token disappears and the assertion **passes** against a page that genuinely reads `searchParams`. Silent false negative.
  - `adminPageContract.test.ts`'s await guard splits on `requireAdminPageSession(`. A swallowed call site vanishes from the split, leaving zero segments, so `.some()` returns false and the page is not flagged despite carrying an unawaited call.
  - Only the `cache()` presence check in `p/[page]/page.test.tsx` fails loudly, as documented.
  The trigger is not exotic here: block comments are stripped *before* line comments, and this codebase quotes comment syntax inside prose routinely — `sourceText.ts`'s own docblock contains a literal `/*`.

  Fix is a single alternation pass, `replaceAll(/\/\*[\s\S]*?\*\/|\/\/[^\n]*/g, " ")`: `replaceAll` scans left to right and never re-enters replaced text, so whichever delimiter opens first consumes the other. Verified against both directions.

  Note for whoever picks this up: swapping the two passes so line comments go first is NOT a fix, and was the wrong recommendation in this file's first draft. It breaks `/** see https://example.com */` — the line pass eats the block terminator, and the orphaned `/**` swallows forward to the next `*/`. URLs in docblocks are far more common here than `/*` quoted in prose, so the swap trades a rare failure for a frequent one. Neither the swap nor the alternation handles string or regex literals; that limitation stands, and `createScanner` remains the durable upgrade the docblock already names.
- **[src/lib/utils/errorMessage.ts — `errorDetails`]** — `name`/`message`/`stack` bypass `isJsonSerializable` on the stated assumption that they "are strings by construction". A subclass assigning a non-string `message` (or a foreign-realm error) reintroduces exactly the throw-while-reporting-a-failure this change exists to prevent, and it bypasses the one guard added to stop it. TypeScript's `Error.message: string` is not enforcement at a boundary that accepts `unknown`.
- **[src/app/admin/adminPageContract.test.ts — `pagesRequiringBodyGuard`]** — both guard tests share the same filtered list, so pages on `PAGES_WITH_NO_BODY_DATA_READ` (`posts/new`, `posts/bulk`, `projects/new`) are exempt from the await check as well as the presence check. Correct today (none of them call the function), but a page that gains a guard while staying on the allowlist gets no await enforcement — the narrower check is the one that should run over *every* admin page, since it costs nothing where there are no call sites.
