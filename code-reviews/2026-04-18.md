## Issues and observations

### 1. `lookupLegacySlug` doesn't filter by `published: true` ✅ fixed

**File:** [`src/lib/legacySlug.ts:19-26`](src/lib/legacySlug.ts)

Both the `post` and `project` queries omit a `published: true` (or `visible`/equivalent) guard. A legacy slug pointing to an unpublished draft will produce a 308 redirect to `/blog/section/slug`, which then 404s at the destination. Not a security issue (unpublished posts aren't served), but the user gets two round-trips for a 404 and the 308 is cached in the browser indefinitely. If the post is later published, that's fine; if it stays unpublished, crawlers and anyone with a stale bookmark follow the redirect then hit a wall.

Added `published: true` to the post query. Test updated to assert the new filter. Projects have no `published` field, so no change there.

### 2. `defaultProto` is unexported and untested ✅ fixed

**File:** [`src/lib/request.ts:3-14`](src/lib/request.ts)

The old port-based heuristic was removed and replaced with a hostname-prefix check — a meaningful behavior change that affects feed and sitemap URL generation. The function was private with no `request.test.ts`.

Exported `defaultProto`; added `src/lib/request.test.ts` with 7 cases: `localhost`, `localhost:3000`, `127.0.0.1`, `127.0.0.1:8080`, a plain domain, a domain with explicit port (the regression case — port must not imply dev), and a domain with "localhost" in a non-prefix position.

### 3. `sanitizeFilename` produces a lone `-` key prefix on all-stripped input ✅ fixed

**File:** [`src/app/api/upload/route.ts:58`](src/app/api/upload/route.ts)

When `file.name` consists entirely of stripped characters, the UUID key ends with a trailing `-`. The test pinned this as intentional, but the route itself had no comment. Added a one-liner at the key-construction site to match.
