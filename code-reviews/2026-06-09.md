## Issues and Observations

- **[scripts/import-projects.ts — `listExistingBlobs` pagination]** — `@vercel/blob` `list()` is paginated (`cursor`/`hasMore`), but the call ignores both. A project that ever exceeds the default page size silently treats missing pages as "doesn't exist" and re-uploads them. Idempotency landmine; cheap to fix by looping until `!hasMore`.
- **[scripts/import-projects.ts — `listExistingBlobs` warn-and-overwrite]** — A transient `list()` failure is downgraded to a warning, and `resolveImageUrls` then uploads every image with `allowOverwrite: true`. The documented "reuse on re-run" guarantee silently degrades to "re-upload everything"; the final summary doesn't surface that this happened.
- **[scripts/import-projects.ts — `resolveImageUrls` reuse heuristic]** — Reuse is keyed on `(key, byte size)`. Two different files of the same byte size keep the stale blob; the `↺` log line is the only signal, and it's only seen by a human eyeballing output. A content hash or the `etag` from `list()` would make this defensible against the real failure mode.
- **[scripts/import-projects.ts — unknown-flag error message]** — `KNOWN_FLAGS` (`scripts/import-projects.ts:43`) includes `--reupload`, but the error string at `:430` lists `"--dry-run, --cleanup"` only. A typo'd `--reupload` triggers misleading help. Derive the message from `KNOWN_FLAGS` so they can't drift.
- **[scripts/import-projects.ts — `processProject` catch-all]** — Every thrown error becomes `status: "failed"` with a stringified message. Programmer errors (`TypeError`/`ReferenceError` from a future regression in `projectMappers`) are indistinguishable from a missing image. Rethrow non-`Error` and non-validation errors so CI surfaces the real cause.
- **[scripts/import-projects.ts — `writeProject` id churn]** — `deleteMany` + `create` per re-run rotates the integer `id`. Public surface keys on `slug` so this is fine today, but any future external reference that pinned `id` would break silently. Worth a one-line comment so a future caller doesn't assume id stability.
- **[scripts/seed-projects.ts — links pointing at `http://localhost:300/about`]** — Three entries (`:104`, `:179`, `:228`) use `localhost:300` instead of `localhost:3000`. Almost certainly a typo; renders broken anchors on any local demo and would embarrass-leak if the seed ever ran against a non-local DB. Trivial fix.
- **[scripts/seed-projects.ts / seed-posts.ts — `DATABASE_URL!` non-null assertion]** — Both seed scripts assert `process.env.DATABASE_URL!`. If unset, the adapter throws far from the cause. `import-projects.ts` got this right with an explicit guard; the seeds should mirror it (or share a helper).
- **[scripts/import-projects.ts / seed-projects.ts / seed-posts.ts — duplicated bootstrap]** — `makePrisma`/`DATABASE_URL` guard / per-project try-catch error formatting now exists in three near-identical copies across `scripts/`. The seed typo above is exactly the failure mode shared scaffolding would prevent. Centralize when a fourth script appears.
- **[scripts/seed-*.ts — `console.error("...: ${error}")`]** — String-interpolated error in both seed files drops `.stack`. Use `console.error("...", error)` to preserve the stack for debug.
- **[src/components/privacy/AppleLegalLink.tsx — missing `target`/`rel`]** — External `<a href="https://www.apple.com/legal/privacy/">` has neither `target="_blank"` nor `rel="noopener noreferrer"`. `Footer.tsx` uses both for similar cross-origin links; this is the inconsistency the refactor consolidated into one easily-fixable point. Without `rel="noopener"`, the linked page can navigate the opener.
- **[src/components/privacy/PrivacyPageLayout.tsx — em-dash in boilerplate]** — `"...may change from time to time — be sure to consult..."` is a single mid-sentence em-dash. Per `~/.claude/rules/ai-tone.md`, em-dashes come in pairs around a parenthetical; replace with a period or semicolon. User-facing prose.
- **[src/app/privacy/{continuum,reckon,body-tracking}/page.tsx — em-dash cadence]** — Each per-app page opens with a single em-dash introducing a list (`"...PII — no name, address..."`). Defensible per page, but stacked across three pages it becomes a uniform rhythm tell. Vary one (colon) to break the cadence.
- **[src/app/privacy/continuum/ — untracked sibling routes]** — `dpia/page.tsx` and `responsible-use/page.tsx` exist as untracked Next.js route files. If they don't go through `PrivacyPageLayout`, they break the visual consistency the refactor just established. Decide whether to commit through the layout or remove. See Notes.
- **[src/components/projects/ProjectContent.tsx — tablist `overflow-x-auto` keyboard scroll]** — Adding horizontal overflow is correct for narrow viewports, but arrow-key navigation (`handleTabKeyDown`) doesn't scroll an off-screen active tab into view. On a narrow screen with many sections, the user can `aria-selected` an invisible tab. Add `scrollIntoView({ inline: "nearest" })` in the same effect that focuses the active button.

## Architecture & Coupling

- **[scripts/import-projects.ts — `ProjectManifest` vs `projectCreateSchema`]** — Two independent structural definitions of the same shape (the `projectImport.ts` file comment calls this out). Fine for now because the manifest type is intentionally loose ("untrusted JSON"), but a schema field added without updating the manifest type will type-check and run, then drop the field at write. If field count grows, derive `ProjectManifest` from `z.input<typeof projectCreateSchema>` with image fields swapped to local-path strings.
- **[scripts/import-projects.ts — `BLOB_KEY_PREFIX = "projects"` vs admin upload route]** — `src/app/api/admin/upload/route.ts` writes blobs with `${randomUUID()}-${sanitizeFilename(file.name)}` — no per-project namespace. The two key schemes don't collide (UUID prefix), but a future "list everything for project X" tool only sees the importer's blobs. Worth a doc line, or aligning the admin route on the same `projects/<slug>/` prefix.
- **[src/components/privacy/PrivacyPageLayout.tsx — implicit section ordering]** — Boilerplate ("Last update", "Contact") is always appended after `sections`. No escape hatch for a page that needs a different order (e.g. Changelog after Contact). Fine at four pages; flag if a fifth needs different ordering.
- **[src/components/privacy/PrivacyPageLayout.tsx — `contactPronoun: "me" | "us"`]** — Literal union assumes English. Localization later means a refactor; noting only because it's the kind of assumption that's easy to record now.

## Observability

- **[scripts/import-projects.ts — final summary line]** — `${imported.length} imported, ${failed.length} failed` doesn't break down by reason or surface per-project detail. `result.detail` is built but never re-printed at the end. A second-pass summary listing each failed project's name + first error line would make a CI run debuggable without scrolling.
- **[scripts/import-projects.ts — `resolveImageUrls` aggregate]** — Per-file `↑`/`↺` lines, no per-project aggregate ("3 reused, 12 uploaded"). With dozens of images this is hard to scan; matters because reuse is the file header's headline claim.

## Performance

- **[scripts/import-projects.ts — `loadImages` no size cap]** — Reads every image fully into a `Buffer` in memory before any upload, with no per-file ceiling. The "trusted, first-party staged files" comment defends this, but a 2 GB accidental `.mov` dropped into `scripts/imports/` will OOM the process before it hits Blob. Cheap defense: a documented soft cap (e.g. 50 MB) that throws with a clear message.

## Missing Tests

- **[src/lib/import/projectImport.test.ts — Windows path separators]** — `sanitizePathSegment`'s regex includes `\\`, but the split is on `/` only. A manifest authored on Windows with backslashes would feed one giant "segment" into `sanitizePathSegment`, collapse to a single dash-joined key, and degrade silently. Either `.split(/[\\/]+/)` and test, or assert in a test that backslash paths throw / are normalized.
- **[src/lib/import/projectImport.test.ts — `resolveManifestImageRefs` boundaries]** — No coverage for `images: undefined` vs `[]`, a manifest where `icon` is a hosted URL but `heroImage` is local, or a `resolve` callback that throws. Happy path is solid; the boundaries the importer actually depends on are not.
- **[scripts/import-projects.ts — no integration test]** — The imperative shell (`loadImages`, `listExistingBlobs`, `resolveImageUrls`, `writeProject`, `processProject`) has zero tests. The load-bearing reuse-on-re-run claim, `--dry-run`, `--reupload`, and the `deleteMany`+`create` transaction live in the shell and would benefit from a mocked-`put`/`list` test asserting "second run with same files = zero `put` calls".
- **[src/lib/db/projectMappers.test.ts — empty-array case]** — Tests cover `undefined` and populated cases but not `sections: []` / `links: []` (which produces `{ create: [] }` — Prisma-valid but semantically distinct from `undefined`). The existing `undefined`-skip test implies this distinction matters; assert both ways.
- **[src/components/privacy/PrivacyPageLayout.test.tsx — section order]** — No test asserts that boilerplate "Last update"/"Contact" render *after* page-supplied `sections`. A regression flipping the spread order would silently change the page reading order and pass current tests.
- **[src/components/privacy/PrivacyPageLayout.test.tsx — empty sections array]** — No test for `sections: []` (degenerate case where only boilerplate should render).
- **[src/components/privacy/AppleLegalLink — no test file]** — Trivial to add a single render test pinning the href + accessible name, which would catch URL/label drift in the one place it now lives.
