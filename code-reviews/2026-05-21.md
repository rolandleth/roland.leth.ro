# Code Review — 2026-05-21

## Issues and Observations

- [x] **src/lib/api/schemas.ts — bucket/tag cross-validation gap** — Zod accepts `{bucket: Web, platformTags: [iOS]}` (or any bucket+tag mismatch). Comment says the picker enforces it, but any non-UI caller (admin script, future API client, mistaken PATCH) can corrupt the invariant that `compactLabel`, `isCompactLabelRedundant`, and `groupByBucket` lean on. Add a `superRefine` checking `tags ⊆ BUCKET_SUGGESTED_TAGS[bucket]` (or at least the natural set) at the API boundary. **Resolved 2026-05-21**: added `refineBucketTagCoherence` `superRefine` (against `BUCKET_SUGGESTED_SETS`) on both create and update schemas; runs only when both fields are present in the same payload (PUT semantics).
- [x] **src/lib/api/schemas.ts — `projectUpdateSchema.partial()` drops `.min(1)`** — On PUT, `platformTags: []` validates and reaches Prisma as "set to empty"; create requires ≥1. Pick a consistent invariant — either re-impose `.min(1).max(8)` when the field is present on update, or document explicitly that PUT may clear what POST requires. **Resolved 2026-05-21**: claim was false — Zod `.partial()` keeps inner validations alive when a value is present; pinned with a regression test in `schemas.test.ts`.
- [x] **src/lib/api/schemas.ts — no duplicate-tag guard on `platformTags`** — `[iOS, iOS]` validates and persists; `compactLabel` then treats it as a 2-tag set and may flip from "iOS" to "Multiplatform" depending on the second tag. Add `.refine(arr => new Set(arr).size === arr.length, ...)` or pre-dedupe in the schema. **Resolved 2026-05-21**: added `.refine(unique)` on the new `platformTagsSchema`, carried through to update via `.partial()`.
- [x] **src/lib/utils/platforms.ts:131 — Web/OpenSource + `[Next]` alone → "Fullstack"** — Because `Next` is cross-listed in both `WEB_FRONTEND_TAGS` and `WEB_BACKEND_TAGS`, a Web project tagged only `[Next]` satisfies the spanning condition and renders as "Fullstack" instead of "Next.js". Unclear if intended (Next.js is fullstack by nature) — pin the choice in a test either way. **Resolved 2026-05-21**: false positive — the single-tag branch fires before the Fullstack branch, so the output is "Next.js". Pinned with an explicit regression test in `platforms.test.ts`.
- [x] **src/lib/utils/platforms.ts:87–92 — `BUCKET_SUGGESTED_TAGS.OpenSource = all 18 tags`** — Effectively unconstrained, which defeats the picker's narrowing purpose for that bucket and lets `[Library, iOS]`-style mixed states reach `compactLabel`'s "Multiplatform" fallback. Either narrow OpenSource to its natural set + opt-in override, or add an inline comment naming the "catch-all by design" intent. **Resolved 2026-05-21**: false positive — the "catch-all by design" rationale is already documented inline at `platforms.ts:82–86`.
- [x] **src/components/admin/PlatformPicker.tsx:31–40 — silent tag pruning on bucket switch** — Selection vanishes with no toast, no warning, no log. Show an inline "removed N tags incompatible with X" hint, or warn before pruning. Also an observability gap — no trace if pruning fires spuriously. **Resolved 2026-05-21**: added a `role="status" aria-live="polite"` "Removed N tag(s) not valid for this bucket" hint that auto-clears on any tag interaction.
- [x] **src/components/admin/PlatformPicker.tsx:117–127 — hidden `required readOnly` text input as submit gate** — Fragile: the browser's required-error UX points at an invisible field, screen readers won't announce it, and the value template `${bucket}:${tags.join(",")}` is brittle (e.g. `"null:"` if state desyncs). Replace with explicit `<ErrorMessage>` validation in `ProjectForm`'s submit handler, matching the rest of the form's error surface. **Resolved 2026-05-21**: dropped the hidden input; `ProjectForm.handleSubmit` now early-returns with a `<ErrorMessage>` when bucket or tags are empty.
- [x] **src/components/admin/ProjectForm.tsx — `state.bucket as PlatformBucket` cast** — "Safe" only because of the picker's hidden-input gate; an undocumented coupling. If the picker is ever swapped or its gate regresses, `null` is silently coerced. Add an explicit guard + error before the cast (and remove the cast). **Resolved 2026-05-21**: cast removed; the new submit-handler early-return narrows `state.bucket` from `null` to `PlatformBucket` naturally.
- **src/components/projects/FeaturedProjectCard.tsx — always-on platform pill** — Unlike `CompactProjectCard` which hides the capsule when `compactLabel === bucketLabel`, Featured renders it unconditionally. For featured projects where the label collapses to the bucket name, the pill duplicates info shown elsewhere. Mirror Compact's `isCompactLabelRedundant` check.
- [x] **src/components/projects/CompactProjectCard.tsx — discontinued treatment scoped to icon only** — Only the icon gets `opacity-60 grayscale`; name and platform capsule render at full opacity, which reads as a glitch rather than intent. Fade the whole card or add an explicit "discontinued" badge so the signal isn't carried by icon styling alone. **Resolved 2026-05-21**: false positive — current scoping is intentional, with a WCAG-AA rationale documented inline at `CompactProjectCard.tsx:42–47`.

## Architecture & Coupling

- [x] **src/lib/db/projects.ts — `getAllProjectsForGallery(sortDiscontinued)`** — One boolean toggles both cache usage and ordering — two orthogonal concerns coupled in one signature. Split into `getProjectsGalleryCached()` (cached, discontinued-last) and `getProjectsForAdmin()` (uncached, sortOrder+name) so the cache contract is local and callers can't accidentally hit it with the wrong ordering. **Resolved 2026-05-21**: split per the recommendation; updated all three call sites (`projects/page.tsx`, `projects/[slug]/page.tsx`, `listProjectsForAdmin`).
- [x] **src/lib/db/projects.ts — duplicated select shapes** — `gallerySelect` and the gallery-shaped `getAllProjects` select are structurally identical. Extract one const and reference it from both; the next field addition (next time something like `platformTags` is added) will silently miss one site otherwise. **Resolved 2026-05-21**: false positive — `getAllProjects` returns `ProjectListItem` (smaller subset, no `summary`/`heroImage`/`accentColor`/`role`), `gallerySelect` returns `ProjectGalleryItem`; shapes are intentionally different.
- [x] **src/app/api/admin/projects/route.ts & [id]/route.ts — duplicated Serializable reorder** — Both routes implement clamp-and-shift `sortOrder` under a Serializable txn. Extract `reserveSortOrderSlot(tx, target, current?)` into `lib/db/projects.ts`. Two copies of subtle txn logic is the kind of DRY violation that becomes a bug when one side is patched. **Resolved 2026-05-21**: false positive — POST appends only (`updateMany gte: targetOrder`); PUT does bidirectional shift differentiating move-up vs move-down. Different logic, not real duplication.
- [x] **PlatformPicker ↔ ProjectForm invisible contract** — The picker's hidden-input submit gate is the implicit invariant that justifies the form's `as PlatformBucket` cast; nothing in either file references the other's expectation. Move the gate into the form (explicit) or comment the contract in both places. **Resolved 2026-05-21**: gate moved into `ProjectForm.handleSubmit`; cast removed (see Issues block above).

## Observability

- [x] **src/app/api/admin/projects/route.ts & [id]/route.ts — Serializable retry path** — Serializable txns can fail with `40001` serialization errors under contention; neither route distinguishes that from a real validation/Prisma error, and there's no log line tagging the txn boundary. Single-admin app makes contention rare, but a swallowed serialization failure would look identical to a 500 with no breadcrumb. **Resolved 2026-05-21**: false positive — PUT comment at `[id]/route.ts:82–92` explicitly defers the retry loop ("At single-admin volumes conflicts are essentially impossible, so no retry loop"). Known design choice.
- [x] **src/components/admin/PlatformPicker.tsx:31–40 — destructive prune with no signal** — Silent tag drop on bucket switch has no log, no toast, no callback-level indication that pruning happened. If a future bug causes spurious pruning, there's no trace. **Resolved 2026-05-21**: now surfaces a `role="status"` hint on every prune (see Issues block above).

## Risk Assessment

**Medium.** The platform refactor is well-scoped: storage shape now matches editorial intent, Postgres NULL defense via `@default([])` is in place, and the removed `Project.platform` string field has zero dangling references. The PUT route's `...rest` spread is already a known watch-out (journal-tracked). What raises the risk above Low: (1) the invariant that bucket/tags stay coherent is enforced *only* in the UI (picker's hidden-input gate) and is not re-checked on the API boundary or in Zod — any non-UI caller can corrupt it, with cascading effects on `compactLabel` / `groupByBucket`; (2) `projectUpdateSchema.partial()` silently relaxes `platformTags.min(1)` on PUT versus POST; (3) the picker's silent tag pruning on bucket switch is a UX hazard and an observability gap. Tests are thorough on the new domain helpers but thin on the route/DB shape and the picker's submit gate, leaving the load-bearing assumptions un-pinned.
