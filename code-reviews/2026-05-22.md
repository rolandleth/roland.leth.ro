A regression that wrapped this in `unstable_cache` (mirroring `getProjectsGalleryCached`) would silently violate the documented "uncached so edits surface immediately" contract and the current tests wouldn't catch it. Low likelihood given the function naming, but the cache split was the whole point of the rename. **Resolved 2026-05-22**: switched the file's `next/cache` mock to `nextCacheSpyFactory`, snapshotted `unstable_cache.mock.calls` at module-load time, and pinned the exact `[{projects-gallery}, {all-project-slugs}]` set so any new module-load wrap (including a regression on the admin reader) drifts the snapshot.

## Risk Assessment

**Low.** What landed closes the four real themes from yesterday's review: a `superRefine` for bucket/tag coherence + dedupe shared across create/update via a common `projectFields` map; replacement of `PlatformPicker`'s hidden `required readOnly` input with an explicit submit-handler gate in `ProjectForm` (drops the `state.bucket as PlatformBucket` cast); split of `getAllProjectsForGallery({ sortDiscontinued })` into `getProjectsGalleryCached` + `getProjectsForAdmin`; single-pass partition with precomputed `showPlatformCapsule` on the projects gallery page. The schema-side contract narrowed (rejects duplicate tags and bucket/tag incoherence the API previously accepted) — a narrowing change on an admin-only surface, so blast radius is contained to the admin form, which now produces compliant payloads by construction. No load-bearing plumbing touched. Test coverage is the only weak spot, and it's narrowly missing the empty-tags branch and the cache-contract assertion.
