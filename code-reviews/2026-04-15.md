### 3. `PlatformPicker` — cross-bucket initial value entered undeselectable state ✅ fixed

**File:** `src/components/admin/PlatformPicker.tsx`

When the initial `value` prop contained keywords spanning multiple buckets (e.g. `"iOS, React"`), the selected keywords were split across buckets but `activeBucket` resolved to only the first matching bucket, locking the other bucket's rows. Those keywords appeared selected but could not be deselected.

Fix: before initialising state, check how many buckets the parsed keywords span. If more than one, discard them and treat the whole value as freeform instead.

**File:** `src/components/admin/ProjectForm.tsx`

Moved `ROLE_OPTIONS` to module level, matching the pattern already used by `LINK_LABEL_OPTIONS` in `LinkManager.tsx`.

### 5. `LinkRow` state drifts on reorder due to index-based keys ✅ fixed

**Files:** `src/components/admin/LinkManager.tsx`, `src/components/admin/ProjectForm.tsx`

`LinkRow` initialises its dropdown/freeform state from props once; index-based keys meant React reused rows in place during reorder, leaving the displayed label out of sync with the underlying data.

Fix: `_key: string` (a `crypto.randomUUID()` value) was added to `LinkItem` and assigned when a link enters `ProjectForm`'s state — on init from `initialData` and in `addLink`. `LinkRow` uses `link._key` directly as its key; no parallel state or module-level counter needed. `_key` is stripped before the API request since it is a client-only concern.
