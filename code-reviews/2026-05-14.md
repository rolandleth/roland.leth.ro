## Issues and Observations

- **[src/app/api/upload/route.ts — `sanitizeLogString`]** — The regex covers only `\r\n\t\0`; other C0 controls (`\v`, `\f`, `\x1b` ESC) and `\x7f` (DEL) still pass through. Newline-forgery is the primary log-injection vector and is closed, but an attacker-controlled `\x1b[…` could re-paint a tailing terminal. A `/[\x00-\x1f\x7f]+/g` would close the gap with no scope change.
- **[src/components/admin/ProjectForm.tsx — `handleSubmit` / `sortOrderText` desync]** — `handleSubmit` calls `setSortOrderText(String(sortOrder))` but does NOT also call `setField("sortOrder", sortOrder)`. Today's invariant ("every committed `state.sortOrder` was a digit-only string, so the fallback already equals what we re-snap to") carries correctness; a future change to either source breaks the lockstep silently. Cheap fix: mirror `setField("sortOrder", sortOrder)` alongside the text setter.
- **[src/components/admin/ProjectForm.tsx — digit-only regex duplicated 3×]** — `/^\d+$/` lives in `onChange` (line 254), `onBlur` (line 262), and `handleSubmit` (line 155). DRY violation re-creating exactly the drift Phase 5 was meant to prevent. Extract a `snapSortOrder(text, fallback)` colocated with the input.
- **[src/lib/metadata.ts — `buildPageMetadata` dev guard]** — `title.includes("Roland Leth")` is case-sensitive; a future caller typing `"roland leth"` or `"ROLAND LETH"` would slip past. The brand is only ever written in one casing today, so risk is low; `/roland\s*leth/i` would close it with no cost.
