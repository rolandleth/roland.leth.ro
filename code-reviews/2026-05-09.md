Worth deciding once for the whole site (about + footer + markdown output) rather than re-flagging per touch.

## Observability

- [x] **[src/app/error.tsx, src/app/global-error.tsx — `console.error` only]** — Errors land in the browser console with no external reporting (no Sentry / Vercel error capture wired). For a personal site this is a deliberate-enough position, but the `digest` from Next is currently shown only in `global-error.tsx` and dropped on the inline boundary — surfacing it (or at least logging it) on `error.tsx` too would close the gap when a server-side error reaches the client. **Resolved 2026-05-09**: dropped digest rendering from both boundaries — without external log aggregation it's user-uncorrelatable on Vercel Hobby (~1h runtime-log retention). Re-introduce paired with Sentry or extended-retention logs.

## Missing Tests

Personal-site call to skip is reasonable; raising it because these are exactly the files that get noticed only when broken. **Resolved 2026-05-09**: added RTL tests for both boundaries (3 cases each — render, reset wiring, console.error logging).
