- [ ] **`src/app/privacy/weekly-gym/page.tsx` — iCloud-off paragraph** — the page now promises that turning iCloud off for Weekly Gym makes Apple's sync remove the app's data from that device, and that the data comes back when iCloud is turned on again. The app code does not do this (`StoreContainer.make`, `AppData.openRealStore`); it is SwiftData/CloudKit mirroring behaviour, and no code or test in either repo checks it. Check the removal claim on a device before relying on it, or word it so it doesn't depend on Apple's purge behaviour.

## Architecture & Coupling

- [ ] **`src/components/privacy/LegalPageLayout.tsx` — `LegalRelatedLink.href: string`; `src/components/privacy/relatedLegalLinks.ts` — `currentPath: string`** — `8de400a9` typed the cluster functions' `currentPath` as `LegalPagePath`, but the `href`s in `continuumLegalLinks`, `digestLegalLinks` and `weeklyGymLegalLinks` are still plain strings. If a page is renamed, `tsc` catches the caller but not the dead related link, and a stale `href` silently stops filtering the current page out. The 2026-10-20 watch-out is only half closed. Typing the cluster arrays' `href` as `LegalPagePath` (for example with `satisfies`) would close it. The inline `<Link href="/privacy/weekly-gym">` in `src/app/terms/weekly-gym/page.tsx` has the same gap.
