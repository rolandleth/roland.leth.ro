# Code Review — 2026-07-27

Scope: commits `e53ad2c` + merge `1d27807` — "Harden admin auth: anchor the middleware matcher, guard every admin handler, floor SESSION_SECRET." 16 source files, ~20 handlers, plus tests and mocks.

## Issues and Observations

- [x] **[src/proxy.ts — `config.matcher` comment]** — The inline comment asserted "The auth gate lives only in this middleware — no admin handler re-checks the session — so a path that misses the matcher is an unauthenticated request reaching a privileged handler." This same commit made that false: `requireAdmin()` now runs in every admin handler and `src/lib/api/requireAdmin.ts` calls itself "the second lock." A matcher miss now 401s loudly at the handler, not a silent bypass. The two files' security rationales contradicted each other. **Resolved 2026-07-27** — rewrote the comment: middleware is "the first gate but not the only one," handlers independently re-check via `requireAdmin`, and the explicit entries keep that handler check a backstop rather than the sole defense. (The journal's Watch-out #1 carries the same outdated "middleware is the only gate" framing and should be updated on the next journal pass.)

- **[src/app/api/admin/**/route.ts — `requireAdmin` guard block]** — The 4-line `const unauthorized = await requireAdmin(tag); if (unauthorized) return unauthorized` block is duplicated across ~20 handlers. A `withAdmin(tag, handler)` higher-order wrapper would remove the repetition. **Decision 2026-07-27: deliberate no-op.** The wrapper wouldn't make omission impossible (a bare `export async function POST` still bypasses it) — the real guarantee stays with `adminAuthContract.test.ts`, which already fails on omission. And `requireAdmin` is intentionally the same inline early-return idiom as its siblings `parseIdParam` / `parseJsonBody`; wrapping only auth in a HOF would trade local repetition for global inconsistency. If the duplication is ever revisited, it should be a pattern-wide decision (wrap all three or none), not a one-off for auth.

## Risk Assessment

**Low.** A well-scoped, well-tested security hardening pass. It closes a real auth bypass — the unanchored extension group in the middleware matcher let any path containing `.js`/`.css`/etc. before the end (e.g. `/api/admin/posts/1.json`) skip the gate — and backstops it two ways: the `$` anchor plus explicit `/admin` and `/api/admin/:path*` matcher entries, and a handler-level `requireAdmin()` second lock. The `SESSION_SECRET` 32-char floor lives in the accessor, not the schema, so a short secret fails only the session path and can't take the public site down (consistent with the `isValidIndexNowKey` precedent). Test coverage is strong: `adminAuthContract.test.ts` asserts every admin handler 401s on its own AND that the hand-maintained route list matches the filesystem (drift-guarded), the matcher regex is exercised against bypass and real-asset paths, and the secret floor is tested at the boundary. No caller-facing contract widened; the only behavioral narrowing (handlers independently reject sessionless requests) is the intent. Residual risk is the documented denylist-matcher completeness and the incidental integer-id dependency — pre-existing watch-outs, not new hazards.
