# Code Review — 2026-09-14

## Issues and Observations

- [x] **scripts/import-projects.ts — `writeProject`** — the import deletes the row and creates it again, and writes `isOwnApp: data.isOwnApp ?? false`. The local Reckon and Continuum manifests (`scripts/imports/*/project.json`) do not have the field. If you tick "Own app" in the admin (2026-09-13 open thread) and then import either manifest again, the flag goes back to false and the badge disappears. `isFeatured` and `isDiscontinued` do not have this problem, because both manifests set them. **Resolved 2026-09-14**: `assertRequiredFlags` fails an import that omits any of the three flags; both manifests now set `isOwnApp`.
- [x] **src/components/projects/ProjectContent.tsx — `storeLink` / `badgeStorefront` / `ctaLabel`** — the rule "a store link is live only when the project is not discontinued" is written three times: in `storeLink`, in `badgeStorefront` (`isOwnApp && !isDiscontinued`) and in `ctaLabel`. `ProjectLinkCta` receives both `isDiscontinued` and `badgeStorefront`, so a later change to what "discontinued" means has three places to update and nothing that keeps them the same. On the pill path, `isStoreUrl` also runs twice for the same link. **Resolved 2026-09-14**: `linkCtasFor` in `platforms.ts` decides every link's CTA once, discontinued rule included.
- [x] **src/components/projects/ProjectContent.tsx (section `prose` wrapper) and src/components/projects/ProjectFaq.tsx — `prose dark:prose-invert max-w-none`** — commit 2c1ad66 added `prose-img:mx-auto` to `PostMarkdownContent` only. An image in a project section or in an FAQ answer still sits at the left edge, but in posts and guides it is centred. No project content has images yet. The cause is four components that each type their own `prose` class string. This is a different problem from the `MarkdownEditor` open thread. **Resolved 2026-09-14**: one unlayered `.prose img { margin-inline: auto }` rule in `globals.css` centres images in every `.prose` wrapper.
- [x] **public/images/app-store/*.svg — file mode** — git stores all four badge SVGs as `100755` (executable). This does no harm at runtime. But it probably came from the downloaded Apple kit, so the next asset drop from that kit will do the same. **Resolved 2026-09-14**: files set to 644; mode-only commit (the kit's archive stores them as 0700).

## Architecture & Coupling

- [x] **src/lib/import/projectImport.ts — `ProjectManifest`; src/lib/db/projects.ts — `ProjectDetail`; scripts/seed-projects.ts — `ProjectInput`** — adding one boolean touched about eight hand-kept field lists: Prisma, Zod `projectFields`, `ProjectDetail`, `ProjectManifest`, the POST route, `writeProject`, the seed type and the form state. `readManifest` casts with `JSON.parse(raw) as ProjectManifest` before the Zod parse, so that type and `projectFields` can drift apart with no compiler error. Also, the POST route and `writeProject` both repeat `?? false` for each flag, which copies `@default(false)` from the schema. The pattern existed before; this commit makes it larger. **Resolved 2026-09-14**: withdrawn as overstated, no change — `ProjectManifest` is loose on purpose and Zod validates right after the cast; the explicit `?? false` is now covered by route tests.
- [x] **src/lib/utils/platforms.ts — `storefrontFor` vs src/components/projects/ProjectContent.tsx — `STORE_HOSTNAMES` / `isStoreUrl`** — the `Storefront` type is in lib, but the rule that decides whether a link is a storefront is still inside a `"use client"` component. The badge shows only when both agree. A server consumer, for example JSON-LD, cannot use the host rule without importing from a client component. Low severity while `ProjectContent` is the only consumer. **Resolved 2026-09-14**: `STORE_HOSTNAMES` and `isStoreUrl` moved into `platforms.ts`, behind `linkCtasFor`.

## Observability

- [x] **scripts/import-projects.ts — `writeProject` result output** — when a manifest has no `isOwnApp`, the import writes false and prints nothing about it. The CLI output does not show that an admin-set flag was overwritten (see the first issue). **Resolved 2026-09-14**: no silent default any more; a missing flag fails the import with an error naming it.

## Performance

- [x] **src/components/projects/AppStoreBadge.tsx — both `Image` elements** — neither image has `loading`, `priority` or `preload`, so `next/image` renders `loading="lazy"`. The hero badge is above the fold, so its 40px box can show empty for a short time. The variant hidden with `display:none` is probably not fetched until the first theme toggle, so the badge can be blank for a moment after a toggle. If you make both images eager, every view downloads both SVGs (about 10–12 KB each). Only the hero badge is a candidate for eager loading. The `lazy` attribute is confirmed; the visible effect is plausible, not observed. **Resolved 2026-09-14**: both images `loading="eager"`; the repeated CTA reuses the same URLs, so each SVG downloads once.

## Risk Assessment

**Low.** 8519ad3 adds one column that is not nullable and defaults to false (applied with `db:push`), plus one render branch shown only on the project detail page. Existing rows and the API contract stay compatible: `isOwnApp` is optional in both Zod schemas. 2c1ad66 is a one-class change. b6d3c63 recompresses three favicons. Nothing touches auth, caching tags or routing. The one risk to data integrity is that importing again quietly clears `isOwnApp`, and that is exactly the step the open thread asks you to take by hand. The rest are test gaps where jsdom cannot see what users see (theme classes, image loading, artwork paths), and hand-kept field lists that grew by one more field.
