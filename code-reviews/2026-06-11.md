# Code Review — 2026-06-11

## Issues and Observations

- **[src/app/api/auth/login/route.ts — `POST` invalid-credentials path]** — Recomputes `clientBucketKey(request, ipHashSecret)` on the invalid-credentials log line even though `bucketKey(request)` was already called earlier in the handler; the per-IP HMAC runs twice per failed login. Hoist the key into an outer scope and reuse it; also prevents the two paths from drifting if `clientBucketKey` ever gains normalization.
- **[src/app/api/auth/login/route.ts — `globalBucketKey` vs `clientBucketKey` namespace]** — Both share Upstash's `rl:login` prefix without a sub-namespace. Collision risk between a 22-char base64url HMAC and the literal `"global"` is effectively zero, but the two key spaces are not formally disjoint. Prefer explicit partition (`ip:<hash>` vs `global`) so any future helper change can't conflate them.
- **[src/app/api/auth/login/route.ts — leftmost `x-forwarded-for` assumption]** — Reads the leftmost XFF entry, which is correct on Vercel but attacker-controlled on any deploy fronted by a non-trusted proxy. Lock the deploy assumption in a code comment; flip to `request.ip` / `x-real-ip` if the target ever changes.
- **[scripts/import-projects.ts — header comment]** — Still says reuse is gated by "same key + same byte size"; the implementation now reuses on key match alone (content-addressed). Stale doc misleads on the new contract.
- **[scripts/import-projects.ts — `Unknown flag(s)` help text]** — Omits `--reupload` from the supported flag list even though the flag is honored elsewhere in the same file. Will mislead anyone who mistypes the flag.
- **[src/lib/import/projectImport.ts — `blobKeyFor` orphan accumulation]** — Content-addressed keys cleanly bust the CDN on change, but every re-import of an edited image leaves the previous key in the Blob store forever; nothing scans-and-deletes the project's prefix. On the 1 GB free tier this grows monotonically with edits; the commit message ("clean cache-busting") oversells the change. Either add a sweep of unreferenced keys after a successful write, or document the cleanup as out-of-band.
- **[scripts/import-projects.ts — 48-bit hash truncation]** — `sha256` is sliced to 12 hex chars. Collision probability is realistic only at very large N, but the dedupe contract is "same key ⇒ same bytes," so on a collision the importer would silently reuse the stale URL and serve wrong content. Either widen the prefix or assert byte-equality on reuse.
- **[scripts/import-projects.ts — `list({ prefix })` first-page only]** — `@vercel/blob`'s `list` is paginated (`cursor`/`hasMore`); the code reads only page one. Once a project accumulates >1000 blobs (likely given the orphan growth above), later entries are invisible to the reuse path and re-upload spuriously.
- **[src/app/terms/continuum/page.tsx — chrome duplication]** — Reimplements `PrivacyPageLayout`'s shell (PageGlow + `max-w-2xl` wrapper + h1 + `space-y-8` + trailing Last update / Contact sections) because the auto-rendered boilerplate calls itself a "privacy policy"; the in-file comment documents the workaround rather than fixing it. Generalize the layout (rename to `LegalPageLayout`, parameterize the boilerplate label) so terms reuses the same shell — currently any spacing/typography tweak must land in two places.
- **[src/app/privacy/continuum/{dpia,responsible-use}/page.tsx — discoverability]** — Neither page links to the privacy policy or to each other; only `terms/continuum` cross-links. A reader landing on the DPIA cannot reach responsible-use without going up to the index.
- **[src/app/privacy/continuum/{page.tsx,dpia/page.tsx,responsible-use/page.tsx} + terms/continuum/page.tsx — date drift]** — Four files carry four different `lastUpdated` dates (May 30, Jun 8, Jun 9, Jun 10). Likely intentional, but worth a once-over before shipping in case any is a copy-paste artifact.
- **[src/components/privacy/AppleLegalLink.tsx vs src/app/terms/continuum/page.tsx — outbound link convention]** — `AppleLegalLink` opens `apple.com/legal/privacy` in the same tab without `rel`; the new terms page uses `target="_blank" rel="noopener noreferrer"` for the Apple EULA link. Pick one convention.
- **[src/app/privacy/continuum/responsible-use/page.tsx — list marker double-numbering]** — `<ol className="list-none">` with hand-rendered `01`/`02` markers in sibling `<span>`s leaves the `<ol>` still semantically ordered, so assistive tech reads e.g. "1. 01 Opinions, not verdicts." Switch to a CSS counter or drop the inline markers in favor of the native `<ol>`.
- **[src/lib/content/metadata.ts — `buildPageMetadata` robots field]** — Never emits a `robots` field. Confirm the DPIA in particular is meant to be indexed (probably yes — it's a trust signal); if any future legal draft needs noindex, the helper has nowhere to express that.

## Architecture & Coupling

- **[src/app/api/auth/login/route.ts — module-load construction]** — `Redis`, `Ratelimit`, env reads, and the missing-secret `console.warn` all execute at module import. Fine for production but couples test setup to `vi.resetModules()` + dynamic import per env permutation, and forces any later reuse of `clientBucketKey` / `bucketKey` to drag the Redis client. If those helpers move into shared use, extract them to `src/lib/auth/rateLimit.ts` with no module-load side effects.
- **[src/lib/import/projectImport.ts — `syntheticBlobUrl` prefix construction]** — Builds the `projects/<slug>/<dirs>/` prefix inline instead of routing through `blobKeyFor`. Two call sites now have to stay in sync if `BLOB_KEY_PREFIX` or the segment-join changes. A no-hash overload of `blobKeyFor` would keep the contract local.
- **[scripts/import-projects.ts — upload-before-write ordering]** — Uploads run before the DB transaction; if `writeProject` fails, every uploaded blob is an orphan with no row referencing it. Pre-existing, but the content-addressed scheme makes the leak more visible (old keys also linger). No rollback path.
- **[scripts/import-projects.ts — `allowOverwrite: true` masks collision]** — With content-addressed keys, identical bytes resolve to the same key so the flag is load-bearing only on a hash collision. Tightening to `false` would surface a collision as an error instead of a silent overwrite.
- **[src/lib/import/projectImport.ts — no migration for legacy URLs]** — Pre-existing DB rows still hold non-content-addressed URLs and continue to resolve, but any re-import wipes their rows and the old blobs become permanent orphans. Either a one-off cleanup or a documented coexistence note belongs in the journal.
- **[src/app/terms/continuum/page.tsx — wrong abstraction boundary]** — The structural fix for the chrome duplication above is to rename `PrivacyPageLayout` → `LegalPageLayout` and parameterize the boilerplate label; privacy pages stay one-line callers and terms joins them. Worth treating as a small refactor, not a one-off page.

## Observability

- **[src/app/api/auth/login/route.ts — invalid-credentials log payload]** — When `ipHashSecret` is null, passes an empty object `{}` as the second arg to `console.warn`, which prints as a noisy empty object in the line. Either drop the second arg in the global-bucket path or always include the resolved key (`"global"` is at least information).
- **[src/app/api/auth/login/route.ts — collapsed log levels]** — Routine 429 (hostile traffic, expected) and the limiter-throw fail-open path (Redis down, alert-worthy) both log at `warn`. Splitting these — `info` for 429s, `error` (or a distinct tag) for the throw — would let a dashboard partition by severity.
- **[scripts/import-projects.ts — `listExistingBlobs` catch-all]** — Catches all errors and warns; an auth/permission failure on the blob token silently downgrades to "treat nothing as existing," combined with `allowOverwrite: true` this can convert a misconfigured token into a full re-upload (cost on prod) without surfacing. At minimum distinguish transient/network errors from credential ones.
- **[scripts/import-projects.ts — reuse/upload log lines]** — The `↺` / `↑` lines no longer include `formatBytes(image.size)` that the old code emitted; per-image audit on a large gallery is harder without the size column. Low cost to keep.

## Performance

- **[scripts/import-projects.ts — sequential `await put` loop]** — Uploads run serially per project. For a 10–30 image gallery this is the dominant wall-clock cost of a re-import. A bounded `Promise.all` (concurrency ~4) is correctness-safe because each `put` targets a distinct content-addressed key.

## Missing Tests

- **[src/app/api/auth/login/route.ratelimit.test.ts — fail-open on per-IP path]** — The "fails open when limiter throws" test only covers the global-bucket config. The per-IP-secret config should assert the same fail-open semantics; the catch path is shared but a regression that escaped only one branch wouldn't be caught.
- **[src/app/api/auth/login/route.ratelimit.test.ts — success path under limiter]** — Tests assert 429 and 401, but never the 200 path with the limiter active, including that the `[api:auth:login] success` info fires and the rate-limit `warn` does not. `verifyCredentials` is hard-wired to false in the file.
- **[src/app/api/auth/login/route.ratelimit.test.ts — empty-string `x-forwarded-for`]** — Covers null (header omitted) and a comma-list, but not the literal empty string. A regression that removed the `forwarded !== ""` guard would silently HMAC the empty string into a separate bucket no test catches.
- **[src/app/api/auth/login/route.ratelimit.test.ts — secret-routing assertion]** — `expectedKey` uses the same `PER_IP_SECRET` constant the route is stubbed with, so a regression that hard-coded the secret would still pass. Two `loadRoute` runs with different secrets producing different keys for the same IP would lock the routing in.
- **[src/lib/import/projectImport.test.ts — hash-stability idempotency]** — The new test asserts different hashes produce different keys, but never asserts the same hash produces the same key (the other half of the contract). One-liner.
- **[src/lib/import/projectImport.test.ts — content-derivation untested]** — Hashing lives in `scripts/import-projects.ts`, not in the pure module, so "same bytes → same hash → same key" has no test. If the algorithm, slice length, or input domain shifts, nothing fails. Consider extracting `contentHashFor(buffer)` into `projectImport.ts` so it's unit-testable alongside `blobKeyFor`.
- **[src/lib/import/projectImport.test.ts — `syntheticBlobUrl` vs `blobKeyFor` shared prefix]** — No test asserts the two now-independent constructions share the same `projects/<slug>/<dirs>/` prefix. A desync would only surface when validation passes but uploads land in a different prefix.
- **[scripts/import-projects.ts — partial-failure mid-batch]** — No test exercises image 3-of-5 failing after 1 and 2 uploaded. Given the upload-before-write ordering and orphan accumulation, this is the most consequential untested path.
- **[scripts/import-projects.ts — `list` pagination]** — No test simulates `hasMore: true` to assert the importer walks all pages.

## Risk Assessment

**Medium.** The auth/rate-limit work is the headline change and lands clean for the documented path — Upstash-backed limiter, HMAC keying, fall-safe to a global bucket when `IP_HASH_SECRET` is missing — with 6 new tests covering the per-IP branch. Two latent issues warrant follow-up: the HMAC and `"global"` keyspaces share the `rl:login` prefix without explicit partitioning, and the leftmost-XFF read implicitly trusts Vercel topology. Neither blocks the change. The importer's move to content-addressed keys correctly fixes the CDN cache-busting problem flagged on 2026-06-09, but introduces two silent failure modes — old blobs are never garbage-collected (monotonic growth on the 1 GB free tier) and `list({ prefix })` reads only the first page — both of which will bite over time, not on the next deploy. The new Continuum legal pages ship correct content, but `terms/continuum` formalizes a DRY miss the author already documented in-source rather than generalizing `PrivacyPageLayout`; treat as design debt to schedule, not a regression. No contract changes that affect downstream code or stored data.

## Resolution — 2026-06-13

Addressed across three commits (cc25158 auth/rate-limit, 0d2fc91 importer, e0d4a42 legal pages). Full suite green (1160 tests).

**Auth / rate-limit (`route.ts` + tests):** hoisted the bucket key so the HMAC runs once and the limiter/invalid-credentials logs can't drift; partitioned the keyspace (`ip:<hash>` vs `global`); split log levels (429 → `info`, fail-open → `error`); the invalid-credentials payload now always carries the resolved key (`"global"` when no secret). Added the five missing tests: per-IP fail-open, 200-under-limiter (with `success` info / no warn), empty-string XFF, secret-routing (two secrets → two keys), and the 429-logs-at-info assertion. XFF trust assumption documented in-code.

**Importer (`projectImport.ts`, new `blobSync.ts` + tests, `import-projects.ts`):** extracted the I/O-free `contentHashFor` and a shared `keyPathFor` so the real and synthetic key constructions can't desync; widened the content hash to 64 bits and added a byte-size assert on reuse as a collision backstop; paginated the blob listing; uploads now run bounded-concurrent (4) with fail-fast; **prune-after-import** sweeps unreferenced blobs under the project prefix (old keys of edited images, legacy non-content-addressed keys, strays from failed writes), gated by `--no-prune`; `listExistingBlobs` now distinguishes credential/store misconfig (rethrow) from transient errors (warn + treat-as-empty); restored the byte-size column in reuse/upload logs; help text derives from `KNOWN_FLAGS`; stale header comment corrected. New tests cover pagination walk, size-mismatch reject, concurrency cap, mid-batch partial failure, prune selection/batching, and hash idempotency + shared-prefix.

**Legal pages:** generalized `PrivacyPageLayout` → `LegalPageLayout` with a `documentKind: "privacy" | "terms"` switch for the boilerplate wording; `terms/continuum` now reuses the shell instead of hand-rolling it. Added a shared `continuumLegalLinks` module and a `relatedLinks` "Related" section cross-linking the four-page Continuum cluster. Fixed the responsible-use ordered-list double-numbering (`aria-hidden` decorative markers + `role="list"`), standardized `AppleLegalLink` on the `target="_blank" rel="noopener noreferrer"` convention, and aligned all four `lastUpdated` dates to June 10.

**Deliberately not changed (with rationale):**
- *`buildPageMetadata` robots field* — skipped as premature abstraction. The DPIA and the other legal pages are intentionally indexable (trust signals); no current page needs `noindex`, so adding an unused param isn't warranted. Revisit if a draft-stage legal page ever needs to be hidden.
- *Extract rate-limit helpers to `src/lib/auth/rateLimit.ts`* — the review framed this as conditional ("If those helpers move into shared use"). They remain single-consumer in `route.ts`, so the module-load coupling to `vi.resetModules()` is contained and the extraction would be speculative. Revisit when a second caller appears.
- *Date alignment caveat* — aligning to June 10 post-dates the privacy policy (text unchanged since May 30) and DPIA (June 8). Per the request to make the four consistent; switch to per-page substantive-revision dates if the forward bump on unchanged text is a concern.
