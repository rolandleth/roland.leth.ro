# Code Review — 2026-05-18

## Issues and Observations

- **`prisma/schema.prisma` — Post.summary NOT NULL flip** — no migration/backfill committed; project uses `db:push`, so any existing row with `summary IS NULL` breaks the deploy. Either commit a backfill snippet or run it ahead of push.
- **`src/lib/api/schemas.ts` — `postCreateSchema.summary` cap 300 → 160** — tightened input contract; defensible for single-user admin but worth flagging.
- **`src/lib/api/schemas.ts` — duplicate `160` literal** — `SUMMARY_MAX_CHARS` is centralized in `src/lib/content/markdown.ts` but `schemas.ts` hardcodes `.max(160)`; import the constant to prevent drift.
- **`src/app/api/admin/posts/[id]/route.ts` — PUT summary resolution** — re-typing identical authored summary while body changes is indistinguishable from "untouched" and triggers re-derive, silently overwriting the intentional value. Defensible but warrants an inline comment.
- **`src/lib/content/markdown.ts` — `deriveSummary` boundary** — `lastSpace > 0` discards a space at index 0 (rare but reachable).
- **`src/lib/api/keepalive.ts` — misfiled bucket** — Upstash Redis client factory, not API-shape (no request/response/Zod/error helpers). Better fit in `db/` or a new `infra/` bucket.
- **`src/lib/db/boundedCache.ts` — generic LRU under `db/`** — fully generic `Map<string, T>` LRU with no Prisma coupling; belongs in `utils/`. Current placement is the kind of premature coupling the bucketing was meant to remove.
- **`src/lib/client/theme.ts` — server-side surface in `client/`** — declares `cookieToThemeClass` for server components ("the server can set the correct class"). Either rename intent or split client vs. server halves.
- **`src/test/user.ts` — module-level `setupUser()` shared across files** — `userEvent.setup()` returns a stateful instance; v14 docs recommend re-setup in `beforeEach`. Works today because `cleanup()` unmounts the DOM, but fragile if a test fails to release a key/pointer.
- **`src/test/setup.dom.ts` — global `framer-motion` `mode="sync"` mock** — behavior-altering override applied project-wide; masks any production bug that only manifests under `mode="wait"`.
- **`ExpandableSearch.test.tsx`, `AdminSearch.test.tsx`, `BlogSectionHeader.test.tsx`** — `mode="wait"` workaround comments are stale after the global override; revisit or tighten the call-count assertions they justified loosening.
- **`src/components/admin/ProjectForm.test.tsx` — inline mocks drop `required`** — `PlatformPicker` / `PresetOrFreeformInput` mocks deliberately omit the attribute; documented gap, but submit-blocking-on-missing-role is no longer asserted at this layer.

## Architecture & Coupling

- **`src/lib/db/db.ts` → `src/lib/auth/env.getDatabaseUrl`** — `db` depends on `auth` because env config was lumped under `auth/`. `env.ts` is plumbing, not auth; promote it to its own `config/` (or `utils/`) bucket so the dependency direction makes sense.
- **`PostDetail.summary` narrowed `string | null → string`** — fallbacks deleted in `src/app/api/feed/[section]/route.ts` and `src/app/blog/[section]/[slug]/page.tsx`. Safe only after every prod row is backfilled; order-of-deploy risk.

## Observability

- **`src/lib/content/markdown.ts` — `deriveSummary` is silent** — overrides a user-cleared field and re-derives on body change with no audit-log breadcrumb. Acceptable for single-user admin, but makes "why did my summary change after edit?" hard to reconstruct.

## Missing Tests

- **`src/lib/content/markdown.test.ts` — `deriveSummary` edges** — whitespace-only body, empty body (pin behavior), pure image/link-only bodies, exact-boundary length === 160, non-ASCII / multi-byte char near the cap.
- **`src/app/api/admin/posts/bulk/route.test.ts` — bulk derive 160-cap** — no test asserts derived summary respects the cap when bulk skips Zod on summary.
- **`src/app/api/admin/posts/route.test.ts`, `[id]/route.test.ts` — boundary at 160** — current tests pin 161-fail; missing 160-pass boundary.
- **`src/app/api/admin/posts/[id]/route.test.ts` — PUT no-op on unrelated change** — no test asserts `data.summary` is `undefined` when only `imageUrl` (or other non-body, non-summary field) changes.

## Risk Assessment

**Medium.** The Post.summary NOT NULL flip is the load-bearing risk: no backfill committed and the project deploys via `db:push`, so a single historical NULL row breaks the deploy. The lib reorganization is behavior-preserving (`tsc=0`, no orphaned imports, no circular deps), but introduces a semantically backwards `db → auth` dependency through the `env` placement and a few other bucket-labeling judgment calls worth follow-up. Test improvements are a net win — `setupUser({ delay: null })` and the userEvent migration are the right shape — but the global `framer-motion` `mode="sync"` mock and the shared `user` instance are flake-and-mask risks worth tightening before more tests pile on the patterns.
