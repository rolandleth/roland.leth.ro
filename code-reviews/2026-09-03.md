## Performance

## Resolution — same session

Everything above is closed except the two `[ ]` items, both deliberate: the admin affordance is a
feature needing a design call, and the enumeration cost is a documented trigger rather than a
defect.

Each new guard was mutation-tested against a deliberately broken implementation before being
called done:

- `dynamic` flipped to `"force-static"` → only the route-config test went red.
- A succeeding `verifySession()` call added to the page body → both not-called assertions went
  red **while the body-render test stayed green**, which is the specific weakness the finding
  named. The auth modules are mocked in the test despite the route not importing them, and
  `beforeEach` gives them a hostile default (a session that validates), so nothing incidental
  does the catching.
- The `console.info` line deleted → only the log test went red.

The log line is a tagged `console.info` matching the `[blog:p]` and `[ProjectPage]` convention,
not `auditLog` — that tag enum is typed to admin *writes* (`ADMIN_AUDIT_TAGS`), and widening it
for an anonymous public read would break the shape its docblock promises aggregators. A second
test pins that a live-post redirect logs nothing, so the signal doesn't drown in bot traffic.
