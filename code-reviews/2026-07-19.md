## Issues and Observations

- [ ] **[src/proxy.ts:119-129 — `gatedPath` / `isAdminPage`]** — The `toLowerCase()` was applied to the *exemption* arm too, so `gatedPath !== "/admin/login"` now exempts every case variant (`/admin/Login`, `/ADMIN/LOGIN`). Pre-change (`5417785^`, raw `pathname`) those matched `startsWith("/admin/")` and were **gated**; they are now ungated. The comment directly above asserts the change "can only ever ADD protection, never remove it" — that invariant is false for this arm. Not exploitable today (Next routing is case-sensitive, so these 404 and `/admin/login` is public anyway), but a comment that lies about a security boundary is the part that goes load-bearing later. Match the prefixes on `gatedPath`, keep the exemption on exact `pathname`.
- [ ] **[src/app/api/admin/revalidate/route.ts:114-116 — `applyGuidesRevalidation`]** — Discards `revalidateGuideSlugs`'s `Promise<string[]>` return (the slugs that matched a real row) and reports `applied: guides`, the raw pasted input. A typo'd slug issues a no-op bust and is reported as "revalidated" — the exact undiagnosable-stale-page failure the `skipped` shape exists to prevent. Not a one-liner: an unmatched slug may legitimately be a *topic* slug, so honest reporting needs a `guideTopic` lookup too.
- [ ] **[src/app/api/admin/revalidate/route.ts — `runResource` / `applyPostsRevalidation`]** — Error isolation stops at the resource boundary; each resource's loop is still all-or-nothing on its own report. A throw on entry 3 of 5 discards the two already-busted entries from `applied`, so the response carries `errors.posts` and no `applied.posts`. Same "report doesn't match what happened" defect this commit fixed, one level down. Harmless to retry (`revalidateTag` is idempotent) but the operator is told nothing landed when something did.
- [ ] **[src/components/admin/guideFormOptions.ts — `NONE`]** — The `"none"` string sentinel collides with a real project slug: `projectSlug === NONE ? null : …` (GuideForm.tsx:101, GuideTopicForm.tsx:74) silently writes `null` for a project slugged `none` (a project named "None" produces exactly that). Pre-existing, but this pass centralized it across two forms *and* added a doc comment asserting the sentinel is safe. A value outside the slug charset (`"__none__"`) removes the bug class.
- [ ] **[src/lib/db/guideMappers.ts — `compareGuides`]** — Tie-break uses `title.localeCompare` (ICU) while `guideOrder`'s `{ title: "asc" }` is Postgres `ORDER BY title` under the DB collation. These agree on plain ASCII but diverge on case/accents/punctuation, so the "MUST encode the same ordering" doc claim and the ASCII-only invariant test are both stronger than the code delivers. Low impact — the ungrouped set is the only in-memory-sorted collection, so the visible effect is the ungrouped section on `/guides` ordering by slightly different rules than the grouped sections beside it.
- [ ] **[src/lib/import/guideImport.ts:207-215 — `MAX_SORT_ORDER`]** — The new const and its doc were inserted *between* `parseSortOrder`'s JSDoc and its signature, orphaning the doc from the function it describes. Move the const above the JSDoc.

## Observability

- [ ] **[src/app/api/admin/revalidate/route.ts — `errors[key]`]** — Every failure of every resource yields the same opaque `"revalidation failed"`, rendered by the panel as "Please retry." The map's `string` value type promises per-resource detail it never delivers, so a transient DB timeout (retry helps) and a persistent connection failure (retry won't) are indistinguishable to the operator. Even `"lookup failed"` vs `"bust failed"` would tell them whether retrying is worth it.
- [ ] **[scripts/import-guides.ts — `changeLabel`]** — Renders `"topic"` only when `update.data` is empty (pure move). A guide both content-edited *and* moved logs only its changed fields, hiding the re-group — and a move changes which hub pages list it, so the dry run an operator reviews before applying gives no signal. Structurally best-effort (the plan can't cheaply recover prior topic), so at minimum note the pure-move-only limitation.
- [ ] **[src/lib/utils/errorMessage.ts — `errorMessage`]** — Surfaces `.message` and drops `Error.cause`. Nothing is lost today (no call site wraps with `cause`), but as *the* single shared extraction point, a future `new Error(msg, { cause })` would silently omit the root cause from every log.

Risk concentrates in one regression and one theme. The regression is the `proxy.ts` exemption widening — harmless today only because Next routing is case-sensitive, but it inverts the invariant its own comment asserts, and the comment is what the next reader will trust. None block ship; the revalidate reporting is the one to close before the next content-heavy import cycle, since post-import hub freshness is the exact use case the panel exists for.
