# Code Review — 2026-08-12

## Issues and Observations

- [x] **[src/proxy.ts — `config.matcher` comment]** — The new comment claims "every admin handler independently re-checks the session via `requireAdmin`", and uses that to demote the explicit `/admin` + `/admin/:path*` entries to "a backstop rather than the sole defense". `requireAdmin` covers the `/api/admin/*` route modules only. The two page-namespace entries the sentence is defending have no `requireAdmin` — they have `(protected)/layout.tsx`, whose own comment states it is *not* a complete backstop because nested `generateMetadata` runs outside it. The previous comment was accurate; the replacement understates the cost of trimming the matcher on exactly the paths where middleware is still the only gate. **Resolved 2026-08-12**: comment rewritten to split the claim per namespace, and the underlying gap closed so it's accurate.
- [x] **[src/app/admin/(protected)/{posts,projects,guides,guide-topics}/[id]/edit/page.tsx — `generateMetadata`]** — Confirms the above: each does a DB read (`loadPostForAdmin` and siblings) before any session check. Unauthenticated reach here depends solely on the middleware matcher. **Resolved 2026-08-12**: all four now route through `adminEditMetadata`, which runs `verifySession()` before the loader.
- [x] **[src/components/projects/ProjectContent.tsx — `isStoreUrl`]** — Hostname is hardcoded to `apps.apple.com`. Any other storefront (Google Play, Setapp, Gumroad, a direct download) silently gets no `Get on` prefix and no repeated CTA, with nothing surfaced to the author. Correct for today's data; the failure mode is invisible. **Resolved 2026-08-12**: behaviour unchanged (YAGNI), but hoisted to a `STORE_HOSTNAMES` set that names the extension seam; carried to watch-outs.
- [x] **[src/components/projects/ProjectContent.tsx — `ctaLabel` + identity row]** — The hero row (`mb-8 flex items-center justify-between gap-6`) has no wrap and no responsive stacking, and the links grid is `shrink-0`. `Get on ` widens every store pill by 7 characters while `projectLinkSchema` permits a 60-char label, so the extra width comes out of the `min-w-0` title column. Worth checking at 375px before this reaches a project with 3+ links. **Resolved 2026-08-12**: measured on the live site — already overflowing at 375pt with one link (`scrollWidth` 379 vs 375); row now stacks below `sm`.
- [x] **[src/components/projects/ProjectContent.tsx — `storeLink`]** — The repeated CTA ignores `isDiscontinued`. A discontinued project that still carries a store link now renders a prominent "Get on …" twice, asserting availability that the Discontinued badge contradicts. **Resolved 2026-08-12**: discontinued projects get a bare label and no repeated CTA.

## Architecture & Coupling

- **[src/components/projects/ProjectContent.tsx — `isStoreUrl`] vs [src/lib/content/projectJsonLd.ts — `buildSoftwareApplicationJsonLd`]** — Two independent notions of "this is a shipping app": the CTA keys off link hostname, the JSON-LD keys off `APP_BUCKETS.has(project.bucket)`. `bucket` and `links` are authored separately, so a project can emit `SoftwareApplication` markup with no CTA, or show the CTA with no app markup. No duplication to collapse yet — worth keeping the two definitions aligned if a third consumer appears.

## Missing Tests

- [x] **[src/components/projects/ProjectContent.tsx — `isStoreUrl` catch branch]** — The malformed-URL → non-store path is documented in the helper's doc comment but untested. `projectLinkSchema` validates `url` on write, so the branch only protects legacy or hand-edited rows; that is exactly the case no test pins. **Resolved 2026-08-12**: covered.
- [x] **[src/components/projects/ProjectContent.test.tsx — "repeats the store CTA below the content"]** — Placement is asserted only against the Guides heading. With `guides.length === 0` the CTA should land above the FAQ, and nothing covers that ordering. **Resolved 2026-08-12**: covered.
- [x] **[src/components/projects/ProjectContent.tsx — `storeLink`]** — `links.find` picks the lowest-`sortOrder` storefront when a project has several (an iOS and a Mac listing are both `apps.apple.com`). The choice is deterministic and author-controlled, but neither documented nor tested. **Resolved 2026-08-12**: verified `links` are queried `sortOrder`-ascending, documented on `storeLink`, and pinned by a test.

## Risk Assessment

**Low.** One presentation-layer change to `ProjectContent` — a shared pill class, a `Get on` prefix keyed off URL rather than label, and a repeated store CTA above the guides — plus a comment-only edit in `src/proxy.ts`. No schema, contract, or data-flow changes; 20 tests in `ProjectContent.test.tsx` pass, and the three new cases cover the main branches. Keying the prefix off hostname instead of label is the right call and the doc comment says why. The only item touching load-bearing plumbing is the `proxy.ts` comment: it makes a security invariant sound broader than it is, on the file whose matcher was the subject of the 2026-07-26 incident. Nothing is exploitable today — the change is textual — but the comment is the reasoning a future edit would lean on.
