# Code Review — 2026-10-18

## Issues and Observations

- [ ] **`src/components/projects/gallery/AppTile.tsx` — tile doc comment** — says a non-live app's status takes the place of its store links, but `gallerySectionOf` (`src/lib/utils/projectsGallery.ts`) sends every discontinued project to "more", and only the `high` section renders `AppTile`. A discontinued tile can't happen. The comment describes a case that doesn't exist; narrow it to coming-soon, or say why discontinued is unreachable.
- [ ] **`src/components/projects/product/ProductPage.tsx` — `storeButton` comment** — "An app that isn't live has no store link" is wrong. The link exists, and `linkCtasFor` (`src/lib/utils/platforms.ts`) turns it into a `plainPill` that the store-link filters drop. The next reader may "fix" the wrong layer.
- [ ] **`ProductHero.tsx`, `ProductClosing.tsx`, `ProductPage.tsx`, `AppTile.tsx` — status CTA markup** — the same `label != null && <p className="product-status-cta">` line is repeated four times, and the "store links or label" row condition is written once in Hero and again in Closing. `ProductPage` computes `label` and also passes `status` down, so Hero and Closing call `statusLabel` again. A small shared `StatusCta` (or passing `label` down) would remove three copies. Low effort; the cost of leaving it is drift when the styling or semantics change.
- [ ] **Status label meaning differs across components** — Hero, Closing, the pricing slot and `AppTile` show any non-null `statusLabel`. `MoreProjects.tsx` and `CompactProjectCard.tsx` show it only for `comingSoon` and fade the icon for discontinued instead. This predates the commit, but the commit widened the generic path. Worth one line in `projectStatus.ts` docs saying which surfaces use which rule.
- [ ] **`src/components/privacy/weeklyGymLegalLinks.ts`, `continuumLegalLinks.ts` — per-app wrappers** — `relatedLegalLinks` factored out the filter, but each app still has a two-line wrapper of the same shape. Exporting only the link arrays and calling `relatedLegalLinks(links, path)` at the call sites would make app three free. Optional; the current shape is consistent.
- [ ] **`src/app/privacy/digest/page.tsx` — new "Purchases" section, no `/terms/digest`** — Digest's privacy page now names Pro as monthly, yearly or one-time. Continuum (paid) and Weekly Gym (not paid yet) both have terms pages; Digest has none. Decide whether Digest needs terms before its listing ships.
- [ ] **`src/app/terms/weekly-gym/page.tsx` — subscription bullets for purchases that don't exist** — the privacy page hedges ("If Weekly Gym offers purchases"), but the terms carry detailed renewal and free-trial bullets. Consistent with "may require … in the future"; confirm that's the intended commitment.
