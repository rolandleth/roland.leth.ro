# Code Review — 2026-04-22

## Issues and Observations

- **`src/lib/markdown.ts` — `extractText`**: `node.alt ?? ""` on `image`/`imageReference` is unreachable — both mdast types declare `alt: string` (required). The fallback is harmless but worth knowing it's dead code; a bare `return node.alt` would be more honest about the invariant.

## Missing Tests

- **`src/lib/markdown.test.ts` — `imageReference` with empty alt**: `![][ref]` produces `alt: ""` — the empty path is covered for inline image (`![](/img.png)`) but not explicitly for the reference variant. Low risk given the implementations are the same branch, but worth noting for completeness.

## Risk Assessment

**Low.** Two small hardening commits: CDATA terminator escape in the feed route, and typed mdast walk in `stripMarkdown`. Both are targeted fixes for known-but-latent bugs found in yesterday's review. Every changed behaviour has a corresponding test — CDATA split, image alt extraction (inline and reference), empty-alt, and the raw-HTML-drop lock-in for `markdownToHtml`. No new dependencies, no schema changes, no data-path widenings. The `Nodes` type swap is strictly better than the local shim it replaced.

## Notes

- Both commits close all four findings from `code-reviews/2026-04-21.md` (Review 2 block). The feed cache payload size watch-out from 2026-04-21 remains open — no action taken today, monitoring only.
- The raw-HTML-drop test is intentionally inverted from the original assumption: `remark-rehype` drops raw HTML by default. If `allowDangerousHtml: true` is ever added, the test will break and force a deliberate sanitization decision.
