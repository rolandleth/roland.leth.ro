# Code Review — 2026-05-07 — Full codebase

## Issues and Observations

- [x] **`src/lib/format.ts` — `parseIntId`** — `Number.parseInt("12abc", 10)` returns `12`, so `/admin/posts/12abc/edit` resolves to id=12 instead of 400. Tighten with `^-?\d+$` test (or `Number(raw)` + `Number.isInteger`). Same hole at the route boundary via `parseIdParam`. **Resolved 2026-05-07**: strict `^-?\d+$` regex applied; tests pin trailing/leading garbage rejection.
- [x] **`src/lib/format.ts` — `parsePageParam`** — no upper bound; `?page=999999999` flows through to `skip = (page-1)*PAGE_SIZE` against Postgres. Cap to a sane max (e.g., `Math.min(n, 10_000)`); the existing watch-out flagged "no clamp on invalid page" but a giant valid integer is the bigger DoS lever. **Resolved 2026-05-07**: clamp at `MAX_PAGE = 10_000`; test added.
- **`src/lib/format.ts` — `formatDate`** — uses `new Date(y, m-1, d).toLocaleDateString` in local time; server renders yield the Vercel-region-localized day, which can drift one day from the author's intent at TZ boundaries. Pin to UTC or document the drift.
- [x] **`src/lib/format.ts` — `createSlug`** — does not normalize Unicode (accents survive lowercased), nor strip leading/trailing hyphens, nor collapse repeated hyphens; en-dash/em-dash also pass through. Migrate to `slugify` or normalize via `.normalize("NFKD").replace(/[̀-ͯ]/g, "")` plus `.replace(/-+/g, "-").replace(/^-|-$/g, "")`. **Resolved 2026-05-07**: NFKD normalization + dash-variant fold + collapse/trim; tests cover accents, em-dash, repeated/leading/trailing hyphens.
- [x] **`src/lib/auth.ts` — `verifyCredentials`** — strict `email === credentials.email` is case-sensitive; "Admin@example.com" vs stored lowercase silently fails. Normalize `.toLowerCase().trim()` at the auth boundary (or in `loginSchema`). **Resolved 2026-05-07**: normalized in `loginSchema` transform; tests pin lib-level case-sensitivity AND route-level normalization.
- [x] **`src/lib/schemas.ts` — `loginSchema.email`** — `z.string().email()` accepts mixed-case/whitespace as-is. Add `.toLowerCase().trim()` to pair with the auth fix above. **Resolved 2026-05-07**: `.transform(v => v.trim().toLowerCase())` added.
- [x] **`src/lib/posts.ts` — `searchPosts` ILIKE on `body`** — substring scan over full `body` text with no minimum term-length gate; `?q=a` triggers a sequential scan with millions of substring checks. Enforce `term.length >= 2` (or 3) at the schema; consider `pg_trgm` later. **Resolved 2026-05-07**: `MIN_SEARCH_TERM_LENGTH = 2` enforced in `searchPosts`. `pg_trgm` deferred until row count grows.
- **`src/lib/legacySlug.ts` — `cachedLookup` invalidation surface** — `unstable_cache` revalidates on `["posts", "projects"]` tags, but the project routes only fire `projects` (no `revalidatePostSection` equivalent). Cross-domain slug collisions can stay stale up to 300s. Audit that every post + project mutation fires both tags consistently.
- [x] **`src/lib/env.ts` — `ADMIN_HASH_PASSWORD` regex** — `^[0-9a-f]*$` accepts empty string and odd-length hex; `Buffer.from(odd, "hex")` silently truncates the last nibble. Tighten to `^([0-9a-f]{2})+$` (or document why odd-length is allowed). **Resolved 2026-05-07**: regex tightened to `^([0-9a-f]{2})*$` (even-length, empty still allowed for the nonEmpty path).
- [x] **`src/lib/loanCalculator.ts` — input validation** — accepts negative `annualInterestRate` (yields negative `totalInterest` and a flipped `percentageOfOverpay` sign); also `period <= 0` skips the loop but PMT may NaN via division. Validate `>= 0` for interest and `>= 1` for period at the entry. **Resolved 2026-05-07**: throw on negative `annualInterestRate` and `period < 1`; tests added.
- [x] **`src/lib/loanCalculator.ts` — `formatNumber`** — `toLocaleString(undefined, …)` differs across SSR/hydration locales → React hydration warning risk. Pin to `"en-US"`. **Resolved 2026-05-07**: pinned to `"en-US"`; tests now use exact-string assertions.
- [x] **`src/lib/platforms.ts` — `platformBucket` substring match** — `lower.includes("web")` will match `"Webhook tool"`. Tighten to whole-word matching (e.g., word-boundary regex or token split). **Resolved 2026-05-07**: word-boundary regex per keyword (`\b<keyword>\b`); multi-word keywords still match within longer phrases.
- **`src/lib/reorder.ts` — `moveAndReorder`** — JSDoc promises "every sortOrder reassigned by position so the list stays contiguous starting at 0", but OOB early-returns skip that reassignment. Either always reassign or correct the doc; tests don't pin the actual contract.

## Concurrency & Thread Safety

- [x] **`src/components/admin/IsFeaturedToggle.tsx` + `ProjectSortOrderInput.tsx`** — both write to `/api/admin/projects/:id`; rapid toggle + nudge in succession produces last-write-wins on the server. Either serialize via a per-project mutation queue, or have the API merge partial updates. **Resolved 2026-05-07**: `AbortController` on both components covers the rapid-fire and unmount races; the API already merges partial updates via Prisma `undefined`-as-skip semantics, so cross-toggle racing remains semantically safe (different fields).
- [x] **`src/components/admin/ProjectSortOrderInput.tsx` — `handleBlur`** — a blur fired by tab/focus change to another sort-order input still triggers a save; tabbing through inputs fires parallel PUTs. Debounce or gate on value change. **Resolved 2026-05-07**: pre-existing change-gate (`if (nextSortOrder === initialSortOrder) return`) verified; AbortController added to drop responses from superseded blurs.
- [x] **`src/components/admin/useAdminResource.ts` — `save`/`remove`** — no `AbortController`; navigating away mid-PUT lives the request on. `isMountedRef` prevents the warning but not the wasted call. **Resolved 2026-05-07**: AbortController per call, aborted on unmount via cleanup; `AbortError` swallowed silently.
- [x] **`src/components/admin/IsFeaturedToggle.tsx` — `handleChange`** — fetch is not aborted on unmount; same pattern as the `ImageUpload` race-fix would help. **Resolved 2026-05-07**: AbortController + cleanup; `AbortError` swallowed silently.
- **`src/app/api/admin/projects/route.ts` — POST insert under Serializable** — correct against concurrent inserts (one txn aborts), but no retry. Single-admin OK; if a future admin-CSV-import lands, the first conflict surfaces as 500. Document the no-retry contract or add a single retry for `P2034` / serialization_failure.
- **`src/lib/boundedCache.ts` — `Map` ops not atomic** — two concurrent calls for the same missing key both call `create()` and the second `set` overwrites the first; the `if (map.size > max)` eviction can run twice on the same key on race. Practical impact at single-process Node is none; flag if ever moved to a shared environment.
- **`src/lib/markdown.ts` — module-scope unified processors** — sharing `unified()` pipelines across concurrent requests is safe today, but `markdownProcessor.use(...)` mid-render would mutate the singleton. Add a comment marking the constraint.

## Performance

- **`src/lib/posts.ts` — `searchPosts`** — full-table ILIKE on `body`; dominant N×len(body) hot path. Add `pg_trgm` (or tsvector) once post count exceeds ~100; pair with the term-length gate above.
- **`src/app/projects/[slug]/page.tsx` — `markdownToReact` per request** — runs sequentially-resolved-in-parallel for every section per project view, no caching. Wrap in `cache()` keyed on `(slug, sectionId, updatedAt)` or precompute on write.
- [x] **`src/app/projects/page.tsx` — `getAllProjectsForGallery`** — every projects-index render hits the DB; not in `unstable_cache`. Tag-cache with `projects` tag, busted on project mutation (same pattern as `getAllPublishedPostSlugs`). **Resolved 2026-05-07**: finding withdrawn — verified that `getAllProjectsForGallery` is already wrapped in `unstable_cache` for the default `sortDiscontinued: true` path (`projectsGalleryCache`, tagged `projects`). The original review missed the existing wrapper.
- **`src/components/admin/PostForm.tsx` + `ProjectForm.tsx` — child re-renders** — `MarkdownEditor`, `ImageUpload`, `LinkManager`, `SectionManager` aren't `React.memo`-wrapped; every keystroke on Title re-renders all of them. The `setField` callback is stable, so memoizing the children would skip the work — `ProjectForm` even calls this out as future work.
- **`src/components/Typewriter.tsx` — re-render cascade** — single effect re-runs on every `displayedText` change → setTimeout teardown + re-arm per character. Use a single `requestAnimationFrame` loop or store the timer in a ref to avoid the cleanup churn.
- [x] **`src/components/home/LandingBackground.tsx` — animated blobs** — three permanently-animating `blur-[100/120px]` divs with `willChange: transform` on every visit to `/`; no `prefers-reduced-motion` gate. On mobile/low-power devices this keeps the GPU busy. **Resolved 2026-05-07**: CSS `@media (prefers-reduced-motion: reduce)` rule on `[data-blob-bg]` overrides `animation: none`; component stays server-rendered.
- **`src/components/loan-calculator/LoanCalculatorClient.tsx` — `computeLoan`** — runs synchronously inside `useMemo` for every keystroke; for a 360-month loan with extra payments it's cheap but typing on lower-end devices benefits from `useDeferredValue` or debouncing.
- **`src/app/api/admin/projects/[id]/route.ts` — PUT sections/links replace** — per-edit DELETE+INSERT for all sections/images on every PUT, even for a 1-character description tweak. Negligible at current scale; flag if a project ever exceeds ~50 sections/images.
- **`src/lib/posts.ts` — `findMany` + `count` parallel** — fine; for very-low-row-count tables, a `findMany({ take: PAGE_SIZE+1 })` + "has more" boolean is cheaper than `count` (which scans). Revisit if pagination becomes hot.

## Risk Assessment

**Medium.** The codebase improved materially since the 2026-04-24 sweep — env validation centralized, bcrypt timing defense, Serializable transactions on project sortOrder, bounded caches, hex regex, AST-based markdown stripping. The current sweep surfaces three medium-severity themes: (1) **input validation** — `parseIntId` accepts trailing garbage, `parsePageParam` has no upper bound, `createSlug` doesn't normalize Unicode, `loanCalculator` accepts negatives; small individually but they cluster around uncovered failure paths. (2) **observability gaps that grow with traffic** — `verifyToken` logs expired tokens at error level (will dominate after secret rotation), `lookupLegacySlug` DB outages collapse into 404s with no structured signal, internal errors return no correlation id. (3) **silent test gaps** — `vitest.config.ts` does not include `src/app/**/*.test.tsx`, so two existing edit-page tests have never run and one of them would fail today. Pair that with no tests for the rate-limit branch, no tests for cross-section post moves, and no proxy tests for the actual `/api/admin/*` 401 contract, and the most security-sensitive surfaces are largely unverified. Architecture-level concerns are smaller — admin auth split across three layers is the only one worth a dedicated fix. Nothing landed that touches load-bearing plumbing in a destructive way.
