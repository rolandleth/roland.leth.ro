# Code Review — 2026-05-07 — Full codebase

## Issues and Observations

- **`src/lib/format.ts` — `parseIntId`** — `Number.parseInt("12abc", 10)` returns `12`, so `/admin/posts/12abc/edit` resolves to id=12 instead of 400. Tighten with `^-?\d+$` test (or `Number(raw)` + `Number.isInteger`). Same hole at the route boundary via `parseIdParam`.
- **`src/lib/format.ts` — `parsePageParam`** — no upper bound; `?page=999999999` flows through to `skip = (page-1)*PAGE_SIZE` against Postgres. Cap to a sane max (e.g., `Math.min(n, 10_000)`); the existing watch-out flagged "no clamp on invalid page" but a giant valid integer is the bigger DoS lever.
- **`src/lib/format.ts` — `formatDate`** — uses `new Date(y, m-1, d).toLocaleDateString` in local time; server renders yield the Vercel-region-localized day, which can drift one day from the author's intent at TZ boundaries. Pin to UTC or document the drift.
- **`src/lib/format.ts` — `createSlug`** — does not normalize Unicode (accents survive lowercased), nor strip leading/trailing hyphens, nor collapse repeated hyphens; en-dash/em-dash also pass through. Migrate to `slugify` or normalize via `.normalize("NFKD").replace(/[̀-ͯ]/g, "")` plus `.replace(/-+/g, "-").replace(/^-|-$/g, "")`.
- **`src/lib/auth.ts` — `verifyCredentials`** — strict `email === credentials.email` is case-sensitive; "Admin@example.com" vs stored lowercase silently fails. Normalize `.toLowerCase().trim()` at the auth boundary (or in `loginSchema`).
- **`src/lib/schemas.ts` — `loginSchema.email`** — `z.string().email()` accepts mixed-case/whitespace as-is. Add `.toLowerCase().trim()` to pair with the auth fix above.
- **`src/lib/posts.ts` — `searchPosts` ILIKE on `body`** — substring scan over full `body` text with no minimum term-length gate; `?q=a` triggers a sequential scan with millions of substring checks. Enforce `term.length >= 2` (or 3) at the schema; consider `pg_trgm` later.
- **`src/lib/legacySlug.ts` — `cachedLookup` invalidation surface** — `unstable_cache` revalidates on `["posts", "projects"]` tags, but the project routes only fire `projects` (no `revalidatePostSection` equivalent). Cross-domain slug collisions can stay stale up to 300s. Audit that every post + project mutation fires both tags consistently.
- **`src/lib/env.ts` — `ADMIN_HASH_PASSWORD` regex** — `^[0-9a-f]*$` accepts empty string and odd-length hex; `Buffer.from(odd, "hex")` silently truncates the last nibble. Tighten to `^([0-9a-f]{2})+$` (or document why odd-length is allowed).
- **`src/lib/loanCalculator.ts` — input validation** — accepts negative `annualInterestRate` (yields negative `totalInterest` and a flipped `percentageOfOverpay` sign); also `period <= 0` skips the loop but PMT may NaN via division. Validate `>= 0` for interest and `>= 1` for period at the entry.
- **`src/lib/loanCalculator.ts` — `formatNumber`** — `toLocaleString(undefined, …)` differs across SSR/hydration locales → React hydration warning risk. Pin to `"en-US"`.
- **`src/lib/platforms.ts` — `platformBucket` substring match** — `lower.includes("web")` will match `"Webhook tool"`. Tighten to whole-word matching (e.g., word-boundary regex or token split).
- **`src/lib/reorder.ts` — `moveAndReorder`** — JSDoc promises "every sortOrder reassigned by position so the list stays contiguous starting at 0", but OOB early-returns skip that reassignment. Either always reassign or correct the doc; tests don't pin the actual contract.
- **`src/lib/request.ts` — `siteBase`** — throws on missing `host` header. Called from `layout.tsx` `generateMetadata` and `sitemap.ts` per request. A misconfigured reverse proxy 500s the site. Fall back to `process.env.VERCEL_URL` or a configured base before throwing.
- **`src/lib/analytics.ts` — `filterAdminEvents`** — `event.url.includes("/admin")` will also drop a hypothetical `/blog/tech/admin-tools`. Anchor with `pathname.startsWith("/admin")` (parse from `event.url`).
- **`src/app/api/admin/posts/[id]/route.ts` — PUT cross-section move** — only invalidates the new section: `revalidatePostSection(post.section)`. A `tech` → `life` move leaves stale entries in `feed-tech` / `blog-tech` / archive. Read previous `section` inside the txn and bust both when they differ.
- **`src/app/api/admin/posts|projects/route.ts` POST + `[id]/route.ts` PUT** — six handlers do `await request.json()` without try/catch; a malformed body returns 500 instead of 400. `auth/login` already has the pattern; extract a `parseJsonBody<T>(req, schema)` helper and reuse.
- **`src/lib/schemas.ts` — `postCreateSchema.datetime`** — only `z.string().min(1)`; format `yyyy-MM-dd-HHmm` is enforced implicitly via `postDatetimeToISO`, which throws synchronously inside feed/sitemap render. A bad value surfaces as a 500 at read time, not at write time. Tighten with the regex literal already in `format.ts`.
- **`src/app/api/admin/projects/route.ts` — POST sortOrder gap** — schema accepts any `sortOrder >= 0` including values past `count()`. The `updateMany({ sortOrder: { gte } })` matches nothing and the new project lands at `sortOrder = N`, leaving gaps `[count..N-1]`. Clamp to `[0, count]` before the shift.
- **`src/app/api/upload/route.ts` — POST gating** — `process.env.NODE_ENV !== "production"` collapses dev/test/preview into one bucket; the 403 "only allowed in production" message misleads in CI/preview deploys. Switch to a dedicated `ALLOW_UPLOADS` flag or check Vercel env explicitly.
- **`src/app/api/upload/route.ts` — POST size check** — `file.size` runs after `request.formData()` has already buffered the entire body; the early-413 intent is moot. Add a `Content-Length` precheck for cheap rejection.
- **`src/app/api/auth/login/route.ts` — POST rate-limit key** — hardcoded `"global"`; a botnet of 5 stale requests/15min DOS-locks the legitimate admin. Add an IP-derived bucket as a secondary key alongside the global one (or extend window/burst).
- **`src/app/api/auth/login/route.ts` — module-scope `ratelimit`** — constructed at module load; if Upstash is briefly unreachable, the first `ratelimit.limit("global")` throws and bubbles as 500. Wrap in try/catch and fail-open with a logged warning.
- **`src/app/admin/(protected)/posts|projects/[id]/edit/page.tsx` — `parseIntId`** — same trailing-garbage hole as in `format.ts`; `/admin/posts/12abc/edit` resolves to id=12 instead of `notFound()`. Fixed by tightening `parseIntId`.
- **`src/app/sitemap.ts` — `sitemap`** — uses `getAllPublishedPostSlugs` which filters only `published: true`, not `datetime <= now`. Future-dated published drafts get listed (still in watch-outs).
- **`src/app/admin/login/page.tsx` — `LoginForm.handleSubmit`** — `router.push("/admin")` after success without `router.refresh()`; relies on RSC cookie pickup. Cheap insurance: add `router.refresh()` after `push`.
- **`src/components/admin/AdminNav.tsx` — `handleLogout`** — still pushes the user to `/admin/login` even when the POST returns non-ok; console-only logging hides server rejection. Either surface a toast/error or block the redirect on hard server errors.
- **`src/components/admin/PlatformPicker.tsx` — derived state in useState init** — `useState(validParsedKeywords)` only seeds from the first prop value; if `value` changes externally (parent prefill) the picker won't re-sync. Derive entirely from `value` (like `PresetOrFreeformInput`).
- **`src/components/admin/PlatformPicker.tsx` — hidden mirror `<input required readOnly>`** — enforces required via a hidden field, but a user clearing all keywords sees no visible required indicator. Move `required` onto the visible inputs (mode-dependent), as `PresetOrFreeformInput` does.
- **`src/components/projects/ProjectContent.tsx` — `<style>` injection** — per-page `:root { --color-header-accent: ${accentColor}; }` enters the global cascade and persists in DOM order; fast SPA navigation can briefly compose conflicting `:root` rules. Set the variable as inline `style` on a wrapper `<div>` to scope it.
- **`src/components/loan-calculator/LoanCalculatorInput.tsx` — accessibility** — `<span>` is used as the label rather than `<label htmlFor>`. Screen readers won't associate the label with its input.
- **`src/components/loan-calculator/LoanCalculatorSummary.tsx` — colors** — `text-[coral]` and `text-[lightseagreen]` are arbitrary CSS color names hard-coded in a Tailwind v4 project. Move to design tokens (`--color-positive` / `--color-negative`).
- **`src/components/Header.tsx` — pathname active match** — `pathname.startsWith(href + "/")` would mark `/blog/tech` active for `/blog/technology`. Tighten to a regex with segment boundary.

## Architecture & Coupling

- **Admin auth split across three layers** — `src/proxy.ts` (middleware), `src/app/admin/(protected)/layout.tsx`, and per-route handlers. The layout's own comment admits it's not a complete backstop because `generateMetadata` runs outside it. Single source of truth: extract `assertAdminRequest()` used by middleware and every admin `generateMetadata`.
- **`src/proxy.ts` — `isAdminApi` boundary** — `/api/admin` (no trailing slash) bypasses auth (`startsWith("/api/admin/")`); confirmed by a "boundary" test pinning this as intentional. Any future controller mounted at the bare `/api/admin` would land unauthenticated. Add `pathname === "/api/admin"` to the guard, or move the gate into a route-group layout.
- **`src/lib/posts.ts` vs `src/lib/projects.ts` — duplicated cache wrapper template** — both build `createBoundedWrapperCache` + `unstable_cache` factory + `React.cache(...)` dedupe with near-identical structure. Extract `bySlugLoader<T>(buildFetch, tagFn, sectionTags)`.
- **`src/lib/projects.ts` — no `revalidateProjects` helper** — `revalidatePostSection` exists in `posts.ts`, but the three project route handlers duplicate `revalidateTag("projects", "max")` + `revalidateTag(\`project-${slug}\`, "max")` literally. One drift and tags desync.
- **`src/lib/format.ts` — mixed concerns** — holds id/page parsing, datetime formatting, slug, reading time, and body truncation. Highest concept-density file in `lib/`. Split into `format/datetime.ts`, `format/slug.ts`, `format/text.ts`.
- **`src/lib/posts.ts` — `loadPost` vs `loadPostForAdmin` naming** — `loadPost` indirects through cached/tagged `getPostBySlug`; `loadPostForAdmin` hits Prisma directly (uncached). Names suggest parallel structure but caching differs. Rename or JSDoc the asymmetry.
- **`src/app/admin/(protected)/page.tsx` — page assembly** — 300-line file mixes `parseTab`, `pageUrl` builders, `PostsSection`/`ProjectsSection`, tab bar, and pagination chrome. Split: `lib/adminQuery.ts` for parsing, `components/admin/PostsTab.tsx` and `ProjectsTab.tsx` for sections; extract `<AdminPagination>` (pattern also in `components/blog/Pagination.tsx`).
- **`src/app/blog/[section]/page.tsx` vs archive vs search — `isValidSection` guard** — same 4-line "if invalid section call notFound()" + matching `generateMetadata` short-circuit appears in three blog pages. Wrap with an `assertValidSection(section)` helper.
- **`src/components/AnimatedCard.tsx` vs `src/components/about/FadeIn.tsx`** — two near-identical thin wrappers around `motion[as] {...fadeUp(delay)}`; `FadeIn` already supports `as`, so `AnimatedCard = FadeIn` with computed delay. Collapse.
- **`src/components/blog/BlogSectionHeader.tsx` outside-click** — reimplements the same pattern that `ui/useClickOutside` already encapsulates and that `ExpandableSearch` consumes. Reuse the hook.
- **`src/components/Header.tsx` — pathname-based hide** — header decides to render based on path matching (`/admin`, `/`); per-route `layout.tsx` opt-out would remove the client-component requirement entirely.
- **`src/components/home/HomeHero.tsx` — `"use client"` scope** — only `motion.div` and `Typewriter` need it; the static `<Link>` list at the bottom does not. Splitting into a server shell + a small `<Typewriter>` client island shrinks the JS sent for `/`.
- **`src/app/AnalyticsWithFilter.tsx` + `SpeedInsightsWithFilter.tsx`** — two 8-line `"use client"` wrappers around different Vercel components with the same `beforeSend={filterAdminEvents}`. Could be one file `<ClientAnalytics />` exporting both.

## Concurrency & Thread Safety

- **`src/components/admin/IsFeaturedToggle.tsx` + `ProjectSortOrderInput.tsx`** — both write to `/api/admin/projects/:id`; rapid toggle + nudge in succession produces last-write-wins on the server. Either serialize via a per-project mutation queue, or have the API merge partial updates.
- **`src/components/admin/ProjectSortOrderInput.tsx` — `handleBlur`** — a blur fired by tab/focus change to another sort-order input still triggers a save; tabbing through inputs fires parallel PUTs. Debounce or gate on value change.
- **`src/components/admin/useAdminResource.ts` — `save`/`remove`** — no `AbortController`; navigating away mid-PUT lives the request on. `isMountedRef` prevents the warning but not the wasted call.
- **`src/components/admin/IsFeaturedToggle.tsx` — `handleChange`** — fetch is not aborted on unmount; same pattern as the `ImageUpload` race-fix would help.
- **`src/app/api/admin/projects/route.ts` — POST insert under Serializable** — correct against concurrent inserts (one txn aborts), but no retry. Single-admin OK; if a future admin-CSV-import lands, the first conflict surfaces as 500. Document the no-retry contract or add a single retry for `P2034` / serialization_failure.
- **`src/lib/boundedCache.ts` — `Map` ops not atomic** — two concurrent calls for the same missing key both call `create()` and the second `set` overwrites the first; the `if (map.size > max)` eviction can run twice on the same key on race. Practical impact at single-process Node is none; flag if ever moved to a shared environment.
- **`src/lib/markdown.ts` — module-scope unified processors** — sharing `unified()` pipelines across concurrent requests is safe today, but `markdownProcessor.use(...)` mid-render would mutate the singleton. Add a comment marking the constraint.

## Observability

- **`src/lib/auth.ts` — `verifyToken`** — logs every failure (`ERR_JWT_EXPIRED` etc.) at error level; routine session expiry will dominate the log noise. Demote `ERR_JWT_EXPIRED` to debug/info; keep signature-verification failures at error.
- **`src/proxy.ts` — auth failures** — `verifyToken` returns `null` for both "expired token" and "wrong signature"; the proxy redirects both to login with no UX hint. Surface "session expired" on the login page when the cause is expiry.
- **`src/app/[slug]/page.tsx` — `lookupLegacySlug` failure** — DB miss vs DB outage collapse into one `notFound()`; `console.error` is the only signal. A sustained DB outage is invisible except as a 404 spike. Tag the log with a stable code (e.g., `[legacy-slug:db-failure]`) and include the slug.
- **`src/app/api/admin/posts/[id]/route.ts` — `handlePrismaError`** — a 404 from a missing record returns "Not found" with no log line; for deletes/updates this masks "stale UI tried to delete record N" vs "DB lost the record". Add `console.warn` with route tag + id when `isPrismaNotFound` fires.
- **`src/app/api/auth/login/route.ts` — schema validation log** — `console.error("[api:auth:login] schema validation failed")` doesn't include `parsed.error.issues`. Log issue paths (not values) or downgrade to `warn`.
- **`src/lib/apiErrors.ts` — `respondInternalError`** — flat `{ error: "Internal server error" }` with no request-id. On Vercel the platform request id correlates, but a self-hosted run has nothing to grep on. Return an opaque error id (`crypto.randomUUID()`) and log it alongside the stack.
- **`src/components/admin/AdminNav.tsx` — `handleLogout`** — logs to console but never surfaces to the user; failed logout silently redirects to `/admin/login` while the session may still be alive.
- **`src/components/admin/useAdminResource.ts` — `readErrorMessage`** — catches malformed JSON and returns the literal `"Request failed"` regardless of HTTP status; the status code itself isn't logged or surfaced. Include status in the surfaced message.
- **Multiple admin error renders** — `IsFeaturedToggle`, `ProjectSortOrderInput`, `ImageUpload`, `LoginForm`, `PostForm`, `ProjectForm`, `MarkdownEditor` mostly carry `role="alert"` but inconsistent `aria-live` qualifiers; VoiceOver may announce inconsistently. Standardize via a shared `<ErrorMessage>` component.

## Performance

- **`src/lib/posts.ts` — `searchPosts`** — full-table ILIKE on `body`; dominant N×len(body) hot path. Add `pg_trgm` (or tsvector) once post count exceeds ~100; pair with the term-length gate above.
- **`src/app/projects/[slug]/page.tsx` — `markdownToReact` per request** — runs sequentially-resolved-in-parallel for every section per project view, no caching. Wrap in `cache()` keyed on `(slug, sectionId, updatedAt)` or precompute on write.
- **`src/app/projects/page.tsx` — `getAllProjectsForGallery`** — every projects-index render hits the DB; not in `unstable_cache`. Tag-cache with `projects` tag, busted on project mutation (same pattern as `getAllPublishedPostSlugs`).
- **`src/components/admin/PostForm.tsx` + `ProjectForm.tsx` — child re-renders** — `MarkdownEditor`, `ImageUpload`, `LinkManager`, `SectionManager` aren't `React.memo`-wrapped; every keystroke on Title re-renders all of them. The `setField` callback is stable, so memoizing the children would skip the work — `ProjectForm` even calls this out as future work.
- **`src/components/Typewriter.tsx` — re-render cascade** — single effect re-runs on every `displayedText` change → setTimeout teardown + re-arm per character. Use a single `requestAnimationFrame` loop or store the timer in a ref to avoid the cleanup churn.
- **`src/components/home/LandingBackground.tsx` — animated blobs** — three permanently-animating `blur-[100/120px]` divs with `willChange: transform` on every visit to `/`; no `prefers-reduced-motion` gate. On mobile/low-power devices this keeps the GPU busy.
- **`src/components/loan-calculator/LoanCalculatorClient.tsx` — `computeLoan`** — runs synchronously inside `useMemo` for every keystroke; for a 360-month loan with extra payments it's cheap but typing on lower-end devices benefits from `useDeferredValue` or debouncing.
- **`src/app/api/admin/projects/[id]/route.ts` — PUT sections/links replace** — per-edit DELETE+INSERT for all sections/images on every PUT, even for a 1-character description tweak. Negligible at current scale; flag if a project ever exceeds ~50 sections/images.
- **`src/lib/posts.ts` — `findMany` + `count` parallel** — fine; for very-low-row-count tables, a `findMany({ take: PAGE_SIZE+1 })` + "has more" boolean is cheaper than `count` (which scans). Revisit if pagination becomes hot.

## Risk Assessment

**Medium.** The codebase improved materially since the 2026-04-24 sweep — env validation centralized, bcrypt timing defense, Serializable transactions on project sortOrder, bounded caches, hex regex, AST-based markdown stripping. The current sweep surfaces three medium-severity themes: (1) **input validation** — `parseIntId` accepts trailing garbage, `parsePageParam` has no upper bound, `createSlug` doesn't normalize Unicode, `loanCalculator` accepts negatives; small individually but they cluster around uncovered failure paths. (2) **observability gaps that grow with traffic** — `verifyToken` logs expired tokens at error level (will dominate after secret rotation), `lookupLegacySlug` DB outages collapse into 404s with no structured signal, internal errors return no correlation id. (3) **silent test gaps** — `vitest.config.ts` does not include `src/app/**/*.test.tsx`, so two existing edit-page tests have never run and one of them would fail today. Pair that with no tests for the rate-limit branch, no tests for cross-section post moves, and no proxy tests for the actual `/api/admin/*` 401 contract, and the most security-sensitive surfaces are largely unverified. Architecture-level concerns are smaller — admin auth split across three layers is the only one worth a dedicated fix. Nothing landed that touches load-bearing plumbing in a destructive way.
