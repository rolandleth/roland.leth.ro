## Architecture & Coupling

- [ ] **`src/lib/db/posts.ts:400` — `getPostBySlug` bypasses the memo it exists alongside** —
  it calls `resolvePost` directly rather than `loadPostResolution`, so a future caller using
  it in the same render as the page would take two independent row fetches and two
  `currentDatetimeString()` reads. That is the exact split verdict `loadPost` was deleted to
  prevent (`dev-journal/2026-09-01.md`: "a surviving `loadPost` would let a future caller
  reintroduce the split verdict"). Keeping the accessor is a recorded decision; leaving it
  *uncached* is the part that reopens the door. Routing it through `loadPostResolution`
  keeps the accessor and closes it.
- [ ] **`src/lib/content/metadata.ts` — `buildPageMetadata` has opt-in alternates but forced
  OG** — `canonicalPath`, `markdownPath` and `feed` are all strict opt-in while `openGraph`
  and `twitter` are unconditional. A caller wanting site-consistent `alternates` without a
  social card structurally cannot get one; that asymmetry, not the call site, is why the
  scheduled branch picked up a card as a side effect of fixing feed inheritance.
- [ ] **`src/lib/db/detailCacheMiss.test.ts:63-224` — the detail-cache regression suite is
  anchored to the non-production accessor** — miss, hit, error-rethrow and scheduled-caching
  are all asserted through `getPostBySlug`, so the cache behaviour of the entry point
  production actually uses (`loadPostResolution`) is covered only by proxy. Repoint before
  any cleanup of `getPostBySlug`, not after.

## Performance

- [ ] **`src/lib/db/cacheMiss.ts:38-50` — 404 probes under `/blog/:section/:slug` each cost a
  function invocation plus a real Postgres query** — misses are deliberately thrown rather
  than cached so they are "never pinned into the durable cache", and `generateStaticParams`
  covers published slugs only, so under default `dynamicParams: true` scanner traffic on
  nonexistent slugs re-renders every time. Same cost pattern the project already acted on
  when it removed root-level legacy slugs, surviving one path segment deeper. Negative
  caching has a real downside (unbounded garbage keys), so this warrants a decision rather
  than an automatic change.

## Risk Assessment

**Low.** The commit is a clean set of fixes for the prior day's review, and the central
change is the right one: `resolvePost` collapses two row fetches and two clock reads into
one, closing the publish-boundary 404 race, and `isFutureDatetime` makes live and scheduled
exact complements by construction rather than by matching hand-rolled operators. No Prisma
query shape, cache key, or tag changed — the refactor sits entirely above the query
boundary, so no new invalidation machinery and no risk of live and scheduled views
disagreeing about a row. Contracts narrowed (four exports became two) rather than widened.
Targeted suites (218 tests across 7 files), `tsc --noEmit`, and `yarn lint` all pass on a
clean tree.

What warrants caution is that the refactor's central invariant — one row, one clock read,
per render — is now enforced by convention alone. `getPostBySlug` is an exported, uncached
twin of the production path, and no test binds the memoized entry point to a single call, so
the defect that was just fixed has an unguarded route back in. The second caution is
coverage drift rather than code: the scheduled branch's metadata changed shape, the
assertion pinning the old shape was removed, and the test that remains is named as though it
still covers it.
