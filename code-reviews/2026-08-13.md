## Issues and Observations

- [x] **[src/lib/content/metadata.ts — `siteTwitter`] + [src/app/layout.tsx — `generateMetadata`]** — `card: "summary_large_image"` now reaches every page, but the `images` half is still empty for every page with no asset of its own: `/`, `not-found`, `/about`, `/guides`, `/projects`, `/blog/:section`, `/privacy*`, `/tools/loan-calculator` and any imageless post or project. A large-image card with no image is a degraded card, and `/` is the most-shared URL on the site. There is no `src/app/opengraph-image.*` and no default in `siteOpenGraph`, so one asset in one place would close all of them. **Resolved 2026-08-13**: `defaultOgImage` points at a committed `public/images/og-card.png`, generated by the new dev-only `src/app/og` route and used as the fallback in both `buildPageMetadata` and the root layout.
- [x] **[src/lib/content/projectJsonLd.ts — `buildSoftwareApplicationJsonLd`]** — `ebc0a54` removed the "Get on …" CTA for discontinued projects because it "asserts availability the Discontinued badge contradicts", but the JSON-LD still emits `offers` with a live price for the same project. That is the same assertion in machine-readable form, aimed at search and answer engines. schema.org carries `availability` (`https://schema.org/Discontinued`) for exactly this; `isDiscontinued` is never read in this file. **Resolved 2026-08-13**: every offer shape carries `schema:Discontinued` when the project is; a live project still asserts nothing.

## Architecture & Coupling

- [x] **[src/lib/content/metadata.ts — `siteOpenGraph`/`siteTwitter`]** — the constants fix the four dropped fields but not the bug class. Next still replaces `openGraph`/`twitter` wholesale from any deeper segment, so a future page that writes a raw `openGraph` object instead of calling `buildPageMetadata` silently reintroduces the exact defect. The invariant is "every page goes through `buildPageMetadata`", and nothing enforces or tests it — today it holds only because `src/app/layout.tsx` is the sole other definition. **Resolved 2026-08-13**: a `no-restricted-syntax` block bans `openGraph`/`twitter` properties in `src/app/**/page.tsx`, verified against a probe file; nested layouts remain uncovered by choice.

## Observability

- [x] **[src/lib/auth/adminMetadata.ts — `adminEditMetadata`]** — the guard returns the fallback title silently when `verifySession()` fails. Reaching that branch means a request got past the `src/proxy.ts` matcher, which is the precise condition `src/lib/api/requireAdmin.ts` logs at error level and calls "a security event, not a routine 401". The page namespace discards the one signal that the matcher has a hole. **Resolved 2026-08-13**: logs at error level with a per-page `tag` argument, matching `requireAdmin`'s wording; an unparseable id still returns before the check and stays quiet.
- [x] **[src/app/admin/(protected)/layout.tsx — `ProtectedLayout`]** — same class: redirects to `/admin/login` with no log. Between this and `adminEditMetadata`, an unauthenticated request reaching `/admin/*` produces zero telemetry, while the equivalent on `/api/admin/*` produces an error line. **Resolved 2026-08-13**: logs `[admin:layout]` before the redirect.

## Performance

- [x] **[src/lib/auth/auth.ts — `verifySession`]** — not wrapped in React `cache()`, so an admin edit page now pays two cookie reads and two JWT verifies per request (`generateMetadata` via `adminEditMetadata`, then `ProtectedLayout`). Every DB loader beside it (`loadPostForAdmin`, `loadProjectForAdmin`, `loadGuideForAdmin`, `loadGuideTopicForAdmin`) is already `cache()`-wrapped, which is why the doubled loader read the same change would have caused does not exist. `src/proxy.ts` uses `verifyToken`, not `verifySession`, so wrapping is safe. **Withdrawn 2026-08-13** (not fixed): the gain is one avoided HMAC verify per admin page load on a single-user admin, against changing behaviour on the auth path using a memoization primitive whose route-handler scope was not established. Consistency judged not worth touching auth for. Do not re-raise without a measured cost.

## Missing Tests

Half the fix has no regression guard. **Resolved 2026-08-13**: three cases covering the spread, the exact resolved shape, and the default card.
- [x] **[src/app/admin/(protected)/guides/[id]/edit/page.tsx] + [.../guide-topics/[id]/edit/page.tsx — `generateMetadata`]** — neither directory has a test file at all. Two of the four pages that gained the session guard have no per-page wiring coverage; the posts and projects equivalents both got the "does not query the db without a valid session" case. `src/lib/auth/adminMetadata.test.ts` covers the helper's logic, so the gap is the wiring, not the guard. **Resolved 2026-08-13**: 10 cases each, including the no-session guard and the per-page log tag.

## Risk Assessment

**Low.** Three changes: a shared metadata constant pair, a shared admin-metadata
auth guard, and presentation-layer edits to `ProjectContent`. The auth guard is
the only one touching load-bearing plumbing, and it narrows rather than widens —
`generateMetadata` now runs `verifySession()` before any DB read on all four
admin edit pages, pinned by tests on the helper and on two of the four pages.
`adminEditMetadata`'s callback signature is new indirection but keeps the guard
structural, which is the right trade for a security-relevant shape repeated four
times. The metadata change is additive: fields are spread, nothing is removed,
and the site-wide constants have one definition. 2076 tests pass. What keeps this
from "very low" is that both new shared pieces rely on convention for their
invariant rather than enforcement — a new admin page reading data outside the
layout, or a new page writing a raw `openGraph`, silently reopens the respective
gap, and neither has a failing test to catch it.
