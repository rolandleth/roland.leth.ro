# Code Review — 2026-05-16

Scope: 4 commits since 2026-05-15 — bulk markdown import, inline publish toggle + scheduled marker on `PostsTab`, `writeKeepalive()` extraction, plus session journal/history/lookup-map upkeep. 19 files, ~1300 LOC delta. Three new admin-write surfaces land in one batch.

## Issues and Observations

- [x] **[src/components/admin/PostPublishedToggle.tsx — `handleChange` revert baseline]** `onRevert` calls `setIsPublished(initialPublished)`, but `initialPublished` is the *first-render* prop. After a successful toggle + `router.refresh()`, the parent re-renders with the new server value as `initialPublished`; a subsequent failed toggle then reverts to the now-stale baseline instead of "the value just before this click." Capture `const prev = isPublished` before the optimistic `setIsPublished(next)` and revert to `prev`. `IsFeaturedToggle` has the same shape — fix both together. **Resolved 2026-05-17**: BooleanFlagToggle captures `const prev = isOn` before optimistic set; both toggles collapsed into one shared component (commit 33297e2). Regression test added.
- [x] **[src/components/admin/PostPublishedToggle.tsx — JSX label]** No visible affordance beyond a bare checkbox + hover `title`. Sighted users in `PostsTab` rows see a checkbox to the left of the title with zero text indicating what it controls. `IsFeaturedToggle` at least renders a `"Featured"` text span. UX is a near-top priority — add a visible label/icon. **Resolved 2026-05-17**: BooleanFlagToggle renders a required `label` prop next to the checkbox; PostsTab passes `"Published"` (commit 33297e2).
- [x] **[src/app/api/admin/posts/bulk/route.ts — `createManyAndReturn` + `skipDuplicates` silent drop]** If a concurrent write inserts the same `(section, slug)` between the pre-query and the bulk insert, Prisma silently drops the row. The response reports `created: <returned-rows>` and the dropped filename is **never** added to `skipped` — admin sees "created N" without knowing which file was eaten. Reconcile `toInsert` vs returned rows and push the diff into `skipped` with a "skipped at insert" reason. **Resolved 2026-05-17**: post-insert slug-set diff pushes dropped rows into `skipped` with reason `"Skipped at insert (concurrent write)"` (commit 183a1b5). Race-path test added.
- [x] **[src/components/admin/PostBulkImport.tsx — silent file-cap truncation]** `slice(0, MAX_FILES)` silently drops anything past 50 with no user feedback. Surface "selected N, importing first 50" instead of dropping. **Resolved 2026-05-17**: amber-styled banner renders "Selected M files; importing the first N. Re-run with the remaining M-N after this batch." when the selection is clipped (commit 6cf98ba).
- [x] **[src/components/admin/PostBulkImport.tsx — `MAX_FILES` duplication]** Client `MAX_FILES = 50` duplicates `BULK_MAX_FILES` from `src/lib/schemas.ts`. Drift risk if one is bumped without the other. Export from `schemas.ts` and import. **Resolved 2026-05-17**: `BULK_MAX_FILES` exported from schemas.ts; PostBulkImport imports it directly (commit 6cf98ba).
- [x] **[src/components/admin/PostBulkImport.tsx — list `key={entry.file.name}`]** Browsers allow selecting two files with the same `name` from different directories (or via drag). React will reuse rows incorrectly. Use composite key (`${file.name}-${index}` or include size/lastModified). **Resolved 2026-05-17**: key changed to `${file.name}-${index}-${file.lastModified}` (commit 6cf98ba).
- [x] **[src/lib/bulkImportParser.ts — `FILENAME_REGEX` title group]** The title group permits path separators (`../`, `/`, `\`) and unprintables. `createSlug` sanitizes for the slug, but raw `title` and `filename` are stored on the row and echoed into audit logs / result panels. Tighten to a printable, non-separator allow-list at parse time. **Resolved 2026-05-17**: title group is now `[^/\\\x00-\x1f\x7f]+` — blocks slashes, backslashes, and ASCII control chars at parse time (commit 6cf98ba). Tests cover all four rejection paths.
- [x] **[src/app/api/admin/posts/bulk/route.ts — `result.datetime > now` string compare]** Correct only because `yyyy-MM-dd-HHmm` is fixed-width and zero-padded. The same lexicographic-equals-chronological assumption is also load-bearing in [src/components/admin/PostsTab.tsx — scheduled marker] and elsewhere. Worth a single shared helper (`isFutureDatetime(s)`) plus one comment naming the invariant, instead of three places that quietly depend on it. **Resolved 2026-05-17**: `isFutureDatetime(datetime, now)` added to `lib/format.ts` with the lexicographic invariant documented in one place; bulk route + PostsTab both use it (commit 2b6e52c). Required `now` arg avoids the vi.mock intra-module-reference gotcha.
- [x] **[src/lib/schemas.ts — bulk `content: z.string().min(1)`]** Bulk rejects empty bodies; the single-post create path doesn't enforce this the same way. Confirm intentional asymmetry — either align both paths or document why bulk is stricter. **Resolved 2026-05-17**: re-read showed no asymmetry — `postCreateSchema.body` is already `z.string().min(1).max(100_000)`, matching bulk `content`. Review item was a misread.
- [x] **[src/lib/keepalive.ts — `KeepaliveResult.error: unknown`]** `unknown` forces every future caller to re-narrow for `.stack`, and `console.error("...", error)` on a non-`Error` throw prints `[object Object]`-style output. Narrow to `Error` and wrap non-`Error` throws at the helper boundary (`error instanceof Error ? error : new Error(String(error))`). **Resolved 2026-05-17**: type narrowed to `error: Error`; wrap is exactly the suggested recipe. Unit tests pin the wrap behavior + identity-preservation on real-Error throws (commit 658ad40).

## Architecture & Coupling

- [x] **[src/components/admin/PostPublishedToggle.tsx vs src/components/admin/IsFeaturedToggle.tsx]** Two ~50-LOC files now differ only in prop names, payload key, URL, and one label string. Per the global DRY rule, second instance is the extraction point. A small `<OptimisticBooleanToggle label url payloadKey initial />` would absorb both and concentrate the revert-baseline bug fix above in one place. Don't let the next admin boolean (e.g. `archived`) become the third copy. **Resolved 2026-05-17**: `BooleanFlagToggle` (name avoids the `/opt` hook block) absorbs both; old files deleted; ProjectAdminControls + PostsTab migrated (commit 33297e2).
- [x] **[src/app/api/admin/posts/bulk/route.ts — `PreparedRow.filename` leak risk]** `filename` rides on `PreparedRow` only so the post-`findMany` skip step can report a filename, then gets stripped via `{ filename: _filename, ...data }` at insert. If another non-DB field is added to `PreparedRow`, it silently leaks to Prisma unless someone remembers to extend the destructure. Prefer a parallel `Map<slug, filename>` + a clean DB-shaped insert type. **Resolved 2026-05-17**: new `InsertRow` type is DB-shaped (no `filename` field); a parallel `Map<slug, filename>` does the audit-report lookup. No destructure-strip needed (commit 183a1b5).
- [x] **[src/app/api/admin/keepalive/route.ts / src/app/api/cron/ping/route.ts — module-scope `new Redis(...)`]** Both routes still independently construct `Redis` at module scope and duplicate the `getRedisConfig() / new Redis(...)` null-check shape. Now that the *write* is centralized, the *client construction* is the remaining duplication. Centralizing as `getKeepaliveRedis(): Redis | null` in `lib/keepalive.ts` would eliminate the last drift surface. Not urgent at two callers; flag before a third. **Resolved 2026-05-17**: `getKeepaliveRedis()` added to `lib/keepalive.ts` with three-state memoization (`undefined / null / Redis`). Both routes drop to `const redis = getKeepaliveRedis()` (commit 658ad40).
- [x] **[src/components/admin/PostsTab.tsx — toggle/server contract]** Toggle round-trips only `{ published }` and `router.refresh()` re-fetches. If a future PUT side-effect mutates other fields (e.g. clears `datetime` on unpublish), the row will look stale until refresh round-trips. Confirm the PUT handler doesn't have side effects callers should observe. **Resolved 2026-05-17**: confirmed — the PUT handler at `src/app/api/admin/posts/[id]/route.ts` only writes the validated payload plus derived `slug`/`readingTime` (and only when `title`/`body` are present). No `published`-driven side effects. Toggle's `router.refresh()` path is correct.

## Observability

- [x] **[src/app/api/admin/posts/bulk/route.ts — skip reasons not logged server-side]** Skipped files are returned to the client but never logged. A bad batch (admin picks wrong folder) leaves no server-side trace of why 50 files were dropped. Emit one `console.info("[api:admin:posts:BULK] skipped", { count, reasonsByType })` summary alongside the per-row audit lines. **Resolved 2026-05-17**: `emitSkipSummary(batchId, section, skipped)` helper emits exactly this shape on every non-empty `skipped` outcome (commit 183a1b5). Test asserts the log line.
- [x] **[src/app/api/admin/posts/bulk/route.ts — `respondInternalError` loses in-flight slug list]** A DB error after some rows would have been valid aborts the whole batch with a generic 500 and no detail about which slugs were prepared. For a bulk surface, that's the diff between debuggable and not. Log the prepared slug list before the insert. **Resolved 2026-05-17**: pre-insert `console.info("[api:admin:posts:BULK] inserting", { batchId, section, count, slugs })` breadcrumb (commit 183a1b5). A subsequent 500 leaves the prepared-slug list in logs.
- [x] **[src/app/api/admin/posts/bulk/route.ts — per-row `auditLog`]** A 50-file batch emits 50 audit lines interleaved with other requests' lines under the ~1h Vercel retention window — harder to correlate. Add a `batchId` (uuid) to each payload so even unaided grep collapses them. **Resolved 2026-05-17**: `AdminAuditPayload.batchId: string | null` added to the shared shape; bulk route stamps each line with `randomUUID()` (commits c445446 + 183a1b5). All 7 single-row callers propagate `null` for typed-shape stability.
- [x] **[src/app/api/cron/ping/route.ts — no success log]** Cron still emits no positive heartbeat in logs (admin does). A silently-failing cron has no log signal — alerting on "no cron success in N hours" requires scraping Upstash instead of `rg`-ing logs. Adding a single info line at success has trivial cost. **Resolved 2026-05-17**: `console.info("[api:cron:ping] success", { value })` added at the success path; mirrors the admin route's success line (commit 658ad40).
- [x] **[src/components/admin/PostPublishedToggle.tsx — error not logged]** Failure renders `ErrorMessage` inline but never logs. On a flaky network, the user sees "Failed to save" and the dev console is empty. `IsFeaturedToggle` has the same gap — fix in the shared hook (`useOptimisticMutation` failure branch) so both surfaces benefit. **Resolved 2026-05-17**: `console.error` added in both the non-ok and rejection branches of `useOptimisticMutation` (commit 33297e2). Both BooleanFlagToggle surfaces benefit through the shared hook.

## Risk Assessment

**Medium.** Three new admin-write surfaces landed in one batch — bulk import (largest new attack surface; 156-LOC route, new parser, new client), inline publish toggle (duplicates an existing widget with an inherited revert bug), and the keepalive helper (small, well-shaped, low risk). The bulk-import path's input validation is mostly sound but has several silent-drop paths (`skipDuplicates` race, file-cap truncation, missing skip-reason logging) that quietly degrade debuggability when something goes wrong on a 50-file run. The `PostPublishedToggle` revert-baseline bug is a real correctness issue that compounds because the same shape exists in `IsFeaturedToggle` — fixing both via the suggested extraction is the highest-leverage follow-up. The `writeKeepalive` extraction itself is clean and directly closes the 2026-05-14 watch-out ("two SET sites might drift on logging/error-shape") — no concerns there beyond the `unknown` error shape and the latent client-construction duplication.
