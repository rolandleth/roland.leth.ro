# Code Review — 2026-09-28

## Issues and Observations

- [x] **`src/app/api/auth/login/route.ts` — `POST`** — The only write route that runs neither `refuseCrossSiteWrite` nor the `parseJsonBody` content-type gate. The rate limiter counts a request before it parses the body. So a page the admin visits can send 5 cross-site `text/plain` POSTs from the admin's own browser. With `IP_HASH_SECRET` set, that uses up the admin's per-IP bucket and locks the admin out for 15 minutes. Fix: call `refuseCrossSiteWrite` before the limiter, as `logout` now does.
- [x] **`src/components/admin/useAdminResource.ts` — `save`/`remove` with `useFormState.isDirty` and `useUnsavedChangesGuard`** — `isDirty` has no reset after a successful save, so the guard stays armed until the list renders. In that gap an AdminNav click shows "You have unsaved changes", and closing the tab shows "Leave site?", for data that is already saved. If the App Router falls back to a full page load and the admin clicks Stay, the form stays up with Save disabled for good (`isNavigating` skips `setIsSubmitting(false)`). The doc comment at `useUnsavedChangesGuard.ts:24-26` ("leaves without a prompt") is true only for the `router.push` itself. Fix: disarm the guard once the save succeeds, for example with a re-baseline or an `isSaved` flag.
- [x] **`src/lib/client/adminListReturn.ts` — `adminListUrlFor`** — The doc comment says the code ignores another tab's list because returning there "would hide the item just saved". But on the same tab, a remembered `q=` search hides a new or renamed item in the same way, and the code still returns there. Make the code or the comment match.
- [x] **`scripts/init-post-slugs.ts` — hand parser (lines 40–51)** — When `--section=` is given twice, the first value wins and nothing is reported. `parseCliArgs` now refuses this case in `import-posts`. This script writes files, so a silently chosen section changes which rows the stamps match.
- [x] **`scripts/import-posts.ts` — `resolveSection` (called at line 250)** — An invalid or empty `--section=` throws, and `main().catch` prints a full stack trace for a usage mistake. Every other argument error prints one clean line through `cliArgsProblem`. `init-post-slugs.ts:224` has the same pattern.
- [x] **`src/app/api/admin/upload/route.ts` — `adminUploadKey(file.name)`** — The blob key keeps the client's extension (for example `…-page.html`), while `contentType` is now the type sniffed from the bytes. Browsers are safe because they follow `Content-Type`. But a downloaded file opens by its extension, and only 12 bytes are sniffed, so a polyglot file is possible. The new test pins the `.html` key. Take the extension from `detectedMime` instead.

## Architecture & Coupling

- [x] **`scripts/import-guides.ts:55-61`, `scripts/init-post-slugs.ts:40-51`, `scripts/prune-uploads.ts:44-46` — hand-rolled argument parsers** — There are now three parsers that disagree with `parseCliArgs`:
  - A `-typo` is a usage error in one script and "unknown flag" in another.
  - Repeated flags are handled differently in each.
  - This is not a safety risk: each script needs exactly one positional or refuses unknown arguments, so a typo cannot turn a dry run into a real write.
  - `resolveSection` is duplicated in `import-posts.ts` and `init-post-slugs.ts`. The `simplified:` note says to extract it "if a third script needs it", but the two copies already drift.
- [x] **`scripts/import-posts.ts` — `cliArgsProblem`** — It reads module-level values, so no test can reach it. A pure `cliArgsProblem(parsed, usage)` in `src/lib/import/cliArgs.ts` would test the checks once, and would let the scripts above use the shared checks.
- [x] **`src/components/admin/ProjectForm.tsx:180-190` — `sortOrderText` baseline** — `String(initialData?.sortOrder ?? 0)` appears twice: once as the `useState` seed and once as the guard's baseline. That is a second dirty-state baseline outside `useFormState`. If one copy changes and the other does not, the guard either misses edits or shows the form as dirty on mount.

## Risk Assessment

**Medium.** These commits change load-bearing admin plumbing:
- **Cross-site and content-type checks:** every admin write now goes through `requireAdmin(request, …)`, plus the new `refuseCrossSiteWrite` and a content-type gate. The request contract is now narrower, and every client caller already complies.
- **Uploads:** the stored content type now comes from the sniffed bytes, not the file name.
- **Unsaved-changes guard:** new, and backed by a module-level registry.
- **Return to list:** backed by `sessionStorage`.
- **Import scripts:** a shared CLI parser for `import-posts`.

The tests are broad, and the code is careful about edge cases. The review found no data-integrity or auth-bypass problem. The medium rating has two causes. First, the Origin check can 403 every admin write on a proxy or domain setup that nobody has verified yet. Second, the guard misfires after a successful save, which is a UX regression on the path the admin uses most. The login route's gap is narrow, but it is the one write route the new hardening missed.
