# Code Review — 2026-06-28

Scope: one commit, `5e85251` ("Initial fix for image sizes"). Two source files — `ProjectImageLightbox.tsx` and `ProjectSectionCarousel.tsx` — totalling ~40 LOC of behavioural change. A follow-up to the 2026-06-27 gallery overhaul, aimed at retina rendering quirks under `width/height={0}`.

## Issues and Observations

- **`src/components/projects/ProjectSectionCarousel.tsx` — strategy reversal from prior review** — the 2026-06-26 session's documented lesson was "round the image, not the container" (because `object-contain` letterboxes and the container's `rounded-xl` then misses the visible image). This commit reverses the carousel back to container rounding (`overflow-hidden rounded-xl` on the stage + `fill object-contain` on the image). The comment acknowledges the tradeoff (off-aspect screenshots letterbox + round the box, not the image), so this is deliberate — but a future reader following the dev-journal will see the lesson contradicted in code without a back-pointer. Consider a one-line `simplified:` note tying the regression to the DPR fix and the planned real-dimensions migration.
- **`src/components/projects/ProjectImageLightbox.tsx` — `sizes` attribute coupling to `max-w-5xl`** — the new `sizes="(max-width: 1024px) 100vw, 1024px"` is hand-aligned with the stage's `max-w-5xl` class. If anyone later relaxes the stage (`max-w-6xl`, `max-w-7xl`), the `sizes` hint will under-serve and the same retina-half-size issue re-surfaces. The two numbers (`1024px` in `sizes`, `max-w-5xl` in className) should be paired in a comment or hoisted to a constant.
- **Two galleries, two image-sizing strategies** — the lightbox keeps aspect-true sizing (`w-full h-auto object-contain`); the carousel switches to `fill object-contain`. Both are correct for their constraint (lightbox can't fix stage height without stranding the caption; carousel fixes stage height to prevent layout shift). Worth a brief header note in one of the files documenting that the asymmetry is intentional and converges once real dimensions are stored.

## Architecture & Coupling

- **Planned "store real dimensions" work is now load-bearing for two files** — both new comments reference the same future fix as the path to drop their respective workarounds (`w-full` in lightbox, container rounding in carousel). The dev-journal's open thread frames it as "visually confirm `width={0} height={0}` sizing"; this commit elevates it to "store the real dimensions so neither workaround is needed." Worth promoting from session-level open thread to a tracked watch-out in the next journal entry, since two surfaces' visual quality depends on it.

## Risk Assessment

**Low.** The change is a narrow visual fix on top of last session's gallery refactor, both files were already covered by tests in the prior commit, and the existing lightbox/carousel test suites still apply (image-rendering specifics aren't testable in happy-dom anyway). The "visually confirm in browser" open thread from 2026-06-26 was the only validation, and the user shipped this commit so that confirmation happened. What keeps it from being negligible: the carousel's regression to container rounding is a deliberate visual quality tradeoff with a stated workaround dependency, and the lightbox's `sizes` value is now numerically coupled to a Tailwind class in another part of the same component.
