# Code Review — 2026-09-29

## Issues and Observations

- [x] **`src/app/api/admin/upload/uploadHelpers.ts` — `detectImageMime`, AVIF branch** — major brand `mif1` is accepted as `image/avif` without a check of the compatible brands. A HEIF/HEIC file with major brand `mif1` gets through, is stored as `.avif` with `contentType: image/avif` (from ed8e9f7), and does not render. There is no error at upload time. `route.test.ts` pins `mif1` as valid. Fix: for `mif1`, require `avif` or `avis` in the compatible brands.
- [x] **`scripts/import-projects.ts` — the image read (~L136–140) and `readManifest` (~L356–362)** — bare `catch {}` blocks report any read error (EACCES, EISDIR, EMFILE) as "Image not found" or "No project.json", and the real error is lost. `isMissingPathError` was added to fix this misreport, but only `discoverProjectDirs` uses it. JSON parse errors are handled separately and are not affected.
- [x] **`scripts/*.ts` — `parseCliArgs` + `flagsProblem` pairing** — each of the five scripts passes `KNOWN_FLAGS`/`VALUE_FLAGS` twice and repeats the same `problem → console.error → exitCode = 1 → return` block. `import-posts` and `init-post-slugs` also repeat the `"problem" in sectionArg` exit block word for word. If the two calls get different sets, `--section=x` is refused as unknown while "Supported" still lists it. One helper that parses and validates in a single call removes both the duplication and the mismatch risk.
- [x] **`scripts/import-guides.ts`, `import-posts.ts`, `init-post-slugs.ts`, `prune-uploads.ts` — hardcoded `Usage:` strings** — these are written by hand, not derived from `KNOWN_FLAGS` like the "Supported" list. A renamed or added flag leaves them stale, with no error.
- [x] **`src/lib/import/sectionArg.ts` — `resolveSectionArg` problem message** — says `--section=<value>`, while `flagsProblem` and the usage lines say `--section=<section>`. One CLI names the same flag two ways.
- [x] **eebb1be commit title** — it says the non-JSON login check runs "before the rate limiter". Only `refuseCrossSiteWrite` does. `refuseNonJsonBody` runs after the limiter in `src/app/api/auth/login/route.ts`. The journal shows the order is intentional, and it is sound. Add a short why-comment at the `refuseNonJsonBody` call so the title doesn't mislead a later reader.

## Missing Tests

- [x] **`src/app/api/auth/login/route.ratelimit.test.ts` — 415 vs limiter order** — no test pins that a same-origin `text/plain` POST reaches the limiter and then gets 415. A later reorder in either direction would pass silently.
- [x] **`src/app/api/admin/upload/route.test.ts` — `detectImageMime`** — no case for a `mif1` major brand with `heic` compatible brands expecting `null` (pairs with the AVIF finding).
- [x] **`src/components/admin/GuideForm.test.tsx`, `GuideTopicForm.test.tsx`, `ProjectForm.test.tsx` — guard after a failed save** — only `PostForm.test.tsx` checks that the unsaved-changes guard stays on after a 409/500. Each form builds its own `… && !hasSucceeded` expression (accepted duplication), so a per-form test is the only safety net against a wrong operator or a stale flag.
- [x] **`src/components/loan-calculator/LoanCalculatorClient.test.tsx` — "empties the live region and drops it from the description once valid again"** — `toContain(region.id)` / `not.toContain(region.id)` check a substring of `aria-describedby`, not a whole token. An ID that is a prefix of another ID passes the first check falsely and fails the second falsely. Split on whitespace and assert on the token list.
- [x] **`scripts/import-posts.ts`, `scripts/init-post-slugs.ts` — `main()` argument wiring** — three behavior changes (a repeated `--section` refused, single-dash args rejected, an invalid section sets the exit code instead of throwing) are covered only through the pure helpers. Nothing checks that a script stops before any DB or blob side effect when an argument is bad.

## Resolutions

- **AVIF `mif1`** — `isAvifFtyp` accepts `mif1` only with `avif`/`avis` among the compatible brands, read up to the box's declared size. The route now sniffs `SNIFF_HEADER_BYTES` (64) instead of 12, because the compatible brands start at byte 16. Tests cover a HEIC, a bare `mif1`, brands past the box end, a cut-off header, and a route-level mif1 AVIF upload.
- **`import-projects` read errors** — the image read and `readManifest` now use `isMissingPathError`; any other error is reported with its message.
- **CLI duplication, usage drift, section copy** — one `CliSpec` per script (`command`, `positionals`, `knownFlags`, `valueFlags`) feeds `parseScriptArgs` (flags, then positional count), the "Supported" list and `cliUsage`. `parsePostScriptArgs` in `src/lib/import/sectionArg.ts` adds `--section` and resolves `folder`/`section` for both post scripts. Each script's `main()` keeps one `cli.problem` refusal block. This reverses the 09-28 choice to keep positional checks per script: the spec's `positionals` states the difference instead.
- **`main()` wiring** — the three behavior changes are now tested through `parsePostScriptArgs` with full argv. The scripts themselves are still not run under test; the only untested line is each `main()`'s first `if (cli.problem != null)`.
- **Login order** — a why-comment at `refuseNonJsonBody`, plus tests that a same-origin `text/plain` POST spends the bucket before its 415 and gets 429 once the bucket is empty.
- **Form failure paths and `aria-describedby`** — added as listed.

## Risk Assessment

**Low.** Three themes landed. First, login now runs the shared cross-site and Content-Type checks. Second, upload keys take the sniffed type's extension. Third, the import scripts share one argument contract, and the admin forms stop prompting after a successful save. The login change touches auth plumbing and widens the refusal surface: a host-rewriting proxy would now block login too, not only saves. That risk is already tracked as a post-deploy check. No contracts widened. `adminListUrlFor` gained a required `isAfterCreate` parameter, and all call sites are updated. The only production-behavior defect is the pre-existing AVIF `mif1` gap, which the new extension naming makes more visible. The rest is half-applied helpers, duplication and test gaps.
