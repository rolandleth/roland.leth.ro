# Code Review — 2026-04-29

## Issues and Observations

- **`src/app/api/cron/ping/route.ts:60` and `route.test.ts:124` — duplicated `"keepalive:last"` literal** — the key name appears verbatim in both files; renaming it requires two edits. Exporting a `KEEPALIVE_KEY` constant from the route and importing it in the test would be a safe refactor, though the risk is low since this key is only used in one place.

## Missing Tests

- **`route.test.ts` — `vi.doUnmock` not in `afterEach`** — if an assertion throws before `vi.doUnmock("@upstash/redis")` runs (lines 127, 145), the mock leaks for the remainder of the describe block. Pre-existing pattern. `vi.resetModules()` at the top of each test is the actual safety net, but moving the unmock to `afterEach` would make the intent explicit and guard against a future test order that skips the reset.

## Risk Assessment

**Low.** Single-commit change swapping `redis.ping()` for `redis.set("keepalive:last", <iso>)` — a correct fix for Upstash's idle-database detection exclusion of `PING`. No auth changes, no data model changes, no contract widening. The updated tests assert the specific key name and ISO timestamp pattern, explicitly guarding against regression to `ping()`. The observable side-effect (the key is visible in the Upstash data browser as a last-run timestamp) is a net improvement.
