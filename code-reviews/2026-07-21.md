## Issues and Observations

- [x] **[src/lib/auth/env.ts — `nonEmpty`, 95-97]** — Doesn't trim, so a trailing-newline or whitespace-padded `INDEXNOW_KEY` (a realistic paste/env-UI footgun) is served verbatim at `/indexnow-key.txt` with 200, yet `describeKeyProblem` rejects it as "malformed" (the anchored regex fails on whitespace). The operator sees "malformed" for a key that looks correct on screen, with the invisible whitespace as the undiagnosable cause. Trim in `getIndexNowKey`, or call out whitespace explicitly in the malformed message. **Resolved 2026-07-21**: `getIndexNowKey` trims before the empty check (`0ae37c4`).

## Architecture & Coupling

- [x] **[src/components/admin/IndexNowPanel.tsx / RevalidatePanel.tsx — outcome region]** — The hook + `adminButtonClass`/panel classes were extracted, but the outcome live-region block is still duplicated byte-for-byte: the `<div role="status" aria-live="polite">` wrapper (IndexNow 361-373 vs Revalidate 213-221), the `OUTCOME_ID` + `aria-controls`/`aria-busy` button wiring, and the trailing `{error && <ErrorMessage>}`. The wrapper class `"flex flex-col gap-1 empty:hidden"` is an inline literal in both, not a `controlStyles` constant — the same duplication class the refactor set out to kill, one layer down. An `<AdminOutcome>` (or shared class) is the next extraction before a third panel copies it. **Resolved 2026-07-21**: extracted `adminOutcomeClass`; kept per-panel markup, not a wrapper component, per the shared-class preference (`eb7ed00`).
- [x] **[src/components/admin/useAdminAction.ts — split state ownership]** — The hook resets its own `error` on each `run` but the panels own `result`/`warnings`/`preview` and must remember to clear them in `start()` before calling `run` (IndexNow 282-284, Revalidate 110-111). Nothing enforces this; a future panel that forgets the manual reset shows stale results under a fresh action. Consider a hook-provided reset callback the panel registers, so "new run clears prior output" lives in one place. **Resolved 2026-07-21**: `reset` moved into `useAdminAction.run` as a third param (`0bfbe68`).

## Observability

- [x] **[src/app/api/admin/indexnow/route.ts — `logResult`, 224-241]** — Logs `statuses: batches.map(b => b.status)` only, dropping each batch's `message`/`errorName`. `submitBatch` now captures `errorName` specifically to distinguish `TimeoutError` from a DNS/network failure, and that detail reaches the panel — but a transport failure logs `statuses: [0]` server-side with no way to tell the two apart from logs alone. Partial fix of the prior "rejected submission invisible" finding: level is now `error`, but the diagnostic that was added is not logged. **Resolved 2026-07-21**: failure path now logs per-batch `errorName`/`message` (`c698faa`).
- [x] **[src/components/admin/useAdminAction.ts — `run` catch, 82-84]** — A superseded request that fails with a *non-abort* error hits `!isLatest()` and returns before the `console.warn`, so a real failure on a request the user moved past leaves no trace. Correct not to surface it to the UI; silently dropping it from the log too means an intermittent perform failure under rapid re-submits is undiagnosable. A debug-level log on the superseded-error branch would keep it visible. **Resolved 2026-07-21**: superseded non-abort errors now log at `console.debug` (`c698faa`).

## Accessibility

- [x] **[src/components/admin/IndexNowPanel.tsx / RevalidatePanel.tsx — `aria-controls` vs error routing]** — Both buttons set `aria-controls={OUTCOME_ID}`, but on the failure path the primary message routes to `setError` → the separate `role="alert"` `ErrorMessage` region, while `OUTCOME_ID` holds only `warnings`/`preview`. The failure is still announced (both are live regions), but the button's declared controlled region doesn't contain the headline it produced. Minor semantic mismatch; either route the failure headline into `OUTCOME_ID` or drop the claim that the button controls it. **Resolved 2026-07-21**: `aria-controls` now names both regions; `ErrorMessage` wrapped in an always-mounted `empty:hidden` div so the IDREF never dangles (`eb7ed00`).

## Risk Assessment

**Low.** The fixes are sound and land on the right side of every prior finding: the `attempted`/`accepted` split is implemented and now has genuine multi-batch tests (the module's only non-trivial control flow, previously uncovered); IP-literal rejection matches its comment and is tested against private-range and IPv6 hosts; the status-code rework (503 config-gaps, 422 empty, 502 upstream, 500 site-URL) is consistent with the sibling `keepalive`/`revalidate` routes; `sitemap()` and `getSiteUrl()` are guarded; the `?dryRun=false` parsing bug is fixed; and `IndexNowPanel` went from zero tests to 402 lines. The new `useAdminAction` hook — the largest new surface — is correct under supersede and unmount (the commit-gating `isLatest()` guard blocks post-unmount state writes on both the success and abort paths) and is well-tested. What remains is residual, not regressive: an observability gap where the newly-captured `errorName` is surfaced to the client but not to server logs; a second layer of panel duplication the refactor didn't reach; a whitespace-key edge that produces a confusing operator-facing "malformed"; and a cluster of test gaps concentrated in the new hook's subtlest branches and RevalidatePanel's now-shared network path. Nothing touches data integrity or the load-bearing safety property (never submit a non-public origin), which stays implemented, tested, and dry-run-defended.
