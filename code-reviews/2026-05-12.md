# Code Review — 2026-05-12

## Issues and Observations

- **[src/app/layout.tsx — skip-link target]** — Skip target is a `<div id="main-content" tabIndex={-1}>` wrapping `{children}`, while every page renders its own `<main>`. The link lands on a generic div above two `<main>` candidates and forces programmatic-focus on a non-landmark; either hoist `<main>` into the layout or move `id="main-content"` onto the per-page `<main>`.
- **[src/components/admin/ProjectSortOrderInput.tsx — number `<input>`]** — Phase 6 a11y sweep added accessible names to LinkManager URL/SectionManager title but missed this spinbutton; SR announces "spin button, 3" with no context. Add `aria-label="Project sort order"` (or wire a visually-hidden label).
- **[src/app/api/admin/posts/[id]/route.ts vs src/app/api/admin/projects/[id]/route.ts — `previousSlug` audit semantics]** — Posts PUT sets `previousSlug = previous.slug !== post.slug ? previous.slug : null`; projects PUT emits `previousSlug` regardless. Two routes, two contracts for the same audit field. Centralize in a helper both routes call.
- **[src/components/admin/IsFeaturedToggle.tsx — `setError("Failed to save")` in catch]** — Non-ok branch routes through `readErrorMessage` (Phase 6 fix), but the network-rejection catch hard-codes the generic string while sibling `ProjectSortOrderInput` surfaces `err.message`. Inconsistent across two near-identical optimistic-revert components.
- **[src/components/admin/ProjectForm.tsx — sortOrder coercion]** — `setField("sortOrder", isNonNegativeInteger ? Number(raw) : 0)` silently coerces rejected input to `0` — same data-loss class the Phase 6 strict parse fixed elsewhere. `ProjectSortOrderInput.handleBlur` snaps back to `initialSortOrder + 1`; this should match (snap back to prior committed value, not `0`).
- **[src/components/projects/ProjectSectionCarousel.tsx — root]** — No guard for `images.length === 0`; `current = images[0]` is `undefined` and `<Image src={current.url}>` throws. Callers gate at the parent, but make the contract local with `if (images.length === 0) return null`.
- **[src/components/blog/PostCard.tsx + PostContent.tsx — `postDatetimeToISO(post.datetime)`]** — Helper throws on malformed input; one bad row 500s the entire blog list (PostCard is a server component). Catch and fall back to the raw string in `dateTime`, or validate at the DB read boundary.
- **[src/components/ui/PresetOrFreeformInput.tsx — duplicate `aria-label`]** — Same accessible name applied to both the dropdown and the freeform input; SR users hear two indistinguishable controls and the rotor collapses them. Differentiate or `aria-hidden` the disabled side.
- **[src/components/projects/ProjectSectionCarousel.tsx — caption outside live region]** — `aria-live="polite"` wraps the image area, so SRs hear `alt` on swap; the caption sits outside (`<p className="text-secondary mt-2">`) and never re-announces. Move caption inside the live region or add a hidden announcement element.
- **[src/components/ThemeProvider.tsx — `getServerColorSchemeSnapshot` always returns `false`]** — On a system-dark user with the cookie-set class on `<html>`, the SSR snapshot disagrees with the rendered class; `applyTheme`'s effect can briefly flip light → dark on hydration. Confirm the inline boot script suppresses this, or seed the snapshot from the cookie.
- **[src/lib/format.ts — createSlug regex character class]** — `[\s.‐-―−­]+` mixes the U+2010..U+2015 range with bare U+2212 and U+00AD; soft hyphen renders invisibly in most fonts. Use Unicode escapes (`−`, `­`) so the next reader doesn't "fix" what looks like a typo.
- **[src/app/api/upload/route.ts — `disallowed mime` vs `mime mismatch`]** — Both return 415 with the same body `"Unsupported file type"`. Server-side logs distinguish, but the second branch only logs `claimedType`; ensure `detectedMime` makes it into the log payload as well so a future dashboard can split spoof rate from typo rate.
- **[src/app/page.tsx — title.absolute]** — Correct fix for the double-brand bug, but nothing structurally prevents another future top-level page from re-introducing it. Add a comment in the metadata builder warning that titles already containing the brand must use `title.absolute`.
- **[src/lib/auditLog.ts — `tag: string`]** — Untyped `tag` parameter; a typo at the call site silently emits a malformed line that breaks log-aggregator greps. Accept a typed enum or document the format contract on the function.

## Architecture & Coupling

- **[src/components/admin/useAdminResource.ts — `readErrorMessage` lives in a hook module]** — Now consumed by 5 call sites (LoginForm, AdminNav, useAdminResource, IsFeaturedToggle, ProjectSortOrderInput) — past the dev-journal's "flag at the 4th caller" trigger. Move `readErrorMessage` + `formatZodIssues` + `ZodIssueLike` to `src/lib/readErrorMessage.ts` so non-hook consumers don't pull in `"use client"` semantics.
- **[src/components/admin/IsFeaturedToggle.tsx + ProjectSortOrderInput.tsx — duplicated optimistic-mutation pattern]** — Both reimplement the same ~70-line shape: `abortRef` + controller-vs-abort guard + optimistic value + revert on non-ok + revert on catch + `setIsSaving` in finally. A `useOptimisticMutation({ url, method, body, optimisticValue, revertValue })` hook would collapse both before the third widget arrives.
- **[src/app/api/admin/posts/[id]/route.ts vs projects/[id]/route.ts — asymmetric isolation]** — Posts PUT runs at default READ COMMITTED inside `prisma.$transaction`; projects PUT escalates to Serializable. Documented in dev-journal as deliberate (project PUT does the sortOrder shift), but two near-identical handlers diverging on isolation is a coupling smell — extract `withPriorRead` so the choice is explicit at the call site.
- **[src/lib/schemas.ts → src/lib/format.ts coupling]** — `producesNonEmptySlug` couples schema rejection to `createSlug` output; the two test suites assert the same characters in parallel rather than via a shared fixture (e.g. `EMPTY_SLUG_INPUTS`). If `createSlug` later strips a new char, `schemas.test.ts` won't fail unless someone updates both.
- **[src/lib/apiErrors.ts — `describeZodIssues` not exported]** — Comment says "mirror the login route's pattern" but the helper is module-private, so the login route can't reuse it; the second call site already drifts. Export it (or extract `logSchemaFailure(tag, issues)`) to prevent further drift.
- **[src/app/api/upload/route.ts — `ALLOWED_UPLOAD_MIMES` and `detectImageMime` independently maintained]** — Adding a MIME to the allowlist without a corresponding magic-byte branch turns the upload into a hard 415. Derive both from one source, or assert at module load that every entry in `ALLOWED_UPLOAD_MIMES` has a `detectImageMime` branch.
- **[src/components/projects/ProjectContent.tsx — tablist arrow-nav duplication]** — Phase 5 added arrow-key nav to the dashboard tab and now to ProjectContent; same logic will appear on the next tablist. Extract `useRovingTabIndex({ length, onActivate })` before the third consumer.
- **[Cache-snapshot staleness — three copies]** — `getPostBySlug`, `getAllPublishedPostSlugs`, and `legacySlug.cachedLookup` all capture `now`/`currentDatetimeString()` inside cached fns; only the post-detail comment documents the trap. Either factor a shared `withFutureDateFilter(cacheFn)` helper or add a parallel comment at each site so the contract isn't only legible at one of three call sites.

## Concurrency & Thread Safety

- **[src/app/api/admin/posts/[id]/route.ts — PUT diff comment overpromises]** — Comment says the txn "matches the project PUT" but post PUT is at READ COMMITTED; two concurrent posts moving tech↔life can still observe the same `previous.section`. The transaction makes read+write atomic but doesn't serialize against another concurrent transaction's read. Either drop the comment or escalate to Serializable.
- **[src/components/admin/AdminNav.tsx — `handleLogout` finally]** — Adds `abortRef` + cleanup but does **not** apply the `if (abortRef.current === controller) setIsSaving(false)` guard that LoginForm uses. Lower probability than LoginForm (success navigates), but the asymmetry is gratuitous.
- **[src/components/admin/IsFeaturedToggle.tsx + ProjectSortOrderInput.tsx — controller-vs-abort guard real risk]** — Comments call the guard "dead code today" because `disabled={isSaving}` blocks reentry, but the load-bearing case is `router.refresh()` triggering a parent rerender that changes the prop (`initialIsFeatured`/`initialSortOrder`) mid-flight, in which case the catch reverts to a stale snapshot. Worth verifying the parent dashboard memoizes/keys these around the prop.
- **[src/app/api/auth/login/route.ts — `clientBucketKey` header trust]** — Leftmost `x-forwarded-for` trusted unconditionally; off-Vercel a client can rotate the header to bypass the 5/15min limit. Documented as intentional in dev-journal; flag-only.
- **[src/lib/posts.ts — `createBoundedWrapperCache.get` single-flight assumption]** — `findUnique → findFirst` widens the inner-fn work; if `get(key, factory)` isn't single-flighted, two concurrent first-accesses for the same `(section, slug)` build two wrappers (last write wins). Worth confirming the wrapper cache de-dupes concurrent miss-builders.

## Observability

- **[src/app/api/upload/route.ts — `formData()` malformed-multipart catch]** — The 400 catch has no log line, while every other 4xx in the route logs (`oversize precheck`, `disallowed mime`, `mime mismatch`). A botnet sending garbage multipart bodies gets a clean 400 with zero log signal — inconsistent with the route's own pattern.
- **[src/lib/apiErrors.ts — `describeZodIssues` unbounded path-set]** — No cap on `paths.join(", ")` length. A pathological payload with hundreds of nested issues produces a multi-KB log line per request; with the warn-level demotion this is now log spam per malformed probe. Slice with a `+M more` suffix.
- **[src/lib/auditLog.ts — `console.info` is the audit sink]** — On Vercel Hobby, ~1h log retention; "audit log" in the name oversells what `console.info` provides. Same tradeoff as `error.digest` on 2026-05-09 — re-introduce a durable sink paired with aggregation, not before.
- **[src/components/admin/ImageUpload.tsx — bare error-to-string in catch]** — `setError(err instanceof Error ? err.message : "Upload failed")` with no `console.warn` tag, while LoginForm/AdminNav got tagged warns this session. Apply the warn-tag pattern uniformly across the three "use client" mutations or remove it from the others.
- **[src/app/api/cron/ping/route.ts — 401 on missing CRON_SECRET]** — Returning 401 (not 500) hides a server-config bug from monitoring tools that only alert on 5xx. The server-side `console.error` is the only signal; confirm log-grep alerting on `[api:cron:ping] CRON_SECRET not configured` is wired before treating this as covered.
- **[src/lib/apiErrors.ts — union/discriminatedUnion log signature]** — `describeZodIssues` reads the structural top-level shape; for unions the useful detail lives in `unionErrors[].issues`, which the helper drops, leaving a single bare code in the log.
- **[src/components/blog/PostCard.tsx — `postDatetimeToISO` throw context]** — When the throw bubbles into a server component, only Next's default error boundary sees it; no `{ postId, datetime }` context is logged. Wrap with try/catch that logs at warn before re-throwing or falling back.

## Risk Assessment

**Medium.** This was a 28-commit, 81-file, ~4k-LOC sweep across two days of "fix every code-review finding" work — high churn touching load-bearing plumbing (admin write paths, the legacy-slug router, sitemap generation, the auth/login route, the upload pipeline, and the theming subsystem). Almost every commit message describes a contract change rather than a bug fix: response shapes (`{error: ZodIssue[]}` introduced alongside `{error: string}`), audit-log payloads (now required-keys), `findUnique → findFirst` migration on `getPostBySlug`, magic-byte sniff added to upload, `prisma.$transaction` wrapping the posts PUT, the `useSyncExternalStore` rewrite of ThemeProvider. Test coverage moved up materially in lockstep (Phases 6–7 explicitly added coverage for Phases 6 and 8), which absorbs most of the risk. What warrants caution: (1) the asymmetric isolation in posts vs projects PUT plus a comment that overpromises atomicity; (2) `readErrorMessage` and the optimistic-mutation pattern have crossed the "extract" threshold and the next consumer will reify the duplication; (3) three independent copies of the "capture `now` inside the cached fn" trap, only one of which is documented; (4) `console.info` as the audit-log sink with no aggregation pipeline yet — same tradeoff that 2026-05-09 deferred for `error.digest`. Nothing landed that's actively broken, but the cumulative coupling debt grew faster than the abstraction count.
