# Code Review — 2026-06-13

## Architecture & Coupling

- **[src/lib/import/blobSync.ts:69, 106 — listProjectBlobs ↔ syncImages key contract]** — `listProjectBlobs` keys the existing map by `blob.pathname`; `syncImages` looks up by the `key` we pass to `put`. The "pathname == put-key" invariant is enforced only by `addRandomSuffix: false` in the adapter (scripts/import-projects.ts:154). A flag flip or SDK change silently breaks dedup → full re-upload every time. Worth documenting on `BlobStore.put` or asserting in the adapter.
- **[scripts/import-projects.ts:149–159 — blobStore adapter]** — `Buffer.isBuffer(body) ? body : Buffer.from(body)` is a dead branch: `body` is typed `Uint8Array`, and `Buffer extends Uint8Array`. The `Buffer.from(uint8Array)` fallback would copy unnecessarily (extra MB-scale allocation per image) if it ever fired.
- **[src/app/api/auth/login/route.ts:12–28 — module-load construction]** — Limiter and config resolve once at cold-start. On Vercel that's per-cold-start, so flipping `IP_HASH_SECRET` or KV vars needs a deploy. Worth a one-line doc-comment so future operators don't expect runtime pickup.
- **[src/app/api/auth/login/route.ts:68–86 — `x-forwarded-for` trust]** — Vercel-only assumption is in the inline comment but not codified. A future self-hosted preview silently becomes spoofable. Consider `TRUST_X_FORWARDED_FOR=vercel` or a hostname assertion to fail loud.
- **[src/components/privacy/continuumLegalLinks.ts:22 — `relatedContinuumLegalLinks(currentPath)`]** — `currentPath: string` (not a union of the four known hrefs). A typo (`/privacy/continuum/dpai`) silently returns the full four-link list including the self-link; no compile or runtime guard. Tighten to `(typeof continuumLegalLinks)[number]["href"]`.
- **[src/components/privacy/LegalPageLayout.tsx:5–14 — `LegalSectionEntry` / `LegalRelatedLink` location]** — Both types live in the layout file, but `continuumLegalLinks.ts` needs `LegalRelatedLink` and imports back into a presentational module purely for a type. Hoist to a `legalTypes.ts` or co-locate with the data file.

## Observability

- **[src/lib/import/blobSync.ts:144–146, 155 — `errors.push(error); throw errors[0]`]** — Only the first error rethrows; if multiple uploads fail simultaneously (e.g. token expiry → 3 × 401), the others are silently dropped, no log. Destructive sweep+upload path should at least log every failure.
- **[scripts/import-projects.ts:194–198 — "couldn't list… uploading all"]** — Fail-open is sensible, but the warn doesn't note the gallery size about to be re-uploaded. On the 1 GB free tier a transient `list` failure can silently blow the budget.
- **[src/lib/import/blobSync.ts:191 — pruned-blob log]** — Logs `pathname` only — no URL, no bytes freed. Destructive operation deserves a real audit trail.
- **[scripts/import-projects.ts:413–418 — prune-failure warn]** — Catches and warns, returns success. Reasonable (rows are live), but no structured surface for "you have N orphans left from a partial sweep" — they accumulate silently across runs.
- **[src/app/api/auth/login/route.ts:122 — `console.info("rate limit exceeded", { key })`]** — Fires on every blocked request, not just the transition to blocked. Under sustained attack from one IP this floods function logs at request rate. Consider sampling or transition-only.

## Concurrency & Thread Safety

- **[src/lib/import/blobSync.ts:133–148 — drain pool, no AbortSignal]** — `errors.length === 0` guard prevents new claims but doesn't cancel in-flight `put`s. If one fails and siblings hang on a Vercel stall, `Promise.all` waits forever — no cancellation, no timeout. Liveness risk; thread an `AbortController` through `BlobStore.put`.
- **[scripts/import-projects.ts — project-level prune races a concurrent importer]** — If two importer runs touch the same project prefix, run-1's prune lists every blob and deletes anything not in run-1's DB row — including blobs run-2 just uploaded but hasn't DB-committed yet. No lockfile, no advisory lock. Realistic only for deliberate concurrent runs; worth a tiny per-project lockfile or a defaulted `--no-prune` warning.
- **[src/lib/import/blobSync.ts:127–155 — error-collection ordering]** — `errors[0]` is whichever rejected first by wall-clock. The failure test asserts a specific message; real runs with multiple simultaneous failures get a non-deterministic surface error.

## Accessibility

- **[src/app/privacy/continuum/responsible-use/page.tsx:35 — `<ol role="list">` with hidden markers]** — `role="list"` correctly restores semantics dropped by `list-style:none` in WebKit, and `aria-hidden` on `01`–`06` prevents the double-read. Tradeoff: AT-announced ordinals (1–6) won't match visible markers (01–06) for low-vision users who see and hear. Intentional, but worth a code comment saying so.
- **[src/components/privacy/AppleLegalLink.tsx:11–18 — new-tab link with no AT cue]** — `target="_blank"` opens a new tab with no visible "(opens in new tab)" or `aria-label`. Users on AT can lose focus context (WCAG 2.4.4). Same for the two inline external anchors in `terms/continuum/page.tsx`.
