# Code Review — 2026-10-06

Scope: merge `5ae5b6f` (`worktree-post-media` into `release`, branch commits dated 2026-10-03) and journal commit `6cc7e48`. Post media: video rendering from image syntax, admin "Upload video" through a signed client token, `db:import-posts` media upload to Blob, media cleanup on admin delete.

## Issues and Observations

- [x] **`src/app/api/admin/upload/video/route.ts` — `generateClientTokenFromReadWriteToken` call** — no `validUntil` is set, and the SDK default for this function is 30 seconds (`@vercel/blob` client, not the one-hour default of the `handleUpload` path). A slow 20 MiB upload, or an SDK retry after 30 s, can fail with an error the author can't act on. With `allowOverwrite` off, a retry after a lost response fails with "already exists" and leaves an orphan. Set an explicit lifetime sized to the cap. Whether Blob checks expiry at request start or end is not verified. **Resolved 2026-10-18**: `validUntil` is an hour out (`VIDEO_UPLOAD_TOKEN_LIFETIME_MS`, matching `handleUpload`); the 30 s default was confirmed in the installed SDK. When Blob checks the expiry is still not verified.
- [x] **`src/lib/content/rehypeVideo.ts` — `convertToVideo`; `rehypeVideo.test.ts` "inside a link" case** — `[![alt](x.mp4)](https://…)` renders a `<video controls>` inside an `<a>`, with a fallback `<a>` nested inside that: two kinds of invalid HTML, and the test asserts it as correct. The browser re-parses the markup, and a click on the controls can follow the outer link. Skip the conversion or the fallback link when the image sits inside a link. **Resolved 2026-10-18** (owner's pick: the player, then the link): `liftVideosOutOf` turns the link into a `<span>` with the videos first and the link after them. A link with nothing else to read shows its URL. A video URL with a scheme other than http(s) is no longer converted, so a fallback link can't carry `javascript:`.
- [ ] **`src/lib/import/postMediaRun.ts` — `deletePostMedia`; `scripts/import-posts.ts` — `pruneWrittenMedia` / `orphanedPostMedia`** — prefix ownership assumes a post never changes section. Case: a post moved life→tech still links to `posts/life/foo/…`, and a new life post takes slug `foo`. An import of the new post prunes the moved post's live blobs, and so does an admin delete of the new post. Content-addressed keys also let both posts share one URL, so deleting the moved post removes the new one's blob. Rare (section change plus slug reuse), but it destroys live media without a trace. One fix closes all three paths: freeze the section after import, or check every row's body before deleting a blob.
- [ ] **`src/components/admin/PostForm.tsx` — `handleVideoUploaded`** — inserts `![](url)` with the cursor in the empty alt. Nothing warns on save when a video has no alt, so it renders without an `aria-label`. The fallback link text "Video" isn't exposed while the player shows.
- [ ] **`src/lib/import/blobSync.ts` — `syncImages` size-mismatch error** — tells the author to re-run with `--reupload`, which `db:import-posts` doesn't have. On the post path the hint points to a flag that doesn't exist.
- [ ] **`src/lib/utils/markdownInsert.ts` — `insertionPoint`** — snaps to the end of the cursor's line only. With the cursor inside a fenced code block, the video markdown lands in the code. Inside a hard-wrapped paragraph or a list item, it splits the paragraph or restarts the list numbering. The preview shows it, so it is a UX issue, not data loss.
- [ ] **`src/lib/import/localFiles.ts` — `readFileInFolder`** — the containment check is lexical (`path.resolve` + `startsWith`), with no `realpath`. A symlink in the import folder that points outside it is followed, and its target is uploaded to a public URL. Low risk (own folder), but it defeats the check the function exists for.
- [ ] **`src/lib/import/postMedia.ts` — `collectDestinations`** — on a duplicate reference definition, `definitions.set` keeps the last; CommonMark renders the first. The definition that renders stays relative and resolves to nothing, without the warning the function's doc promises.
- [ ] **`scripts/import-posts.ts` — `makeMediaListing` / dry-run branch** — a dry run with a token always lists Blob, even when no post has media, which contradicts the "none for a run that never asks" doc. Fix the doc or the code.
- [x] **`src/app/api/feed/[section]/route.ts` — `markdownToHtml` on the body** — a relative video URL (`/videos/…`) and its fallback link stay relative in the Atom feed. Images already behave so; only `public/` videos are affected. **Resolved 2026-10-18**: the feed renders with `baseUrl: getSiteUrl()`, and `rehypeAbsoluteUrls` makes root-relative `src` and `href` absolute: videos, images and links. Post-relative paths and fragments stay as written.
- [ ] **`src/lib/utils/video.ts` — `VIDEO_SNIFF_HEADER_BYTES`** — repeats `SNIFF_HEADER_BYTES` (both 64) in `src/app/api/admin/upload/uploadHelpers.ts`. `detectImageMime` keeps its own `12` literal, and `hasCompatibleAvifBrand` a literal `16`, beside the new `ftyp.ts` offsets. Make the client-safe `lib/utils` values the single source.

## Observability

- [ ] **`src/lib/api/mediaCleanup.ts` — `runCleanup`** — the failure warning carries the error message only: no stack, no count. `deleteBlobs` deletes in sequential batches of 50, so a failure partway leaves an unknown split, and the per-blob lines are muted by `silent`. The log can't tell the admin what is left.

## Performance

- [x] **`src/components/blog/PostCard.tsx` + `rehypeVideo`** — list cards render the truncated body through the page pipeline, so a video near the top of a post shows as a `preload="metadata"` player on every list page. Nothing checks that an MP4 is faststart (index at the front); without it, the browser can fetch a large part of the file for metadata on each view, against the 10 GB allowance. Use `preload="none"` in cards, or check faststart at import and upload. **Resolved 2026-10-18**: cards render through a processor whose videos use `preload="none"` (`markdownToReact(…, { isListCard: true })`). Faststart is still unchecked on the post page itself.
- [ ] **`src/app/api/admin/posts/[id]/route.ts` — DELETE** — awaits one paginated list per section, then the deletes, before the 204. Awaiting is correct, but `after()` from `next/server` keeps the work alive without making the admin wait. Small at one admin.

## Risk Assessment

**Medium.** A large, well-tested feature (6.4k lines, about half tests) landed on `release` before any real Blob call ran. The load-bearing change for existing content is the admin delete: it now deletes Blob files under `posts/<section>/<slug>/` and `projects/<slug>/`, and the section-change case above can delete media another post still uses. The likeliest first failure on real use is the 30-second client token default on a slow video upload. The invalid nested markup is narrow (only a video wrapped in a link) but a test locks it in. Auth on the token route is sound: the server builds the key, the client can't pick a path, and overwrite is off. Contracts widened in CSP (site-wide `media-src` and `connect-src`) and in the delete routes' side effects.
