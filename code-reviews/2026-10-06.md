# Code Review — 2026-10-06

Scope: merge `5ae5b6f` (`worktree-post-media` into `release`, branch commits dated 2026-10-03) and journal commit `6cc7e48`. Post media: video rendering from image syntax, admin "Upload video" through a signed client token, `db:import-posts` media upload to Blob, media cleanup on admin delete.

## Issues and Observations

- [x] **`src/app/api/admin/upload/video/route.ts` — `generateClientTokenFromReadWriteToken` call** — no `validUntil` is set, and the SDK default for this function is 30 seconds (`@vercel/blob` client, not the one-hour default of the `handleUpload` path). A slow 20 MiB upload, or an SDK retry after 30 s, can fail with an error the author can't act on. With `allowOverwrite` off, a retry after a lost response fails with "already exists" and leaves an orphan. Set an explicit lifetime sized to the cap. Whether Blob checks expiry at request start or end is not verified. **Resolved 2026-10-18**: `validUntil` is an hour out (`VIDEO_UPLOAD_TOKEN_LIFETIME_MS`, matching `handleUpload`); the 30 s default was confirmed in the installed SDK. When Blob checks the expiry is still not verified.
- [x] **`src/lib/content/rehypeVideo.ts` — `convertToVideo`; `rehypeVideo.test.ts` "inside a link" case** — `[![alt](x.mp4)](https://…)` renders a `<video controls>` inside an `<a>`, with a fallback `<a>` nested inside that: two kinds of invalid HTML, and the test asserts it as correct. The browser re-parses the markup, and a click on the controls can follow the outer link. Skip the conversion or the fallback link when the image sits inside a link. **Resolved 2026-10-18** (owner's pick: the player, then the link): `liftVideosOutOf` turns the link into a `<span>` with the videos first and the link after them. A link with nothing else to read shows its URL. A video URL with a scheme other than http(s) is no longer converted, so a fallback link can't carry `javascript:`.
- [x] **`src/lib/import/postMediaRun.ts` — `deletePostMedia`; `scripts/import-posts.ts` — `pruneWrittenMedia` / `orphanedPostMedia`** — prefix ownership assumes a post never changes section. Case: a post moved life→tech still links to `posts/life/foo/…`, and a new life post takes slug `foo`. An import of the new post prunes the moved post's live blobs, and so does an admin delete of the new post. Content-addressed keys also let both posts share one URL, so deleting the moved post removes the new one's blob. Rare (section change plus slug reuse), but it destroys live media without a trace. One fix closes all three paths: freeze the section after import, or check every row's body before deleting a blob. **Resolved 2026-10-18** (owner's pick: the body check): `deletePostMedia` and `prunePostMedia` take a `NamedElsewhere` check and keep what it returns; `namedByOtherPosts` (`src/lib/db/postMediaReferences.ts`) asks the posts table, leaving out the swept post on import. A failed check deletes nothing. Guide and project bodies are not checked.
- [x] **`src/components/admin/PostForm.tsx` — `handleVideoUploaded`** — inserts `![](url)` with the cursor in the empty alt. Nothing warns on save when a video has no alt, so it renders without an `aria-label`. The fallback link text "Video" isn't exposed while the player shows. **Resolved 2026-10-18**: a hint under the editor counts the videos with no alt (`countVideosWithoutAlt`, which shares `rendersAsVideo` with the renderer); it doesn't block the save.
- [x] **`src/lib/import/blobSync.ts` — `syncImages` size-mismatch error** — tells the author to re-run with `--reupload`, which `db:import-posts` doesn't have. On the post path the hint points to a flag that doesn't exist. **Resolved 2026-10-18**: the caller passes the fix; the post path says to delete the blob, then re-run (`POST_MEDIA_COLLISION_FIX`).
- [x] **`src/lib/utils/markdownInsert.ts` — `insertionPoint`** — snaps to the end of the cursor's line only. With the cursor inside a fenced code block, the video markdown lands in the code. Inside a hard-wrapped paragraph or a list item, it splits the paragraph or restarts the list numbering. The preview shows it, so it is a UX issue, not data loss. **Resolved 2026-10-18**: the unit is the top-level markdown block (parsed): before the block a cursor starts, after the one it sits in.
- [x] **`src/lib/import/localFiles.ts` — `readFileInFolder`** — the containment check is lexical (`path.resolve` + `startsWith`), with no `realpath`. A symlink in the import folder that points outside it is followed, and its target is uploaded to a public URL. Low risk (own folder), but it defeats the check the function exists for. **Resolved 2026-10-18**: both the folder and the file go through `realpath`, and a file that lands outside is refused.
- [x] **`src/lib/import/postMedia.ts` — `collectDestinations`** — on a duplicate reference definition, `definitions.set` keeps the last; CommonMark renders the first. The definition that renders stays relative and resolves to nothing, without the warning the function's doc promises. **Resolved 2026-10-18**: the first wins, as in `mdast-util-to-hast` (checked in the installed package).
- [x] **`scripts/import-posts.ts` — `makeMediaListing` / dry-run branch** — a dry run with a token always lists Blob, even when no post has media, which contradicts the "none for a run that never asks" doc. Fix the doc or the code. **Resolved 2026-10-18**, both: the sweep needs the listing for any written post (an edit can drop a file), so it lists only when the run writes one, and the doc says so.
- [x] **`src/app/api/feed/[section]/route.ts` — `markdownToHtml` on the body** — a relative video URL (`/videos/…`) and its fallback link stay relative in the Atom feed. Images already behave so; only `public/` videos are affected. **Resolved 2026-10-18**: the feed renders with `baseUrl: getSiteUrl()`, and `rehypeAbsoluteUrls` makes root-relative `src` and `href` absolute: videos, images and links. Post-relative paths and fragments stay as written.
- [x] **`src/lib/utils/video.ts` — `VIDEO_SNIFF_HEADER_BYTES`** — repeats `SNIFF_HEADER_BYTES` (both 64) in `src/app/api/admin/upload/uploadHelpers.ts`. `detectImageMime` keeps its own `12` literal, and `hasCompatibleAvifBrand` a literal `16`, beside the new `ftyp.ts` offsets. Make the client-safe `lib/utils` values the single source. **Resolved 2026-10-18**: one `SNIFF_HEADER_BYTES` in `src/lib/utils/sniff.ts`; `FTYP_COMPATIBLE_BRANDS_OFFSET` and `FTYP_BRAND_BYTES` in `ftyp.ts`; `IMAGE_MAGIC_BYTES` named in the upload helpers.

## Risk Assessment

**Medium.** A large, well-tested feature (6.4k lines, about half tests) landed on `release` before any real Blob call ran. The load-bearing change for existing content is the admin delete: it now deletes Blob files under `posts/<section>/<slug>/` and `projects/<slug>/`, and the section-change case above can delete media another post still uses. The likeliest first failure on real use is the 30-second client token default on a slow video upload. The invalid nested markup is narrow (only a video wrapped in a link) but a test locks it in. Auth on the token route is sound: the server builds the key, the client can't pick a path, and overwrite is off. Contracts widened in CSP (site-wide `media-src` and `connect-src`) and in the delete routes' side effects.
