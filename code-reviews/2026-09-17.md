- [x] **src/lib/import/uploadPrune.ts — `reasonToRefuseApply` (L128-129)** — It refuses only when the database references zero uploads. ## Risk Assessment

**Medium.** Three changes set the rating:

- **Slug check.** `1520309` correctly lets import and bulk accept a title that empties the slug. But `postUpdateSchema` still runs that check, so those posts cannot be saved from the edit form. The last two reviews fixed this same kind of bug.
- **Title collapsing.** The rule "titles collapse at input" (`aef0665`) holds for the admin API only. All four file write paths store the raw value, and the journal's warning before `--overwrite` gives the wrong cause.
- **Upload sweep.** `d6e27ec` adds a script that permanently deletes production blobs. Its matching logic is sound: it reads all 8 models, and matching by UUID can only err toward keeping a blob. But its safety guard catches only a total database/store mismatch, the script never prints its target, and the documented credential path loads an env file the scripts do not read.

The public content, feed, cron and guide changes do not change live behaviour. What is left there is stale comments and docs that could mislead a later edit, one helper that is not used everywhere, one duplicate that is still there, and one test that always passes. No API contract widened. The contract that narrowed is the one that should not have: PUT still rejects titles that the create paths now accept.
