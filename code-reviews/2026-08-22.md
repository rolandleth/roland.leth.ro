## Issues and Observations

- [x] **`src/lib/auth/middlewareBypass.ts` — `requireAdminPageSession` /
  `src/app/admin/adminPageContract.test.ts` — `admin page-body session guard`** —
  the contract test matches `source.includes("requireAdminPageSession(")`, which
  passes for an un-awaited call. The function's own docblock names this exact
  hazard and states no lint rule catches it, so the one mechanism that could is
  the test — and it doesn't. Matching `await requireAdminPageSession(` closes it
  for the cost of six characters. **Resolved 2026-08-22**: added an `awaits every
  requireAdminPageSession call` test that strips comments, splits on each call
  site, and requires `await` immediately before every one; verified it fails (and
  only it fails) with the `await` removed from `guides/new/page.tsx`.

- [x] **`src/lib/db/posts.ts` — `makeBlogPageCache`** — the count is read by
  calling `getSectionPageCount` (itself an `unstable_cache`) from inside another
  `unstable_cache` callback. The outer entry stores the value it saw, so a warm
  page entry serves a `totalPages` frozen at its own generation while
  `isRealPage` reads the count entry live. That nesting is the mechanism behind
  the divergence the docblock describes; nothing records it as the cause, so the
  next reader sees "shared cache entry" and a backstop with no link between them.
  **Resolved 2026-08-22**: docblock now names the nesting, says the callback runs
  only on a miss so a warm entry returns a frozen `totalPages`, and warns against
  reading "shared cache entry" as "shared at read time". Behaviour unchanged —
  the nesting is the right trade against a second independent `count()`.

- [x] **`src/app/blog/[section]/(list)/page.test.tsx` — the `searchParams`
  guard** — strips only `//` line comments before the substring check, so a
  `/* */` block or a JSDoc mentioning `searchParams` fails the test with nothing
  wrong. Fails in the safe direction, but the comment reads as if comments are
  handled generally. **Resolved 2026-08-22**: extracted `stripComments` into
  `src/test/sourceText.ts` (handles block comments and JSDoc) and routed this
  test through it. Also applied to `p/[page]/page.test.tsx`'s `cache()`
  assertions, which had the same weakness in the worse direction — those are
  presence checks, so a comment could have satisfied them against a page that no
  longer wrapped anything.

## Observability

- [x] **`src/lib/utils/errorMessage.ts` — `errorDetails`** — the docblock still
  promises a "JSON-safe object", but `{...error}` now copies whatever own
  enumerable properties the error carries. A `BigInt`, a function, or a circular
  own property makes `JSON.stringify` throw inside the log pipeline — a failure
  while reporting a failure, which is the worst place for one. The guarantee is
  now conditional on the error's shape and nothing states the condition.
  **Resolved 2026-08-22**: made the guarantee true rather than documenting the
  hole. Each extra property is now filtered through `isJsonSerializable`, which
  defers to `JSON.stringify` itself in a `try`/`catch` instead of hand-rolling a
  type check — so a value with `toJSON` (a `Date`, a Prisma timestamp) is kept
  while a `BigInt`, cycle, or function is dropped. Per-property, so one hostile
  field doesn't cost the diagnostics beside it; `message`/`stack`/`name` are
  never filtered.

- [x] **`src/lib/utils/errorMessage.ts` — `errorDetails`** — the same spread
  widens what reaches a log line from `{message, stack}` to everything the error
  hangs off itself, unredacted and unbounded. Prisma's `meta` naming columns is
  the intended win; a subclass carrying a request body, a token, or a large
  payload is the same mechanism with a different outcome. Low impact on a
  single-user site — worth knowing the contract changed shape, not just size.
  **Resolved 2026-08-22**: documented rather than restricted. The docblock now
  states the return contract is deliberately wide, unredacted, and unbounded, and
  names the thing to remember before attaching a payload to a custom error. No
  redaction layer added — a single-user site with no error subclasses of its own
  doesn't have the problem yet, and a denylist that has never been exercised is
  the kind of machinery that rots.

## Performance

- [x] **`src/components/admin/{Posts,Projects,Guides}Tab.tsx`** — the
  out-of-range redirect lives in the pager, which renders after the tab's
  `findMany`/`count` have already run, so a bad `?page=` pays for the query it
  exists to skip. The cost is small (Postgres skips only rows that exist, and the
  corpus is tiny) and centralizing was the right trade against duplicating the
  check three times; noting it so the ordering is a known choice rather than a
  surprise. **Resolved 2026-08-22**: recorded in `AdminPagination`'s docblock as
  an accepted cost, with the reason skipping it isn't free (it needs the page
  count before the list query — the per-tab duplication centralizing avoided) and
  the bound that keeps it cheap (`MAX_SAFE_ADMIN_PAGE`). No code change.

## Risk Assessment

**Low.** The headline change is a real security fix — `requireAdminPageSession`
extended from two pages to all seven data-reading admin bodies, with a contract
test, per-page bypass-logging tests, and a closed `AdminPageTag` union replacing
hand-typed strings. It narrows an exposure rather than widening one, and the
`adminTags.ts` split resolves the import cycle cleanly. Type-check, lint, and all
2,312 tests pass. Two things keep this from being trivially low: `errorDetails`
widened a logging contract in a way its own docblock no longer fully describes,
and the admin guard's single documented failure mode — a missing `await` — is
still uncovered by the test written to enforce it. Neither is a live defect. The
`prefers-reduced-motion` work is additive and well-tested, including a test that
pins Framer's default so the wrapper can't become quietly redundant.

**Post-remediation: Low, and lower than the above.** Both caveats are closed —
the `await` gap now has a test that was verified to fail, and `errorDetails` is
genuinely JSON-safe rather than documented as conditionally so. See
`Remediation, same day` in the notes.

- One new shared helper: `src/test/sourceText.ts` — `stripComments`, for the
  three tests that assert on source text because the thing they protect is
  syntactic (`searchParams` absence, the `cache()` wrapper, a missing `await`)

  scanner, not a tokenizer, and the docblock names the failure it can't handle

  source-text assertion — a guard that has never been seen to fail is a guard
