# Code Review — 2026-04-27

## Issues and Observations

- **[src/lib/auth.ts — verifyCredentials()]** — No try/catch around `bcrypt.compare`; a native-binding failure or corrupt hash throws and propagates as a 500, breaking the timing-safe no-op path and potentially leaking the email-match branch via a differential error. Wrap in try/catch, log, return `false`.

- **[src/lib/auth.ts — cookie `secure` flag]** — `secure: process.env.NODE_ENV === "production"` means Vercel preview deployments (which are HTTPS but not `NODE_ENV=production`) issue non-secure cookies. Gate on `VERCEL_ENV !== "development"` or the request protocol instead.

- **[src/app/api/auth/login/route.ts — rate-limit key "global"]** — A single shared bucket means any attacker can exhaust the 5-req window and lock out the real admin. Partition by IP (or IP+UA) so brute-force attempts don't consume the owner's quota.

- **[src/components/projects/ProjectContent.tsx — accentColor CSS injection]** — `accentColor` is interpolated directly into a `<style>` block without sanitization. Even though only admin-authored, a malformed value (`}body{...`) closes the rule and injects arbitrary CSS. Validate against a hex regex before injection, or set the custom property via `style={{ "--color-header-accent": accent }}` on a wrapper element (bypasses the injection vector entirely).

- **[src/components/projects/ProjectContent.tsx — sections[activeTab] stale state]** — `activeTab` can survive a sections-count reduction (e.g. edit removes the last section), leaving a stale index. The `activeSection &&` guard hides it visually but the state remains invalid. Clamp `activeTab` in a `useEffect` watching `sections.length`.

- **[src/components/admin/ProjectForm.tsx — `||` coercion]** — Uses `value || null` to convert empty strings to null in the submit payload. This also drops any legitimately falsy-but-non-empty value (unlikely today, brittle as fields are added). Use `value === "" ? null : value` explicitly.

- **[src/components/admin/useAdminResource.ts — no request timeout]** — A hung request leaves the form permanently stuck in `isSubmitting` with no user recourse. Add an `AbortController` with a timeout (e.g. 30 s) and surface a timeout-specific error.

- **[src/components/admin/useOrderedList.ts — add() sortOrder collision]** — `sortOrder` is set to `value.length` at call time, so two `add()` calls within the same render cycle produce identical sortOrders. Use `Math.max(...existing.map(x => x.sortOrder), -1) + 1` or a functional updater to avoid collisions.

## Architecture & Coupling

- **[src/app/api/cron/ping/route.ts — 502 on Redis failure]** — Returning 502 on a Redis ping failure causes Vercel's cron runner to retry on 5xx, compounding load on a recovering dependency. Return 200 with a structured `{ ok: false, redis: "down" }` body so retries don't amplify the outage.

## Observability

- **[src/lib/auth.ts — verifyToken() admin-claim log level]** — A valid JWT signature with a missing/false `admin` claim is logged at `console.error`. This is an expected denial path (e.g. stale tokens), not an integrity failure — it will pollute error alerting. Downgrade to `console.warn`.

- **[src/components/projects/ProjectContent.tsx — image error handling]** — Failed image loads produce no signal (no `onError`, no console warning, no placeholder). Breakage in production is invisible; add an `onError` handler that at minimum logs a warning.

## Code Quality

- **[src/lib/env.ts — SESSION_SECRET minimum length]** — `ADMIN_HASH_PASSWORD` gets a hex regex; `SESSION_SECRET` has no length or entropy check. A 4-char value boots fine and silently weakens every session. Add `.min(32)` (or similar) at the schema level so misconfiguration fails at startup.

- **[src/lib/env.ts — readRequired() single varName]** — `EnvConfigError` exposes only the first failing var's name even when multiple are missing; the error message contains all, but callers branching programmatically can't enumerate them. Expose `varNames: string[]` so health-check routes can report all misconfigured vars at once.

- **[src/components/admin/ProjectForm.tsx — sortOrder client min]** — Negative values are accepted on the client (only backend Zod rejects them). Add `min={0}` to the input and clamp in the NaN guard so UI and schema invariants match without a server round-trip.

## Missing Tests

- **[src/lib/auth.test.ts — cookie `secure` in non-production]** — The `NODE_ENV === "production"` gate is exactly the kind of conditional that breaks on preview deployments and is currently untested. Add a test that stubs `NODE_ENV` and asserts the `secure` option.

- **[src/app/api/cron/ping/route.test.ts — timing-safety coverage]** — The constant-time dummy-compare path is the entire point of `isAuthorized` but is untested. Add a test that spies on `crypto.timingSafeEqual` and asserts it's called on both equal- and unequal-length inputs.

- **[src/lib/env.test.ts — multi-issue aggregation]** — Only single-failure paths are tested; if multiple vars are missing simultaneously, there's no assertion on which ones are reported. Add a test with two missing vars.

- **[src/lib/env.test.ts — DATABASE_URL / SESSION_SECRET baseline]** — Both are production-critical but have zero schema-level coverage. Add missing/empty cases so any future validation tightening has a regression net.

- **[src/components/admin/ProjectForm.tsx — no tests]** — 13 fields, NaN guards, and null-coercion logic with zero coverage. At minimum: sortOrder partial-input NaN guard, empty-string→null payload shape, error rendered via `role="alert"`.

- **[src/components/projects/ProjectContent.test.tsx — coverage gaps]** — Single regression test (null accent). Valid-accent rendering, dynamic `<style>` injection, tab switching, and the `activeTab`-out-of-range guard are all untested.

- **[src/components/admin/useAdminResource.test.tsx — network/error-shape gaps]** — `readErrorMessage` branches (fetch rejection, non-JSON body, `{ error: "" }`, `{ error: null }`) are untested; each branch is a user-facing failure path.

- **[src/components/admin/useAdminResource.test.tsx — double-submit]** — `isSubmitting` guard against concurrent submits is not tested; a double-click can fire two simultaneous requests.

- **[src/components/admin/useOrderedList.test.tsx — edge cases]** — Missing: `add()` on empty list, two `add()` calls same render (sortOrder collision), `update({})` no-op, `move(-1)`. Also clarify whether `move()` out-of-bounds firing `onChange` with an unchanged list is intentional.

## Risk Assessment

**Medium.** This batch is primarily security hardening (timing-safe auth, typed env errors, NaN guards, CSS variable fallbacks) and is well-structured. Two correctness gaps warrant prompt attention: `verifyCredentials` has no protection against bcrypt exceptions bubbling as 500s, and the global rate-limit key allows an attacker to lock out the admin entirely. The `||`-coercion pattern in `ProjectForm` is a latent data-loss hazard as new fields are added. The CSS injection in `ProjectContent` is low-risk today (admin-only) but should be closed before accentColor becomes any less controlled. Test coverage for the new security primitives (timing-safe path, cookie secure flag, env multi-issue) is the most urgent gap — these are exactly the invariants that are hard to spot-check by reading.
