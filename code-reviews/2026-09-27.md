## Issues and Observations

- [x] **`src/components/loan-calculator/LoanCalculatorInput.tsx:132` — `NumberField` className** — `aria-[invalid=true]:border-red-500[&::-webkit-inner-spin-button]:appearance-none` is two utilities fused into one token (missing space). Tailwind generates neither, so an invalid field gets no red border and the WebKit inner spin button comes back. The per-field error UX from 5054a52 loses its visual cue. _Resolved: split, with a class-token test that fails on the fused form._
- [x] **`src/app/api/admin/projects/[id]/route.ts:203-206` — DELETE `countProjectReferences` comment** — says a guide pointed at the project mid-delete "aborts one of the two". It does not: the guide/topic write paths check the project in `src/lib/db/guideValidation.ts` with plain `prisma.project.findUnique` outside any transaction, and Postgres SSI only detects conflicts between serializable transactions. A concurrent guide write can still leave a dangling `projectSlug` (no FK by design). Single-admin, so rare; fix the comment or move the guide check into a serializable transaction. _Resolved: comment rewritten as a `simplified:` note naming the gap and the upgrade path; behaviour unchanged by decision._
- [x] **`src/lib/import/postImport.ts` — `resolveSlug`** — the import and bulk-upload path has no `SLUG_MAX_LENGTH` check (`createSlug` has no cap, `postFileSchema` has no slug), while `postCreateSchema`, `SlugField` and `requireManifestSlug`+`projectCreateSchema` all cap at 100. A long `slug:` imports fine but the same post could not be created through the admin form. Same class as the journal watch-out on normalization; decide whether import enforces the canonical contract. _Resolved: a normalized slug over the limit is skipped with its own reason, never cut._
- [x] **`scripts/import-posts.ts:70-85` — inline argv parser** — keeps the `--`-only flag check that `src/lib/import/cliArgs.ts` documents as the bug it fixes (`-dry-run` becomes a positional). With one folder argument the `positionals.length !== 1` guard catches it; `import-posts -dry-run` alone treats `-dry-run` as the folder. DRY and consistency gap; `parseCliArgs` would need a prefix/value form (`--section=`) to replace it. _Resolved: `parseCliArgs` gained value flags (`--name=value` only) and reports a repeated one; import-posts now uses it and refuses a repeated `--section`._
- [x] **`src/components/admin/GuideForm.tsx`, `GuideTopicForm.tsx` — `SlugField`** — guide and topic slugs now get the browser `pattern` and `maxLength` they did not have before. A stored non-canonical guide/topic slug would now block every save of that row in the browser. Confirm no such rows exist (the server already rejects them per the journal, so likely none). _No change needed: the guide and topic schemas already require `canonicalSlug` (`src/lib/api/schemas.ts`), so such a row already failed on the server; the pattern only moves the failure earlier._
- [x] **`src/components/loan-calculator/LoanCalculatorInput.tsx` — error `<p>`** — no `role="alert"` or `aria-live`; screen readers only hear the error on refocus via `aria-describedby`. Minor a11y gap. _Resolved: the error `<p>` is always mounted with `aria-live="polite"` (a region mounted with its content stays silent); `empty:mt-0` keeps the layout unchanged when there is no error._

## Risk Assessment

**Medium.** The slug work narrows contracts on purpose: post and project creates now require an authored canonical slug, updates strip it, and project DELETE refuses while guides reference the project. Route, schema and form tests cover these well. The `useOrderedList` rewrite (key-addressed, functional updates) touches every admin list editor and has solid stale-closure tests. The one user-visible defect is the fused Tailwind class, which silently drops the invalid-field border added in the same commit. The DELETE concurrency comment overstates what Serializable buys. The remaining items are consistency gaps between the import path and the admin/API path.
