## Issues and Observations

- ~~**`src/lib/posts.ts` — `postBySlugWrappers` / `src/lib/projects.ts` — `projectBySlugWrappers`**~~ — resolved. Extracted `createBoundedWrapperCache` in `src/lib/boundedCache.ts` (FIFO eviction at 256 entries, LRU touch on hit) and swapped both call sites. 404 probes can no longer grow either map unbounded.
- **`src/lib/legacySlug.ts` — `cachedLookup`** — the `unstable_cache` wrapper has no tags, only `revalidate: 300`. A newly-published post that collides with a cached miss stays invisible for up to 5 minutes; add `["posts", "projects"]` tags so `revalidatePostSection` busts it.
- **`src/app/api/feed/[section]/route.ts` — canonical `<id>` and `<link>`** — uses `new URL(request.url).origin` as the Atom feed base, making entry `<id>` values vary by the request's host (preview URLs, proxy domains). Prefer `siteBase()` (used by `sitemap.ts`) for a stable, canonical origin.
- **`src/app/api/cron/ping/route.ts`** — `KV_REST_API_URL` is never checked despite `Redis.fromEnv()` requiring it; `hasRedis` only gates on `KV_REST_API_TOKEN`, so a config with only the token throws at module-load time with no diagnostic. Check both vars before constructing the client.
- **`src/lib/auth.ts` — `verifyToken` payload cast** — payload is cast `as SessionPayload` without runtime validation; a valid-signed JWT with a different shape still authenticates. `isAuthenticated` in `proxy.ts` checks only `payload !== null`, not `payload.admin === true`. Add a shape guard on the payload.
- ~~**`src/app/api/admin/projects/[id]/route.ts` + `route.ts` POST — `sortOrder` isolation**~~ — resolved. All three `$transaction` calls (POST, PUT, DELETE) now run at `Prisma.TransactionIsolationLevel.Serializable`. Postgres aborts one of two conflicting transactions with a serialization_failure instead of silently producing duplicate sortOrder values. No retry loop — at single-admin volumes conflicts are essentially impossible.
- ~~**`src/app/api/admin/posts/[id]/route.ts` PUT — no transaction**~~ — skipped. A single `prisma.update` is already atomic at the SQL level; the review's "field interleaving" concern would require multi-statement partial updates, which this handler doesn't emit. Concurrent-edit last-write-wins is a separate concern covered by the site-wide single-writer invariant in `dev-journal/2026-04-20.md`.
- **`src/lib/schemas.ts` — `accentColor`** — accepted as a free string with no hex/CSS validation. A non-color value renders a broken page. Add a `/^#[0-9a-fA-F]{3,8}$/` refine.
- **`src/lib/schemas.ts` — uncapped nested fields** — `role`, link `label`, link `url`, section image `caption` have no `.max()` bounds while top-level post/project fields do. Cap at sensible lengths (e.g. `label: 60`, `caption: 300`) for consistency.
- **`src/app/api/admin/posts/route.ts` GET + `src/app/api/admin/projects/route.ts` GET** — unbounded list endpoints returning every row; the admin UI paginates through the lib helpers separately so these routes appear dead. Confirm and delete, or add pagination.
- **`src/app/privacy/page.tsx` + `src/app/privacy/body-tracking/page.tsx`** — duplicate page skeleton (sections array + `PrivacySection.map`) with inconsistent date formatting (`"Apr 7, 2026"` vs `"Apr 07, 2026"`). Share a `<PrivacyPage title sections lastUpdated>` component.
- **`src/lib/format.ts` — `DATETIME_REGEX`** — used without anchors so `postDatetimeToISO` accepts `"garbage2024-06-15-1200garbage"` as valid. Add anchors (`^...$`) or `fullMatch` guard.
- ~~**`prisma/schema.prisma` — `Post.datetime String`**~~ — deferred with rationale inline on the field. Migrating to `DateTime` would touch every caller (admin form, create/update routes, sitemap, feed, `currentDatetimeString`, `yearFromDatetime`, `postDatetimeToISO`) and their tests, for no behavioural win — lex-sort on `yyyy-MM-dd-HHmm` already orders chronologically. Revisit when timezone-aware queries or cross-date range filtering become load-bearing.
- ~~**`prisma/schema.prisma` — missing composite index**~~ — resolved. Added `@@index([section, published, datetime])` to `Post`. Run `yarn db:push` to apply.

## Architecture & Coupling

- **`src/lib/projects.ts` imports `PAGE_SIZE` from `@/lib/posts`** — couples two otherwise-independent domains. Extract `PAGE_SIZE` to a neutral module (e.g. `lib/pagination.ts`) or duplicate it.
- **`src/app/api/admin/posts/[id]/route.ts` PUT** strips `undefined` via `Object.fromEntries`; **`src/app/api/admin/projects/[id]/route.ts` PUT** relies on Prisma treating `undefined` as "skip". Two opposite conventions for the same problem across sibling handlers — standardise on one.
- ~~**`src/components/projects/ProjectContent.tsx` — `--color-header-accent` via `useEffect`**~~ — resolved. Rule now renders as an inline JSX `<style>` block, putting the override in the component's first paint instead of a post-mount effect. SPA navigation no longer flashes through the default accent.
- **`src/proxy.ts` — admin-API boundary at `startsWith("/api/admin/")`** — a request to `/api/admin` (no trailing slash) bypasses the auth check and falls through the generic `/api/` pass-through. Not currently routable, but a future accidental route at that path would be unauthenticated.
- **`src/proxy.ts` — `pathname.includes(".")` dot filter** — also excludes any legitimate slug containing a dot (`.NET`, `node.js`, `v1.2`). The matcher already handles static assets; this redundant check causes false exclusions.
- **`src/proxy.ts` — `FEED_REGEX` default section** — falls back to `SECTIONS[0]` (tech). If `SECTIONS` is ever reordered, `/feed` silently changes meaning. Pin explicitly rather than relying on array order.
- **`src/app/admin/(protected)/layout.tsx` — auth scope overstated** — the layout's "defense-in-depth" only guards page rendering; `generateMetadata` functions in `posts/[id]/edit/page.tsx` and `projects/[id]/edit/page.tsx` hit the DB before any auth check runs. Middleware is the real gate; the layout comment overstates its reach.
- ~~**`src/components/admin/PostForm.tsx` + `ProjectForm.tsx` — per-field `useState` slices**~~ — resolved. Each form now carries one state object plus a memoized `setField(name, value)` callback. PostForm went 7 → 1 useState; ProjectForm went 13 → 1.
- ~~**`src/components/admin/LinkManager.tsx` + `SectionManager.tsx` — duplicated reorder logic**~~ — resolved. Extracted `useOrderedList<T>` (`src/components/admin/useOrderedList.ts`) — generates `_key`, compacts `sortOrder` on remove, defers move to `moveAndReorder`. Applied to both managers and SectionCard's nested image list.
- ~~**No startup env validation**~~ — resolved. Centralized in `src/lib/env.ts` with typed accessors (`getDatabaseUrl`, `getSessionSecret`, `getAdminCredentials`, `getCronSecret`, `getRedisConfig`). Required vars throw with the same message format the existing code emitted; optional vars return `null` so callers can choose between graceful degradation and 500.

## Concurrency & Thread Safety

- **`src/components/admin/ImageUpload.tsx` — `handleFileChange`** — two quick file selections race: both uploads run in parallel and `onChange(url)` may fire with the older URL last. No abort controller or sequencing. `setIsUploading(false)` is also not guarded against unmount.
- **`src/components/admin/IsFeaturedToggle.tsx` + `ProjectSortOrderInput.tsx`** — rapid interaction fires parallel PUTs; the optimistic UI can end up out of sync with server state (last-write-wins on server, UI reflects last click). Add in-flight guards or debounce.
- **`src/components/admin/useAdminResource.ts` — `save` / `remove`** — no abort controller; if the user navigates away while a request is in flight, `setState` runs on an unmounted component. The disabled-button mitigation doesn't cover navigation.
- **`src/components/admin/ProjectSortOrderInput.tsx` — blur-triggered save** — tabbing through inputs fires multiple simultaneous PUTs on the same project. Debounce or gate on value change.

## Observability

- **`src/lib/auth.ts` — `verifyToken`** — swallows every `jose` error as `null`; expired, tampered, and malformed tokens are indistinguishable in logs. Log the error type at debug level before returning null.
- **`src/proxy.ts` — `isAuthenticated`** — returns `false` for both "no cookie" and "bad signature" with no logging. A sudden spike in invalid sessions (e.g. after secret rotation) would be invisible.
- **`src/app/api/auth/login/route.ts`** — no logging anywhere: rate-limit hits, bad credentials, and `createSession` calls all produce zero output. At minimum log 401 count/timestamp.
- **`src/app/api/admin/**` catch blocks** — all log with bare `console.error(error)` and no route/operation tag. Vercel logs can't distinguish "unique constraint failed on posts PUT" from any other Prisma error. Prefix with `[api:admin:posts:PUT]` (or equivalent).
- **`src/app/api/cron/ping/route.ts`** — missing-secret returns 500 silently; `redis.ping()` has no try/catch. A Redis outage or env regression produces no structured log.
- **`src/app/api/upload/route.ts`** — `await request.formData()` is unwrapped; a malformed multipart body throws as an unhandled rejection.
- **`src/components/admin/AdminNav.tsx` — `handleLogout`** — swallows the logout response; a failed logout silently redirects the user to `/admin/login` leaving the session cookie alive. No try/catch around the fetch.
- **`src/components/admin/IsFeaturedToggle.tsx` + `ProjectSortOrderInput.tsx`** — `fetch` rejections (network down) leave `isSaving=true` forever with no recovery or user feedback; neither has a `try/catch` around the fetch call.
- **Error feedback elements** — `<p className="text-sm text-red-500">` in `LoginForm`, `PostForm`, `ProjectForm`, `IsFeaturedToggle`, `ProjectSortOrderInput`, `ImageUpload` are not wrapped in `role="alert"` or `aria-live="polite"`; screen readers won't announce submission failures.

## Risk Assessment

**Medium-High.** The codebase is well-structured and the recent simplify/review arcs left the data layer and feed code in good shape. The highest-risk items cluster around three themes: (1) **auth observability** — `verifyToken`, `isAuthenticated`, and the login route all swallow or never log errors, making secret-rotation incidents or token-tampering attempts invisible in production; (2) **admin concurrency** — `sortOrder`, `ImageUpload`, and `IsFeaturedToggle` all have documented or latent race windows that grow more dangerous if a second admin account is ever added; (3) **test coverage gaps** — the login route, proxy redirect semantics, `loanCalculator`, and most admin component mutation paths are entirely untested, meaning regressions in the most security- and correctness-sensitive areas ship silently. Config-level items (`lucide-react@^1.7.0`, missing `typecheck` script, no startup env validation) are lower-risk but worth cleaning up.
