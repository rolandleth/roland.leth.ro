# Code Review — 2026-06-29

## Issues and Observations

- [x] **`src/app/projects/[slug]/page.tsx:87,94` — JSON-LD via unescaped `JSON.stringify`** — `JSON.stringify(jsonLd)` is dropped into `<script type="application/ld+json" dangerouslySetInnerHTML>`. `JSON.stringify` does not escape `<`, `>`, `&`, U+2028, U+2029. A FAQ Q/A (or `summary`/`name`) containing literal `</script>` would close the tag and inject arbitrary HTML. Admin-authored content narrows the blast radius, but a copy-paste from external docs would silently corrupt the page. Replace those characters with unicode escapes before embedding. **Resolved 2026-06-29**: added `safeJsonLdString` in `projectJsonLd.ts` (commit `1ca0bd5`).
- [x] **`src/lib/content/projectJsonLd.ts:115` — AggregateOffer silently picks first currency** — When `offers` mixes currencies, the node labels the price range with `offers[0].priceCurrency` and pairs it with `lowPrice`/`highPrice` from a numeric sort over *all* prices. Mislabels one of the bounds. Comment acknowledges the single-currency assumption; no runtime guard. **Resolved 2026-06-29**: mixed-currency now emits an array of `Offer` nodes (schema.org-correct) instead of a mislabeled AggregateOffer (commit `1ca0bd5`).
- **`src/components/projects/ProjectSectionCarousel.tsx:139` — `onLoad` race against rapid image swap** — Under fast nav, an earlier image's `onLoad` resolves after the URL has changed, so `aspectRatio` is set from the new image while the prior one is still painted. No index/id guard inside the handler; stage height jumps unpredictably. **Correction 2026-06-29**: not reproducible — browsers abort in-flight image loads on `src` change, so the aborted request never fires `load`. Finding withdrawn; only the dev-warn for invalid dimensions was kept.
- **`src/components/projects/ProjectImageLightbox.tsx:60` — body-scroll lock has no stack** — Stores `previousOverflow` straight on `document.body.style`. Safe as the only modal today; a second concurrent modal would clobber the outer lock on restore. Flag for the next dialog addition.
- [x] **`scripts/import-projects.ts` — `writeProject` transaction lacks isolation level** — `prisma.$transaction` runs at Prisma's READ_COMMITTED default. API routes (`src/app/api/admin/projects/route.ts:55`, `[id]/route.ts:143`) use Serializable for the same write shape. Concurrent re-import + admin edit on the same slug observes a race window the API path is explicitly hardened against. **Resolved 2026-06-29**: added `isolationLevel: Serializable` to the `$transaction` call (commit `5637cf1`).
- **`src/lib/content/metadata.ts:44` — `ogTitle` can exceed SERP truncation** — `metaTitle` is capped at 60 chars by zod; appending " | Roland Leth" (~14) brings the OG/Twitter title to ~74, past Google's typical truncation. Not a bug — cap `metaTitle` at ~46 if you want a clean SERP.

## Architecture & Coupling

- **`src/lib/client/navigationType.ts:10-11` — module-level singleton state** — Two module-scoped booleans (`cameFromBackForward`, `isInstalled`) are the contract that `motion.ts` reads from. Works because exactly one tracker is mounted in the root layout; globalThis-style state in a library module is harder to reason about than a context. Acceptable for the current footprint; revisit if a second tracker (per-route, per-feature) appears.
- **`src/lib/client/motion.ts:21` — SSR/hydration agreement is path-dependent** — `fadeUp()` reads `isBackForwardNavigation()` at call time. On both server and first client render the module value is `false`, so HTML agrees. Wasted payload through the `unstable_cache` layer (a few KB per row × N rows × 5 FAQs). Either narrow the gallery type or define a lean select for list surfaces. **Correction 2026-06-29**: incorrect finding — `gallerySelect` at lines 101-129 does not include `faqs`, only sections (first image each). Finding withdrawn.
- **`src/components/projects/ProjectSectionCarousel.tsx` — `AnimatePresence` and slide direction removed** — The carousel now swaps images instantly (no slide-in/out). Direction prop was deleted from the parent contract. UX change is material — confirm manually in browser that the lack of directional feedback isn't disorienting; dev-journal documents this as intentional.

## Observability

- [x] **`src/lib/client/navigationType.ts:40-42` — Navigation API fallback is undetectable** — Silent early-return when `window.navigation` is missing (Firefox / Safari ≤17). No counter, log, or DOM hint. If users report "the entrance still replays on back", there's no way to confirm the fallback path without browser inspection. A one-shot `console.warn` or `data-nav-tracker="missing"` on `<body>` would make it diagnosable. **Resolved 2026-06-29**: `<html>` now carries `data-navigation-api="available|missing"` set at install time (commit `4ce9832`).
- [x] **`src/components/projects/ProjectSectionCarousel.tsx:142` — invalid `naturalWidth/Height` silently ignored** — Reasonable guard, but combined with the `aspectRatio === null → h-120` fallback, an image that never reports dimensions stays at the default forever and nothing surfaces the case. **Resolved 2026-06-29**: dev-only `console.warn` now fires when `naturalWidth`/`naturalHeight` is ≤ 0 (commit `9d20f8a`).
- [x] **`src/app/projects/[slug]/page.tsx:65` — FAQ Markdown failure 500s the whole page** — `Promise.all` over `markdownToReact(f.answer)` propagates any single answer's parse error to Next's error boundary. `Promise.allSettled` with a per-FAQ fallback `<p>` would degrade gracefully, or validate submit-time against the same pipeline (the admin's preview-only catch isn't sufficient). **Resolved 2026-06-29**: switched to `Promise.allSettled`; each rejected answer renders an inline `<p>{f.answer}</p>` and logs to `console.error` (commit `7bb176c`).
- **`src/components/admin/MarkdownEditor.tsx:58-68` — preview-only catch lets unparseable Markdown ship to DB** — A FAQ answer that throws in preview can still be submitted; public render then 500s per the previous finding. Validate against the same pipeline on submit, not just preview.

## Risk Assessment

**Medium.** Bulk landed across two themes: the FAQ + SEO data layer (schema, JSON-LD, admin, public render) and gallery/animation polish. Schema changes are additive and nullable, cascade-delete on `ProjectFaq` is correct, and API routes use Serializable isolation. The 2026-06-28 watch-out about `scripts/import-projects.ts` duplicating mappers was *reconciled* this session via `toFaqCreate`. Two material risks remain: (1) JSON-LD is emitted via `dangerouslySetInnerHTML` without escaping `<`/`>`/`&`, exposing a self-inflicted XSS / page-corruption vector if any FAQ ever contains `</script>` or HTML; (2) end-to-end wiring for the back/forward animation-skip and the gallery swipe gestures is untested by design (open threads acknowledge this). The Navigation-API silent fallback is observable only via the user-visible symptom in production. Entrance animations were *removed* across the gallery, lightbox, and tabpanel — a meaningful UX change worth a manual cross-browser pass.
