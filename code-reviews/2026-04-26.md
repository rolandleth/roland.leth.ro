# Code Review — 2026-04-26

## Issues and Observations

- ~~**`src/components/projects/ProjectContent.tsx:77` — `accentColor` (nullable) used in `color-mix()` instead of `accent` fallback**~~ — resolved. The icon-fallback `color-mix` now interpolates the `accent` constant (which falls back to `var(--color-accent)`), and a render test in `ProjectContent.test.tsx` pins that no `undefined`/`null` leaks into any style attribute.

- ~~**`src/components/admin/ProjectForm.tsx` — `Number(e.target.value)` returns `NaN` on empty `sortOrder` input**~~ — resolved. The `onChange` handler now coerces non-finite results (empty input, partial entries like `"-"`) to `0` before calling `setField`, so the payload always carries a valid number.

- ~~**`src/app/api/cron/ping/route.ts` — cron Bearer token compared with string equality**~~ — resolved. Comparison goes through a new `isAuthorized` helper that uses `crypto.timingSafeEqual` over equal-length buffers and runs a same-length dummy compare on length mismatch.

- ~~**`src/lib/auth.ts:112` — `verifyCredentials` short-circuits before bcrypt when credentials are null**~~ — resolved. The function now precomputes a dummy bcrypt hash at module load and runs `bcrypt.compare` against it on the no-credentials path, so the timing-defense contract holds whether or not `ADMIN_*` is configured.

## Architecture & Coupling

- ~~**`src/app/api/auth/login/route.ts` + `src/app/api/cron/ping/route.ts` — `getRedisConfig()` gate + `Redis.fromEnv()` bypass**~~ — resolved. Both routes now hold the resolved config and pass it to `new Redis(redisConfig)`, so `env.ts` is the single source of truth for which env vars Redis needs.

- ~~**`src/lib/env.ts:14` — deferred hex-format validation never happens at consumer site**~~ — resolved (scoped). The schema now enforces `^[0-9a-f]*$` on `ADMIN_HASH_PASSWORD` so non-hex deployments fail loudly via `EnvConfigError` instead of silently decoding to garbage and producing a 401. `SESSION_SECRET` is consumed via `TextEncoder().encode()` (not hex-decoded), so no format check is needed there — `CLAUDE.md` was updated accordingly.

## Performance

- **`src/lib/env.ts:51` — full Zod `safeParse(process.env)` on every `readRequired` call** — `getSessionSecret()` is called on every protected request; each call runs `safeParse` against the entire env schema. Memoize `readEnv()` at module scope (a one-time parse is sufficient; `vi.stubEnv` modifies `process.env` in-place and the result would still reflect the stub if read once after the stub is applied per test).

## Risk Assessment

**Medium.** The six new/modified files are well-structured and the env-centralization and state-consolidation are genuine improvements. Two correctness bugs land in this batch: the `accentColor`/`accent` mismatch in `color-mix()` (invalid CSS on projects with no accent) and `NaN` entering the `sortOrder` payload on empty input. The cron timing leak and auth short-circuit are low-severity on a single-user site but violate explicit safety contracts in the code. The `getRedisConfig()`/`Redis.fromEnv()` bypass is an architectural gap that will cause a silent regression if the env var names ever change. Nothing touches the critical auth JWT path, the feed, or the Prisma query layer.
