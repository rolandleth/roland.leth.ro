# Code Review — 2026-04-26

## Issues and Observations

- **`src/components/projects/ProjectContent.tsx:77` — `accentColor` (nullable) used in `color-mix()` instead of `accent` fallback** — `backgroundColor: color-mix(in srgb, ${accentColor} 15%, ...)` produces invalid CSS when `accentColor` is null (renders `color-mix(in srgb, null 15%, ...)`); the correctly-falled-back `accent` constant at line 31 is already available.

- **`src/components/admin/ProjectForm.tsx` — `Number(e.target.value)` returns `NaN` on empty `sortOrder` input** — clearing the field puts `NaN` into state and into the server payload; Zod/Prisma will reject it but the error message is confusing. Guard with `Number.isFinite` or coerce to `0`.

- **`src/app/api/cron/ping/route.ts` — cron Bearer token compared with string equality** — `auth !== \`Bearer ${expected}\`` short-circuits on the first differing byte, leaking secret length and prefix via timing. Use `crypto.timingSafeEqual` over equal-length buffers (running the compare even on length mismatch against a dummy buffer).

- **`src/lib/auth.ts:112` — `verifyCredentials` short-circuits before bcrypt when credentials are null** — the early `return false` runs before `bcrypt.compare`, contradicting the inline comment ("always run bcrypt regardless of email match"); a probe against a production instance where creds haven't been configured yet is observably faster.

## Architecture & Coupling

- **`src/app/api/auth/login/route.ts` + `src/app/api/cron/ping/route.ts` — `getRedisConfig()` gate + `Redis.fromEnv()` bypass** — both routes call `getRedisConfig() !== null` as a gate, then instantiate via `Redis.fromEnv()`, which re-reads `process.env` directly. If the var names in `env.ts` ever drift from what `fromEnv()` requires, the gate passes but the constructor throws. Pass the resolved `{token, url}` object to `new Redis({...})` instead.

- **`src/lib/env.ts:14` — deferred hex-format validation never happens at consumer site** — the doc comment promises "format checks live at the consumer site" but `auth.ts:116` calls `Buffer.from(credentials.passwordHash, "hex")` with no hex validation; a non-hex `ADMIN_HASH_PASSWORD` produces garbage bytes and `bcrypt.compare` silently returns `false`, indistinguishable from wrong credentials. Same for `SESSION_SECRET` (expected hex per CLAUDE.md).

## Performance

- **`src/lib/env.ts:51` — full Zod `safeParse(process.env)` on every `readRequired` call** — `getSessionSecret()` is called on every protected request; each call runs `safeParse` against the entire env schema. Memoize `readEnv()` at module scope (a one-time parse is sufficient; `vi.stubEnv` modifies `process.env` in-place and the result would still reflect the stub if read once after the stub is applied per test).

## Observability

- **`src/lib/env.ts:54` — required-var throws are generic `Error` with no `code`** — indistinguishable from business logic errors; `auth.ts:78` already special-cases `error.code` for jose errors; an `EnvConfigError` subclass (or a `.code: "ENV_MISSING"` property) would let middleware distinguish "misconfigured deploy" from other runtime errors.

- **`src/app/api/auth/login/route.ts` — successful login has no audit log** — failed attempts are logged; successes are not, so the access log has no signal for "did the legitimate user log in at 3am". One `console.info` with timestamp on success closes the gap.

## Missing Tests

- **`src/components/admin/useOrderedList.test.tsx` — `update` never asserts `sortOrder` preservation** — only `_key` is checked at line 57; a regression that overwrites `sortOrder` would pass all current tests.

- **`src/components/admin/useOrderedList.test.tsx` — no out-of-range index coverage for `remove`/`update`** — current behavior (silent no-op via `value.map`/`filter`) is unspecified; pinning it prevents a future refactor from silently changing semantics and surfacing as a production bug.

- **`src/components/admin/useAdminResource.test.tsx` — unmount guard test asserts `expect(true).toBe(true)`** — relies on Vitest unhandled-rejection detection rather than asserting the guard's actual effect; spy on `setError` (or `console.error`) and assert it was not called after unmount.

- **`src/lib/env.test.ts` — no whitespace-only value test for `nonEmpty`** — `nonEmpty(" ")` returns `" "` (truthy), so `ADMIN_HASH_PASSWORD=" "` passes the null check and `bcrypt.compare` runs against garbage. Pin the current behavior or trim in `nonEmpty`.

- **`src/components/projects/ProjectContent.tsx` — no test for null `accentColor` path** — the line 77 `color-mix()` bug would be caught by a render test with `accentColor: null`; no such test exists.

## Risk Assessment

**Medium.** The six new/modified files are well-structured and the env-centralization and state-consolidation are genuine improvements. Two correctness bugs land in this batch: the `accentColor`/`accent` mismatch in `color-mix()` (invalid CSS on projects with no accent) and `NaN` entering the `sortOrder` payload on empty input. The cron timing leak and auth short-circuit are low-severity on a single-user site but violate explicit safety contracts in the code. The `getRedisConfig()`/`Redis.fromEnv()` bypass is an architectural gap that will cause a silent regression if the env var names ever change. Nothing touches the critical auth JWT path, the feed, or the Prisma query layer.
