## Issues and observations

### 1. `post-${section}-${slug}` tag in `getPostBySlug` is never explicitly revalidated

**File:** [`src/lib/posts.ts:157`](src/lib/posts.ts)

The Map wrapper preserves the `post-${section}-${slug}` tag for potential future use, but `revalidatePostSection` only calls `feed-${section}`, `blog-${section}`, and `posts`. Section-level revalidation (`blog-${section}`) does cover `getPostBySlug`'s entries since that tag is also on the wrapper, so cache correctness is not broken. The per-post tag is dead weight today — it exists by symmetry with projects, where it is load-bearing.

No change required. Worth knowing: if a caller ever needs to invalidate a single post without busting the whole section (e.g. preview or draft toggle), the tag is already in place. If that use case never materialises, the tag can be removed when convenient.

**File:** [`src/app/api/feed/[section]/route.ts:12`](src/app/api/feed/[section]/route.ts)

`excerptFromBody` now calls `stripMarkdown` (added to `src/lib/markdown.ts`) before slicing to 300 characters. `stripMarkdown` uses `unified` + `remark-parse` + `remark-gfm` (already in the dependency graph) to parse the AST and extract text node values, skipping fenced code blocks entirely and collapsing whitespace. 10 tests added to `markdown.test.ts` covering plain text passthrough, heading/bold/italic/link/inline-code/blockquote handling, fenced code block omission, paragraph joining, empty input, and GFM strikethrough.

### 3. `ADMIN_HASH_PASSWORD` env var rename requires a Vercel config update ✅ resolved

**File:** [`src/lib/auth.ts:82`](src/lib/auth.ts)

The rename from `ADMIN_PASSWORD_HASH` to `ADMIN_HASH_PASSWORD` is purely a code-side change. Until the Vercel project's environment variable is renamed to match, `verifyCredentials` will read `undefined`, return `false`, and lock out the admin login entirely. If the Vercel var was updated before or alongside this deploy, no action needed. If not, admin login is silently broken.

No code change needed; just a deployment checklist item. The silent-false-return is the correct safe default — lockout is better than a crash.
