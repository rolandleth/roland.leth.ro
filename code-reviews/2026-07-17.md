# Code Review — 2026-07-17

## Issues and Observations

- **[src/lib/import/frontmatter.ts — `readField`/`unquote`]** — `readField` trims trailing whitespace before comparing, so `slug: hello ` (trailing space) parses to `"hello"` and `slugRewriteFor` sees `fileSlug === slug` → no rewrite planned. The on-disk file keeps drift that the "self-heal" narrative claims to erase. Fix: also plan a rewrite when the trimmed value differs from the raw remainder, or normalize on write-out.
- **[src/lib/import/postImport.ts — `resolveSlug` skip reason]** — A file with `slug:` present but empty reports `"Title produces an empty slug"`, identical to a file with no `slug:` line. The author whose blank field was ignored gets no signal. Retain raw-parsed value (empty string vs. null) and branch the message.
- **[scripts/init-post-slugs.ts:88 — `matchRow` datetime + title fallback]** — Datetime→row match binds a `length === 1` row even when the file's title disagrees (only a passive `(title differs from DB)` note is printed and the write proceeds); title fallback binds any file whose title collides with a row at a different datetime. A new file added post-import that shares a title with an existing row gets stamped with the wrong `slug:`; a subsequent `import-posts.ts --overwrite` then overwrites the wrong DB row with the new file's body. The tool never refuses a mismatched match.
- **[scripts/init-post-slugs.ts:33 — argv parsing / no unknown-flag guard]** — Unlike `import-posts.ts:68`, `init-post-slugs.ts` does not reject unknown flags. A typo (`--dryrun`, `--dry_run`, `--dry-Run`) is filtered out of `positionals` because it starts with `--`, but `argv.includes("--dry-run")` requires exact match — the script silently proceeds to rewrite files while the operator believes they are dry-running. High-blast-radius footgun on a bulk file-rewriter.
- **[scripts/import-posts.ts — `applySlugRewrites`]** — `writeFile` isn't atomic; SIGKILL, out-of-disk, or a read-only-mount race mid-write leaves a truncated `.md`. The content repo is the source of truth here, so a partial write is worse than the DB errors the script defends against. `writeFile(tmp, …)` + `rename(tmp, final)` from `node:fs/promises` closes the window cheaply.

## Architecture

- **[scripts/import-posts.ts — `main` sequence]** — `applySlugRewrites` runs before `planPostImport`, so a file whose body will later fail schema validation (>100 KB, empty section, etc.) still has its `slug:` line written to disk. Idempotent and low-blast-radius, but "dry-run reports the plan, then commit" is quietly weaker than the docstring implies; defer the write until after `planPostImport` skips, or note the ordering explicitly.

## Observability

- **[scripts/import-posts.ts — `applySlugRewrites` failure path]** — A per-file `writeFile` rejection (EACCES on one file, EROFS on one mount) throws out of the loop into `main().catch`, killing every remaining rewrite and the DB step. Per-file try/catch with an end-of-run failure summary would let a partial batch proceed.
- **[scripts/init-post-slugs.ts:272 — top-level `main().catch`]** — Errors surface only as `error.message` with no filename, phase, or already-written count. A mid-run permission failure leaves the operator unable to tell which file broke or which earlier files were already mutated; per-file logs stop mid-stream and only the tail exception remains.
- **[scripts/init-post-slugs.ts:167 — `wrote … (title differs from DB)`]** — The most dangerous outcome (matched by datetime but title disagrees — the case likeliest to be a mismatch) is logged at the same visibility as a benign stamp. No warning prefix, no summary count, no non-zero exit. Should surface separately (like `problems`) or gate behind an explicit `--allow-title-mismatch` flag.

## Missing Tests

- **[scripts/init-post-slugs.ts — entire file, ~275 LOC]** — Zero coverage. Untested branches include `matchRow` datetime-hit vs. title-fallback vs. ambiguous vs. null; `stampFile` for unparseable filename, missing `title:`, `fileSlug === row.slug` no-op, dry-run vs. write; `initFolder` fileless-rows path and problem-vs-write exit-code interaction; `resolveSection` folder-basename vs. `--section=` flag. Given the false-positive matching risk above, `matchRow` and the "title differs" branch are the load-bearing gaps.
- **[scripts/import-posts.ts — `applySlugRewrites`]** — Not asserted anywhere: rewrite runs before any DB work and mutates source files unconditionally on non-dry-run. No test pins that a subsequent DB failure leaves file-side rewrites in place (documented as intended in the header comment) or that dry-run truly suppresses writes end-to-end.
- **[src/lib/import/postImport.test.ts — `parsePostFiles`]** — No case exercising `slug:` present-but-empty (falls back to title, plans a rewrite with `previous: null`). `parseFrontmatter` covers it in isolation; the composed behavior is unpinned.
- **[src/lib/import/postImport.test.ts — `parsePostFiles`]** — No CRLF-input fixture with a needed `slugRewrite` asserting the rewritten content preserves CRLF end-to-end. `setFrontmatterSlug` has the logic and a unit test, but no integration guarantee.
- **[src/lib/import/frontmatter.test.ts — `setFrontmatterSlug`]** — Idempotency isn't asserted (`setFrontmatterSlug(setFrontmatterSlug(x, "a"), "a")` = single application). Guards against a regression that would make every re-run of the importer plan phantom rewrites.
- **[src/lib/import/postImport.ts — `resolveSlug` idempotency invariant]** — No test pins `createSlug(createSlug(x)) === createSlug(x)` for the input class the canonical-shape check relies on (accented chars, dashes, `&`). Break the invariant for one input and every canonical file starts planning a phantom rewrite silently.
- **[src/lib/import/postImport.test.ts — `planPostImport`/`resolveOverwriteSummary`]** — Edge where DB summary was derived AND `next === existing.summary`: code returns undefined so no update is planned, but no test — a regression that always writes the summary back on a no-op change wouldn't trip the suite.

## Risk Assessment

**Medium.** The library refactor (shared `parsePostFiles` between admin bulk route and import script) is clean — it deletes a class of drift bug the admin route had actually regressed into, and the existing route tests held zero-modification against the new pipeline. The bulk route's concurrent-write reconciliation (`route.ts:186-199`) and its paired test are the strongest part of the diff. The risk sits entirely on the file-mutation surface: `init-post-slugs.ts` is a new ~275-LOC script with zero test coverage and two failure modes that silently write wrong data — the `matchRow` title-mismatch path (data-corrupting) and the typo'd `--dry-run` flag (footgun on a bulk rewriter). Neither has landed in production behavior, but the tool is intended to run against real content on demand, so both should be closed before the next resync.
