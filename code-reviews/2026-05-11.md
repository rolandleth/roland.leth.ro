## Issues and Observations

- **[src/app/about/AboutContent.tsx:135 — missing `{" "}` before the Deutsche Bank `<a>`]** — The text node ends with `in large corporations like` on its own line, followed directly by the `<a>` on the next line. JSX strips the trailing newline whitespace, so the rendered DOM is `likeDeutsche Bank` with no space. Every sibling link in the same paragraph correctly uses `{" "}` (DeinDeal:143, Therme Media:159, Eventa:175→176, open source:192, this blog:200). This is a regression introduced in this commit when "in big corporations" was rewritten to "in large corporations like Deutsche Bank". Add `{" "}` after `like` or merge `like ` into the prior text node.
- **[src/app/about/AboutContent.tsx:126 — "Over the past year"]** — Carryover from the 2026-05-10 review's voice note; still unaddressed in the rewrite pass. The earlier "In the past year" reads more idiomatic in this register. Minor; subjective; flagging because the rest of the paragraph was already revised this commit, so the cost to fix is one word.
- **[src/app/error.test.tsx:39-49, src/app/global-error.test.tsx:35-45 — digest negative assertion is narrower than the contract it claims to lock]** — The comment says "the digest is intentionally not surfaced". The assertion uses `expect(container.textContent).not.toContain(error.digest)` with a 28-char literal. A future regression that rendered a truncated digest (e.g. `error.digest.slice(0, 8)`) would leak partial digest text but still pass this test, because the full literal isn't a substring. The prior review explicitly suggested `not.toMatch(/[a-f0-9]{20,}/)` or a `queryBy*` against the prior `<p>` for exactly this reason. Tighten to a regex match (or both) so partial-leak regressions also fail.
