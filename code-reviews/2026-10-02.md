## Issues and Observations

- [ ] **`src/components/admin/ProjectForm.tsx` — `PRODUCT_PAGE_FIELDS` / `metaDescription`** — the field shows only while "Own app" is ticked, but `src/app/projects/[slug]/page.tsx` `generateMetadata` uses `metaDescription ?? summary` for every project. When the author unticks "Own app", the value stays hidden, still sets the search snippet, and can't be cleared. Send null when `isOwnApp` is false, or show the field for every project.
- [x] **`src/lib/content/rehypeNumberedSteps.ts` — `STEP_PREFIX` / `parseStepHeading`** — only the heading's first text node is tested, so `### 1. **Log** a meal`, `### 1. [Log](…)` and `### 1. \`x\`` stay plain h3s with no warning (the first text node is "1. ", which fails `(?=\S)`). A bold or linked first word is a normal way to write a step title. **Resolved 2026-10-02**: the markdown steps parser is gone; steps are a `steps` section's own items.
- [x] **`src/lib/utils/productPage.ts` — `hasNumberedSteps` / `STEP_HEADING_LINE`** — the comment says it "mirrors" the plugin, but it doesn't. It says yes to a bold/link/code start and to `### 1.` inside fenced code. It says no to 1–3 leading spaces and to an escaped `1\.`. So `ProductPage` `stepsIndex` can show "See how it works" for a section with no steps, or hide it for a section that has them. Use one shared predicate, or detect steps on the tree. **Resolved 2026-10-02**: `hasNumberedSteps` is gone; "See how it works" points at the `steps` section by its kind.
- [ ] **`src/lib/utils/productPage.ts` — `sectionAnchors` / `RESERVED_ANCHORS`** — only bare ids are reserved. The rendered `faq-title`, `pricing-title`, `get-title`, `guides-heading` and each `${anchor}-title` are not, so sections "Foo" and "Foo title" both produce `foo-title`: duplicate ids and an ambiguous `aria-labelledby`. Also, `guides` is reserved but nothing renders that id. (Both the rendering and the helper analyzers found this.)
- [ ] **`src/components/projects/product/ProductToc.tsx` — observer callback** — the callback uses only entries that enter the band and never clears `activeId`. After a scroll back into the hero, the first item stays marked, and FAQ stays marked after you scroll into the closing. That doesn't match the unmarked state at load.
- [ ] **`src/components/projects/GalleryTrack.tsx` — `isLazy`** — every non-priority slide is `loading="lazy"`, including the neighbours clipped by the `overflow-hidden` stage. The lazy-load margin doesn't apply to clipped content, so each first swipe in a product carousel shows a blank slide while it loads. The tabbed layout still loads neighbours eagerly.
- [ ] **`src/lib/api/schemas.ts` — `refineProjectPlans`** — a partial PUT that sends `plans` alone (for example, renaming a plan) skips the offer checks. Stored offers then point at a plan that doesn't exist, and `groupOffersByPlan` drops them, so the cards show no price and nothing reports it. The reverse case (offers without `plan`, with plans already stored) ends the same way. Only a raw API client can do this today, because the form never sends `plans`/`offers`.
- [ ] **`src/lib/api/schemas.ts` — `priceCurrency` / `billingPeriod`** — `priceCurrency` is checked only as `length(3)`, so a value like "US$" passes and `Intl.NumberFormat` in `formatPrice` throws a RangeError during render, which takes down the whole product page. `billingPeriod` is checked only as `max(10)`: `""` gets no label where "once" is meant, and `P0M` reads "every 0 months". - [ ] **`src/lib/api/schemas.ts` — `projectFields.plans` / `palette`** — `.optional()` without `.nullable()`, so a PUT can't clear them, and only a re-import (delete + recreate) can. This differs from the new nullable text fields.

## Risk Assessment

**Medium.** A large feature landed in one day: three new nullable schema areas (product text, `plans`/`palette` Json, `hasPlans`/`alt`), a new rehype plugin and processor, nine product components and a Header restyle hook. The data changes are additive, so `db:push` loses nothing. Revalidation is unchanged. The slug route still serves a real 404 (no `loading.tsx` above it), and nothing makes it dynamic. The write-side validation of the colours written into `<style>` is solid and tested. The risk is at the edges, not in the plumbing:
- The step detection rule exists twice and the two copies already disagree.
- The schema accepts a currency string that crashes the render.
- A partial PUT can orphan offers.
- A hidden admin field still controls every project's meta description.
- The lazy neighbour slides blank out on the first swipe.

None of these are reachable through normal admin use, apart from the `metaDescription` toggle, the blank slides and the step-title markup. Those three are what visitors or the author will actually hit.
